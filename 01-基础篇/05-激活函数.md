# 激活函数

> 激活函数的演进直接影响 LLM 性能，SwiGLU 是当下主流。

---

## Q1: 经典激活函数对比？

**答**：

| 激活函数 | 公式 | 优点 | 缺点 |
|---------|------|------|------|
| Sigmoid | $1 / (1 + e^{-x})$ | 输出 $(0,1)$ 可解释 | 饱和导致梯度消失，非零中心 |
| Tanh | $(e^x - e^{-x}) / (e^x + e^{-x})$ | 零中心 | 仍饱和 |
| ReLU | $\max(0, x)$ | 简单、快，缓解梯度消失 | 死神经元（负区梯度 0） |
| Leaky ReLU | $\max(\alpha x, x)$ | 缓解死神经元 | 多了超参 |
| GELU | $x \cdot \Phi(x)$ | 平滑、有概率解释 | 计算稍贵 |
| Swish/SiLU | $x \cdot \sigma(x)$ | 平滑、自门控 | 与 GELU 类似 |
| GLU 系列 | $\sigma(xW + b) \otimes (xV + c)$ | 门控、表达强 | 参数翻倍 |

---

## Q2: GELU 的定义和动机？

**答**：
$$\text{GELU}(x) = x \cdot \Phi(x)$$
其中 $\Phi$ 是标准正态 CDF。常用近似：
$$\text{GELU}(x) \approx 0.5 x (1 + \tanh(\sqrt{2/\pi}(x + 0.044715 x^3)))$$

**直观**：GELU 是"软"版的 ReLU，对小的负输入也保留少量信号（与高斯分布的概率成正比）。

**为什么 BERT/GPT-2 用 GELU**：
- 平滑可导，优化更稳。
- 对负值不完全截断，信息保留更多。
- 实验上比 ReLU 略好。

## Q3: SwiGLU 是什么？为什么 LLaMA 选择它？

**答**：
**SwiGLU 是 GLU 家族的成员**：
$$\text{SwiGLU}(x) = \text{Swish}(xW_1) \otimes (xW_3)$$
其中 $\text{Swish}(x) = x \cdot \sigma(x)$，$\otimes$ 是逐元素乘。

**完整 FFN 形式**（LLaMA）：
```python
def FFN(x):
    return W_2 @ (swish(W_1 @ x) * (W_3 @ x))
```

**对比原始 FFN**（GPT-2 / BERT）：
```python
def FFN(x):
    return W_2 @ gelu(W_1 @ x)
```

**为什么 SwiGLU 更好**：
- 引入**门控机制**：$W_3 x$ 控制信息通过的强度。
- "GLU Variants Improve Transformer"（Shazeer, 2020）实验显示 SwiGLU 在多种任务上稳定优于 GELU。
- LLaMA、Qwen、Mistral、DeepSeek 全用 SwiGLU。

## Q4: SwiGLU 的 FFN 中间维度为什么是 $\frac{8}{3}d$？

**答**：
- **原因**：SwiGLU 用 3 个权重矩阵（$W_1, W_2, W_3$），原始 FFN 只用 2 个（$W_1, W_2$）。
- **参数量对齐**：原始 FFN 中间维度 $4d$ → 参数量 $2 \cdot 4d \cdot d = 8d^2$
- 要让 SwiGLU FFN 参数量也是 $8d^2$，需要 $3 \cdot h \cdot d = 8d^2$，得 $h = \frac{8}{3}d$。
- 实际工程上会取 64 或 128 的倍数（对齐 GPU），如 LLaMA-7B 中 $d=4096$，FFN 中间维度 $11008 \approx \frac{8}{3} \times 4096$ 向上取整对齐 256。

## Q5: Softmax 的数值稳定性？

**答**：
直接计算 $e^{x_i} / \sum e^{x_j}$ 会因为 $x$ 较大时 $e^x$ 溢出。

**稳定写法**：
$$\text{softmax}(x_i) = \frac{e^{x_i - \max(x)}}{\sum_j e^{x_j - \max(x)}}$$

减去最大值不改变结果（分子分母同除一个常数），但保证最大指数项为 $e^0 = 1$，不溢出。

**Log-sum-exp**：
$$\log \sum e^{x_i} = \max(x) + \log \sum e^{x_i - \max(x)}$$

PyTorch 中 `F.log_softmax` 和 `F.cross_entropy`（接收 logits）都用这种稳定形式。

**FlashAttention** 中也用 online softmax + 减最大值技巧，分块计算时维护一个 running max。

---

## Q6: 为什么不用 Sigmoid 做注意力的归一化？

**答**：
- Softmax 输出严格归一化到和为 1，是"分配权重"语义。
- Sigmoid 各位置独立 → 可能多个位置都接近 1，分配语义不清。
- 但近年有研究尝试 sigmoid attention（如 Apple 的工作）证明可行性，未成主流。

---

## Q7: 激活函数会影响推理速度吗？

**答**：
会，且 SwiGLU 这种"3 矩阵 + 门控"比 GELU 慢约 50%（多一个矩阵乘 + 一个逐元素乘）。但：
- 现代 LLM 中 FFN 占 ~65% 计算，激活函数本身只占其中小部分。
- 在效果显著提升下，这点代价值得。
- 推理框架（如 vLLM）会做算子融合：Swish + 逐元素乘 + 矩阵乘融合成一个 kernel。

## 🎯 高频追问

1. **GELU 和 Swish 谁更好**？很接近，实际差异 < 0.1 个 PPL。GELU 在 BERT/GPT-2 时代成名，Swish 在 LLM 时代更主流（SwiGLU 选 Swish 作基底）。
2. **ReLU 的死神经元如何缓解**？合理初始化（He/Kaiming）、Leaky ReLU、LayerNorm。
3. **为什么不用 tanh**？饱和区梯度趋零，深层网络梯度消失严重。
4. **Softmax 在长序列上的问题**？输出过度集中（attention 退化为 hard），可结合温度或 sparsemax 缓解。
