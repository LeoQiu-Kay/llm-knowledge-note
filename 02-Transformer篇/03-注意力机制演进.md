# 注意力机制演进：MHA → MQA → GQA → MLA

> 一切演进只为解决一个问题：KV Cache 太大。

---

## 1. 演进的根源：推理瓶颈在 KV Cache

自回归推理时：
- 历史 token 的 K/V 缓存在显存里
- 每生成一个新 token，需要把整个 KV Cache 从 HBM 读到 SRAM 算 attention
- KV Cache 越大 → 显存带宽吃满 → 每 token 延迟越长

**KV Cache 大小**（MHA）：

$$\text{KV Cache} = 2 \cdot L \cdot s \cdot h \cdot d_h \cdot \text{bytes}$$

**符号说明**：
- $2$：K 和 V 两份
- $L$：模型层数（如 LLaMA-2-70B 有 80 层）
- $s$：序列长度（包含 prompt + 生成的 token 数）
- $h$：**KV 头数**（MHA 中等于注意力头数；MQA 中为 1；GQA 中为分组数 $g$）
- $d_h$：每头维度（如 128）
- $\text{bytes}$：每个数值占多少字节（FP16/BF16 = 2，FP8/INT8 = 1）

例：LLaMA-2-70B FP16，4K 序列 → 约 **2.5 GB / 用户**。

```text
压缩 KV Cache → 演进的唯一动机。
```

---

## 2. MHA：基线

每个头独立有 $W^Q_i, W^K_i, W^V_i$。

**符号说明**：
- $h$：头数（典型 32-96）
- $d$：模型隐藏维度
- $d_h = d / h$：每头维度

**KV Cache 包含 $h$ 套 K/V**，是最大的版本。

---

## 3. MQA：所有头共享同一组 K/V

**思路**（Shazeer 2019）：Q 仍然多头，但 **K, V 只有一份**，所有 Q 头共享。

```
MHA:  Q_1 vs K_1, V_1     头 1 独立 K/V
      Q_2 vs K_2, V_2     头 2 独立 K/V
      ...

MQA:  Q_1 vs K, V
      Q_2 vs K, V          所有 Q 头共享同一 K, V
      ...
```

**KV Cache**：缩小 $h$ 倍（公式中 $h$ 从头数变成 1）。

例：32 头 MHA → MQA，KV Cache **缩小 32 倍**。

**代价**：表达力下降，效果略低于 MHA。

**用户**：PaLM、Falcon。

---

## 4. GQA：MHA 和 MQA 的折中

**思路**：Q 仍然 $h$ 头，K/V 分成 $g$ 组（$1 \leq g \leq h$）。每组 K/V 被 $h/g$ 个 Q 头共享。

```
GQA (g=2, h=8):
   Q_1, Q_2, Q_3, Q_4 → K_1, V_1（共享组 1）
   Q_5, Q_6, Q_7, Q_8 → K_2, V_2（共享组 2）
```

**符号说明**：
- $g$：KV 组数（新增的超参）
- $h/g$：每组 K/V 被多少 Q 头共享

**特例**：
- $g = h$：每组只有 1 个 Q 头 → **退化为 MHA**
- $g = 1$：所有 Q 头共享 → **退化为 MQA**

**KV Cache**：缩小 $h/g$ 倍。

**LLaMA-2/3 选择 $h = 64, g = 8$** → 缩小 8 倍，效果几乎无损（< 0.5% PPL 差距）。

```text
GQA 是 MHA 和 MQA 的"调参"折中。
LLaMA / Qwen / Mistral 全用 GQA，现代默认。
```

---

## 5. MLA：低秩压缩替代"粗暴共享"

**DeepSeek-V2/V3** 的方案。换个思路：不"共享 K/V"，而是"压缩 K/V"。

### 5.1 核心机制

把每个 token 的 hidden state 投影到低维潜空间：

$$c^{KV} = W^{D} \cdot h$$

**符号说明**：
- $h \in \mathbb{R}^d$：当前 token 的 hidden state
- $W^D \in \mathbb{R}^{d_c \times d}$：下投影矩阵
- $c^{KV} \in \mathbb{R}^{d_c}$：潜空间向量（$d_c \ll d$，典型 $d_c = 512$）

**只缓存 $c^{KV}$**（潜向量），不缓存完整 K, V。

需要时上投影还原：

$$K = W^{UK} \cdot c^{KV}, \quad V = W^{UV} \cdot c^{KV}$$

**符号**：$W^{UK}, W^{UV} \in \mathbb{R}^{d \times d_c}$ 是上投影矩阵。

**KV Cache 大小**：

$$L \cdot s \cdot d_c \cdot \text{bytes}$$

比 GQA 还小，因为 $d_c \ll g \cdot d_h$。

### 5.2 矩阵吸收技巧

实际推理时不需要显式还原 K, V：
- $W^{UK}$ 可与 $W^Q$ 合并
- $W^{UV}$ 可与 $W^O$ 合并

直接用 $c^{KV}$ 算 attention，更快。

### 5.3 解耦 RoPE：MLA 的难点

**问题**：低秩压缩会破坏位置信息（RoPE 旋转作用在 K 上的）。

**解法**：保留一小段维度专门承载 RoPE，不压缩：

$$K = [\underbrace{K_c}_{\text{压缩还原}}, \, \underbrace{K^R}_{\text{专门给 RoPE，不压缩}}]$$

**符号**：
- $K_c$：压缩还原的部分（不含位置信息）
- $K^R$：独立的小段，承载 RoPE 旋转后的位置信号（维度 $d^R_h$，典型 64）

Q 也对应分段。

---

## 6. 四者对比

| 方案 | KV Cache 大小 | 效果 | 实现复杂度 | 代表 |
|---|---|---|---|---|
| MHA | 基线 $2Lsh d_h$ | 最好 | 简单 | GPT-3、LLaMA-1 |
| MQA | 缩小 $h$ 倍 | 略降 | 简单 | PaLM、Falcon |
| GQA | 缩小 $h/g$ 倍 | 几乎无损 | 简单 | **LLaMA-2/3, Qwen, Mistral** |
| MLA | 缩小到 $L s d_c$ | 最好 | 复杂（解耦 RoPE） | **DeepSeek-V2/V3** |

---

## 7. 显存对比（LLaMA-70B 配置，128K 序列，FP16）

| 方案 | KV Cache（粗估） |
|---|---|
| 假设 MHA（$h = 64$） | ~340 GB |
| GQA（$g = 8$） | ~42 GB |
| MLA（$d_c = 512$） | ~10 GB |

差距决定了**单卡能并发服务多少用户**。

---

## 8. 最简记忆

```text
演进动机：KV Cache 太大，推理是 memory-bound。

MHA  每头独立 K/V       → 基线，但 KV Cache 大
MQA  所有头共享 K/V      → 缩 h 倍，效果略损
GQA  分 g 组共享 K/V     → 缩 h/g 倍，几乎无损（现代主流）
MLA  低秩压缩 K/V        → 缩更多，效果略升（DeepSeek 独家）

MLA 的代价：实现复杂（解耦 RoPE）。
```

## 🎯 高频追问

1. **GQA 训练时有加速吗**？没有明显加速（训练 batch 大，KV Cache 不重要）。GQA 的好处只在推理。

2. **能从 MHA 训练好的模型转 GQA 吗**？可以 "uptraining"：把 K/V 头的若干个平均合并，少量步数微调即可。

3. **MLA 实现复杂在哪**？需要解耦 RoPE、推理时矩阵吸收、训练时两路梯度都要正常。

4. **GQA 的 $g$ 怎么选**？经验 $g = 8$。太小 KV Cache 小但效果损失大；太大接近 MHA。

5. **MLA 和 LoRA 的关系**？都用"低秩"思想。MLA 是架构层用于缓存，LoRA 是微调层用于参数更新。
