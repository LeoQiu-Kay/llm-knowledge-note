# 训练稳定性

> Loss spike、BF16 vs FP16 是大模型训练常见问题。

---

## 1. Loss spike 是什么？

**Loss spike**：训练中 loss 突然飙升（如从 2.5 跳到 8.0），可能恢复也可能彻底发散。

**常见原因**：
1. **学习率过大**：参数更新跨度大
2. **梯度爆炸**：未裁剪或阈值过大
3. **数据异常**：某 batch 编码错误、异常长度
4. **数值精度问题**：FP16 下激活溢出
5. **优化器状态错误**：Adam 的 $v$ 太小，分母趋零
6. **Loss Scaling 不当**

**处理**：
1. 回滚 checkpoint，跳过坏 batch
2. 降低 LR、加严梯度裁剪
3. 切到 BF16（如果原来用 FP16）
4. 检查数据，过滤异常样本

**预防**：BF16 + 充分 warmup + grad_clip = 1.0 + 数据预清洗。

---

## 2. BF16 vs FP16

**问题**：LLM 梯度通常很小（$10^{-6}$ 量级）。

| 格式 | 指数位 | 范围 | 精度 |
|---|---|---|---|
| FP16 | 5 | **小**（$10^{-5}$ 到 65504） | 中 |
| BF16 | **8** | 大（同 FP32） | 低 |

**FP16 问题**：表示不了 $10^{-6}$ 的梯度 → 下溢为 0 → 训练停滞。

**解法**：**Loss Scaling**：
$$\text{loss}' = S \cdot \text{loss}$$

**符号说明**：
- $S$：Loss Scale（典型 65536）
- loss × $S$ → 梯度 × $S$ → 搬到 FP16 可表示范围
- 更新前梯度 ÷ $S$ 还原

**动态 Loss Scaling**：
- 初始 $S$ 设大
- 出现 inf/nan → $S$ 减半
- 连续 N 步无 inf → $S$ 加倍

**BF16 的优势**：指数位与 FP32 相同，范围足够，**几乎不需要 Loss Scaling**。

```text
BF16 是当前 LLM 训练事实标准。
FP16 仅在不支持 BF16 的硬件（如 V100）用。
```

---

## 3. FP8 训练的挑战

**H100 / Blackwell 引入 FP8**：理论 2× over BF16。

**FP8 两种格式**：
- **E4M3**（1 符号 + 4 指数 + 3 尾数）：精度优先，前向用
- **E5M2**（1 符号 + 5 指数 + 2 尾数）：范围优先，反向用

**挑战**：
1. 范围小 → 需要 per-tensor/per-block scaling
2. outlier 容易撑爆量化范围
3. 比 BF16 更敏感

**实践**：
- NVIDIA Transformer Engine 库自动 FP8
- DeepSeek-V3 用 FP8 训练成功，节省 ~50% 显存
- 通常 FP8 计算 + BF16 主权重副本

## 4. 梯度裁剪策略

**两种主流**：

**By value**（逐元素）：
$$g_i \leftarrow \text{clip}(g_i, -c, c)$$

**By norm**（全局 L2 范数）（**主流**）：
$$g \leftarrow g \cdot \min\left(1, \frac{\tau}{\|g\|_2}\right)$$

**符号说明**：
- $\|g\|_2$：所有参数梯度合起来的 L2 范数（标量）
- $\tau$：裁剪阈值（典型 1.0）

**为什么 by norm 更好**：保持梯度方向，只压缩大小。

**经验**：
- 训练初期梯度大、裁剪频繁
- 稳定后裁剪偶发
- 一直在裁剪 → LR 可能过大

---

## 5. Warmup 的作用

训练初期 Adam 的 $v_t$ 由很少样本估计，不准确：

- 大学习率 → $v$ 偶尔很小 → 分母小 → 步子超大 → loss 爆
- Warmup 给 $v$ 时间稳定

**典型**：1000-2000 步，约 0.5%-1% 总步数。

**符号**：从 LR = 0 线性升到 $\eta_{\max}$。

---

## 6. 数据问题导致的不稳

**常见问题**：
- 超长序列截断不当
- tokenizer 失败产生异常 token id
- 空数据
- 海量重复 token（如某网页代码）
- 域偏移大

**检测**：
- 监控 loss per sample 分布
- 设置 loss 阈值告警
- 抽样审查异常 batch

**预防**：长度过滤（如 < 50 字符或 > 200K 丢弃）、N-gram 重复过滤。

---

## 7. 训练监控指标

**必监控**：
1. **Loss**：训练 loss、验证 loss
2. **梯度范数**：监控爆炸
3. **学习率**：调度是否正确
4. **吞吐量**：tokens/sec/GPU
5. **GPU 利用率 / 显存**
6. **梯度 / 权重 norm 比**：参数是否在被有效更新

**进阶**：
- 每层激活 / 梯度的统计（均值、std、norm）
- Attention entropy（是否退化到 hard）
- 输出多样性

**工具**：WandB、TensorBoard、NeMo / DeepSpeed 自带 logger。

---

## 8. 重启训练

**Checkpoint 包含**：
- 模型权重
- 优化器状态（Adam $m, v$, FP32 副本）
- 学习率调度器状态
- 数据加载器状态（处理到哪个 batch）
- 随机种子

**Loss spike 处理**：
- 回滚到 spike 前 checkpoint
- 跳过导致 spike 的 batch
- 重启时降 LR 或加强裁剪

---

## 9. 千卡 / 万卡训练的额外挑战

1. **节点故障**：每天有节点宕机，需要自动检测 + 重启
2. **网络抖动**：通信卡顿导致 step 时长不稳
3. **稳定性**：单点故障 → 整次训练失败
4. **数据加载**：大数据集预处理 + 分发
5. **Determinism**：复现结果困难

**工程实践**：
- 健康检查 + auto-restart
- Async checkpoint（不阻塞训练）
- 定期 checkpoint（每 1000 步）
- 弹性训练（PyTorch elastic）

---

## 10. 最简记忆

```text
Loss spike 常见原因：
  LR 大 / 梯度爆炸 / 坏 batch / FP16 溢出 / 优化器异常

预防三件套：
  BF16 + Warmup + grad_clip = 1.0

精度选择：
  BF16 → 默认首选（不需 Loss Scaling）
  FP16 → 老硬件
  FP8  → H100，DeepSeek-V3 验证可行

梯度裁剪：by norm（全局 L2 范数），τ = 1.0
```

## 🎯 高频追问

1. **BF16 真的完全替代 FP16 了吗**？训练几乎是。推理仍有 FP16 场景（V100 等老硬件）。

2. **梯度爆炸 vs Loss spike**？梯度爆炸是更新过大，loss spike 是结果现象；两者常同时出现。

3. **学习率应该多大**？LLaMA-3 用 $\eta_{\max} \approx 3 \times 10^{-4}$。可用 LR finder 探测。

4. **Pre-Norm 真的解决了不稳定吗**？比 Post-Norm 好得多，但千层级仍需 DeepNorm 等。

5. **FP8 训练成功案例**？DeepSeek-V3 是最有名的（公开技术报告详细）。
