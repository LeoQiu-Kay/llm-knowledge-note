# 通信与显存

> 集合通信原语 + 显存估算，分布式训练面试常考。

---

## 1. 集合通信原语

**符号约定**：以下示意 2 个 GPU 的情况。

### 1.1 AllReduce

每个进程都有一个 tensor，所有进程的 tensor 按某操作（sum/avg）聚合，所有进程最终拥有相同的结果。

```
GPU 0: [1, 2]    AllReduce(sum)    GPU 0: [4, 6]
GPU 1: [3, 4]   ─────────────→    GPU 1: [4, 6]
```

**用于**：DP 梯度同步。

### 1.2 AllGather

每个进程有一个 tensor 分片，所有进程聚合得到完整 tensor，每个进程拥有完整结果。

```
GPU 0: [1, 2]    AllGather    GPU 0: [1, 2, 3, 4]
GPU 1: [3, 4]   ──────────→   GPU 1: [1, 2, 3, 4]
```

**用于**：ZeRO-3 还原参数。

### 1.3 ReduceScatter

AllReduce 的"反向"：每个进程做 reduce，但每个进程只保留一部分结果。

```
GPU 0: [1, 2, 3, 4]   ReduceScatter   GPU 0: [6]   ← sum of GPU0[0], GPU1[0] 
GPU 1: [5, 6, 7, 8]   ────────────→   GPU 1: [10]  ← sum of GPU0[1], GPU1[1]
```

**用于**：ZeRO-3 梯度规约。

### 1.4 All-to-All

每个进程有 $N$ 份数据（$N$ 是进程数），第 $i$ 份发给进程 $i$。

**用于**：MoE 专家路由、序列并行。

### 1.5 数学等价

$$\text{AllReduce} = \text{ReduceScatter} + \text{AllGather}$$

ZeRO-3 把 AllReduce 拆开，更省显存。

## 2. NCCL 通信的硬件层级

**节点内**：
- **NVLink**（A100 ~600 GB/s，H100 ~900 GB/s）：GPU 间直连
- **NVSwitch**：让一个节点内所有 GPU 全互联

**跨节点**：
- **InfiniBand**（HDR 200 Gb/s，NDR 400 Gb/s）
- **以太网 + RoCE**：性价比

**优化**：NCCL 自动选 Tree / Ring / Double-Tree 等拓扑。

## 3. 显存怎么估算（训练）

**训练时显存**（BF16 + Adam）：

| 项 | 大小 |
|---|---|
| 参数（BF16） | $2 \Psi$ |
| 梯度（BF16） | $2 \Psi$ |
| Adam $m$（FP32） | $4 \Psi$ |
| Adam $v$（FP32） | $4 \Psi$ |
| FP32 参数副本 | $4 \Psi$ |
| **模型状态合计** | **$16 \Psi$** |
| 激活值 | $\sim BLH \cdot L_{\text{layers}}$ |

**符号说明**：
- $\Psi$：参数量
- $B$：batch
- $L$：序列长
- $H$：hidden dim
- $L_{\text{layers}}$：层数

### 示例：7B 模型 BF16 训练

- 模型状态：$16 \times 7 = 112$ GB
- 激活（4K seq, batch 4，无 GC）：~30 GB
- 总：~140 GB

**远超单卡 80GB** → 必须 ZeRO 或 TP/PP。

---

## 4. 推理时显存

**推理时**（无梯度、无优化器状态）：

| 项 | 大小 |
|---|---|
| 参数（BF16） | $2\Psi$ |
| KV Cache | 见 KV Cache 篇 |
| 激活 | 小（无反向） |
| 临时缓冲 | 小 |

```text
推理显存 = 参数 + KV Cache + 余量
```

参数和 KV Cache 占主导。

---

## 5. 激活值显存估算

**单层 Transformer 激活值**（粗估）：
- Attention 的 Q, K, V, scores：$\sim 4 BLH$
- Attention 输出：$BLH$
- FFN 中间：$\sim 4 BLH$
- **总：$\sim 12 BLH$ per layer**

**全模型**：$12 BLH \cdot L_{\text{layers}}$ × bytes。

**例**：7B 模型，$B = 4, L = 4096, H = 4096, L_{\text{layers}} = 32$
- $12 \times 4 \times 4096 \times 4096 \times 32 \times 2$ bytes ≈ **50 GB**

```text
所以 Gradient Checkpointing 几乎是必备。
```

## 6. 梯度累积

**目的**：小卡装不下大 batch 时，用多次小 batch 累积。

**伪代码**：
```python
optimizer.zero_grad()
for i in range(accum_steps):
    loss = model(micro_batch_i).loss / accum_steps   # 必须除 accum_steps
    loss.backward()
optimizer.step()
```

**等价**：

$$\text{equivalent\_batch} = \text{micro\_batch} \times \text{accum\_steps}$$

**注意**：
- loss 必须除 accum_steps（取平均）
- LayerNorm/RMSNorm 不受影响（per-sample）
- LR 调度中"step"指优化步

## 7. 梯度检查点（Gradient Checkpointing）

**目的**：用计算换显存。

**思路**：
- 前向只存少量"检查点"
- 反向时**重算**中间激活

**效果**：
- 显存：$O(L_{\text{layers}}) \to O(\sqrt{L_{\text{layers}}})$
- 计算：约 +33%（多一次前向）

**PyTorch 实现**：
```python
from torch.utils.checkpoint import checkpoint

def forward(x):
    for layer in layers:
        x = checkpoint(layer, x)
    return x
```

**Selective Checkpointing**：只对显存大的层 checkpoint（如 attention 中间结果）。FlashAttention 内部也用这个思想。

## 8. CPU / NVMe Offload

**DeepSpeed ZeRO-Offload**：把 Adam 状态（FP32 momentum + variance）放 CPU 内存或 NVMe。

**适用**：单卡装不下、不在意速度。

**缺点**：PCIe 带宽是瓶颈，训练慢得多。

---

## 9. 通信与计算重叠

**机会**：
- DP 反向算靠后层时，靠前层的梯度可同时 AllReduce
- ZeRO-3 参数 AllGather 可与前向前几层重叠

**PyTorch DDP** 自动桶（bucket）合并 + 重叠。

---

## 10. 显存碎片

**问题**：训练 / 推理中频繁分配释放，导致内存碎片。

**PyTorch 措施**：
- `torch.cuda.empty_cache()` 清理 cached 但未用的 block
- `PYTORCH_CUDA_ALLOC_CONF` 调整 allocator 策略（如 `expandable_segments:True`）

**推理（vLLM）**：PagedAttention 直接解决。

---

## 11. 最简记忆

```text
集合通信：
  AllReduce      → DP 梯度同步
  AllGather      → ZeRO-3 还原参数
  ReduceScatter  → ZeRO-3 梯度规约
  All-to-All     → MoE 路由、序列并行

显存大头（训练）：
  模型状态 16Ψ + 激活值 ~12BLH × layers
  Gradient Checkpointing 几乎必备

换的两个维度：
  显存 ↔ 计算（gradient checkpointing）
  显存 ↔ 通信（ZeRO）
  显存 ↔ 速度（CPU offload）
```

## 🎯 高频追问

1. **AllReduce 的通信量**？Ring AllReduce：$2(N-1)/N \cdot \Psi \approx 2\Psi$，与 GPU 数无关。

2. **ZeRO-3 比 ZeRO-2 多多少通信**？多一次 AllGather（前向时），总通信约 1.5×。

3. **CPU Offload 适合什么**？资源极有限（单卡）+ 不在意速度。

4. **NVLink 满载 AllReduce 多快**？A100 节点内 8 卡 AllReduce 100 GB 数据约 200 ms。

5. **激活值能切吗**？可以，SP（序列并行）和 Megatron-SP 就是切激活。
