# 并行策略（DP / TP / PP / SP / EP）

> 训练 LLM 必须懂的并行方法，3D 并行是工业标准。

---

## Q1: 数据并行（DP）的核心？

**答**：
**朴素 DP**：每张卡持有完整模型，处理不同数据，反向后 **AllReduce** 同步梯度。

**问题**：
- 模型必须放得下单卡（大模型不行）
- 每步通信全部梯度（巨大）

**PyTorch DDP**：
- 反向同时进行 AllReduce（计算/通信重叠）
- 桶（bucket）合并小 tensor 减少通信次数

**适用规模**：小模型（< 单卡显存）。

---

## Q2: ZeRO（DeepSpeed）的三个阶段？

**答**：
**ZeRO 思想**：DP 中每张卡持有完整模型状态有大量冗余。ZeRO 把模型状态切分到多卡。

**三个阶段**：

| 阶段 | 切分什么 | 显存节省 | 通信开销 |
|------|---------|---------|---------|
| **ZeRO-1** | 优化器状态（Adam 的 m、v、FP32 副本） | ~4× | 无额外 |
| **ZeRO-2** | + 梯度 | ~8× | 反向加 AllReduce |
| **ZeRO-3** | + 参数 | ~$N$× | 前后向需要 AllGather |

**模型状态构成**（Adam，FP16 训练）：
- 参数 FP16: $2\Psi$ bytes（$\Psi$ 是参数量）
- 梯度 FP16: $2\Psi$ bytes
- Adam 状态: $12\Psi$ bytes（m FP32 + v FP32 + 参数 FP32 副本）
- 总: $16\Psi$ bytes

**ZeRO-3 显存**：理论上 $16\Psi / N$（N 是 GPU 数），但激活值另算。

---

## Q3: FSDP 是什么？与 ZeRO 的关系？

**答**：
**FSDP**（Fully Sharded Data Parallel）：PyTorch 原生的 ZeRO-3 实现。

**对应关系**：
- FSDP 的 `ShardingStrategy.FULL_SHARD` ≈ ZeRO-3
- FSDP 的 `ShardingStrategy.SHARD_GRAD_OP` ≈ ZeRO-2
- FSDP 的 `ShardingStrategy.HYBRID_SHARD` ≈ 节点内 ZeRO-3 + 节点间 DP

**优势**：
- PyTorch 原生维护，与生态兼容性好
- 性能近年追平 DeepSpeed

**劣势**：
- 配置不如 DeepSpeed 灵活
- 大集群训练 DeepSpeed 仍受青睐

---

## Q4: 张量并行（TP）的核心？

**答**：
**TP（Megatron-LM 提出）**：把单层的权重矩阵切分到多卡，**层内并行**。

**Self-Attention 中的 TP**：
- **列并行 $W^Q, W^K, W^V$**：每张卡持有一部分头
  - 输出按列拼接（concat）
- **行并行 $W^O$**：每张卡处理对应头的输出
  - 输出 AllReduce 合并

**FFN 中的 TP**：
- **列并行 $W_1$**（$d \to 4d$）：输出按列分布
- **行并行 $W_2$**（$4d \to d$）：输入对应列，输出 AllReduce

**关键技巧**：列并行 + 行并行交替，AllReduce 只在 block 边界。

**通信**：每层 2 次 AllReduce（attention + FFN），**通信量大**。

**适用**：节点内（NVLink 高带宽），TP 大小通常 = 单节点 GPU 数（如 8）。

---

## Q5: Pipeline 并行（PP）的核心？

**答**：
**PP**：把模型按层切分到多卡，**层间并行**。

**朴素 PP**：
- 卡 1 算前 N/M 层，卡 2 算后 N/M 层
- 卡 1 做完传给卡 2
- **问题**：大量气泡（bubble，卡空闲）

**GPipe**（Google）：
- 把 batch 切分成 microbatch
- 第一个 microbatch 沿管道流，第二个跟着进
- 减少气泡，但仍有

**PipeDream / 1F1B**（One-Forward-One-Backward）：
- 前向和反向交错执行
- 进一步减少气泡

**Interleaved 1F1B**（Megatron）：
- 每张卡持有不同的层 chunk（如卡 0 持有 1-4 层 + 13-16 层）
- 进一步减少气泡

**气泡公式**：朴素气泡比例 $(P-1)/M$（P 是 stage 数，M 是 microbatch 数）。

**适用**：跨节点（PP 通信少，只在边界传 activation）。

---

## Q6: 序列并行（SP）的核心？

**答**：
**问题**：训练长序列时，attention 计算 + 激活值显存巨大。

**Megatron-SP**：
- 在 TP 基础上，把 LayerNorm 和 dropout 的激活也按序列维度切分
- 不能切的部分（attention）保持 TP

**DeepSpeed-Ulysses**：
- 用 All-to-All 在 attention 计算时按头维度切分
- 其他部分按序列维度切分
- 支持百万 token 训练

**Ring Attention**：
- 在多设备间环形传递 K/V
- 与 FlashAttention 兼容
- Gemini 1.5（1M context）用此

---

## Q7: 专家并行（EP）：MoE 必备？

**答**：
**MoE 模型的特殊性**：
- 每层有 N 个专家（如 8 或 256 个）
- 每个 token 只激活 K 个（如 2 个）
- 总参数大，激活参数小

**EP**：把不同专家放到不同卡。
- 卡 0 持有专家 1-32
- 卡 1 持有专家 33-64
- ...

**通信**：
- **All-to-All**：token 按路由结果发到对应卡上的专家
- 计算完后再 All-to-All 返回
- 通信开销大（每层 2 次 All-to-All）

**与其他并行组合**：
- DP + EP + TP 是 MoE 训练标准配置

---

## Q8: 3D / 4D 并行的组合？

**答**：
**3D 并行**（Megatron + DeepSpeed）：
- **DP**（外层）：扩展 batch
- **PP**（中层）：跨节点
- **TP**（内层）：节点内

**典型配置**（例如 GPT-3 175B 训练）：
- TP = 8（单节点）
- PP = 16（跨节点）
- DP = ZeRO-1 数据并行
- 总卡数 = TP × PP × DP

**4D 并行**（加入 SP 或 EP）：
- 长上下文：3D + SP
- MoE：3D + EP

**组合规则**：
- TP 通信最重 → 用最高带宽（节点内 NVLink）
- PP 通信轻 → 跨节点
- DP 灵活，对带宽要求最低

---

## Q9: 如何选择并行配置？

**答**：
**核心约束**：
1. **单卡显存**：模型 + 优化器 + 激活 + KV Cache（如训练）
2. **集群拓扑**：节点内带宽 vs 跨节点带宽
3. **效率**：尽量减少通信和气泡

**经验规则**：
- 模型权重单卡放不下 → 必须 TP 或 PP
- 节点内放得下一层 → TP 用满单节点，PP 跨节点
- 节点内放不下一层 → PP + TP 同时切
- Batch 大 → 加 DP/ZeRO
- 长序列 → 加 SP
- MoE → 加 EP

**例**：LLaMA-3 70B 训练，假设 H100 80GB × 256 卡：
- TP=8, PP=4, DP=8 是常见配置

---

## Q10: 各种并行的通信开销对比？

**答**：

| 并行 | 通信类型 | 频率 | 量级 |
|------|---------|------|------|
| DP | AllReduce gradient | 每 step | $O(\Psi)$ |
| ZeRO-3 | AllGather param + ReduceScatter grad | 每层每 step | $O(\Psi)$ 但分散 |
| TP | AllReduce activation | 每层 2 次 | $O(BLD)$ |
| PP | P2P activation | 每 stage 边界 | $O(BLD)$ 小 |
| SP | All-to-All | 每层 | $O(BLD)$ |
| EP | All-to-All | 每层 2 次（MoE） | $O(BLD)$ 大 |

$\Psi$：参数量，$B$：batch，$L$：序列长度，$D$：hidden dim。

**关键**：TP 通信最重（每层都通信），PP 通信最轻（只在边界）。

## 🎯 高频追问

1. **TP 大小为什么不能跨节点**？跨节点带宽（IB ~50GB/s）远低于节点内 NVLink（~600GB/s），TP 通信会成为瓶颈。
2. **PP 的气泡怎么减少**？1F1B、Interleaved 1F1B、加大 microbatch 数。
3. **ZeRO-3 vs PP 怎么选**？ZeRO-3 通信更多但更灵活；PP 通信少但实现复杂。中小集群用 ZeRO-3 + DP，大集群用 3D 并行。
4. **FSDP 能不能替代 Megatron**？中等规模可以；超大规模（千卡以上）Megatron 仍更优。
5. **MoE 的 EP 通信怎么优化**？All-to-All 是瓶颈；可以用 Flux、DeepEP 等定制 kernel 优化。
