## Q1: 训练崩溃有哪几种典型形态？根因都是什么？
> 难度 ⭐⭐ ｜ 高频 🔥🔥

三种典型形态：

| 形态 | 现象 | 是否可救 |
|---|---|---|
| **Loss Spike**（毛刺） | loss 突然从 2.5 飙到 8.0，可能恢复 | 多半能救 |
| **发散** | loss 一路上扬停不下来 | 必须回滚 |
| **NaN/Inf** | 直接出现 nan，训练立刻挂掉 | 必须回滚 |

**共同根源**：

$$\text{训崩} = \text{数值精度问题} + \text{梯度过大} + \text{数据异常} + \text{调度不当}$$

**追问：梯度爆炸和 Loss Spike 是一回事吗？** 不是。**梯度爆炸**是原因（反向连乘越来越大），**Loss Spike** 是结果现象。Spike 也可能由坏 batch、Adam 异常、Loss Scaling 错等其他原因导致。

---

## Q2: Loss Spike 6 大常见原因？怎么处理？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥🔥

**6 大原因**：

| # | 原因 | 通俗解释 |
|---|---|---|
| 1 | **学习率过大** | 步子太大，更新一下跳到错误区域 |
| 2 | **梯度爆炸** | 反向连乘越来越大 |
| 3 | **数据异常** | 编码错误 / 超长 / 全重复的坏 batch |
| 4 | **数值精度** | FP16 表示不了的数变成 0 或 inf |
| 5 | **优化器状态异常** | Adam $v_t$ 偶然很小，分母趋零 → 步长爆炸 |
| 6 | **Loss Scaling 不当**（FP16 下） | scale 选错导致下溢或溢出 |

**当下处理**：
1. 回滚 checkpoint
2. 跳过坏 batch（找出元凶过滤掉）
3. 降低学习率
4. 加严梯度裁剪 $\tau$

**长期预防三件套**：
```text
✅ BF16 替代 FP16      避免数值精度问题
✅ 充分 Warmup         前期 loss 稳，避免 v_t 估计不准
✅ 梯度裁剪 τ = 1.0    防止单步更新过大
+ 数据预清洗（过滤超长/异常/重复样本）
```

## Q3: 推导 BF16 vs FP16 的位宽分配，为什么 LLM 训练选 BF16？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥🔥

浮点数 = 符号位 + 指数位（决定**范围**）+ 尾数位（决定**精度**）。

| 格式 | 总位 | 指数 | 尾数 | 范围 | 精度 |
|---|---|---|---|---|---|
| FP32 | 32 | 8 | 23 | $\pm 10^{38}$ | 高 |
| **FP16** | 16 | **5** | 10 | $\pm 65504$（小！） | 中 |
| **BF16** | 16 | **8** | 7 | $\pm 10^{38}$（同 FP32） | 低 |
| FP8 (E4M3) | 8 | 4 | 3 | 极小 | 很低 |

**关键洞察**：BF16 把一半位拿去存指数——**牺牲精度换范围**。

**为什么 LLM 选 BF16**：
- LLM 梯度普遍很小（$\sim 10^{-6}$）
- FP16 最小可表示数 $\approx 6 \times 10^{-5}$ → 梯度直接**下溢成 0** → 训练原地踏步
- BF16 最小可表示数 $\approx 10^{-38}$（同 FP32）→ 根本不会下溢
- BF16 不需要 Loss Scaling，配置简单
- A100/H100/TPU 都原生支持

**追问：BF16 精度比 FP16 还低，为什么训练不出问题？** 训练中"精度"主要影响参数更新的细节，"范围"决定梯度是否被表示出来。BF16 的低精度可以用 FP32 主权重副本 + Adam FP32 状态来弥补，但范围不够会让梯度直接消失——后者无解。

## Q4: FP16 训练需要 Loss Scaling，动态 Loss Scaling 怎么调？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥

**思路**：训练前把 loss 乘一个大数 $S$（如 65536 = $2^{16}$），让梯度跟着放大 $S$ 倍，**搬到 FP16 可表示范围**。更新前再除回去。

```python
loss = compute_loss(model, batch)
scaled_loss = loss * S          # 放大
scaled_loss.backward()           # 梯度也是 S 倍
for p in params:
    p.grad = p.grad / S          # 还原
optimizer.step()
```

**动态 Loss Scaling**（像 PID 控制器自适应找最大可用 $S$）：

```text
开始：S 设很大（如 65536）
每步：
  if 检测到 inf/nan:
      S /= 2          ← 减半
      跳过这一步
  elif 连续 N 步无 inf:
      S *= 2          ← 加倍
```

**追问：BF16 训练完全不需要 Loss Scaling 吗？** 训练几乎不需要。极少数情况（如某些梯度极小的稀疏算子）仍可能用到，但默认就是关闭的。

## Q5: FP8 训练为什么难？E4M3 和 E5M2 区别？
> 难度 ⭐⭐⭐⭐ ｜ 高频 🔥🔥

H100/Blackwell 引入 FP8——理论速度比 BF16 翻倍，显存减半。

**两种 FP8 格式**：

| 格式 | 用途 | 特点 |
|---|---|---|
| **E4M3**（4 位指数 + 3 位尾数） | **前向**用 | 精度优先，范围窄 |
| **E5M2**（5 位指数 + 2 位尾数） | **反向**用 | 范围优先，精度差 |

**为什么前向用 E4M3、反向用 E5M2**：前向激活值数值相对集中（精度优先），反向梯度数值跨度大（范围优先）。

**FP8 难点**：
1. **范围更小** → 必须做 per-tensor 或 per-block scaling 管理动态范围
2. **outlier 致命**：少数极大值就让整个 tensor 量化失效
3. **比 BF16 更敏感**：调参经验少、参考案例少

**实践**：
- NVIDIA **Transformer Engine** 库自动做 FP8 缩放和 cast
- **DeepSeek-V3** 是最有名的公开成功案例（节省 ~50% 显存）
- 通常 **FP8 计算 + BF16 主权重副本**

**追问：FP8 推理是不是更普及？** 是。推理只需前向，且对数值精度容忍度更高（不累积更新）。训练 FP8 仍在快速演进期。

## Q6: 梯度裁剪 by value vs by norm 区别？为什么主流是 by norm？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥🔥

**By value（逐元素裁剪）**：

$$g_i \leftarrow \text{clip}(g_i, -c, c)$$

每个元素超过 $c$ 就截断到 $\pm c$。**缺点**：每个元素被独立修改 → **改变梯度方向**。

**By norm（全局 L2 范数）—— 主流**：

$$g \leftarrow g \cdot \min\left(1, \frac{\tau}{\|g\|_2}\right)$$

- $\|g\|_2$：所有参数梯度合起来的 L2 范数（标量）
- $\tau$：裁剪阈值（典型 1.0）

如果 $\|g\|_2 \leq \tau$：不变；如果 $\|g\|_2 > \tau$：整体按比例缩小到 norm = $\tau$。

**关键好处**：保持梯度**方向不变**，只压缩"步长"。

**直观例子**：$g = [3, 4]$，$\|g\| = 5$。设 $\tau = 1$：
$$g \leftarrow g \times (1/5) = [0.6, 0.8], \quad \|g'\| = 1.0 \checkmark$$

**经验**：
- 训练初期梯度大，频繁触发
- 稳定后偶发触发
- **整个训练都在裁剪 → 学习率太大**

PyTorch 一行：`torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)`

**追问：为什么 $\tau$ 一般设 1.0？** 是经验值，对绝大多数 LLM 训练都合适。如果观察到梯度 norm 长期远小于 1（如 0.1），可以放宽到更大值；如果频繁触发裁剪，先考虑降学习率而不是放大 $\tau$。

## Q7: 为什么训练必须 Warmup？没有 Warmup 会发生什么？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥🔥

**根因**：Adam 每个参数的更新步长是 $\eta \cdot \hat m_t / \sqrt{\hat v_t}$。

**训练刚开始的问题**：
- $v_t$ 由**很少的样本**估计，极不准确
- 如果 $v_t$ 偶然估出一个很小的值
- $\sqrt{v_t}$ 很小
- 步长 $\eta / \sqrt{v_t}$ **爆炸式增大**
- 一步直接崩

**Warmup 怎么做**：前 1000-2000 步（约总步数 0.5%-1%）线性从 0 升到 peak LR，给 $v_t$ 时间稳定。之后 Cosine Decay。

```
LR
  |
peak +--------___
     |   /        \___（cosine decay）
     |  /              \___
   0 +/-----------------------→ step
     0  warmup     总步数
```

**追问：Warmup 步数怎么定？** 经验上 1000-2000 步（覆盖 Adam 的 $\beta_2$ 记忆窗口 $1/(1-\beta_2)$）。$\beta_2 = 0.999$ → 窗口 1000 步；$\beta_2 = 0.95$（LLM 常用）→ 窗口 20 步，Warmup 可适当缩短。

## Q8: 数据问题导致的 Loss Spike 有哪些？怎么检测预防？
> 难度 ⭐⭐ ｜ 高频 🔥🔥

很多 Loss Spike 不是模型问题，**是数据问题**：

| 类型 | 例子 | 后果 |
|---|---|---|
| 超长序列 | 一条 200K token | 截断不当 → 信息丢失或异常梯度 |
| Tokenizer 失败 | 编码出 id = 257000（超词表） | 嵌入查表越界 |
| 空数据 | tokenize 后空列表 | loss 异常或 NaN |
| 重复轰炸 | 一段 HTML 含 1000 次 `<br>` | loss 异常低（模型秒记忆） |
| 域偏移 | 90% 中文突然来全英文 batch | loss 突然飙高 |

**检测**：
- 监控 **per-sample loss 分布**（不只 batch 平均）
- 设阈值告警：单 sample loss > 阈值 → 留样审查
- 抽样审查触发 spike 的 batch

**预防**：
- 长度过滤：< 50 字符或 > 200K token 一律丢
- N-gram 重复检测：3-gram 重复占比超阈值就丢
- PII / 毒性 / 语言识别过滤

**追问：发现一个坏 batch 后该立刻丢，还是事后回滚？** 看影响。spike 没发散 → 加严 grad_clip 继续跑 + 标记坏样本下次过滤；已经 NaN/发散 → 必须回滚最近 checkpoint，重启时跳过那批。

## Q9: 一个完整的训练 checkpoint 要存哪些东西？少存一项会怎样？
> 难度 ⭐⭐ ｜ 高频 🔥🔥

**一个完整 checkpoint 必须包含**：

```text
✓ 模型权重
✓ 优化器状态（Adam m, v, FP32 主权重）
✓ 学习率调度器状态（当前 step 数）
✓ 数据加载器状态（处理到哪个 batch）
✓ 随机种子（保证 dropout 等可复现）
```

**少存一项的后果**：

| 漏存的项 | 后果 |
|---|---|
| Adam $m, v$ | 重启等于"momentum 清零"，loss 短期内会反弹 |
| LR 调度器状态 | 重启从 step=0 重新 Warmup → 大学习率打飞稳定参数 |
| 数据加载器状态 | 重训已见过的数据 / 跳过未见数据 → 数据分布偏 |
| 随机种子 | Dropout / 数据 shuffle 不一致 → 难复现 bug |

**Loss Spike 处理流程**：
```
检测 spike → 停止训练 → 回滚最近稳定 checkpoint
   ↓
分析根因（数据 / LR / 精度）
   ↓
处理（跳坏 batch / 降 LR / 加严 clip）
   ↓
重启
```

**追问：千卡训练怎么做高效 checkpoint？** ① **Async checkpoint**：保存不阻塞训练（后台线程写盘）；② **Sharded checkpoint**：每张卡只存自己那段（如 FSDP）；③ **定期保存** + **保留最近 N 份**（防止单份损坏）。

## Q10: 千卡训练有哪些额外挑战？工程上怎么应对？
> 难度 ⭐⭐⭐ ｜ 高频 🔥

| 挑战 | 解释 | 应对 |
|---|---|---|
| **节点故障** | 每天总有几台机器宕机 | 自动检测 + auto-restart |
| **网络抖动** | IB 偶尔慢 → step 时长不稳 | 网络监控 + 异常处理 |
| **单点故障** | 一台节点挂 → 整训失败 | 弹性训练（PyTorch elastic） |
| **数据加载** | 大数据集预处理 + 分发几千节点 | 流式加载 + WebDataset |
| **不可复现** | 不同节点随机性叠加 | 严控种子、记录所有随机源 |

**工程实践五件套**：
```text
✓ 健康检查 + auto-restart：节点挂了自动拉起
✓ Async checkpoint：保存不阻塞训练
✓ 定期 checkpoint：每 1000 步存一次
✓ 弹性训练：节点数变化时能自适应
✓ 详细训练日志：spike 出现后能回查
```

**追问：训练监控要盯哪些指标？**
- **必看**：train/val loss、梯度 norm $\|g\|_2$、学习率、吞吐（tokens/sec/GPU）、GPU 利用率、梯度/权重 norm 比
- **debug 用**：每层激活/梯度统计、Attention entropy、输出多样性
- **工具**：WandB / TensorBoard / NeMo / DeepSpeed dashboard
