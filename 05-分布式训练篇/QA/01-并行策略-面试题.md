## Q1: DP / TP / PP / SP / EP 各自切的是什么？一句话说清
> 难度 ⭐⭐ ｜ 高频 🔥🔥🔥

| 名字 | 缩写 | 切的对象 | 一句话直觉 |
|---|---|---|---|
| 数据并行 | **DP** (Data Parallel) | 切**数据** | 每卡一份完整模型，分头处理不同 batch |
| 张量并行 | **TP** (Tensor Parallel) | 切**层内矩阵** | 一道大乘法题切给多人合算 |
| 流水线并行 | **PP** (Pipeline Parallel) | 切**层** | 工厂流水线，前几层 → 后几层 |
| 序列并行 | **SP** (Sequence Parallel) | 切**序列长度 $L$** | 一段长文本切给多人各看一段 |
| 专家并行 | **EP** (Expert Parallel) | 切 **MoE 专家** | 每卡负责一部分专家 |

记忆口诀：**DP 解决"训得快"，TP/PP/EP 解决"装得下"，SP 解决"序列太长"**。

**追问：为什么 DP 不能解决"装不下"？** DP 每张卡都存完整模型副本，模型本身大于单卡显存时无济于事——这才需要 ZeRO/TP/PP 把模型本身也切开。

## Q2: 推导 ZeRO 三个阶段的单卡显存公式（$16\Psi$ 模型）
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥🔥

模型状态拆成 3 部分（BF16 + Adam，每参数 $16$ 字节）：
- **参数**：$2\Psi$
- **梯度**：$2\Psi$
- **优化器状态**（Adam $m$ + $v$ + FP32 主权重）：$12\Psi$

| 阶段 | 切什么 | 单卡需存 | 通信代价 |
|---|---|---|---|
| 普通 DP | 啥都不切 | $16\Psi$ | 1× AllReduce |
| **ZeRO-1** | 只切优化器状态 | $4\Psi + 12\Psi/N$ | 1× |
| **ZeRO-2** | + 梯度也切 | $2\Psi + 14\Psi/N$ | 1× |
| **ZeRO-3** | + 参数也切 | $16\Psi/N$ | **1.5×** |

例：7B 模型、8 卡 ZeRO-3：$16 \times 7 / 8 = 14$ GB——装得下 80GB 卡。

**追问：为什么 ZeRO-3 通信是 1.5×？** 多了一次 AllGather（前向时拉回切走的参数），所以梯度同步 1× + 参数 AllGather 0.5× ≈ 1.5×。

## Q3: TP 在 FFN 中怎么切？为什么是"列并行 + 行并行"配对？
> 难度 ⭐⭐⭐⭐ ｜ 高频 🔥🔥🔥

FFN：$y = W_2 \cdot \text{GELU}(W_1 x)$，$W_1$ 把 $d \to 4d$，$W_2$ 把 $4d \to d$。

**列并行 $W_1$**（按"输出维度"切）：把 $W_1$ 切成 $[W_1^A \mid W_1^B]$
- GPU0 算 $\text{GELU}(W_1^A x)$ → 中间结果前一半 $a$
- GPU1 算 $\text{GELU}(W_1^B x)$ → 中间结果后一半 $b$
- 拼起来就是完整的 $\text{GELU}(W_1 x)$，**不需要通信**

**行并行 $W_2$**（按"输入维度"切）：把 $W_2$ 切成上下两段
- GPU0 算 $W_2^A \cdot a$，GPU1 算 $W_2^B \cdot b$
- 两边**AllReduce 相加** = $W_2 \cdot [a;b]$ = 完整 FFN 输出

**关键设计**：中间结果天然按"输出维度"切片，行并行的输入正好需要这种切片 → **整个 FFN 只在末尾 AllReduce 一次**。

**追问：Attention 怎么切？** 按"头"切——GPU0 持头 1-16、GPU1 持头 17-32，每张卡独立算自己的头，输出再 AllReduce 一次。每个 Transformer block 共 **2 次 AllReduce**（Attn 后 + FFN 后）。

## Q4: 为什么 TP 必须在节点内、PP 才能跨节点？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥🔥

核心是**通信频率 × 通信量 × 带宽**的匹配。

| 并行 | 通信频率 | 单次通信量 | 适合带宽 |
|---|---|---|---|
| **TP** | 每层 2 次 AllReduce | $O(BLD)$，激活值 | 节点内 NVLink（600-900 GB/s） |
| **PP** | 只在 stage 边界一次 P2P | $O(BLD)$，但**频次极低** | 跨节点 IB（25-50 GB/s）够用 |

跨节点 IB 比 NVLink 慢 **10-30 倍**。TP 每个 Transformer 层都要传几 GB 激活——跨节点立刻让 GPU 大部分时间在等通信。

**经验铁律**：TP size ≤ 单节点 GPU 数（通常 8）。

**追问：DP 通信也大，为什么能跨节点？** ① 频次低（每 step 才一次梯度 AllReduce）；② Ring AllReduce 实现下通信量 $\approx 2\Psi$ 与 GPU 数几乎无关；③ 可与反向计算重叠（bucket 机制）。

## Q5: PP 的"气泡"是什么？GPipe 怎么减少？气泡比例公式？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥🔥

**气泡（bubble）** = 流水线启动/收尾时各 GPU 闲置的时间。朴素 PP 跑 1 个 batch 时，每张卡只有 $1/P$ 的时间在算——浪费严重。

**GPipe 思路**：把一个 batch 切成 $M$ 个 microbatch，让流水线**填满**。

**气泡比例**：

$$\text{Bubble} = \frac{P-1}{M}$$

- $P$：流水线段数（卡数）
- $M$：microbatch 数

例：$P=4, M=16$ → 气泡 = $3/16 \approx 19\%$。$M$ 越大气泡越小。

**追问：1F1B 和 Interleaved 1F1B 又解决了什么？**
- **1F1B**（One Forward One Backward，前向反向交错）：让反向尽早开始，**减少同时存活的激活值显存**
- **Interleaved 1F1B**（Megatron）：每张卡持有**不连续的层 chunk**（如 GPU0 持 1-4 + 13-16 层），气泡比例进一步减为 $\frac{P-1}{vM}$（$v$ 是 chunk 数）

## Q6: 实际训 LLaMA-3 70B，256 卡 H100 怎么配 3D 并行？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥

**典型配置**：
```
TP = 8   （每节点 8 张卡内部切层 → 用 NVLink）
PP = 4   （每 4 个节点接力算不同层 → 用 IB）
DP = 8   （8 份"PP 流水线"并行训不同数据）
总卡数 = TP × PP × DP = 8 × 4 × 8 = 256 ✓
```

**为什么这样排（内层 TP、中层 PP、外层 DP）**：
- TP 通信最重 → 必须在**最内层**（节点内 NVLink）
- PP 通信最轻 → 放**中层**（可跨节点 IB）
- DP 在**最外层** → 跨"3D 副本"扩 batch，AllReduce 可与反向重叠

**追问：DeepSeek-V3 是 4D 怎么加的？** 它是 MoE → 加 EP（专家并行）。组合是 DP + PP + EP。长上下文场景还会再加 SP（序列并行）凑成 4D/5D。

## Q7: ZeRO-3 和 PP 都能"装下大模型"，怎么选？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥

| 维度 | ZeRO-3（= FSDP FULL_SHARD） | PP（Megatron） |
|---|---|---|
| 实现复杂度 | **简单**（FSDP 一行代码） | 复杂（要切层 + 调度气泡 + 1F1B） |
| 通信代价 | 大（~1.5× DP，每层 AllGather） | 小（只在 stage 边界 P2P） |
| 适用规模 | **中小集群**（< 256 卡）首选 | 千卡以上更优 |
| 显存效率 | 模型状态 $/N$ | 模型按层段切 |
| 节点内/外 | 节点内为佳 | 天然适合跨节点 |

**选型经验**：
- 单节点 8 卡训 7-13B：FSDP（ZeRO-3）+ DP
- 多节点 32-256 卡训 30-70B：FSDP + DP 仍可用，但通信开销变大
- 千卡训 100B+：Megatron 3D 并行（TP + PP + DP）

**追问：FSDP 能完全替代 Megatron 吗？** 中等规模可以；千卡级别 Megatron 仍更优——它对 TP+PP 的调度（重叠、气泡、激活管理）更精细。

## Q8: 序列并行 SP 解决什么问题？三种方案对比
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥

**问题**：训练 128K 上下文时，激活值显存爆炸：
- Attention 中间矩阵 $\sim L^2$
- 即使有 FlashAttention，激活也是 $\sim BLD$

**SP 思路**：把序列长度 $L$ 切给多卡，每卡只看一段。

| 方案 | 思路 | 适用 |
|---|---|---|
| **Megatron-SP** | 在 TP 基础上，把 LayerNorm/Dropout 的激活按序列维切 | 配合 TP 用 |
| **DeepSpeed-Ulysses** | Attention 时按"头"切、其他时按"序列"切，用 **All-to-All** 转换 | 中等上下文 |
| **Ring Attention** | 设备间环形传 K/V 块，支持任意长度 | 超长上下文（1M+） |

**追问：为什么 Attention 算子本身按"序列"切不能直接做？** Attention 的每个 query 都要看全序列的 K/V，序列切片后每张卡只有局部 K/V，必须通过通信（All-to-All 或环形传递）凑齐"全局"信息——三种方案的差别就是这步怎么通信。

## Q9: MoE 的 EP 通信有什么特殊？为什么需要 All-to-All？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥

**MoE 特点**：每层 $N$ 个专家（如 256），每个 token 只激活 $K$ 个（如 8）。把 $N$ 个专家分到 $P$ 张卡上，每卡持 $N/P$ 个专家。

**问题**：路由器决定每个 token 去哪 $K$ 个专家——目标专家分散在多张卡上，必须把 token 发到对应卡。

**通信流程**（每 MoE 层 2 次 All-to-All）：
```
① 把 token 按路由结果发到对应专家所在卡   ← All-to-All
② 专家在本地计算
③ 把结果发回原来的卡                       ← All-to-All
```

**为什么用 All-to-All**：每卡的 token 要发给的目标卡是**不同且多样**的（不像 DP 那种"所有人发给所有人一样的东西"），All-to-All 正是这种"每人发不同的东西给每个人"的原语。

**追问：All-to-All 是 EP 的瓶颈，怎么优化？** ① **DeepEP**（DeepSeek 开源）/ **Flux**（NVIDIA）做定制 kernel，把通信和计算重叠；② **专家路由均衡 loss** 避免某些专家过载导致通信不均；③ **节点内优先**安排高频路由路径。

## Q10: 列一份"显存换通信"的递增顺序（选型直觉）
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥

**省显存递增 = 通信代价递增**：

$$\text{DP} < \text{ZeRO-1} < \text{ZeRO-2} < \text{ZeRO-3} < +\text{PP} < +\text{TP}$$

| 配置 | 单卡模型状态 | 通信代价 |
|---|---|---|
| DP | $16\Psi$ | 1× AllReduce |
| ZeRO-1 | $4\Psi + 12\Psi/N$ | 1× |
| ZeRO-2 | $2\Psi + 14\Psi/N$ | 1× |
| ZeRO-3 | $16\Psi/N$ | 1.5× |
| + PP | 按层切，进一步减半 | + P2P 激活 |
| + TP | 层内切，最省 | + 每层 AllReduce |

**选型决策树**：
- 模型 < 单卡显存 → 纯 DP / FSDP
- 模型 < 单节点显存 → FSDP 或 TP（节点内）+ DP
- 模型 > 单节点显存 → TP + PP + DP（3D）
- 长上下文 → + SP
- MoE → + EP
