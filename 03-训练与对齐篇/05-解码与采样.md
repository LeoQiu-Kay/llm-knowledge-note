# 解码与采样

> Top-k、Top-p、温度 + 投机解码原理。

---

## 1. 解码策略一览

| 方法 | 选择策略 | 优 | 缺 |
|---|---|---|---|
| **Greedy** | 每步选概率最大 | 确定、快 | 局部最优、单调 |
| **Beam Search** | 维护 Top-B 条路径 | 比 greedy 好 | 单调、计算大 |
| **Sampling** | 按概率采样 | 多样 | 可能采到长尾噪声 |
| **Top-k** | 只从 Top-k 中采 | 限制长尾 | k 固定不灵活 |
| **Top-p**（Nucleus） | 累积概率 ≥ p 的最小集合采 | 自适应 | p 调参 |
| **Temperature** | 缩放 logits | 控制随机性 | 不直接截断 |

---

## 2. Temperature

$$P(x_i) = \frac{\exp(z_i / T)}{\sum_j \exp(z_j / T)}$$

**符号说明**：
- $z_i$：第 $i$ 个 token 的 logit（softmax 输入）
- $T$（temperature）：温度，正数
- $P(x_i)$：采样到第 $i$ 个 token 的概率

**性质**：
- $T = 1$：原始 softmax
- $T \to 0$：接近 argmax（greedy）
- $T \to \infty$：接近均匀分布

**典型值**：
- 0.0：完全确定（= greedy）
- 0.3-0.7：保守生成（文档、代码）
- 0.7-1.0：自然对话
- 1.0-1.5：创意写作

## 3. Top-k vs Top-p

### 3.1 Top-k

固定取前 $k$ 个 token 重新归一化：

```python
def top_k_filter(logits, k):
    # 取第 k 大的 logit 作为阈值
    threshold = logits.topk(k).values[-1]
    return logits.masked_fill(logits < threshold, float('-inf'))
```

### 3.2 Top-p（Nucleus Sampling）

取累积概率 ≥ $p$ 的最小集合：

```python
def top_p_filter(logits, p):
    sorted_logits, sorted_idx = logits.sort(descending=True)
    cum_probs = sorted_logits.softmax(-1).cumsum(-1)
    # 找到累积概率刚超过 p 的位置
    cutoff = (cum_probs > p).int().argmax()
    # 截断
    ...
```

### 3.3 对比

- **Top-k**：分布尖锐时保留太多无关 token；分布平时漏掉合理候选
- **Top-p**：分布尖锐时 nucleus 小；分布平时 nucleus 大（**自适应**）

```text
实践：Top-p 更受欢迎，p = 0.9 是常用值。
也可组合：先 top-k 截断，再 top-p。
```

## 4. Beam Search 在 LLM 时代为什么不流行？

**问题**：
1. **重复倾向**：高概率路径常重复（"the the the"）
2. **缺乏多样性**：beam 之间高度相似
3. **倾向短句**：长句概率必然下降，需要 length penalty
4. **不适合开放生成**：聊天/创作需要多样

**适用场景**：翻译、摘要等"有标准答案"的任务。

**LLM chat**：sampling（top-p + temperature）几乎全面替代 beam search。

## 5. Repetition Penalty

**目的**：抑制重复 token。

**实现**：对已经生成过的 token，把其 logit 除以惩罚因子（> 1）：

```python
def apply_repetition_penalty(logits, generated_ids, penalty=1.1):
    for token_id in set(generated_ids):
        if logits[token_id] > 0:
            logits[token_id] /= penalty
        else:
            logits[token_id] *= penalty
    return logits
```

**典型值**：1.0（无惩罚）- 1.2。过大会让生成失流畅。

**变种**：
- **Frequency Penalty**：按出现次数比例惩罚
- **Presence Penalty**：出现过就惩罚一次
- **No Repeat N-gram**：禁止生成已出现过的 n-gram

## 6. 投机解码（Speculative Decoding）

### 6.1 核心思想

用一个**快的草稿模型** $M_q$ 一次生成多个 token，让**慢的目标模型** $M_p$ **并行**验证。

**符号说明**：
- $M_p$：目标模型（target，慢但准）
- $M_q$：草稿模型（draft，快但不准）
- $p(\cdot), q(\cdot)$：两个模型给的概率
- $k$：每轮草稿生成的 token 数（典型 4-8）

### 6.2 算法

```
Repeat:
    1. 草稿: x_1, ..., x_k ~ M_q（顺序生成 k 个 token）
       记录每个 token 的概率 q(x_i)
    
    2. 验证: 用 M_p 一次 forward 这 k 个 token
       得到 M_p 给每个位置的概率 p(x_i)
    
    3. 对每个位置 i = 1..k 顺序检查:
       u ~ Uniform(0, 1)
       if u < min(1, p(x_i) / q(x_i)):
           接受 x_i
       else:
           拒绝 x_i
           从分布 max(0, p - q) 重采一个 token x'
           跳出循环，从下一步重新开始
    
    4. 若全部接受: 从 M_p 的 k+1 位置采一个 bonus token
```

### 6.3 为什么不改变输出分布？

**关键性质**：拒绝采样后的分布等价于直接从 $M_p$ 采样。

**直觉**：
- 接受概率 $\min(1, p / q)$ 调整 $q$ 让其匹配 $p$
- 被拒时从 $\max(0, p - q)$ 采样恰好补足分布差
- 经典拒绝采样的标准结果

```text
意味着：可以放心使用，不损失质量。
```

### 6.4 加速比

$$\text{Speedup} \approx \frac{1 - \alpha^{k+1}}{(1 - \alpha)(1 + c k)}$$

**符号说明**：
- $\alpha$：单 token 接受率（典型 0.5-0.8）
- $k$：草稿长度
- $c$：草稿模型 / 目标模型成本比（越小越好）

**典型加速**：
- 普通投机：1.5-2.5×
- + EAGLE：3-4×

## 7. Medusa

**思路**：不用独立小模型，在目标模型上加多个"head"，并行预测多个未来 token。

**结构**：
```
基础 Transformer 主干
  ↓
LM Head (预测下一个 token)
+
Medusa Head 1 (预测下下个 token)
+
Medusa Head 2 (预测下下下个 token)
+ ...
```

**推理流程**：
1. 一次 forward 得到下一个 token + 多个未来 token 候选
2. 构造**候选树**（每个位置取 top-k，组合成树）
3. 大模型再 forward 验证整棵树（树注意力）

**优点**：不需要独立小模型，硬件友好。
**缺点**：需要训练 Medusa head；多 head 准确度递减。

**典型加速**：1.5-2.5×。

---

## 8. EAGLE：当前 SOTA

**EAGLE**（Extrapolation Algorithm for Greater Language-model Efficiency）：

**核心创新**：用一个**小 Transformer 解码器**作为草稿，输入是目标模型的**隐藏状态**（而非 token）。

**为什么有效**：
- 隐藏状态比 token 信息更丰富（包含上下文）
- 草稿模型从隐藏状态更准确预测下一个 token
- 接受率比 Medusa 高

**EAGLE-2 / EAGLE-3**：当前 SOTA，加速 3-4×。

---

## 9. 不同采样策略的实际选择

**Chat 模型默认**：
- Temperature: 0.7
- Top-p: 0.9
- Top-k: 50（或 0 表示关闭）
- Repetition penalty: 1.05-1.1

**确定性任务**（代码、数学、抽取）：
- Temperature: 0（= Greedy）

**创意写作**：
- Temperature: 0.9-1.2
- Top-p: 0.95

**推理模型（o1/R1 风格）**：
- Temperature: 0.6（推荐）
- Top-p: 0.95
- 不能用 greedy（容易陷入循环）

## 10. 最简记忆

```text
温度 T：缩放 logits 控制随机性
Top-k：固定前 k 个候选
Top-p：累积概率 ≥ p 的最小集合（自适应，主流）

Beam Search 在 LLM 时代基本不用（缺乏多样性）

投机解码：
  草稿模型一次生成 k 个 → 目标模型并行验证
  数学保证：输出分布与目标模型完全一致
  典型加速 1.5-3×；+ EAGLE 可到 3-4×

Medusa：在目标模型上加多 head 并行预测
EAGLE：用小解码器 + 隐藏状态作输入，SOTA
```

## 🎯 高频追问

1. **R1 为什么不推荐 $T = 0$**？greedy 容易陷入重复（"thinking thinking..."），需要少量随机性。

2. **投机解码草稿模型怎么选**？同 tokenizer 的小模型最方便（如 Llama-3-70B + Llama-3-8B 作草稿）。

3. **投机解码会改变输出吗**？理论上不变（与大模型直接采样分布一致）；实现 bug 可能引入微小差异。

4. **多样性怎么衡量**？distinct-n（n-gram 唯一比例）、self-BLEU。

5. **生成停止的判断**？遇到 `<eos>` token、达到 max_new_tokens、命中 stop sequence。
