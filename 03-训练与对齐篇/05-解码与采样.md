# 解码与采样

> Top-k、Top-p、温度的细节，以及投机解码原理。

---

## Q1: Greedy / Beam Search / Top-k / Top-p / Temperature 的区别？

**答**：

| 方法 | 选择策略 | 优点 | 缺点 |
|------|---------|------|------|
| **Greedy** | 每步选概率最大的 token | 确定性、快 | 局部最优，单调 |
| **Beam Search** | 维护 Top-B 条路径 | 比 greedy 好 | 单调、计算大 |
| **Sampling** | 按概率随机采样 | 多样 | 可能采到长尾噪声 |
| **Top-k** | 只从 Top-k 中采样 | 限制长尾 | k 大小固定不灵活 |
| **Top-p（Nucleus）** | 从累积概率 ≥ p 的最小集合采样 | 自适应 | p 调参 |
| **Temperature** | 缩放 logits | 控制随机性 | 不直接截断 |

## Q2: Temperature 的数学形式？

**答**：
$$P(x_i) = \frac{\exp(z_i / T)}{\sum_j \exp(z_j / T)}$$

- $T = 1$：原始 softmax
- $T \to 0$：接近 argmax（greedy）
- $T \to \infty$：接近均匀分布

**典型值**：
- 0.0：完全确定（等于 greedy）
- 0.3-0.7：保守生成（文档、代码）
- 0.7-1.0：自然对话
- 1.0-1.5：创意写作

## Q3: Top-k 与 Top-p 的对比？

**答**：
**Top-k**：固定取前 k 个 token 重新归一化。
```python
def top_k(logits, k):
    values, _ = torch.topk(logits, k)
    threshold = values[..., -1, None]
    return torch.where(logits < threshold, -inf, logits)
```

**Top-p（Nucleus）**：取累积概率 ≥ p 的最小集合。
```python
def top_p(logits, p):
    sorted_logits, sorted_idx = torch.sort(logits, descending=True)
    cum_probs = sorted_logits.softmax(-1).cumsum(-1)
    cutoff = (cum_probs > p).int().argmax(-1)
    # 保留 cutoff 之前的 token
    ...
```

**对比**：
- Top-k：在某些位置（概率分布尖锐时）保留过多无关 token；分布平的时候漏掉合理候选
- Top-p：自适应——分布尖锐时 nucleus 小，分布平时 nucleus 大
- 实践：**Top-p 更受欢迎**，p=0.9 是常用值
- 也可以组合：先 top-k 截断，再 top-p

## Q4: Beam Search 在 LLM 时代为什么不流行？

**答**：
**问题**：
1. **重复倾向**：高概率路径常重复（"the the the"）
2. **缺乏多样性**：beam 之间高度相似
3. **倾向短句**：长句概率必然下降，需要 length penalty
4. **不适合开放生成**：聊天/创作需要多样

**适用场景**：
- 翻译、摘要等"有标准答案"的任务
- 需要稳定输出的场景

**LLM chat**：sampling（top-p + temperature）几乎全面替代 beam search。

## Q5: Repetition Penalty 是什么？

**答**：
**目的**：抑制重复 token。

**实现**：对已经生成过的 token，把其 logit 除以惩罚因子（>1）：
```python
def apply_repetition_penalty(logits, generated_ids, penalty=1.1):
    for token_id in set(generated_ids):
        if logits[token_id] > 0:
            logits[token_id] /= penalty
        else:
            logits[token_id] *= penalty
    return logits
```

**典型值**：1.0（无惩罚）- 1.2。过大会让生成失流畅。

**变种**：
- **Frequency Penalty**：按出现次数比例惩罚
- **Presence Penalty**：出现过就惩罚一次（不累积）
- **No Repeat N-gram**：禁止生成已出现过的 n-gram

## Q6: 投机解码（Speculative Decoding）？

**答**：
**核心思想**：用小模型快速生成多个 token，让大模型一次验证多个。

**算法**：
1. **草稿阶段**：小模型 $M_q$ 自回归生成 $k$ 个 token（如 4-8 个）
2. **验证阶段**：大模型 $M_p$ 一次性 forward 这 k 个 token，并行计算所有位置的概率
3. **接受/拒绝**：
   - 对每个位置 i：以概率 $\min(1, p(x_i) / q(x_i))$ 接受
   - 一旦某个 token 被拒绝，丢弃后续，从大模型分布重采一个
4. **重复**：从接受位置继续

**理论保证**：输出分布**与大模型完全一致**（无效果损失）。

**加速来源**：
- 一次大模型 forward 处理 k 个 token（并行，GPU 利用率高）
- 平均接受率 $\alpha$ 决定加速比，典型 50-80%
- 理论加速 = $(1 - \alpha^{k+1}) / ((1-\alpha)(1 + ck))$，其中 c 是小模型 / 大模型成本比

## Q7: Medusa 是什么？

**答**：
**核心**：不用独立小模型，而是在大模型上加多个"head"，并行预测多个未来 token。

**结构**：
```
[标准 LM head]: 预测下一个 token
[Medusa Head 1]: 预测下下个 token
[Medusa Head 2]: 预测下下下个 token
...
```

**流程**：
1. 训练时：每个 head 训练预测对应位置的 token
2. 推理时：一次 forward 得到多个候选，构造**树状候选**
3. 大模型再 forward 验证整棵树

**优点**：
- 不需要独立小模型
- 实现简单（在 base 模型上加 head）

**缺点**：
- 需要训练（不像 Speculative Decoding 可即插即用）
- Head 越多准确度越低

**典型加速**：1.5-2.5×

---

## Q8: EAGLE 是什么？

**答**：
**EAGLE**（Extrapolation Algorithm for Greater Language-model Efficiency）：
- 用一个轻量 decoder 作为草稿模型
- 输入 base 模型的**隐藏状态**而非 token，信息更丰富
- 比 Medusa 更高效，加速可达 3-4×

**EAGLE-2 / EAGLE-3**：进一步优化，已成为投机解码 SOTA。

---

## Q9: Lookahead Decoding？

**答**：
**核心**：不需要训练，纯算法层面的并行解码。

**思路**：
- 维护多个"n-gram 候选"
- 每步同时生成新候选 + 验证旧候选
- Jacobi 迭代式的并行

**特点**：
- 不需要训练
- 加速 1.5-2×
- 实现复杂

**当前格局**：实际部署仍以 Speculative Decoding（带训练小模型）+ EAGLE 为主流。

## Q10: 不同采样策略的实际选择？

**答**：
**Chat 模型默认**：
- Temperature: 0.7
- Top-p: 0.9
- Top-k: 50（或 0 表示关闭）
- Repetition penalty: 1.05-1.1

**确定性任务**（代码、数学、抽取）：
- Temperature: 0
- 等价于 Greedy
- Beam Search（如果想要更高质量）

**创意写作**：
- Temperature: 0.9-1.2
- Top-p: 0.95

**推理模型**（o1/R1 风格）：
- Temperature: 0.6（推荐）
- Top-p: 0.95
- 不能用 greedy（会陷入循环）

## 🎯 高频追问

1. **为什么 R1 不推荐 temperature=0**？greedy 容易陷入重复（"thinking thinking thinking..."），需要少量随机性。
2. **投机解码的小模型怎么选**？同 tokenizer 的小模型最方便（如 Llama-3-70B + Llama-3-8B 作为草稿）。
3. **投机解码会改变输出吗**？理论上不变（与大模型直接采样分布一致），但实现细节可能导致微小差异。
4. **多样性怎么衡量**？distinct-n（n-gram 唯一比例）、self-BLEU。
5. **生成停止的判断**？遇到 `<eos>` token、达到 max_new_tokens、stop sequence 命中。
