# 预训练（Pre-training）

> 大模型能力的根基，从数据到 Scaling Laws 都是面试常问。

---

## Q1: CLM vs MLM vs PrefixLM 的训练目标？

**答**：

| 目标 | 公式 | 特点 | 代表 |
|------|------|------|------|
| **CLM**（Causal LM） | $P(x_t \| x_{<t})$ | 自回归，单向 | GPT 系列 |
| **MLM**（Masked LM） | $P(x_{\text{mask}} \| x_{\text{rest}})$ | 双向，随机 mask 15% | BERT |
| **PrefixLM** | 前缀双向 + 后缀单向 | 折中 | GLM、UL2 |
| **Span Corruption** | 屏蔽连续 span，预测 | 类似 MLM，但成块 | T5 |
| **DAE**（Denoising AE） | 噪声 → 原文 | 多种噪声形式 | BART |

**CLM 的训练损失**：
$$\mathcal{L} = -\sum_t \log P(x_t | x_{<t}; \theta)$$
每个 token 都贡献 loss（数据利用率 100%）。

**MLM 的训练损失**：
$$\mathcal{L} = -\sum_{i \in M} \log P(x_i | x_{\setminus M}; \theta)$$
只对被 mask 的 token 计算 loss（一般 15%，利用率低）。

---

## Q2: 为什么 GPT 系列用 CLM，BERT 用 MLM？

**答**：
**GPT 用 CLM**：
- 目标是生成（next token prediction）
- 训练与推理一致，无 train/inference gap
- 数据利用率高

**BERT 用 MLM**：
- 目标是理解（分类、抽取）
- 双向 attention 提供更丰富的上下文
- 适合判别式任务

**为什么现在 LLM 都是 CLM**：
- Scaling 后 CLM 模型 zero/few-shot 能力远超 MLM
- 生成需求成为主流（chat、code、agent）
- 见前面"为什么 Decoder-only"那一题

## Q3: 预训练数据来源与清洗？

**答**：
**主要来源**：
- **网页**：Common Crawl（最大）、C4（清洗后的 CC）、RedPajama、FineWeb（HF）
- **书籍**：Books3、Project Gutenberg
- **代码**：GitHub、Stack Exchange
- **学术**：arXiv、PubMed
- **百科**：Wikipedia
- **中文**：WuDaoCorpora、悟道、CCI、Skywork
- **对话**：Reddit、Discord

**清洗步骤**：
1. **语言识别**：fastText 等过滤目标语种
2. **质量过滤**：困惑度过滤、模型分类器（如 KenLM 评分）
3. **去重**：
   - URL/精确去重
   - MinHash（near-duplicate）
   - SemDedup（语义级，用 embedding 聚类）
4. **PII 清除**：邮箱、电话、社安号
5. **毒性/NSFW 过滤**：分类器
6. **格式清理**：去 boilerplate、HTML 标签、广告

## Q4: Scaling Laws 是什么？Kaplan 与 Chinchilla 的区别？

**答**：
**核心思想**：模型损失（loss）随参数量 $N$、数据量 $D$、计算量 $C$ 呈幂律关系。

**Kaplan Scaling Law**（OpenAI, 2020）：
- 给定计算预算 $C$，**模型参数 N 应该更大，数据 D 较小**。
- 公式建议比例约 $N : D \sim 1 : 1.7$（用 token 数算）

**Chinchilla Scaling Law**（DeepMind, 2022）：
- **更正了 Kaplan**：训练应该更平衡，**N 和 D 同步增长**。
- 给定 $C$，最优 $N : D \sim 1 : 20$（每个参数约 20 token）。
- DeepMind 训练了 Chinchilla（70B + 1.4T token），全面超越同算力的 Gopher（280B + 300B token）。

**实际影响**：
- LLaMA-1 (7B) 训练 1T+ token，意识到 token/参数比要大于 20。
- LLaMA-3 在 8B 上训了 15T token（约 1875:1），过度训练但 inference 效率最优。
- **现在普遍认为：参数小 + 更多数据 = 推理友好**（边际收益递减但仍正向）。

## Q5: token/参数比应该怎么选？

**答**：
**Chinchilla 最优**：20:1（最小化 loss 给定计算量）。

**但训练目标不只是 loss**：
- **推理成本**：更小模型 → 部署便宜
- **inference 效率**：现代选择是"训练不足的参数 + 大量数据"
- LLaMA-3 系列 8B 模型训了 15T tokens（1875:1），完全偏离 Chinchilla 最优，但部署友好

**实际选择取决于**：
- 算力预算
- 部署约束（是否在意推理成本）
- 数据可得性

## Q6: 涌现能力（Emergent Abilities）？

**答**：
**定义**：某些能力（如算术、CoT）在小模型上完全没有，但模型超过某个规模后突然出现。

**典型例子**：
- 多位数加减法
- Chain of Thought 推理
- 指令遵循
- 大规模 in-context learning

**争议**：
- Schaeffer et al. (2023) 提出涌现可能是评估方式的伪影（discontinuous metric）。
- 用 continuous metric（如 log-prob）能力是平滑提升的。
- 但"突然能用"的现象（不到 1B 不能做，10B 能做）仍真实存在。

**实际**：
- 100M：基本 LM 能力
- 1-10B：复杂理解、初级生成
- 70B+：复杂推理、多步规划
- 175B+：强 zero-shot 与跨任务泛化

## Q7: 预训练的工程流程？

**答**：
1. **数据准备**：抓取 → 清洗 → 去重 → tokenize → packing 成固定长度序列
2. **架构选择**：层数、宽度、头数、词表大小、序列长度
3. **超参选择**：LR（peak、warmup、decay）、batch size、梯度裁剪
4. **并行策略**：DP + TP + PP + SP（基于硬件配置）
5. **训练**：定期 checkpoint、监控 loss/PPL/eval、处理 loss spike
6. **评测**：MMLU、HellaSwag、C-Eval、GSM8K 等
7. **后处理**：长上下文扩展（YaRN）、bf16 → fp8 推理量化

**典型规模**（LLaMA-3 70B）：
- 数据：15T tokens
- 集群：16000+ H100
- 时间：~1 个月
- 估算成本：$10M+ 量级

---

## Q8: 数据 packing（拼接）是什么？

**答**：
**问题**：训练序列长度固定（如 8K），但文档长度参差，浪费 padding。

**解法**：
- 把多个短文档拼成一个 8K 序列，文档间用 `<eos>` 分隔
- 节省计算（不浪费 padding 位置的 FLOPs）
- 注意：cross-document attention 会让一个文档"看到"前一个文档，可用 attention mask 隔离（document mask），但工程上很多直接不隔离，认为是轻微噪声

---

## Q9: 训练时序列长度的演进？

**答**：
- 早期 BERT：512
- GPT-3：2048
- LLaMA-2：4K
- LLaMA-3：8K（再用 YaRN 等扩到 128K）
- 长上下文模型：32K、128K、1M+
- 训练时通常**先短训后长训**：90% 数据用短上下文（4K-8K），10% 数据用长上下文，节省算力。

## 🎯 高频追问

1. **怎么判断模型 "训过" 了**？看 loss 平台期 + downstream 评估收敛 + token/参数比。
2. **数据混合比例怎么定**？根据 downstream 任务的相对重要性 + Doremi 等自动方法。
3. **是否需要 curriculum learning**？大数据集下效果不明显，但"先简单后复杂"在 SFT 阶段有用。
4. **Loss spike 怎么办**？回滚 checkpoint，跳过坏 batch，或降 LR 重启。BF16 比 FP16 稳定得多。
5. **数据污染（test data leakage）怎么检测**？n-gram 重叠检测，或用模型记忆探测。
