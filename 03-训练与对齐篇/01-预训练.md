# 预训练（Pre-training）

> 大模型能力的根基，从训练目标到 Scaling Laws。

---

## 1. 训练目标：CLM / MLM / PrefixLM

### 1.1 CLM（Causal LM）— GPT、LLaMA

每个位置预测下一个 token：

$$\mathcal{L}_{\text{CLM}} = -\sum_{t=1}^{N} \log P(x_t \mid x_{<t}; \theta)$$

**符号说明**：
- $x_t$：第 $t$ 个 token
- $x_{<t}$：前 $t-1$ 个 token
- $N$：序列长度
- $\theta$：模型参数
- $P(x_t \mid x_{<t}; \theta)$：模型预测 $x_t$ 的概率
- $\mathcal{L}$：loss（负对数似然）

每个 token 都贡献 loss → **数据利用率 100%**。

### 1.2 MLM（Masked LM）— BERT

随机 mask 15% 的 token，预测它们：

$$\mathcal{L}_{\text{MLM}} = -\sum_{i \in M} \log P(x_i \mid x_{\setminus M}; \theta)$$

**符号说明**：
- $M$：被 mask 的位置集合（通常占 15%）
- $x_{\setminus M}$：未被 mask 的 token

只对 mask 的 token 算 loss → **数据利用率 15%**。

### 1.3 PrefixLM、Span Corruption

- **PrefixLM**（GLM）：前缀双向、后缀单向
- **Span Corruption**（T5）：mask 连续片段，预测整个片段

---

## 2. 为什么现在都用 CLM？

1. **数据利用率高**：CLM 100% vs MLM 15%
2. **训练 / 推理一致**：CLM 训练目标就是生成
3. **In-Context Learning**：causal mask 天然支持
4. **Scaling 友好**：弱归纳偏置 + 大数据，符合 scaling laws

---

## 3. 数据：从哪来、怎么清洗

**主要来源**：
- **网页**：Common Crawl（最大）、C4（清洗后的 CC）、FineWeb
- **代码**：GitHub、Stack Exchange
- **学术**：arXiv、PubMed
- **百科**：Wikipedia
- **中文**：WuDaoCorpora、悟道、Skywork
- **书籍**：Books3、Project Gutenberg

**清洗步骤**：
1. **语言识别**：fastText 等过滤目标语种
2. **质量过滤**：困惑度过滤 / 模型分类器
3. **去重**：
   - URL / 精确去重
   - MinHash（near-duplicate）
   - SemDedup（语义级，用 embedding）
4. **PII 清除**：邮箱、电话、社安号
5. **毒性 / NSFW 过滤**
6. **格式清理**：去 HTML、广告、boilerplate

---

## 4. Scaling Laws

**核心思想**：模型 loss 随参数量 $N$、数据量 $D$、计算量 $C$ 呈幂律。

### 4.1 Kaplan Scaling Law（OpenAI 2020）

建议比例 $N : D \sim 1 : 1.7$（参数和数据比例）。

→ 倾向"大模型 + 较少数据"。

### 4.2 Chinchilla Scaling Law（DeepMind 2022）

**纠正了 Kaplan**：给定计算预算 $C$，最优为：

$$N : D \sim 1 : 20$$

**符号说明**：
- $N$：模型参数量
- $D$：训练 token 数

即每个参数约 20 token。DeepMind 训练 Chinchilla（70B + 1.4T tokens）超越同算力 Gopher（280B + 300B tokens）。

### 4.3 实际现状：远超 Chinchilla 最优

**LLaMA-3 8B**：训 15T tokens → 比例约 **1 : 1875**！

为什么？
- 部署友好：小模型更便宜
- 训练贵但一次性，推理省钱（关键考虑）
- Chinchilla 最优是 loss 最小，**不是部署最优**

## 5. 涌现能力（Emergent Abilities）

**定义**：某些能力在模型超过某规模后突然出现。

**典型例子**：
- 多位数加减法
- Chain of Thought 推理
- 指令遵循
- 大规模 in-context learning

**经验门槛**：
- < 1B：基本 LM 能力
- 1-10B：复杂理解、初级生成
- > 10B：复杂推理
- > 70B：强 zero-shot

**争议**：Schaeffer et al. (2023) 认为涌现可能是评估方式的伪影（discontinuous metric）。

---

## 6. 数据 packing

**问题**：训练序列长度固定（如 8K），但文档长度参差，浪费 padding。

**解法**：把多个短文档拼成一个 8K 序列，用 `<eos>` 分隔。

**Document Mask**（可选）：让 attention 不跨文档边界。工程上很多直接不隔离，视为轻微噪声。

---

## 7. 训练序列长度的演进

| 模型 | 训练序列长度 |
|---|---|
| BERT | 512 |
| GPT-3 | 2048 |
| LLaMA-2 | 4K |
| LLaMA-3 | 8K（YaRN 扩到 128K） |
| 长上下文模型 | 32K → 128K → 1M+ |

**通用做法**：**先短训后长训**——90% 数据短上下文（4K-8K），10% 数据长上下文，节省算力。

---

## 8. 训练工程流程

1. **数据准备**：抓取 → 清洗 → 去重 → tokenize → packing
2. **架构选择**：层数、宽度、头数、词表
3. **超参**：LR、batch、梯度裁剪
4. **并行**：DP + TP + PP + SP
5. **训练**：定期 checkpoint、监控 loss/PPL/eval
6. **评测**：MMLU、HellaSwag、C-Eval、GSM8K
7. **后处理**：长上下文扩展、推理量化

**典型规模**（LLaMA-3 70B）：15T tokens、~16000 H100、~1 个月、约 $10M+。

## 9. 最简记忆

```text
训练目标：
  CLM（next token）       → GPT、LLaMA   利用率 100%
  MLM（masked）           → BERT          利用率 15%
  PrefixLM、Span          → GLM、T5       折中

Scaling：
  Chinchilla 最优 1 : 20（参数 : token）
  实际部署偏向 1 : 100+（小模型 + 大量数据）

数据：抓取 → 清洗 → 去重（MinHash/SemDedup）→ packing

涌现能力：随规模突然出现，存在评估争议。
```

## 🎯 高频追问

1. **怎么判断模型"训过了"**？看 loss 平台期 + downstream 评估收敛。

2. **数据混合比例怎么定**？根据 downstream 任务重要性 + Doremi 等自动方法。

3. **是否需要 curriculum learning**？大数据下效果不明显，但"先简单后复杂"在 SFT 阶段有用。

4. **Loss spike 怎么办**？回滚 checkpoint，跳过坏 batch，降 LR 重启。BF16 比 FP16 稳得多。

5. **数据污染怎么检测**？n-gram 重叠检测，或用模型记忆探测。
