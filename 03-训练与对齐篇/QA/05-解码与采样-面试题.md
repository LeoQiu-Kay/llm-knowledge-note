## Q1: 主流解码策略有哪些？各自优缺点？
> 难度 ⭐⭐ ｜ 高频 🔥🔥🔥

| 方法 | 选择策略 | 优 | 缺 |
|---|---|---|---|
| **Greedy** | 每步选 argmax | 确定、快 | 局部最优、单调重复 |
| **Beam Search** | 维护 Top-B 条路径 | 比 greedy 好 | 缺乏多样性、倾向短句 |
| **Sampling** | 按 softmax 采样 | 多样 | 可能采到长尾噪声 |
| **Top-k** | 只从 Top-k 中采 | 限制长尾 | $k$ 固定不灵活 |
| **Top-p**（Nucleus） | 累积概率 ≥ $p$ 的最小集合 | **自适应**，主流 | $p$ 调参 |
| **Temperature** | 缩放 logits | 控制随机性 | 不直接截断 |

工业标准：top-p + temperature 组合（chat 默认 $T=0.7$，$p=0.9$）。

---

## Q2: Temperature 的公式？取不同值的效果？
> 难度 ⭐⭐ ｜ 高频 🔥🔥

$$P(x_i) = \frac{\exp(z_i / T)}{\sum_j \exp(z_j / T)}$$

- $z_i$：第 $i$ 个 token 的 logit
- $T$：温度（正数）

**效果**：
- $T = 1$：原始 softmax
- $T \to 0$：分布变尖 → 接近 argmax（greedy）
- $T \to \infty$：分布变平 → 接近均匀

**典型值**：
- 0.0：完全确定（数学、代码、抽取）
- 0.3-0.7：保守生成（文档、代码补全）
- 0.7-1.0：自然对话
- 1.0-1.5：创意写作

## Q3: Top-k vs Top-p 的本质区别？为什么 Top-p 更受欢迎？
> 难度 ⭐⭐ ｜ 高频 🔥🔥🔥

**Top-k**：固定取前 $k$ 个 token 重新归一化（$k$ 固定）。

**Top-p（Nucleus Sampling）**：累积概率 ≥ $p$ 的最小集合，**集合大小自适应**。

**关键对比**：

| 场景 | 分布尖锐（强自信） | 分布平（模型犹豫） |
|---|---|---|
| **Top-k** | 保留太多无关 token | 漏掉合理候选 |
| **Top-p** | nucleus 小（如 1-3 个） | nucleus 大（如 30 个） |

```text
Top-p 的优势：自适应模型自信度
  - 模型很确定 → 选少数候选
  - 模型不确定 → 给更多候选机会
```

**实践推荐**：$p = 0.9$ 是常用值；也可组合"先 top-k 再 top-p"。

## Q4: Beam Search 在 LLM 时代为什么不流行了？
> 难度 ⭐⭐ ｜ 高频 🔥🔥

**问题**：
1. **重复倾向**：高概率路径常重复（"the the the"），LLM 大词表加剧
2. **缺乏多样性**：beam 之间高度相似（共享 prefix）
3. **倾向短句**：长句概率必然下降（每步 $P<1$ 连乘），需 length penalty 补偿
4. **不适合开放生成**：聊天 / 创作需要多样性

**仍适用场景**：翻译、摘要等"标准答案 / 输出短"的任务。

**LLM chat 主流**：sampling（top-p + temperature）几乎全面替代 beam search。

**追问：beam search 倾向短句的根因？** $P(y_{1:T}) = \prod_t P(y_t \mid y_{<t})$，每多一步概率都被乘一个 $<1$ 的数，所以长句似然天然低于短句。

## Q5: Repetition Penalty 是怎么实现的？典型值多少？
> 难度 ⭐⭐ ｜ 高频 🔥🔥

**目的**：抑制重复 token。

**实现**：对已生成过的 token，按符号对其 logit 做惩罚：

```python
def apply_repetition_penalty(logits, generated_ids, penalty=1.1):
    for token_id in set(generated_ids):
        if logits[token_id] > 0:
            logits[token_id] /= penalty
        else:
            logits[token_id] *= penalty
    return logits
```

**典型值**：1.0（无惩罚）~ 1.2。过大会让生成失流畅。

**变种**：
- **Frequency Penalty**：按出现次数比例惩罚
- **Presence Penalty**：出现过就惩罚一次（固定量）
- **No Repeat N-gram**：禁止生成已出现过的 n-gram

**追问：为什么对正 logit 除、负 logit 乘？** 都是让"已出现 token 的概率下降"——正 logit 除以 >1 的数变小，负 logit 乘 >1 变更负，行为统一。

## Q6: 投机解码（Speculative Decoding）的原理？算法流程？
> 难度 ⭐⭐⭐⭐ ｜ 高频 🔥🔥🔥

**核心思想**：用一个**快的草稿模型** $M_q$ 一次生成多个 token，让**慢的目标模型** $M_p$ **并行**验证。

**算法流程**：

```
Repeat:
    1. 草稿: x_1, ..., x_k ~ M_q（顺序生成 k 个 token）
       记录每个 token 的概率 q(x_i)

    2. 验证: 用 M_p 一次 forward 这 k 个 token
       得到 M_p 给每个位置的概率 p(x_i)

    3. 对每个位置 i = 1..k 顺序检查:
       u ~ Uniform(0, 1)
       if u < min(1, p(x_i) / q(x_i)):
           接受 x_i
       else:
           拒绝 x_i，从分布 max(0, p - q) 重采一个 token
           跳出循环

    4. 若全部接受: 从 M_p 的 k+1 位置采一个 bonus token
```

**符号**：
- $M_p$：target（慢但准）
- $M_q$：draft（快但不准）
- $k$：每轮草稿长度（4-8）

**核心点**：草稿一次出 $k$ 个 token，目标模型用**一次 forward 并行验证**，省去了"$k$ 次自回归 forward"的串行成本。

## Q7: 投机解码为什么"不改变输出分布"？
> 难度 ⭐⭐⭐⭐ ｜ 高频 🔥🔥

**关键性质**：拒绝采样后的分布 = 直接从 $M_p$ 采样。

**直觉证明**：
- 接受概率 $\min(1, p/q)$：当 $p \geq q$ 时全接受；当 $p < q$ 时按比例接受
- 拒绝时从 $\max(0, p - q)$ 重采：恰好补足"草稿没采够的概率"
- 总效果：每个 token 出现概率 = $p$ 自身

**经典拒绝采样的标准结果**，数学上严格保证 $M_p$ 的分布不变。

```text
意义：可以放心用，不损失生成质量。
工程上偶有差异 → 通常是数值精度或实现 bug。
```

**追问：草稿模型怎么选？** 同 tokenizer 的小模型最方便（如 LLaMA-3-70B + LLaMA-3-8B 作草稿）。

## Q8: 投机解码的加速比公式？典型加速多少？
> 难度 ⭐⭐⭐ ｜ 高频 🔥

$$\text{Speedup} \approx \frac{1 - \alpha^{k+1}}{(1 - \alpha)(1 + c k)}$$

**符号**：
- $\alpha$：单 token 接受率（典型 0.5-0.8）
- $k$：草稿长度
- $c$：草稿模型 / 目标模型成本比（越小越好）

**典型加速**：
- 普通投机：**1.5-2.5×**
- + EAGLE：**3-4×**

**关键直觉**：
- $\alpha$ 越高 → 期望接受 token 数 $\approx \frac{1-\alpha^{k+1}}{1-\alpha}$ 越大
- $k$ 太大 → $c k$ 项变大，草稿成本反超收益
- 所以 $k$ 有最优值（典型 4-8）

## Q9: Medusa 和 EAGLE 的核心区别？为什么 EAGLE 是 SOTA？
> 难度 ⭐⭐⭐ ｜ 高频 🔥

**Medusa**：在目标模型上加多个"head"，并行预测多个未来 token：
```
基础 Transformer 主干
  ↓
LM Head (预测下一 token)
+ Medusa Head 1 (预测下下个)
+ Medusa Head 2 (预测下下下个)
+ ...
```

**EAGLE**：用一个**小 Transformer 解码器**当草稿，**输入是目标模型的隐藏状态**（非 token）。

**为什么 EAGLE > Medusa**：
- 隐藏状态比 token 信息更丰富（包含完整上下文）
- 小解码器更灵活，能用 transformer 结构充分利用上下文
- 接受率比 Medusa 更高（更接近目标分布）
- EAGLE-2 / EAGLE-3 SOTA，加速可达 3-4×

**Medusa 的优势**：不需要独立小模型，硬件部署更简单。

## Q10: 不同任务的解码超参怎么选？
> 难度 ⭐⭐ ｜ 高频 🔥

**Chat 模型默认**：
- Temperature: 0.7
- Top-p: 0.9
- Top-k: 50（或关闭）
- Repetition penalty: 1.05-1.1

**确定性任务**（代码、数学、抽取、分类）：
- Temperature: 0（= Greedy）

**创意写作**：
- Temperature: 0.9-1.2
- Top-p: 0.95

**推理模型（o1 / R1 风格）**：
- **Temperature: 0.6**（推荐，不能用 greedy）
- Top-p: 0.95
- **原因**：greedy 容易陷入循环（"thinking thinking..."），需少量随机性打破
