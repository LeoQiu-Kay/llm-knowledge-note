## Q1: Chain of Thought（CoT，思维链）是什么？为什么有效？
> 难度 ⭐⭐ ｜ 高频 🔥🔥🔥

**核心**：让模型"一步步推理"再给答案，而非直接答。

**三种触发方式**：
1. **Zero-shot CoT**：prompt 末尾加 "Let's think step by step."
2. **Few-shot CoT**：示例里带推理过程
3. **Training-based**：SFT 数据中含大量"问题 + CoT + 答案"

**为什么有效**：
- 复杂问题被分解为多步小推理 → 每步只需小算力
- 自回归生成中，CoT 相当于"草稿纸"，保留中间状态
- 让 transformer 多走几个 forward step 来摊薄推理深度（深度 ≈ token 数）

**效果**（GSM8K 经典对比）：
- 直接回答：~20%
- CoT：~60%

**追问：为什么小模型上 CoT 没用？** 小模型推理能力弱，CoT 越长错误传播越多。一般 > 10B 才显著见效。

## Q2: Self-Consistency 是什么？和 Best-of-N 区别在哪？
> 难度 ⭐⭐ ｜ 高频 🔥🔥

**Self-Consistency（SC）**：
1. 用 CoT prompt 调用 LLM $N$ 次（$N$=10~40），temperature > 0
2. 提取每次最终答案
3. **多数投票**选最常见答案

**为什么有效**：
- CoT 一次可能犯随机错
- 不同推理路径到达**同一正确答案**的概率高
- 错误答案因不同原因散布

**SC vs Best-of-N（BoN）对比**：

| | Self-Consistency | Best-of-N |
|---|---|---|
| 选答案 | 多数投票 | RM / verifier 打分选最高 |
| 是否需要外部模型 | 否 | **是**（RM 或 verifier） |
| 适用 | 数学题（有明确最终答案） | 通用任务（开放回答） |
| 代价 | 推理 ×$N$ | 推理 ×$N$ + 打分 |

## Q3: o1 / DeepSeek-R1 的"长 CoT"范式和传统 CoT 区别？
> 难度 ⭐⭐ ｜ 高频 🔥🔥🔥

| 维度 | 传统 CoT | o1 / R1 风格 |
|---|---|---|
| CoT 长度 | 几百 token | **几千-几万 token** |
| 自我修正 | 少 | 频繁（"wait, let me reconsider"） |
| 训练方式 | SFT 模仿 | **大规模 RL** |
| 适用 | 通用 | 数学、代码、复杂推理 |

**训练方法**：
- **OpenAI o1**：未公开，估计是大规模 RL + 过程奖励
- **DeepSeek-R1**：
  - **R1-Zero**：直接在 base 上用 GRPO + 规则奖励 RL，**自发涌现长 CoT**
  - **R1**：用 R1-Zero 数据冷启 SFT + 多阶段 RL，更稳定

详见 [07-DeepSeek-R1论文解读](../07-DeepSeek-R1论文解读.md)。

## Q4: R1-Zero 的"涌现"现象具体表现是什么？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥🔥

DeepSeek-R1 论文报告的三大涌现现象：

1. **"Aha moment"**：训练某一步突然出现 self-correction，模型自发说出 "Wait, I made a mistake, let me reconsider" 类语句
2. **思考长度持续增长**：随训练步数推进，模型对难题的 CoT 长度从几百自动增到几千
3. **多语言混用**：R1-Zero 自由切换中英文（后用"语言一致性奖励"缓解）
4. **Verification / 重新计算**：算完一遍后主动再验证一次
5. **Strategy adaptation**：发现思路不对就换方法

**核心意义**：**无 SFT 引导、纯 RL 就能让 base 模型"自学"复杂推理模式**。这是 R1 论文的标志性发现。

## Q5: PRM（过程奖励）vs ORM（结果奖励）：区别和选择？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥

| 类型 | 输入 | 输出 | 优劣 |
|---|---|---|---|
| **ORM**（Outcome Reward Model） | 完整答案 | 最终对错 | 简单、信号稀疏 |
| **PRM**（Process Reward Model） | 答案 + 每步 | **每步对错** | 细粒度、标注难 |

**ORM 公式**：

$$r_{\text{ORM}}(x, y) = \mathbb{1}[y_{\text{final}} = y^*]$$

其中 $\mathbb{1}[\cdot]$ 为指示函数。

**应用**：
- **数学 / 代码**：可用 verifier（执行结果对错）作 ORM → 简单可靠、规则不可 hack
- **R1 / o1**：偏向 rule-based ORM
- **PRM 的踩坑**：DeepSeek-R1 论文专门说 PRM 失败了——见 Q8

## Q6: Best-of-N 怎么做？和 RM 的关系？
> 难度 ⭐⭐ ｜ 高频 🔥

**最简单的推理时优化**：

1. 对同 prompt 采样 $N$ 个答案
2. 用 RM / verifier 打分
3. 返回分数最高的

$N$ 通常 16-64。

**Best-of-N 与 RM 的关系**：
- BoN 本质就是"穷举多候选 + RM 当裁判"
- 如果 RM 准 → BoN 效果好；如果 RM 容易被 hack → BoN 也被 hack
- 所以 BoN 几乎是 RM 质量的"放大镜"

**与 SC 选哪个**：
- 答案唯一可对比（数学）→ SC（不需要 RM）
- 答案开放（写作、对话）→ BoN（需要 RM 判好坏）

## Q7: MCTS + LLM 怎么做？为什么 DeepSeek-R1 放弃了它？
> 难度 ⭐⭐⭐ ｜ 高频 🔥

**MCTS + LLM 思路**：
1. 把 LLM 当 policy，部分 CoT 作为节点
2. LLM 采样多个"下一步"展开
3. value model 估每分支价值
4. UCB 选 → 展开 → 回传 → 重复
5. 选最优路径

**代表**：AlphaCode 2、ReST-MCTS。

**R1 论文为什么放弃**（Section 4.2 "失败的尝试"）：
1. **搜索空间指数级爆炸**：token 词表远大于围棋的 361 个位置
2. **value model 不可靠**：评估"半句话的价值"非常难
3. **路径过滤弱 / 易陷入局部最优**：限制扩展后又容易卡死

**R1 的最终选择**："把搜索内化到模型权重里"——通过 RL 训练，模型在 forward pass 中自动完成"搜索 + 验证 + 回溯"，不需要外部搜索树。

```text
最朴素的方案（GRPO + 规则奖励）赢了。
复杂的方案（PRM、MCTS）败了。
```

## Q8: 为什么 DeepSeek-R1 论文说 PRM 失败了？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥

R1 论文 Section 4.2 罕见公开"踩过的坑"。PRM 失败的三大问题：

1. **难定义"一步"**：自然语言推理没有明确步骤边界（不像下棋）
2. **标注难扩展**：自动标不准、人工标不 scale
3. **Reward Hacking**：模型学会"刷过程分"而非真推理

**论文原话**：
> "Building a PRM that is smarter than the model it is grading is a paradox."

**深层悖论**：要让 PRM 评判模型，PRM 至少得和模型一样聪明；可如果 PRM 那么聪明，为什么不直接当 policy？

PRM 增加复杂度但不带来稳定收益 → 论文最终用 **ORM + 规则奖励**。

## Q9: 推理时 scaling 和训练时 scaling 是什么关系？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥

**OpenAI o1 的核心洞察**：
- **训练时 scaling**（更大模型、更多数据）边际收益递减
- **推理时 scaling**（更多推理 token、SC、BoN、MCTS）开辟新轴
- 两者**可叠加**，但成本曲线不同

**成本对比**：
- 训练：**一次性、固定**（摊到所有 query）
- 推理：**每次都付**，对延迟敏感

**实际权衡**：
| 路线 | 成本结构 | 适用 |
|---|---|---|
| 小模型 + 长 CoT + SC | 高单次推理成本 | 复杂数学/代码任务 |
| 大模型 + 直接回答 | 高训练成本，低延迟 | 通用对话 |
| o1 / R1 | 推理 token 数十倍 | 用户能等的高价值 query |

**追问：o1 API 为什么远比 4o 贵？** 每次输出大量"thinking" token（即使隐藏），实际生成的 token 数是 4o 的几十倍。

## Q10: 长 CoT 在部署上有哪些挑战？
> 难度 ⭐⭐ ｜ 高频 🔥

1. **延迟**：用户可能要等几十秒到几分钟
2. **成本**：每次推理产生大量 token，按 token 计费场景昂贵
3. **KV Cache 爆炸**：超长输出 → KV Cache 显存巨大
4. **截断风险**：超过 max context 长度被截
5. **可读性**：是否把内部 CoT 给用户看？OpenAI 选择隐藏（防蒸馏 + 用户体验）
6. **推理模型不适合所有任务**：常识对话、开放生成收益小、反而更慢

**追问：R1 为什么不推荐 temperature=0？** Greedy 容易陷入循环（"thinking thinking thinking..."），需要少量随机性打破。官方推荐 $T=0.6$、top-p=0.95。
