## Q1: CLM、MLM、PrefixLM 三种预训练目标有什么区别？
> 难度 ⭐⭐ ｜ 高频 🔥🔥🔥

| 目标 | 代表 | 目标 | 数据利用率 |
|---|---|---|---|
| **CLM**（Causal LM，因果语言建模） | GPT、LLaMA | 每个位置预测下一个 token | **100%** |
| **MLM**（Masked LM，掩码语言建模） | BERT | 随机 mask 15%，预测被 mask 的 token | **15%** |
| **PrefixLM** | GLM | 前缀双向，后缀单向 | 折中 |
| **Span Corruption** | T5 | mask 连续片段，预测整段 | 折中 |

CLM 损失：

$$\mathcal{L}_{\text{CLM}} = -\sum_{t=1}^{N} \log P(x_t \mid x_{<t}; \theta)$$

每个 token 都贡献 loss → 数据利用率 100%，这是 CLM 战胜 MLM 的关键之一。

## Q2: 为什么现在的大模型都用 CLM，不用 MLM？
> 难度 ⭐⭐ ｜ 高频 🔥🔥🔥

四条理由：

1. **数据利用率高**：CLM 每 token 都算 loss，MLM 只算 15% mask 位置
2. **训练/推理一致**：CLM 训练目标就是生成，BERT 训练时见到 `[MASK]`、推理时见不到，存在分布偏移
3. **In-Context Learning 天然支持**：causal mask 让"prompt + few-shot 示例 + 问题"自然成立
4. **Scaling 友好**：CLM 归纳偏置弱、可任意堆数据，符合 scaling laws

**追问：BERT 路线还有用吗？** 在 embedding / retrieval / 分类等判别式任务上 BERT 仍是好基座（双向 attention 信息更密）；但生成 / 通用 LLM 已全部转向 CLM。

## Q3: Chinchilla Scaling Law 说了什么？为什么现在又"不按它办"？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥🔥

**Chinchilla（DeepMind 2022）**：给定计算预算 $C$，模型参数 $N$ 与训练 token $D$ 的最优比例是

$$N : D \sim 1 : 20$$

每个参数约配 20 token。Chinchilla（70B + 1.4T tokens）证明在同算力下超越 Gopher（280B + 300B tokens）—— 纠正了 Kaplan 偏大模型的早期结论。

**LLaMA-3 8B 训了 15T tokens，比例约 1 : 1875，远超 Chinchilla 最优**。原因：

- Chinchilla 最优是"训练 loss 最小"，**不是部署最优**
- 推理成本每次都付，小模型推理便宜
- 训练只一次性贵，所以业界愿意"过训"（over-train）小模型来换部署划算

```text
Chinchilla 算的是"训练 FLOPs 最优"
工业算的是"训练 + 推理总成本最优" → 小模型 + 大数据
```

**追问：Kaplan 和 Chinchilla 错在哪？** Kaplan 的实验里学习率调度有偏（按总步数 cosine 衰减，而比较的不同模型步数不同），导致小模型欠训，结论偏向大模型。Chinchilla 修正了学习率调度。

## Q4: 预训练数据的清洗流程是什么？为什么去重那么重要？
> 难度 ⭐⭐ ｜ 高频 🔥🔥

**典型流程**：
1. **语言识别**：fastText 过滤目标语种
2. **质量过滤**：困惑度过滤 / 训练小分类器（C4、FineWeb 都这么做）
3. **去重**：URL/精确去重 → **MinHash**（near-duplicate）→ **SemDedup**（embedding 语义级）
4. **PII 清除**：邮箱、电话、社保号
5. **毒性 / NSFW 过滤**
6. **格式清理**：去 HTML、boilerplate、广告

**去重为什么重要**：
- 重复数据让模型"过度记忆"而非泛化 → 测试集污染、generation 时直接背原文
- 论文（Lee et al. 2022）显示去重后**同样数据效果显著上升**
- 同一段被重复学很多次相当于浪费算力

## Q5: 数据 packing 是什么？为什么需要 document mask？
> 难度 ⭐⭐ ｜ 高频 🔥🔥

**问题**：训练序列长度固定（如 8K），但单文档长度参差，按文档喂会浪费大量 padding 算力。

**Packing**：把多个短文档用 `<eos>` 拼成一个固定长度（8K）序列。

```
[doc1] <eos> [doc2] <eos> [doc3] <eos> [doc4] ... → 8K
```

**Document Mask**：让 attention 不跨文档边界，避免后文档"读到"前文档的内容污染上下文。

```text
工程上：很多团队（包括早期 GPT）干脆不隔离，
视为轻微噪声 —— 大数据下影响可忽略。
现代实现（如 LLaMA-3）通常加 document mask。
```

## Q6: 涌现能力（Emergent Abilities）是什么？真的存在吗？
> 难度 ⭐⭐ ｜ 高频 🔥🔥

**定义**：某些能力在模型超过某规模后突然出现，规模以下接近随机。

**典型例子**：多位数加减法、CoT 推理、指令遵循、大规模 ICL。

**经验门槛**：
- < 1B：基本 LM 能力
- 1-10B：复杂理解
- > 10B：复杂推理
- > 70B：强 zero-shot

**争议（Schaeffer et al. 2023）**：涌现可能是**评估方式的伪影**——
- 用 exact-match 等离散指标 → 看起来突然跃升
- 用连续指标（log-likelihood、token-level accuracy）→ 平滑改善

**结论**：能力的连续增长是真的；"突然涌现"的视觉效果部分是评估造成的。

## Q7: 长上下文模型怎么训？为什么"先短训后长训"？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥

| 模型 | 训练序列长度 |
|---|---|
| BERT | 512 |
| GPT-3 | 2048 |
| LLaMA-2 | 4K |
| LLaMA-3 | 8K（YaRN 扩到 128K） |
| Claude-3 / GPT-4o | 128K→200K+ |

**做法**：90% 数据短上下文（4K-8K）+ 10% 长上下文（32K-128K）。

**为什么**：
- Attention 显存随长度二次方增长 → 全长训练贵
- 短文本数据多、长文本数据少 → 强行长训会浪费 + 数据不足
- 大部分能力（语言、知识）短上下文就能学
- 长上下文能力主要靠"位置编码扩展"（RoPE 插值、YaRN）+ 少量长样本就能解锁

**追问：YaRN 怎么扩长度？** 对 RoPE 做 NTK-aware 插值，对低频维度直接扩、对高频维度保留，再用少量长样本微调即可把 8K 扩到 128K。

## Q8: Loss spike 怎么办？BF16 比 FP16 强在哪？
> 难度 ⭐⭐ ｜ 高频 🔥🔥

**Loss spike**：训练中 loss 突然爆涨（可能跳数十倍）然后慢慢回来或干脆 NaN。

**对策**：
- 回滚到 spike 前的 checkpoint
- 跳过那个 batch
- 降学习率 / 减小 batch 重训
- 检查数据是否有异常长 / 重复 token

**BF16 vs FP16**：
| | FP16 | BF16 |
|---|---|---|
| 指数位 | 5 | **8（同 FP32）** |
| 范围 | $10^{-5}$ ~ 65504 | 同 FP32 |
| 精度 | 高 | 低 |

LLM 梯度普遍很小（$10^{-6}$）：FP16 表示不了 → 下溢为 0 → 训练崩。BF16 范围大、几乎不用 Loss Scaling、**对 spike 更稳**。现代 LLM 预训练几乎全部用 BF16。

## Q9: 预训练完成的判断标准？训练成本大概多少？
> 难度 ⭐⭐ ｜ 高频 🔥

**判断"训过了"**：
- Training loss 进入平台期（再训也几乎不降）
- Downstream 评估（MMLU、HellaSwag、GSM8K）收敛
- Validation loss 不再降但 train loss 继续降 → 开始过拟合

**典型成本**（LLaMA-3 70B）：
- 15T tokens
- ~16,000 H100
- ~1 个月训练时间
- ~$10M+ 算力成本

**评测主流榜单**：MMLU（通用知识）、HellaSwag（常识）、C-Eval（中文）、GSM8K（数学）、HumanEval（代码）。
