## Q1: RLHF（Reinforcement Learning from Human Feedback）三阶段流程是什么？
> 难度 ⭐⭐ ｜ 高频 🔥🔥🔥

```text
Step 1: SFT     → 用高质量人工示范微调 base 模型
Step 2: RM      → 训标量奖励模型（用偏好数据）
Step 3: RL(PPO) → 用 RM 提供奖励，PPO/GRPO 更新 policy
```

**总目标**：

$$\max_\theta \mathbb{E}_{x, y \sim \pi_\theta}\big[r(x, y) - \beta \, D_{KL}(\pi_\theta(\cdot \mid x) \, \| \, \pi_{\text{ref}}(\cdot \mid x))\big]$$

- $\pi_\theta$：被训的 policy（actor）
- $\pi_{\text{ref}}$：冻结的 SFT 模型，作为参考
- $r(x,y)$：RM 给的奖励
- $\beta$：KL 惩罚系数（典型 0.01-0.1）

**追问：KL 项有什么用？** 防止 policy 偏离 SFT 太多，避免 reward hacking 和 mode collapse。

## Q2: Reward Model（RM）怎么训？为什么损失是 log-sigmoid 形式？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥🔥

**数据**：偏好三元组 $(x, y_w, y_l)$，$y_w$（**w**inner）比 $y_l$（**l**oser）好。

**损失（Bradley-Terry 模型）**：

$$\mathcal{L}_{RM} = -\mathbb{E}_{(x, y_w, y_l)} \big[\log \sigma\big(r_\phi(x, y_w) - r_\phi(x, y_l)\big)\big]$$

**Bradley-Terry 推导**：假设"$y_w$ 被人选中"的概率 = $\sigma(r_w - r_l)$，对偏好数据做 MLE 就得到上式。

**直觉**：让 $r(y_w) - r(y_l)$ 越大越好（log-sigmoid 把差距推开），但因 sigmoid 饱和，差距足够大后不再用力推 → 不会无界放大。

**结构**：通常用 SFT 模型初始化，把 lm_head 换成 scalar head（一个标量输出）。

## Q3: PPO 在 RLHF 里同时持有的 4 个模型分别是什么？各自的职责？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥🔥（**几乎必问**）

| 模型 | 训练状态 | 输入 | 输出 | 角色 |
|---|---|---|---|---|
| **Actor / Policy** $\pi_\theta$ | **可训练** | prompt + 已生成 token | 下一 token 分布 | 被优化的"主角" |
| **Critic / Value** $V_\phi$ | **可训练** | prompt + 已生成 token | **一个标量** | 估"未来总收益"，给 actor 做 baseline |
| **Reward Model** $r$ | 冻结 | 完整 $(x, y)$ | **一个标量** | 给整段回答打"事后总分" |
| **Reference** $\pi_{\text{ref}}$ | 冻结 | prompt + 已生成 token | 下一 token 分布 | SFT 副本，做 KL 约束 |

**最容易混的两点**：
1. **RM ≠ Critic**：RM 给"事后总分"，Critic 估"未来期望"
2. **Reference ≠ Critic**：Reference 用来算 KL（防偏离 SFT），Critic 用来算 advantage（减方差）

```text
Reward Model = 事后总分    （考完给分）
Critic       = 未来期望预言（期中预测期末平均能考多少）
```

## Q4: PPO 为什么需要 Critic？不直接用 reward 行不行？
> 难度 ⭐⭐⭐⭐ ｜ 高频 🔥🔥🔥

PPO 更新用 **advantage**，不是 reward：

$$A_t = R_t - V(s_t)$$

- $R_t$：从 $t$ 步开始的实际累积奖励（事后才知道）
- $V(s_t)$：Critic 估的"从 $s_t$ 起平均能得多少分"

**对比直接用 $R_t$**：

| 直接用 $R_t$（方差极大） | 用 $A_t = R_t - V(s_t)$（baseline 减方差） |
|---|---|
| "这条轨迹总分高 → 鼓励所有 token" | "比预期好就鼓励，比预期差就抑制" |
| 好答案里的差 token 也被鼓励 | 每个 token 只看是否高于平均 |
| 训练高方差、不稳 | 训练稳定 |

**例子**：数学题答对（$R_t = 1.0$）但第 3 步推理错了
- 直接用 $R_t$ → 错误那一步也被鼓励 ❌
- 用 $A_t$ → critic 估该状态下平均也能拿 1.0，所以 $A_t \approx 0$ → 不强化错误 ✓

```text
Critic 的核心作用：提供 baseline → 降低 policy gradient 方差 → 让 RL 能稳定收敛。
没有 critic，PPO 几乎训不起来（除非用组内归一化，即 GRPO）。
```

## Q5: PPO 的 per-token reward 怎么设计？为什么中间 token 只有 KL 惩罚？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥

把 RM 的"事后总分"和 KL 罚组合成 per-token reward。最后一步给 RM 总分，其余只给 KL：

$$r_t = \begin{cases} -\beta \log \dfrac{\pi_\theta(a_t \mid s_t)}{\pi_{\text{ref}}(a_t \mid s_t)}, & t < T \end{cases}$$
$$r_T = r_{\text{RM}}(x, y) - \beta \log \dfrac{\pi_\theta(a_T \mid s_T)}{\pi_{\text{ref}}(a_T \mid s_T)}$$

**为什么这样设计**：
- RM 是对**整段回答**打的分，没法 "per-token 分解"
- 所以总分一次性给在最后一个 token 上（end-of-sequence reward）
- 中间每步加 KL 罚，逐 token 抑制偏离 SFT

**回路**：actor 采样 → RM 算总分 → critic 估每步 V → GAE 算 $A_t$ → CLIP loss 更新 actor，MSE 更新 critic。

## Q6: PPO 的 CLIP 目标怎么写？为什么要 clip？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥🔥

$$\mathcal{L}^{\text{CLIP}}(\theta) = \mathbb{E}_t \big[\min(\rho_t A_t, \, \text{clip}(\rho_t, 1-\epsilon, 1+\epsilon) A_t)\big]$$

**符号**：
- $\rho_t = \dfrac{\pi_\theta(a_t \mid s_t)}{\pi_{\text{old}}(a_t \mid s_t)}$：重要性采样比（新旧 policy 概率比）
- $\epsilon$：clip 阈值（典型 0.2）
- $A_t$：GAE 算的 advantage

**直觉**：
- $A_t > 0$ → 想推高该 token 的概率，但 $\rho_t$ 超过 $1+\epsilon$ 就 clip → **单步更新最多放大 20%**
- $A_t < 0$ → 想降低概率，但 $\rho_t$ 低于 $1-\epsilon$ 也 clip
- **min 操作**：保证 clip 在"过度激进"方向上生效，"过度保守"方向上不生效（pessimistic bound）

**为什么 clip 关键**：
- RL 本身高方差、不稳
- 一次大幅更新可能让 $\pi_\theta$ 远离 $\pi_{\text{old}}$ → 后续重要性采样估计失效
- Clip 把每步更新限制在信赖域内 → 训练能稳

## Q7: GAE（Generalized Advantage Estimation）的公式？$\lambda$ 起什么作用？
> 难度 ⭐⭐⭐⭐ ｜ 高频 🔥🔥

**TD 误差**：

$$\delta_t = r_t + \gamma V(s_{t+1}) - V(s_t)$$

**GAE advantage**：

$$A_t = \sum_{l=0}^{T-t} (\gamma \lambda)^l \delta_{t+l}$$

**$\lambda$ 的角色**（bias-variance tradeoff）：

| $\lambda$ | 退化为 | 偏差 | 方差 |
|---|---|---|---|
| $\lambda = 0$ | $A_t = \delta_t$（1-step TD） | 大 | 小 |
| $\lambda = 1$ | $A_t = R_t - V(s_t)$（蒙特卡洛） | 小 | 大 |
| **0 < $\lambda$ < 1** | 平滑插值 | 中 | 中 |

典型 $\lambda = 0.95$、$\gamma = 1.0$（RLHF 中 $\gamma=1$ 因为奖励集中在最后）。

**Critic 怎么训**：MSE loss，

$$\mathcal{L}_{\text{VF}}(\phi) = \big(V_\phi(s_t) - R_t\big)^2$$

注意 $\delta_t$ 里两次出现 $V$，所以**没有 critic 就算不了 GAE**。

## Q8: DPO（Direct Preference Optimization）怎么推出来？相比 PPO 优势在哪？
> 难度 ⭐⭐⭐⭐ ｜ 高频 🔥🔥🔥

**推导路线**：从 RLHF 的 KL 约束最优解出发：

$$\pi^*(y \mid x) = \frac{1}{Z(x)} \pi_{\text{ref}}(y \mid x) \exp\Big(\frac{r(x, y)}{\beta}\Big)$$

反解出隐式奖励：

$$r(x, y) = \beta \log \frac{\pi^*(y \mid x)}{\pi_{\text{ref}}(y \mid x)} + \beta \log Z(x)$$

代入 Bradley-Terry 偏好损失（同一 $x$ 下 $\log Z(x)$ 被消掉），得到 **DPO 目标**：

$$\mathcal{L}_{\text{DPO}} = -\mathbb{E}\Big[\log \sigma\Big(\beta \log \frac{\pi_\theta(y_w \mid x)}{\pi_{\text{ref}}(y_w \mid x)} - \beta \log \frac{\pi_\theta(y_l \mid x)}{\pi_{\text{ref}}(y_l \mid x)}\Big)\Big]$$

**DPO vs PPO 对比**：

| 维度 | PPO | DPO |
|---|---|---|
| 需要 RM | ✅ | ❌ |
| 模型数量 | 4（actor/critic/RM/ref） | 2（policy/ref） |
| 训练复杂度 | 高（RL、不稳） | 低（监督学习风格） |
| 显存 | 大 | 小 |
| 数据 | on-policy（采新样本） | off-policy（固定偏好集） |
| 效果上限 | 高 | 略低或持平 |

**核心优势**：把 RL 问题降为监督学习问题，稳、简单、显存省。

## Q9: GRPO（Group Relative Policy Optimization）相比 PPO 改了什么？为什么 DeepSeek 用它？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥🔥

**最核心改动：去掉 critic**，用**组内归一化**做 baseline。

**算法**：
1. 对同 prompt $x$ 采样一组 $\{y_1, \dots, y_G\}$（典型 $G$=16-64）
2. 算每个奖励 $r_i$（RM 或规则）
3. **组内归一化**作为 advantage：

$$A_i = \frac{r_i - \text{mean}(r_1, \dots, r_G)}{\text{std}(r_1, \dots, r_G)}$$

4. 用 PPO 风格 CLIP 更新（用 $A_i$）
5. 保留 KL 约束

**好处**：
- **省一半显存**（无 critic，对训 671B 模型至关重要）
- 数学/代码可用 **rule-based reward**（答案对错可验证）→ 不可 hack
- 训练更稳定

**DeepSeek-R1 用 GRPO** 在大规模数学/代码 RL 上做出 R1-Zero 的推理涌现（详见 [07-DeepSeek-R1论文解读](../07-DeepSeek-R1论文解读.md)）。

**追问：组归一化为啥能替代 critic？** Critic 的本质就是给 baseline 减方差，而"同 prompt 多次采样的组内均值"本身就是该状态下的经验 baseline，是 critic 的"无参数"版本。

## Q10: Reward Hacking 是什么？怎么防？
> 难度 ⭐⭐ ｜ 高频 🔥🔥

**定义**：策略找到 RM 漏洞，刷高分但答案质量并未真提升。

**典型表现**：
- 偏好特别长的回答（RM 训练数据偏向长答 → 学到"长 = 好"）
- 总用 markdown 列表 / 特定开场白骗高分
- 重复使用某些"奖励关键词"

**对策**：
1. **KL 约束**：限制偏离 SFT 太远
2. **多 RM 集成**：取多个 RM 平均/最低分
3. **离线评估**：LLM-as-judge 或人评抽查
4. **持续更新 RM**：把 hack 出来的样本作为新负例重训 RM
5. **规则奖励**：能用规则就别用 RM（如数学题），规则不可 hack

## Q11: Alignment Tax（对齐税）是什么？怎么缓解？
> 难度 ⭐⭐ ｜ 高频 🔥

**定义**：RLHF 后模型在通用 benchmark（MMLU、HumanEval 等）上掉点。

**原因**：
- KL 约束不足，策略过度拟合"对齐目标"
- 偏好数据集偏向某种风格（如 OpenAI 风格的"先说总体再分点"）
- 灾难遗忘 RM 不涵盖的知识/代码能力

**缓解**：
- 加大 KL 约束（$\beta$ 调大）
- 在 RL 中**混入预训练 / SFT 数据**
- **多任务 RM**：覆盖知识、推理、安全多维度
- 用 OPD 风格"教师就是早期版本自己"做防遗忘（详见 [06-OnPolicy蒸馏OPD](../06-OnPolicy蒸馏OPD.md)）

## Q12: PPO、DPO、GRPO 三选一怎么选？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥

| 场景 | 推荐 | 理由 |
|---|---|---|
| **资源紧 / 想快速对齐** | **DPO** | 2 模型、监督学习、好调 |
| **追求效果上限 / 工业大厂** | **PPO** | on-policy + KL 控制最细，但调参苦 |
| **数学/代码 + 可验证奖励** | **GRPO** | 去 critic 省显存 + 规则奖励不可 hack |
| **小数据集偏好对** | **DPO / SimPO / KTO** | RL 需要大量 rollout，小数据不够 |
| **训练 reasoning 模型** | **GRPO**（R1 路线） | 规则奖励 + 组内 baseline 是当前 SOTA |
