# 推理时计算（Test-Time Compute）

> o1 / R1 时代的新范式：用更多推理时计算换取更高质量。

---

## 1. Chain of Thought（CoT）

**核心思想**：让模型"一步步推理"再给答案，而非直接给答案。

**触发方式**：
1. **Zero-shot CoT**：在 prompt 末尾加 "Let's think step by step."
2. **Few-shot CoT**：示例中带推理过程
3. **Training-based**：SFT 数据中含大量带推理的样本

**为什么有效**：
- 复杂问题被分解为多步，每步只需小推理
- 模型有了"草稿纸"，可保留中间状态
- 训练时学到了"显式推理"模式

**效果**（GSM8K 经典数据）：
- 直接回答：~20%
- CoT：~60%

---

## 2. Self-Consistency

**核心**：对同一问题用 CoT **采多次**（温度 > 0），对答案做**多数投票**。

**算法**：
1. 用 CoT prompt 调用 LLM $N$ 次（$N = 10 \sim 40$）
2. 提取每次的最终答案
3. 选出现次数最多的答案

**为什么有效**：
- CoT 一次可能犯随机错误
- 不同推理路径达到同一答案的可能性更高（正确答案）
- 错误答案往往因不同原因散布

**代价**：推理成本 $\times N$。

---

## 3. o1 / DeepSeek-R1：长 CoT 范式

**核心**：训练模型生成**超长 CoT**（数千-数万 token），用推理时大量"思考"换效果。

| 维度 | 传统 CoT | o1 / R1 风格 |
|---|---|---|
| CoT 长度 | 几百 token | 几千-几万 |
| 自我修正 | 少 | 频繁（"wait, let me reconsider"） |
| 训练方式 | SFT 模仿 | **大规模 RL** |
| 适用场景 | 通用 | 数学、代码、复杂推理 |

**训练方法**：
- **OpenAI o1**：未公开，估计是大规模 RL + 过程奖励
- **DeepSeek-R1**：
  - R1-Zero：直接在 base 上用 GRPO + 规则奖励 RL，自发涌现长 CoT
  - R1：用 R1-Zero 数据做冷启 SFT，再 RL，更稳定

---

## 4. R1-Zero 的"涌现"现象

DeepSeek-R1 论文报告了几个有趣现象：

1. **"Aha moment"**：训练过程中模型自发学会说"等等，让我重新考虑"（self-correction）
2. **思考长度持续增加**：随训练，模型对难题的 CoT 长度自动增长
3. **多语言混合**：R1-Zero 在 CoT 中混用中英文（后用语言一致性奖励缓解）

**说明**：通过纯 RL（无 SFT 引导），模型可以"自学"复杂推理模式。

---

## 5. PRM vs ORM（过程奖励 vs 结果奖励）

| 类型 | 输入 | 输出 | 优劣 |
|---|---|---|---|
| **ORM**（Outcome RM） | 完整答案 | 最终对错 | 简单、信号稀疏 |
| **PRM**（Process RM） | 答案 + 每步 | 每步对错 | 细粒度、标注难 |

**ORM**：

$$r_{\text{ORM}}(x, y) = \mathbb{1}[y_{\text{final}} = y^*]$$

**符号说明**：
- $y_{\text{final}}$：模型最终答案
- $y^*$：真实答案
- $\mathbb{1}[\cdot]$：指示函数（成立为 1，否则为 0）

**PRM**：对每一步推理 $s_i$ 都打分。

**应用**：
- 数学 / 代码：可用 verifier（执行结果对不对）作为 ORM，简单可靠
- R1 / o1：偏向规则可验证领域（rule-based ORM）

---

## 6. Best-of-N

最简单的推理时优化：

1. 对同一 prompt 采样 $N$ 个答案
2. 用 RM / verifier 打分
3. 返回分数最高的

**符号**：$N$ 通常 16-64。

**与 Self-Consistency 区别**：
- BoN 需要外部打分器
- SC 是多数投票，不需要打分器

---

## 7. MCTS + LLM

**思路**：把 LLM 当 policy，用 MCTS 做推理时搜索。

**流程**：
1. 当前状态：部分推理过程
2. LLM 采样多个"下一步"
3. value model 估计每个分支的价值
4. UCB 选择 → 展开 → 回传 → 重复
5. 选最优路径

**代表**：AlphaCode 2、ReST-MCTS。

**挑战**：LLM 推理慢，单次 MCTS 需要数百次调用，部署成本高。

---

## 8. 推理时 scaling 与训练时 scaling

**OpenAI 的核心洞察**（o1 系列）：
- 训练时 scaling（更大模型、更多数据）边际收益递减
- 推理时 scaling（更多推理 token、SC、BoN）开辟新轴
- 两者可叠加：更小模型 + 更多推理 vs 更大模型 + 直接答案

**实际成本**：
- 训练：一次性、固定
- 推理：每次都付，对延迟敏感
- o1 API 价格远高于 4o

---

## 9. 长 CoT 的部署挑战

1. **延迟**：用户等几十秒到几分钟
2. **成本**：每次推理大量 token
3. **KV Cache**：超长输出导致 KV Cache 巨大
4. **截断**：超过 context 上限被截断
5. **可读性**：是否给用户看 CoT？OpenAI 把内部 CoT 隐藏

---

## 10. 最简记忆

```text
CoT：让模型一步步推理 → 复杂任务大幅提升
Self-Consistency：多次采样 + 投票
长 CoT (o1/R1)：训练生成几千到几万 token 的推理过程
                + 大规模 RL + 规则奖励

Best-of-N：采 N 个，用 RM 选最好的
MCTS + LLM：树搜索 + LLM 当 policy

PRM 细 / ORM 粗
推理时计算是新 scaling 维度
```

## 🎯 高频追问

1. **CoT 在小模型上为什么没效果**？小模型推理能力弱，越长 CoT 错误越多。一般 > 10B 才显效。

2. **R1 训练成本如何**？相比 SFT 大几倍，但相比预训练仍小。论文说 R1-Zero 起步只用了几千 GPU 小时。

3. **过程奖励数据怎么标**？人工标（贵）或用 MCTS 自动标（如 Math-Shepherd）。

4. **o1 用了 MCTS 吗**？未公开，社区猜测可能有搜索机制。

5. **推理模型适合所有任务吗**？数学、代码、逻辑推理收益大；常识对话、开放生成收益小，反而慢。
