# 对齐与强化学习（RLHF / DPO / GRPO）

> 让模型"听话"的核心技术，PPO → DPO → GRPO 演进必背。

---

## Q1: RLHF 的三阶段流程？

**答**：
**Step 1：SFT（Supervised Fine-tuning）**
- 用高质量人工示范数据微调 base 模型。
- 让模型学会基本的指令遵循和对话格式。

**Step 2：RM（Reward Model）训练**
- 收集偏好数据：同一 prompt 下，标注者排序多个回答（如 chosen > rejected）。
- 训练一个标量奖励模型 $r_\theta(x, y)$，目标：
$$\mathcal{L}_{RM} = -\log \sigma(r(x, y_w) - r(x, y_l))$$
（Bradley-Terry 模型）

**Step 3：RL（PPO/GRPO 等）**
- 用 RM 提供奖励，强化学习更新策略 $\pi_\theta$。
- 目标：最大化奖励的同时不要偏离 SFT 模型太远。
$$\max_\theta \mathbb{E}[r(x,y) - \beta D_{KL}(\pi_\theta(\cdot|x) \| \pi_{\text{SFT}}(\cdot|x))]$$

---

## Q2: Reward Model 的训练细节？

**答**：
**数据格式**：$(x, y_w, y_l)$ 三元组，$y_w$ 是被标注为"更好"的答案。

**模型结构**：
- 通常用 SFT 模型作为初始化
- 把 lm_head 替换为单标量输出 head（线性层）
- 输入完整对话，输出一个标量分数

**损失**（Bradley-Terry）：
$$\mathcal{L} = -\mathbb{E}_{(x, y_w, y_l)}[\log \sigma(r(x, y_w) - r(x, y_l))]$$

**经验**：
- 数据质量比数量重要
- 6B-70B RM 都常见
- 越接近 policy 模型大小越好（避免 reward hacking）

---

## Q3: PPO 在 RLHF 中的细节？

**答**：
**PPO 在 RLHF 中需要 4 个模型**：
1. **Actor（Policy）**：被优化的模型 $\pi_\theta$
2. **Critic（Value）**：估计状态价值 $V_\phi(s)$
3. **Reward Model**：提供 $r(x, y)$（冻结）
4. **Reference Model**：SFT 模型副本，用于 KL 约束（冻结）

**RLHF 中的奖励**：
$$r_{\text{total}} = r_\theta(x, y) - \beta D_{KL}(\pi_\theta \| \pi_{\text{ref}})$$

**PPO 目标**（clip 版本）：
$$\mathcal{L}^{CLIP} = \mathbb{E}[\min(\rho_t A_t, \text{clip}(\rho_t, 1-\epsilon, 1+\epsilon) A_t)]$$
- $\rho_t = \pi_\theta(a_t|s_t) / \pi_{\text{old}}(a_t|s_t)$：重要性采样比
- $A_t$：GAE 估计的优势
- $\epsilon$：通常 0.2，限制策略更新幅度

**GAE（Generalized Advantage Estimation）**：
$$A_t = \sum_{l=0}^{T-t} (\gamma \lambda)^l \delta_{t+l}$$
其中 $\delta_t = r_t + \gamma V(s_{t+1}) - V(s_t)$。

---

## Q4: 为什么需要 KL 惩罚？

**答**：
**目的**：防止 policy 模型偏离 SFT 模型过多。

**问题**：
- 如果不约束，policy 可能找到 RM 的"漏洞"（reward hacking）
- 或者偏离自然语言分布，生成奇怪文本（mode collapse）
- 失去 SFT 学到的能力（语言流畅性、知识）

**实现**：
- 在 reward 中减去 KL 项：$r' = r - \beta \log(\pi_\theta / \pi_{\text{ref}})$
- $\beta$ 是 KL 系数（典型 0.01-0.1），太大约束太强、太小失控
- 可以动态调整 $\beta$（adaptive KL）

---

## Q5: DPO 是什么？为什么不需要 RM？

**答**：
**DPO**（Direct Preference Optimization, NeurIPS 2023）核心：直接用偏好数据训练 policy，绕过 RM。

**关键推导**：
- 在 KL 约束下，RLHF 最优解有解析形式：
$$\pi^*(y|x) \propto \pi_{\text{ref}}(y|x) \exp(r(x,y) / \beta)$$
- 反解 reward：
$$r(x,y) = \beta \log \frac{\pi^*(y|x)}{\pi_{\text{ref}}(y|x)} + C$$
- 代入 Bradley-Terry：
$$\mathcal{L}_{DPO} = -\log \sigma\left(\beta \log \frac{\pi_\theta(y_w|x)}{\pi_{\text{ref}}(y_w|x)} - \beta \log \frac{\pi_\theta(y_l|x)}{\pi_{\text{ref}}(y_l|x)}\right)$$

**优点**：
- 训练简单（监督学习形式，无 RL 不稳定）
- 不需要 RM
- 只需 2 个模型（policy + ref）
- 显存友好

**缺点**：
- 数据效率不如 PPO（PPO 可以从单个 prompt 采多个样本）
- 对离线偏好数据敏感（off-policy）
- 容易过优化（policy 把 chosen 概率推高的同时把 rejected 推到很低，可能整体生成质量下降）

---

## Q6: DPO 与 PPO 的对比？

**答**：

| 维度 | PPO | DPO |
|------|-----|-----|
| 需要 RM | 是 | 否 |
| 模型数量 | 4（actor/critic/RM/ref） | 2（policy/ref） |
| 训练复杂度 | 高（RL，不稳定） | 低（监督学习） |
| 显存 | 大 | 小 |
| 数据使用 | on-policy（边训边采样） | off-policy（固定偏好集） |
| 调参 | 复杂 | 简单 |
| 效果上限 | 高（充分调） | 略低或持平 |
| Anthropic Claude | 用 PPO 变种 | -- |
| 学术 / 开源 | -- | 主流 |

**何时用哪个**：
- 资源有限、数据充足、追求快速迭代 → DPO
- 有完善 infra、需要极致效果、有持续在线数据 → PPO/GRPO

## Q7: GRPO 是什么？为什么 DeepSeek 选它？

**答**：
**GRPO**（Group Relative Policy Optimization, DeepSeek-Math, 2024）：PPO 的简化版。

**核心改动**：**去掉 Critic**，用一组样本的平均奖励作为 baseline。

**算法**：
1. 对同一个 prompt $x$，采样一组答案 $\{y_1, ..., y_G\}$（典型 G=4-16）。
2. 计算每个答案的奖励 $r_i$（用 RM 或规则验证器）。
3. 组内归一化作为优势：
$$A_i = \frac{r_i - \text{mean}(r)}{\text{std}(r)}$$
4. PPO 风格更新，但 advantage 用组归一化。
5. 仍保留 KL 约束。

**好处**：
- **省一半显存**（无 Critic）
- 数学/代码任务用 rule-based reward 极简（如答案对不对）
- 训练更稳定

**DeepSeek-R1 的应用**：
- 用 GRPO 在数学/代码题上做大规模 RL
- 触发"推理涌现"（模型自发生成长 CoT、self-correction）
- 是 R1 系列的核心技术

## Q8: 其他对齐方法简介？

**答**：

| 方法 | 思路 | 备注 |
|------|------|------|
| **RLAIF** | 用 AI 生成偏好数据替代人标 | Anthropic Claude 用 |
| **Constitutional AI** | 模型自我修正 + RLAIF | Anthropic 提出 |
| **ORPO** | SFT + 偏好 loss 一起训 | 单阶段，省 ref 模型 |
| **SimPO** | DPO 简化版，去掉 ref 模型 | 实现更简单 |
| **KTO** | 二元反馈（好/坏）即可，无需 pairwise | 数据收集简单 |
| **RSO**（Rejection Sampling Optimization） | 用 RM 拒绝采样后再 SFT | Llama-3 alignment 用 |
| **Iterative DPO** | 反复"采样→标注→DPO" | 持续提升 |

## Q9: Reward Hacking 是什么？

**答**：
**定义**：策略找到 RM 的漏洞，刷高分但实际质量差。

**典型表现**：
- 输出特定格式（如总是 markdown 列表）来骗高分
- 长答案偏好（很多 RM 偏好长答案）
- 重复用某些"奖励关键词"

**对抗方法**：
1. **KL 约束**：限制偏离 SFT 模型
2. **多 RM 集成**：避免单个 RM 的偏差
3. **离线评估**：用 LLM-as-judge 或人工评估
4. **持续更新 RM**：发现 hacking pattern 后补数据重训

---

## Q10: 对齐税（Alignment Tax）？

**答**：
**定义**：RLHF 后模型在通用能力（base benchmark 如 MMLU）上的下降。

**原因**：
- KL 约束不足，模型过度优化对齐目标
- 偏好数据集偏向某种风格（如冗长解释），影响其他任务
- SFT 阶段数据多样性不足

**缓解**：
- 增强 KL 约束
- 在 RLHF 中混入预训练数据
- 多任务 RM（cover 知识、推理、安全多个维度）

## 🎯 高频追问

1. **DPO 中的 β 怎么选**？典型 0.1-0.5。β 大约束强，偏好优化弱；β 小约束弱，可能过优化。
2. **GRPO 中 G（组大小）怎么选**？8-16 常见。太小估计噪声大，太大算力开销大。
3. **PPO 训练为什么不稳定**？RL 内在的高方差 + 4 模型 + on-policy 采样，需要细致调参。
4. **DPO 训练时 ref 模型怎么处理**？冻结 SFT 模型；推理时 ref logits 可以预计算缓存。
5. **R1 风格的 RL 与 RLHF 的差异**？R1 用规则奖励（rule-based）+ GRPO，规模超大；RLHF 用 RM + PPO/DPO。R1 是"过程奖励 + 长 CoT 涌现"。
6. **PRM vs ORM**？过程奖励模型对推理步骤打分（细粒度），结果奖励模型只看最终答案（粗粒度）。复杂推理倾向 PRM，简单任务 ORM 够。
