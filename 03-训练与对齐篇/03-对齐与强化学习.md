# 对齐与强化学习（RLHF / DPO / GRPO）

> 让模型"听话"的核心。PPO → DPO → GRPO 演进必背。

---

## 1. RLHF 三阶段流程

**Step 1：SFT** — 用高质量人工示范微调 base 模型。

**Step 2：RM（Reward Model）** — 训练标量奖励模型。

**Step 3：RL（PPO / GRPO 等）** — 用 RM 提供奖励，强化学习更新策略。

目标：

$$\max_\theta \mathbb{E}_{x, y \sim \pi_\theta}[r(x, y) - \beta \, D_{KL}(\pi_\theta(\cdot \mid x) \, \| \, \pi_{\text{ref}}(\cdot \mid x))]$$

**符号说明**：
- $\theta$：被训练的 policy 参数
- $\pi_\theta$：当前策略（被训的 LLM）
- $\pi_{\text{ref}}$：参考策略（冻结的 SFT 模型）
- $x$：prompt
- $y$：模型回答
- $r(x, y)$：奖励（从 RM 来）
- $\beta$（beta）：KL 惩罚系数（典型 0.01-0.1）
- $D_{KL}(\cdot \| \cdot)$：KL 散度（约束不要偏离 SFT）

---

## 2. Reward Model 训练

**数据格式**：$(x, y_w, y_l)$ 三元组。

**符号**：
- $x$：prompt
- $y_w$：被标为"更好"的答案（**w**inner）
- $y_l$：被标为"更差"的答案（**l**oser）

**损失**（Bradley-Terry 模型）：

$$\mathcal{L}_{RM} = -\mathbb{E}_{(x, y_w, y_l)} \left[\log \sigma(r_\phi(x, y_w) - r_\phi(x, y_l))\right]$$

**符号说明**：
- $r_\phi$：RM 模型（参数 $\phi$），输出标量奖励
- $\sigma$：sigmoid 函数 $\sigma(z) = \frac{1}{1 + e^{-z}}$
- $\mathbb{E}$：在偏好数据上求期望

**直觉**：让 $r(y_w) > r(y_l)$ 的差距尽可能大（log-sigmoid 把差距推开）。

**模型结构**：通常用 SFT 模型初始化，把 lm_head 替换为单标量输出 head。

## 3. PPO 在 RLHF 中的细节

### 3.0 先把 4 个模型的角色讲透（最容易混的概念）

PPO 训练时**同时持有 4 个模型**——它们各自的职责常被搞混，先用一张表对照：

| 模型 | 训练状态 | 输入 | 输出 | 角色 |
|---|---|---|---|---|
| **Actor / Policy** $\pi_\theta$ | **可训练** | prompt + 已生成 token | 下一个 token 的概率分布 | 被优化的"主角" |
| **Critic / Value** $V_\phi$ | **可训练** | prompt + 已生成 token | **一个标量**（状态价值） | 估"未来总收益"，给 actor 提供 baseline |
| **Reward Model** $r$ | 冻结 | 完整 prompt + 完整回答 | **一个标量**（奖励） | 给"整个回答"打分 |
| **Reference** $\pi_{\text{ref}}$ | 冻结 | prompt + 已生成 token | 下一个 token 的概率分布 | SFT 模型副本，用于 KL 约束 |

#### Reward 是"当前生成结果之后得到的奖励信号"

- **何时给**：通常是**回答生成完之后**，对整段 $(x, y)$ 打一个分（end-of-sequence reward）
- **是什么**：人类偏好的代理——RM 模拟"人类会更喜欢哪个答案"
- **直觉**：考完试后老师给的总分

```text
Reward = "事后总分"，反映这次表现到底好不好。
```

#### Critic 不是给 reward 的模型，而是估"未来总收益"的模型

很多人把 critic 和 RM 弄混——它们完全不同：

| | Reward Model | Critic Model |
|---|---|---|
| 给的是 | 已发生事件的"分数" | 还**没发生**事件的"价值期望" |
| 何时打分 | 回答**结束后**给一次（或规则在末尾给） | 每一步状态 $s_t$ 都给一次 |
| 训练数据 | 人类偏好对 $(x, y_w, y_l)$ | rollout 中观察到的真实 returns |
| 直觉类比 | 考完给"总分" | 期中预测"期末平均能考多少" |

```text
Critic 是"对未来的预言家"：
  "从这一步开始算，平均能拿多少分？"
```

#### PPO 为什么需要 critic？—— 关键问题

PPO 更新 policy 时，**不直接用 reward，而是用 advantage**：

$$A_t = R_t - V(s_t)$$

**符号说明**：
- $R_t$：从 $t$ 步开始的实际累积奖励（returns，事后才知道）
- $V(s_t)$：critic 估计的"从 $s_t$ 开始平均能得多少分"

**为什么不直接用 $R_t$ 更新？**

| 直接用 $R_t$（方差极大） | 用 $A_t = R_t - V(s_t)$（baseline 减方差） |
|---|---|
| "这条轨迹总分高 → 鼓励所有 token" | "这条轨迹比预期好 → 鼓励"、"比预期差 → 抑制" |
| 一条好答案里可能有差 token 也被鼓励 | 每个 token 只看"是否比当前状态平均水平好" |
| 训练噪声大、不稳 | 训练稳定 |

**举个例子**：
- 数学题答对了拿满分 1.0，但其中**第 3 步推理有错误**
- 直接用 $R_t = 1.0$ → "推理错的那一步" 也被鼓励 ❌
- 用 advantage：critic 估计"在那个状态下平均也能拿 1.0"，所以 $A_t \approx 0$ → 不强化那一步 ✓

```text
Critic 的核心作用：提供 baseline，把 reward 拆成"相对于平均水平的好坏"。
→ 大幅降低 policy gradient 的方差 → 训练能稳定收敛。
```

**这就是为什么 PPO 必须有 critic** —— 否则方差太大根本训不起来。

而 **GRPO 之所以能去掉 critic**，是因为它用**同 prompt 多次采样的组内均值**作为 baseline 替代了 critic（详见 §7）。

### 3.1 实际奖励信号（per-token + KL 惩罚）

把 RM 的奖励和 KL 惩罚组合成 **per-token reward**：

$$r_t = \begin{cases}
- \beta \log \dfrac{\pi_\theta(a_t \mid s_t)}{\pi_{\text{ref}}(a_t \mid s_t)}, & t < T \\[6pt]
r_{\text{RM}}(x, y) - \beta \log \dfrac{\pi_\theta(a_t \mid s_t)}{\pi_{\text{ref}}(a_t \mid s_t)}, & t = T
\end{cases}$$

**关键设计**：
- **中间 token**（$t < T$）只有 KL 惩罚 → 抑制偏离 SFT
- **最后一个 token**（$t = T$）加上 RM 给的总分 → 这是"事后总分"的体现

### 3.2 PPO clip 目标（Actor 的损失）

$$\mathcal{L}^{\text{CLIP}}(\theta) = \mathbb{E}_t \left[\min(\rho_t A_t, \, \text{clip}(\rho_t, 1-\epsilon, 1+\epsilon) A_t)\right]$$

**符号说明**：
- $\rho_t = \dfrac{\pi_\theta(a_t \mid s_t)}{\pi_{\text{old}}(a_t \mid s_t)}$：重要性采样比（新旧策略概率比）
- $A_t$：第 $t$ 步的 advantage（用 GAE 估计，见 §3.3）
- $\epsilon$：clip 阈值（典型 0.2）
- $a_t$：第 $t$ 步的 action（生成的 token）
- $s_t$：第 $t$ 步的 state（历史 token）
- $\pi_{\text{old}}$：上一轮的策略

**直觉**：
- 如果 $A_t > 0$（这个动作比平均好）→ 推高它的概率
- 如果 $A_t < 0$（比平均差）→ 降低它的概率
- $\rho_t$ 偏离 1 太多就被 clip → **单步更新幅度被限制在 $\pm \epsilon$ 内**，防止 RL 不稳

### 3.3 GAE（Generalized Advantage Estimation）—— Critic 怎么帮 actor 算 advantage

$$\delta_t = r_t + \gamma V(s_{t+1}) - V(s_t)$$

$$A_t = \sum_{l=0}^{T-t} (\gamma \lambda)^l \delta_{t+l}$$

**符号说明**：
- $\delta_t$：TD 误差（时序差分）—— "下一步实际奖励 + 下一步状态价值 − 当前状态价值"
- $\gamma$：折扣因子（典型 0.99，RLHF 常用 1.0）
- $\lambda$：GAE 平滑系数（典型 0.95）
- $V$：**critic 估计的价值**（注意 $\delta_t$ 里出现了两次 $V$，所以没有 critic 就算不了 $\delta$）

**Critic 的训练目标**（用 MSE 让 critic 学准）：

$$\mathcal{L}_{\text{VF}}(\phi) = \big(V_\phi(s_t) - R_t\big)^2$$

**回路串起来**：
```
1. Actor 采样 → 得到 trajectory
2. RM 在结尾给总分 → reward
3. Critic 估每个状态的 V(s_t)
4. 用 r_t 和 V 算 advantage（GAE）
5. Advantage 喂给 actor 的 CLIP 损失 → 更新 actor
6. Returns R_t 喂给 critic 的 MSE 损失 → 更新 critic
```

### 3.4 一张图回顾"4 个模型怎么协作"

```
                  ┌─────────────────────┐
   prompt x ───→  │  Actor π_θ (训练)   │  ──→  生成回答 y
                  └─────────────────────┘            │
                                                     ▼
                  ┌─────────────────────┐    ┌──────────────┐
                  │  Reference π_ref    │←───│  完整 (x, y) │
                  │      (冻结)          │    └──────────────┘
                  │  每个 token KL 约束  │           │
                  └─────────────────────┘           │
                              ▲                     │
                              │   per-token KL      │
                              │                     ▼
                  ┌─────────────────────┐    ┌──────────────┐
                  │  Reward Model       │←───│  最后一步打分 │
                  │      (冻结)          │    └──────────────┘
                  │  r_RM(x, y) 给总分  │
                  └─────────────────────┘
                              │
                              ▼
                  ┌─────────────────────┐
                  │  Critic V_φ (训练)  │ ──→  每个 s_t 的 V(s_t)
                  └─────────────────────┘            │
                              ▲                     │
                              │ MSE(V, returns)     │
                              │                     ▼
                              │            ┌──────────────┐
                              └────────────│ GAE: A_t     │
                                           │   = δ + ...  │
                                           └──────────────┘
                                                  │
                                                  ▼
                                    A_t → Actor 的 CLIP 损失
                                          → 更新 π_θ
```

```text
一句话总结：
  Reward Model 给"事后总分"
  Critic        估"未来期望"
  二者结合 →   advantage = 实际 - 期望
  Advantage 才是 actor 真正用来更新的信号。
```

## 4. 为什么需要 KL 惩罚？

**目的**：防止 policy 偏离 SFT 模型太多。

**问题**：
- 不约束 → policy 找 RM 漏洞（**reward hacking**）
- 或偏离自然语言分布（mode collapse）
- 失去 SFT 学到的能力

**实现**：reward 中减去 KL：

$$r' = r - \beta \log \frac{\pi_\theta}{\pi_{\text{ref}}}$$

$\beta$ 太大约束太强、太小失控。可以**自适应调整 $\beta$**（看 KL 实际值动态变化）。

## 5. DPO：跳过 RM 的革命

**DPO**（Direct Preference Optimization, NeurIPS 2023）：直接用偏好数据训 policy。

### 5.1 推导路线

从 RLHF 最优解（KL 约束下）有解析形式：

$$\pi^*(y \mid x) = \frac{1}{Z(x)} \pi_{\text{ref}}(y \mid x) \exp\left(\frac{r(x, y)}{\beta}\right)$$

**符号**：$Z(x)$ 是归一化常数。

反解 reward：

$$r(x, y) = \beta \log \frac{\pi^*(y \mid x)}{\pi_{\text{ref}}(y \mid x)} + \beta \log Z(x)$$

代入 Bradley-Terry 偏好损失（$\log Z(x)$ 同 prompt 下被消掉）→ DPO 目标：

$$\mathcal{L}_{\text{DPO}} = -\mathbb{E}\left[\log \sigma\left(\beta \log \frac{\pi_\theta(y_w \mid x)}{\pi_{\text{ref}}(y_w \mid x)} - \beta \log \frac{\pi_\theta(y_l \mid x)}{\pi_{\text{ref}}(y_l \mid x)}\right)\right]$$

**符号说明**：
- $\pi_\theta$：要训的 policy
- $\pi_{\text{ref}}$：参考（冻结）
- $y_w, y_l$：偏好对
- $\beta$：温度（典型 0.1-0.5）

**关键性质**：
- 不需要 RM、不需要 RL
- 监督学习形式，训练简单稳定
- 只需 2 个模型（policy + ref）

### 5.2 DPO vs PPO

| 维度 | PPO | DPO |
|---|---|---|
| 需要 RM | ✅ | ❌ |
| 模型数量 | 4 | 2 |
| 训练复杂度 | 高（RL，不稳） | 低（监督学习） |
| 显存 | 大 | 小 |
| 数据使用 | on-policy（采新样本） | off-policy（固定偏好集） |
| 效果上限 | 高 | 略低或持平 |

## 6. GRPO：DeepSeek 的简化版 PPO

**GRPO**（Group Relative Policy Optimization）：**去掉 Critic**。

### 6.1 核心改动

不用 critic 估 value，而是**组内归一化**作为 baseline。

**算法**：
1. 对同一 prompt $x$，采样一组答案 $\{y_1, \dots, y_G\}$
2. 用 RM 或规则计算每个奖励 $r_i$
3. 组内归一化作为 advantage：

$$A_i = \frac{r_i - \text{mean}(r_1, \dots, r_G)}{\text{std}(r_1, \dots, r_G)}$$

**符号说明**：
- $G$：组大小（典型 4-16）
- $r_i$：第 $i$ 个答案的奖励
- $A_i$：组内归一化后的 advantage
- $\text{mean}, \text{std}$：组内均值、标准差

4. 用 PPO 风格 clip 更新（advantage 用 $A_i$）
5. 保留 KL 约束

### 6.2 好处

- **省一半显存**（无 Critic）
- 数学/代码任务用 rule-based reward 极简
- 训练更稳定

### 6.3 DeepSeek-R1 的应用

- 用 GRPO 在数学/代码题上做大规模 RL
- 触发"推理涌现"（长 CoT、self-correction）
- R1 系列的核心技术

## 8. Reward Hacking

**定义**：策略找到 RM 漏洞，刷高分但实际质量差。

**典型表现**：
- 输出特定格式（如总用 markdown 列表）骗高分
- 偏好长答案（RM 偏向长）
- 重复用某些"奖励关键词"

**对策**：
1. KL 约束（限制偏离 SFT）
2. 多 RM 集成
3. 离线评估（LLM-as-judge 或人评）
4. 持续更新 RM

---

## 9. 对齐税（Alignment Tax）

**定义**：RLHF 后模型在通用 benchmark（如 MMLU）上的下降。

**原因**：
- KL 约束不足，过度优化对齐目标
- 偏好数据集偏向某风格

**缓解**：
- 增强 KL 约束
- RLHF 中混入预训练数据
- 多任务 RM（cover 知识、推理、安全多维度）

## 10. 最简记忆

```text
RLHF 三阶段：SFT → RM → RL(PPO)

PPO 目标：max E[r(x,y) - β·KL(π_θ || π_ref)]
  4 模型：Actor / Critic / RM / Reference
  clip 限制单步更新

DPO：从 RLHF 最优解反解 reward → 监督损失
  2 模型：Policy / Reference
  无需 RM

GRPO（DeepSeek）：去 Critic，用组内均值/std 做 baseline
  3 模型：Actor / RM / Reference
  数学/代码用规则奖励极简
```

## 🎯 高频追问

1. **DPO 的 $\beta$ 怎么选**？典型 0.1-0.5。$\beta$ 大 → 约束强、偏好优化弱。

2. **GRPO 的 $G$ 怎么选**？8-16 常见。太小估计噪声大，太大算力开销大。

3. **PPO 不稳定在哪**？RL 高方差 + 4 模型 + on-policy 采样，调参敏感。

4. **DPO 训练时 ref 模型怎么处理**？冻结的 SFT 模型；ref logits 可预计算缓存。

5. **PRM vs ORM**？过程奖励对每步打分（细），结果奖励只看最终答案（粗）。复杂推理倾向 PRM，简单任务 ORM 够。
