# 评测（Benchmarks）

> 各种 benchmark 是衡量 LLM 能力的核心工具，但也存在污染问题。

---

## 1. LLM 评测的几个维度

| 维度 | 代表 benchmark |
|---|---|
| **通用知识** | MMLU、MMLU-Pro、AGIEval、C-Eval、CMMLU |
| **推理** | GSM8K、MATH、BBH、AIME、GPQA |
| **代码** | HumanEval、MBPP、LiveCodeBench、SWE-Bench |
| **对齐 / 偏好** | AlpacaEval、MT-Bench、Arena-Hard、Chatbot Arena |
| **长上下文** | LongBench、RULER、Needle in a Haystack |
| **多模态** | MMMU、MMBench、MathVista |
| **工具调用** | BFCL（Berkeley Function Calling Leaderboard） |
| **安全** | TruthfulQA、ToxicChat、HarmBench |

---

## 2. MMLU

**MMLU**（Massive Multitask Language Understanding）：57 个学科多选题。

- 涵盖 STEM、人文、社科、应用
- 高中到专家级
- 4 选 1
- 约 16K 题

**评测方式**：
- Few-shot（标准 5-shot）
- 看模型选项的 likelihood，选概率最高的

**经典分数**：
- 随机：25%
- GPT-3：~43%
- GPT-4：~86%
- Claude 3 Opus：~87%
- 人类专家：~90%

**变种**：
- **MMLU-Pro**：更难，过滤简单题，10 选 1
- **C-Eval / CMMLU**：中文版

---

## 3. GSM8K / MATH

**GSM8K**：小学数学应用题。
- 8K 题，自然语言
- 答案是单个数字
- CoT 大幅提升表现

**MATH**：高中竞赛数学。
- 12500 题，更难
- 仅顶级模型能做对

**经典分数**：
- GPT-3：GSM8K ~17%
- GPT-4：GSM8K ~92%，MATH ~50%
- **o1**：MATH ~95%+

---

## 4. 代码评测

**HumanEval**：164 道 Python 编程题。
- 给函数签名 + docstring，生成函数体
- 评测：跑测试用例
- 指标：**pass@1**（一次通过率）/ pass@10

**MBPP**：974 道入门级题。

**HumanEval+ / MBPP+**：扩充后测试用例。

**LiveCodeBench**：滚动更新的编程题。
- 解决数据污染（旧 benchmark 已被训）
- 每月新增

**SWE-Bench**：真实 GitHub issue 修复。
- 给 repo + issue → 生成 patch
- 测试用例评估
- **极难**，最强模型 30-50%

---

## 5. AlpacaEval / MT-Bench / Arena-Hard / Chatbot Arena

**AlpacaEval**：805 个开放问题，LLM-as-judge（GPT-4 评分）。

**MT-Bench**：80 个多轮对话题，8 类，GPT-4 当裁判 1-10 分。

**Arena-Hard**：500 高难度题，GPT-4-Turbo 当裁判。

**Chatbot Arena**：**真实用户匿名投票**。
- 同时看两个模型回答，选哪个更好
- Elo 评分
- **最接近真实使用感受**
- 缺点：易受风格偏好影响

---

## 6. 数据污染（Data Contamination）

**问题**：benchmark 数据进入预训练语料，模型"见过答案"。

**检测**：
1. **n-gram 重叠**：测试集 n-gram 在预训练数据中出现？
2. **记忆探测**：直接问模型"题目 X 的答案"
3. **PPL 异常**：模型对 benchmark 数据 PPL 异常低

**影响**：分数虚高，不能反映真实能力。

**应对**：
- 动态 benchmark（LiveCodeBench）
- 私有评测（如 Chatbot Arena）
- 多 benchmark 综合

---

## 7. LLM-as-Judge 的优劣

**优点**：自动化、快、可大规模。

**缺点（偏差）**：
- **位置偏差**：偏好第一个出现的
- **长度偏差**：偏好长答案
- **风格偏差**：偏好特定格式
- **同源偏差**：偏好"和自己相似"的回答

**缓解**：
- 双盲、调换位置消除位置偏差
- 用更强模型当 judge
- 多 judge 集成

---

## 8. 长上下文评测

**NIAH（Needle in a Haystack）**：
- 长文档中插一句关键信息（针）
- 问模型针的内容
- 不同位置 / 长度的召回率
- 可视化为热图

**RULER**（NVIDIA）：13 个合成任务，更全面（比 NIAH 多 retrieval、multi-hop、aggregation、QA）。

**LongBench**：真实任务（QA、摘要、代码补全）。

---

## 9. 推理能力评测（o1/R1 类）

**数学**：
- **AIME**（American Invitational Mathematics Examination）
- **GPQA Diamond**（Graduate-Level Google-Proof Q&A）
- MATH

**代码**：Codeforces、LiveCodeBench。

**特点**：这些 benchmark 在 o1 出现前几乎天花板，o1 大幅突破（如 AIME 从 GPT-4o 的 13% 到 83%）。

---

## 10. 评测的"误区"

1. **单一 benchmark**：MMLU 高不代表所有能力强
2. **不看子项**：MMLU 整体 80% 可能 STEM 强、人文弱
3. **忽视 prompt**：不同模板差异 5-10 分
4. **忽视温度**：sample 与 greedy 差异大
5. **数据污染未检查**

---

## 11. 自建评测体系

**步骤**：
1. 明确业务需求
2. 选公开 benchmark 作 baseline
3. 构造私有 benchmark（真实业务样本）
4. 多维度评测（能力 + 安全 + 偏好）
5. 持续更新避免污染
6. 自动 + 人工

**工具**：OpenCompass、lm-evaluation-harness、HELM。

## 🎯 高频追问

1. **MMLU 88% 已接近人类，模型真这么强吗**？多选题特定形式，实际理解能力有限；MMLU-Pro 仍有差距。

2. **Chatbot Arena 排名公平吗**？用户偏好有偏（如喜欢长答案、Markdown），但仍最接近真实使用感受。

3. **怎么避免数据污染**？用最新 benchmark（LiveCodeBench）、私有测试集、定期更新。

4. **GSM8K 现在还有意义吗**？基本饱和，主要看新模型是否"翻车"。MATH、AIME 仍有区分度。

5. **垂直领域怎么评测**？自建领域数据集是必须的。
