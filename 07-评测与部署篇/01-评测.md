# 评测（Benchmarks）

> 各种 benchmark 是衡量 LLM 能力的核心工具，但也存在污染问题。

---

## Q1: LLM 评测的几个维度？

**答**：

| 维度 | 代表 benchmark |
|------|---------------|
| **通用知识** | MMLU、MMLU-Pro、AGIEval、C-Eval、CMMLU |
| **推理** | GSM8K、MATH、BBH、MMLU-Pro |
| **代码** | HumanEval、MBPP、LiveCodeBench、SWE-Bench |
| **对齐 / 偏好** | AlpacaEval、MT-Bench、Arena-Hard、Chatbot Arena |
| **长上下文** | LongBench、RULER、Needle in a Haystack |
| **多模态** | MMMU、MMBench、MathVista |
| **工具调用** | BFCL（Berkeley Function Calling Leaderboard） |
| **安全** | TruthfulQA、ToxicChat、HarmBench |

---

## Q2: MMLU 是什么？

**答**：
**MMLU**（Massive Multitask Language Understanding）：57 个学科多选题。

- 涵盖 STEM、人文、社科、应用
- 高中到专家级
- 4 选 1 选择题
- 数据集大小约 16K 题

**评测方式**：
- Few-shot（标准 5-shot）
- 看模型选项的 likelihood，选概率最高的

**经典分数**：
- 随机：25%
- GPT-3：~43%
- GPT-4：~86%
- Claude 3 Opus：~87%
- 人类专家：~90%

**变种**：
- **MMLU-Pro**：更难，过滤简单题，10 选 1
- **C-Eval**：中文版（清华）
- **CMMLU**：中文版（覆盖更多本土化领域）

---

## Q3: GSM8K / MATH？

**答**：
**GSM8K**（Grade School Math 8K）：小学数学应用题。
- 8K 题
- 自然语言形式
- 答案是单个数字
- 评测方式：对比生成答案与标准答案
- CoT 大幅提升表现

**MATH**：高中竞赛数学。
- 12500 题
- 涵盖代数、几何、概率等
- 难度远高于 GSM8K
- 仅顶级模型能做对

**经典分数**：
- GPT-3：GSM8K ~17%
- GPT-4：GSM8K ~92%，MATH ~50%
- o1：MATH ~95%+
- 人类奥数：MATH 极难

## Q4: HumanEval / MBPP / LiveCodeBench？

**答**：
**HumanEval**：164 道 Python 编程题。
- 给出函数签名 + docstring，生成函数体
- 评测方式：跑测试用例
- pass@1 / pass@10 指标

**MBPP**（Mostly Basic Python Problems）：974 道入门级题。

**HumanEval+ / MBPP+**：原版测试用例少，扩充后的版本。

**LiveCodeBench**：滚动更新的编程题。
- 解决"数据污染"（旧 benchmark 已被训练过）
- 每月新增题目
- 更真实

**SWE-Bench**：真实 GitHub issue 修复。
- 给 repo + issue → 生成 patch
- 评测方式：通过 issue 的测试用例
- 极难，最强模型也只能做对 30-50%

**Aider / Polyglot**：多语言编辑能力评测。

## Q5: AlpacaEval / MT-Bench / Arena-Hard / Chatbot Arena？

**答**：

**AlpacaEval**：805 个开放问题。
- LLM-as-judge（用 GPT-4 评分）
- 胜率（vs 参考模型，如 GPT-3.5）
- 偏向"听起来好"的回答

**MT-Bench**：80 个多轮对话题。
- 涵盖写作、推理、代码、数学等 8 类
- GPT-4 当裁判，1-10 分
- LMSYS 出品

**Arena-Hard**：500 个高难度题。
- 从 Chatbot Arena 选出
- GPT-4-Turbo 当裁判

**Chatbot Arena**：真实用户匿名投票。
- 用户同时看两个模型回答
- 选哪个更好
- 用 Elo 评分
- **最接近真实使用感受**
- 缺点：易受"风格偏好"影响

## Q6: 数据污染（Data Contamination）问题？

**答**：
**问题**：benchmark 数据可能进入预训练语料，模型"见过答案"。

**检测**：
1. **n-gram 重叠**：测试集中的 n-gram 在预训练数据中出现？
2. **记忆探测**：直接问模型 "题目 X 的答案是？"
3. **困惑度**：模型对 benchmark 数据的 PPL 异常低？

**影响**：
- 分数虚高
- 不能反映真实能力
- 部分模型在公开 benchmark 上"刷分"

**应对**：
- 动态 benchmark（LiveCodeBench）
- 私有评测（如 Chatbot Arena）
- 多个 benchmark 综合

---

## Q7: LLM-as-Judge 的优缺点？

**答**：
**优点**：
- 自动化，无需大量人标
- 速度快
- 可大规模评测

**缺点**：
- **位置偏差**：偏好第一个出现的答案
- **长度偏差**：偏好长答案
- **风格偏差**：偏好特定格式
- **同源偏差**：评测模型偏好"和自己相似"的回答
- 难评估专业领域（如医学）

**缓解**：
- 双盲（隐藏模型名）
- 调换位置消除位置偏差
- 用更强模型（如 GPT-4）当 judge
- 多 judge 集成

## Q8: 长上下文评测：NIAH / RULER？

**答**：
**NIAH（Needle in a Haystack）**：
- 在长文档中插入"针"（一句关键信息）
- 问模型针的内容
- 不同位置 / 上下文长度的召回率
- 可视化为热图

**RULER**（NVIDIA）：
- 13 个合成任务
- 涵盖 retrieval、multi-hop、aggregation、QA
- 比 NIAH 更全面
- 揭示了很多"名义 128K"实际只有 32K 有效

**LongBench**：真实任务（QA、摘要、代码补全）。

## Q9: 推理能力评测（针对 o1/R1 类）？

**答**：
**数学**：
- **AIME**（American Invitational Mathematics Examination）
- **GPQA**（Graduate-Level Google-Proof Q&A）
- **MATH**

**代码**：
- **Codeforces**
- **LiveCodeBench**

**科学**：
- **GPQA Diamond**：博士级问题

**特点**：
- 这些 benchmark 在 o1 出现前几乎天花板，o1 突破天花板
- 推理模型大幅提分（如 o1 在 AIME 上从 GPT-4o 的 13% 到 83%）

## Q11: 评测的"误区"？

**答**：
1. **单一 benchmark**：MMLU 高不代表所有能力强
2. **不看具体子项**：MMLU 整体 80% 可能 STEM 强、人文弱
3. **忽视 prompt**：不同 prompt 模板差异 5-10 分
4. **忽视温度**：sample 与 greedy 差异大
5. **数据污染未检查**：模型可能记住了答案

## Q12: 怎么搭建自己的评测体系？

**答**：
**步骤**：
1. **明确业务需求**：分类？生成？多轮对话？
2. **选公开 benchmark**：MMLU 等作 baseline
3. **构造私有 benchmark**：真实业务样本
4. **多维度评测**：能力 + 安全 + 偏好
5. **持续更新**：避免污染
6. **自动 + 人工**：自动跑分 + 人工抽检

**工具**：
- OpenCompass（上海 AI Lab）
- lm-evaluation-harness（EleutherAI）
- HELM（斯坦福）

## 🎯 高频追问

1. **MMLU 88% 已经接近人类，模型真的这么强吗**？多选题特定形式，实际理解能力有限；MMLU-Pro 等更难的 benchmark 上仍有差距。
2. **Chatbot Arena 排名公平吗**？用户偏好有偏（如喜欢长答案、Markdown），但仍是最接近真实使用感受的评测。
3. **怎么避免数据污染**？用最新 benchmark（如 LiveCodeBench）、私有测试集、定期更新。
4. **GSM8K 现在还有意义吗**？基本饱和，主要看新模型是否"翻车"。MATH、AIME 仍有区分度。
5. **垂直领域怎么评测**？自建领域数据集是必须的。公开 benchmark 不能反映领域能力。
