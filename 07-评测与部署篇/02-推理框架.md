# 推理框架（vLLM / SGLang / TRT-LLM / llama.cpp）

> 工业部署绕不开这些框架，各有取舍。

---

## Q1: 主流推理框架对比？

**答**：

| 框架 | 主导方 | 主要场景 | 关键技术 |
|------|--------|---------|---------|
| **vLLM** | UC Berkeley + 社区 | 通用 GPU 服务 | PagedAttention、Continuous Batching、Prefix Caching |
| **SGLang** | LMSYS + 社区 | 复杂程序流（agent、多请求） | RadixAttention、结构化输出 |
| **TensorRT-LLM** | NVIDIA | 极致性能 GPU 服务 | TRT 优化、专用 kernel、FP8 |
| **llama.cpp** | Georgi Gerganov | CPU / 边缘端 | GGUF 量化、CPU/Metal 推理 |
| **HuggingFace TGI** | HuggingFace | 一站式部署 | 与 HF 生态深度集成 |
| **Ollama** | Ollama | 本地使用 | 基于 llama.cpp，易用 |
| **LMDeploy** | 上海 AI Lab | 多硬件 | TurboMind 引擎 |

## Q2: vLLM 的关键技术？

**答**：
**核心创新**：
1. **PagedAttention**：借鉴 OS 分页，把 KV Cache 切成 block 管理
   - 解决 KV Cache 内存碎片
   - 利用率从 ~30% 提升到 ~90%
2. **Continuous Batching**：每个 step 重新组 batch，GPU 持续满载
3. **Automatic Prefix Caching**：跨请求复用相同前缀的 KV
4. **支持广泛模型**：LLaMA、Qwen、Mistral、DeepSeek、MoE 等

**配套**：
- Speculative Decoding（包括 EAGLE）
- INT8 / INT4 / FP8 量化
- Chunked Prefill
- Tensor Parallel / Pipeline Parallel
- LoRA 多 adapter 服务

**部署**：
```bash
python -m vllm.entrypoints.openai.api_server \
    --model meta-llama/Llama-3-70B \
    --tensor-parallel-size 4
```

## Q3: SGLang 的特色？

**答**：
**SGLang**（Structured Generation Language）：

**核心**：
1. **RadixAttention**：基于 Radix Tree 的 KV Cache 复用
   - 比 vLLM Prefix Caching 更细粒度
   - 适合多分支共享的场景
2. **结构化输出**：原生支持 JSON Schema、正则等约束生成
   - constrained decoding 性能优
3. **前端 DSL**：用 Python 写复杂的 prompt 流（fork、merge）
4. **快速**：在某些 benchmark 上比 vLLM 快 20-50%

**适合场景**：
- Agent 类应用（多次推理）
- 结构化输出（JSON、SQL）
- 复杂 prompt 模板
- 树搜索（Tree-of-Thoughts）

---

## Q4: TensorRT-LLM 的特色？

**答**：
**NVIDIA 官方推理引擎**：

**优势**：
1. **极致性能**：针对 NVIDIA GPU 深度优化
   - 自定义 kernel
   - 算子融合
   - FP8 / INT4 原生支持
2. **In-flight Batching**：类似 Continuous Batching
3. **完整 KV Cache 优化**：分页、量化、复用
4. **多硬件**：A100 / H100 / B200 优化最深入

**劣势**：
- 学习曲线陡（C++ + TRT 编译）
- 模型支持需要适配
- 改 prompt 麻烦（需要重新编译）

**使用场景**：
- 生产环境追求极致 latency / throughput
- 单一模型大规模部署
- 有 NVIDIA 工程资源

## Q5: llama.cpp 的特点？

**答**：
**核心**：纯 C++ 实现，跨平台、低门槛。

**特点**：
1. **CPU 推理**：可在没 GPU 的机器跑大模型
2. **多硬件**：CPU、Apple Silicon、CUDA、ROCm、Vulkan
3. **GGUF 格式**：高效量化模型格式
4. **量化丰富**：Q2_K 到 Q8_0 多档
5. **嵌入式友好**：可跑在手机、树莓派

**典型使用**：
- 本地开发 / 调试
- 边缘部署
- 苹果设备（Metal 加速）
- 个人电脑跑 70B 模型

**性能**：
- CPU 上 7B 模型 5-15 tokens/s（i9 级）
- Apple M3 Max 上 70B Q4 ~5 tokens/s

## Q6: GGUF 是什么？

**答**：
**GGUF**（GGML Universal Format）：llama.cpp 的模型格式。

**特点**：
- 单文件包含模型 + tokenizer + 元数据
- 内置多种量化（Q4_0、Q4_K_M、Q5_K_M 等）
- 跨平台（mmap 加载，快）
- 支持 LoRA 合并

**量化档位**：
- Q2_K：~2.5 bits/param，效果损失大
- **Q4_K_M**：~4.8 bits/param，**推荐**（效果好 + 显存省）
- Q5_K_M：~5.5 bits/param，更好
- Q8_0：8 bits，几乎无损
- 还有 IQ 系列（更新的量化方案）

## Q7: HuggingFace TGI（Text Generation Inference）？

**答**：
**HF 官方推理框架**：

**特点**：
- 与 HF Hub 生态深度集成
- 支持广泛模型
- Continuous Batching
- Flash Attention
- 量化支持（GPTQ、AWQ、Bitsandbytes）

**部署**：
```bash
docker run --gpus all -p 8080:80 \
    ghcr.io/huggingface/text-generation-inference \
    --model-id meta-llama/Llama-3-8B
```

**与 vLLM 对比**：vLLM 更快、更新更频；TGI 与 HF 生态结合好。

## Q8: 推理框架选型指南？

**答**：

**通用云端服务**：
- 通用首选：**vLLM**（活跃、覆盖全）
- 极致性能：**TensorRT-LLM**（NVIDIA 硬件 + 资源充足）
- 复杂程序流：**SGLang**

**边缘 / 本地**：
- CPU / Apple：**llama.cpp** / **Ollama**
- 手机：MLC-LLM / executorch

**研究 / 快速实验**：
- HuggingFace Transformers（功能全但慢）

**国产硬件**：
- 昇腾：MindIE
- 寒武纪：自家框架
- TPU：vLLM 支持

## Q9: 部署时的关键指标？

**答**：

| 指标 | 含义 | 影响 |
|------|------|------|
| **TTFT** | Time To First Token | 用户感知响应速度（聊天） |
| **TPOT** | Time Per Output Token | 后续 token 间隔 |
| **吞吐量** | Total tokens/sec | 容量、成本 |
| **P50/P95/P99 延迟** | 延迟分布 | SLA |
| **GPU 利用率** | 算力 + 显存 | 效率 |
| **并发数** | 同时服务请求数 | 容量 |

**典型 SLA**：
- TTFT < 1s（chat）
- TPOT < 100ms（流畅）
- P99 < 2× P50

## Q10: 推理框架的常见优化技巧？

**答**：
1. **量化**：W4A16 或 FP8
2. **批处理**：Continuous Batching
3. **KV Cache**：PagedAttention + Prefix Caching
4. **投机解码**：EAGLE 或自定义 draft model
5. **并行**：TP 跨卡
6. **预热**：服务启动后跑几个 dummy 请求让 kernel JIT 完成
7. **CUDA Graph**：减少 kernel 启动开销
8. **算子融合**：减少中间数据搬运

## Q11: 模型转换与部署流程？

**答**：
**典型流程**：
1. **训练**：用 PyTorch / Megatron
2. **保存**：HF format / safetensors
3. **量化**（可选）：GPTQ / AWQ / FP8
4. **格式转换**：
   - vLLM / TGI：直接读 HF format
   - TRT-LLM：需要 build engine（编译）
   - llama.cpp：转换为 GGUF
5. **服务化**：启动 server（OpenAI API 兼容）
6. **监控**：Prometheus + Grafana

## 🎯 高频追问

1. **vLLM 和 TRT-LLM 速度差距多大**？相同硬件下 TRT-LLM 一般快 20-50%（深度调优），但开发成本高。
2. **能不能用 vLLM 服务自定义模型**？可以，需要实现模型类（继承 vLLM 抽象类）。
3. **SGLang 在哪些场景碾压 vLLM**？Agent、Tree of Thoughts、多分支共享 prefix。
4. **llama.cpp 跑大模型多慢**？M3 Max + 70B Q4 ~5 tokens/s，慢但能跑。
5. **TGI 和 vLLM 选哪个**？现在 vLLM 更主流，TGI 仍在更新但社区热度较低。
