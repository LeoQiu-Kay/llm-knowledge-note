# 权限模型与最小授权

> **一句话定位**：Agent 权限必须由确定性系统授予和校验，模型只能提出动作，不能决定自己是否有权执行。

---

## 1. 先给结论

Agent 权限必须由确定性系统授予和校验，模型只能提出动作，不能决定自己是否有权执行。最小授权要求按用户、租户、任务、工具、资源和时间缩小 scope，使用短期凭证与逐次授权，并把读取数据和产生副作用分开治理。

### 面试答题路线

回答这类题不要从名词堆砌开始，按下面四步展开最稳：

1. **先定边界**：它解决什么问题，不解决什么问题。
2. **再讲机制**：把核心数据结构、状态机或调用链讲清楚。
3. **补充取舍**：说明复杂度、正确性、资源和可维护性的代价。
4. **落到生产**：给出超时、幂等、观测、压测与回滚方案。

---

## 2. 核心原理

### 主体与授权链

区分最终用户、Agent 服务、模型、工具和外部系统身份。每次调用携带可验证主体与委托关系，工具服务端再次鉴权，不能信任模型生成的 user_id 或资源 ID。

### 能力与范围

优先暴露任务级工具，如“创建指定项目工单”，而不是通用 shell 或全库 SQL。权限限定资源集合、操作类型、字段、额度和有效期，高风险能力按需临时提升。

### 策略执行点

在编排器和工具网关放置策略执行点，结合 RBAC/ABAC、数据分类和审批状态判断。拒绝结果结构化返回，且不能向模型泄露不必要的资源存在性。

## 3. 工作流程与关键路径

```text
[识别用户、Agent 与任务身份]
    │
    ▼
[签发短期、细粒度能力]
    │
    ▼
[工具端验证资源和动作范围]
    │
    ▼
[高风险操作二次审批]
    │
    ▼
[到期撤销并审计使用记录]
```

### 3.1 每一步分别承担什么

- **入口与约束**：`识别用户、Agent 与任务身份` 决定后续处理的语义、权限和容量边界。
- **核心决策**：`签发短期、细粒度能力` 与 `工具端验证资源和动作范围` 是最容易答成“只会背名词”的地方，要讲清状态如何变化。
- **执行与副作用**：中间步骤必须说明失败是否可重试、是否会重复，以及资源何时释放。
- **完成条件**：`到期撤销并审计使用记录` 不能只看“没有抛异常”，还要有业务结果、指标或持久化证据。

### 3.2 复杂度不只是一行大 O

面试里给出时间复杂度后，还要补三件事：**数据规模是否会放大常数项、最坏路径何时触发、资源上限在哪里**。生产环境更常被队列等待、锁竞争、网络、序列化、缓存失效或外部限流拖慢；因此复杂度分析必须和实际访问分布、尾延迟及容量模型一起讲。

| 状态 | 需要回答的问题 |

## 5. 对比与选型

| 决策维度 | 面试中要说清 | 生产验证 |
|---|---|---|
| **信任边界** | 用户、网页、文档、模型和工具输出默认不同信任级别 | 不可信数据不能获得指令优先级 |
| **授权** | 身份、动作、资源和字段都要校验 | 短期能力令牌替代共享长期密钥 |
| **隔离** | 高风险执行进入临时沙箱 | 文件、网络、进程、资源和产物同时受控 |
| **响应** | 检测、阻断、取证、吊销和回归是一套流程 | 红队用例进入持续安全门禁 |

真正的选型结论应带条件：**在什么规模、读写比例、故障模型、SLO 和团队维护能力下选择它**。离开约束谈“谁更快”“谁更高级”没有工程意义。

## 6. 工程实践

- 细粒度权限更安全，但策略数量和调试复杂度更高，需要统一策略平台。
- 代表用户调用便于审计，服务身份适合后台任务；两者不能混为一条永久令牌。
- 缓存权限决定可降延迟，但必须按主体、资源和策略版本失效。

### 6.1 落地检查表

- 网页、邮件、附件和检索文档一律标记为不可信数据。
- 凭证短期化、按任务和资源下发，工具端独立验权。
- 代码与浏览器执行进入无长期密钥的临时沙箱。
- 审计记录谁在何时批准了什么动作，并可快速吊销与回滚。

## 7. 常见故障

1. 多个租户复用同一个连接或 token，导致跨租户访问。
2. 模型通过组合多个低风险工具间接完成高风险操作。
3. 撤销用户权限后，长任务仍持有旧凭证继续执行。

### 7.1 推荐排查顺序

1. **先确认现象**：影响哪些请求、数据、租户与时间窗，是否与发布或流量变化相关。
2. **再沿关键路径定位**：从 `识别用户、Agent 与任务身份` 逐步检查到 `到期撤销并审计使用记录`，不要跳过排队、缓存、代理或外部依赖。
3. **区分原因和结果**：高 CPU、线程多、token 多、连接满可能只是症状；用日志、指标、Trace 和状态快照互相印证。
4. **最后验证修复**：用最小复现、压力或故障注入证明问题消失，同时保留一键回滚。

最常见的错误是：**多个租户复用同一个连接或 token，导致跨租户访问。**
