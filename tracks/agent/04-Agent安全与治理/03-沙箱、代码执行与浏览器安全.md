# 沙箱、代码执行与浏览器安全

## 30 秒回答

代码执行和浏览器工具把模型输出变成真实计算与网络行为，必须运行在一次性、最小权限沙箱中。核心控制包括文件系统、进程、网络、资源、凭证和下载边界，配合域名策略、恶意内容扫描、超时、审计与销毁；容器只是隔离手段之一，不等于天然安全。

## 核心原理

### 执行隔离

每个任务使用独立工作目录和低权限身份，限制 CPU、内存、进程数、磁盘和运行时间。禁用宿主 socket、特权模式和不必要系统调用，敏感场景使用更强虚拟化边界。

### 网络与凭证

默认拒绝出网，仅允许经过代理的域名、协议和端口。凭证按任务短期注入，不写入提示、日志或持久磁盘；外发请求检查目标、数据分类和重定向。

### 浏览器风险

网页可包含间接提示注入、恶意下载和跨站请求。隔离浏览器 profile，限制下载与上传，区分页面文本和可信 UI 状态；支付、发布、删除等动作需要确认。

## 工程权衡

- 完全断网最安全但无法完成研究和依赖安装，可采用分阶段或代理白名单。
- 复用温热沙箱降低启动延迟，却增加跨任务数据残留风险。
- 录制屏幕与网络有助审计，也要控制敏感数据保留。

## 常见故障

1. 沙箱挂载了宿主 Docker socket，等同获得宿主控制权。
2. 浏览器沿用上个用户登录会话，造成账号串用。
3. 依赖安装脚本可任意出网并读取注入的云凭证。
