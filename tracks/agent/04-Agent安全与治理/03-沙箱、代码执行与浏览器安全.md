# 沙箱、代码执行与浏览器安全

> **一句话定位**：代码执行和浏览器工具把模型输出变成真实计算与网络行为，必须运行在一次性、最小权限沙箱中。

---

## 1. 先给结论

代码执行和浏览器工具把模型输出变成真实计算与网络行为，必须运行在一次性、最小权限沙箱中。核心控制包括文件系统、进程、网络、资源、凭证和下载边界，配合域名策略、恶意内容扫描、超时、审计与销毁；容器只是隔离手段之一，不等于天然安全。

### 面试答题路线

回答这类题不要从名词堆砌开始，按下面四步展开最稳：

1. **先定边界**：它解决什么问题，不解决什么问题。
2. **再讲机制**：把核心数据结构、状态机或调用链讲清楚。
3. **补充取舍**：说明复杂度、正确性、资源和可维护性的代价。
4. **落到生产**：给出超时、幂等、观测、压测与回滚方案。

## 2. 核心原理

### 执行隔离

每个任务使用独立工作目录和低权限身份，限制 CPU、内存、进程数、磁盘和运行时间。禁用宿主 socket、特权模式和不必要系统调用，敏感场景使用更强虚拟化边界。

### 网络与凭证

默认拒绝出网，仅允许经过代理的域名、协议和端口。凭证按任务短期注入，不写入提示、日志或持久磁盘；外发请求检查目标、数据分类和重定向。

### 浏览器风险

网页可包含间接提示注入、恶意下载和跨站请求。隔离浏览器 profile，限制下载与上传，区分页面文本和可信 UI 状态；支付、发布、删除等动作需要确认。

## 3. 工作流程与关键路径

```text
[代码或网页任务进入隔离环境]
    │
    ▼
[限制文件、网络、进程和凭证]
    │
    ▼
[执行器设置时间与资源上限]
    │
    ▼
[产物经过扫描和过滤]
    │
    ▼
[销毁环境并保留审计证据]
```

### 3.1 每一步分别承担什么

- **入口与约束**：`代码或网页任务进入隔离环境` 决定后续处理的语义、权限和容量边界。
- **核心决策**：`限制文件、网络、进程和凭证` 与 `执行器设置时间与资源上限` 是最容易答成“只会背名词”的地方，要讲清状态如何变化。
- **执行与副作用**：中间步骤必须说明失败是否可重试、是否会重复，以及资源何时释放。
- **完成条件**：`销毁环境并保留审计证据` 不能只看“没有抛异常”，还要有业务结果、指标或持久化证据。

### 3.2 复杂度不只是一行大 O

面试里给出时间复杂度后，还要补三件事：**数据规模是否会放大常数项、最坏路径何时触发、资源上限在哪里**。生产环境更常被队列等待、锁竞争、网络、序列化、缓存失效或外部限流拖慢；因此复杂度分析必须和实际访问分布、尾延迟及容量模型一起讲。

## 4. 关键实现

下面的片段不是完整框架，而是把最关键的边界写出来：

```yaml
sandbox:
  filesystem: {mode: ephemeral, writable: ["/workspace"]}
  network:
    default: deny
    allow: ["pypi.org:443"]
  process: {maxCount: 32, maxCpuSeconds: 60}
  memoryMb: 1024
  wallClockSeconds: 90
  secrets: []
  artifacts:
    scanBeforeExport: true
```

### 4.1 实现时盯住的状态

| 状态 | 需要回答的问题 |
|---|---|
| 输入 | `代码或网页任务进入隔离环境` 是否已经校验语义、权限、大小与版本？ |
| 中间状态 | `执行器设置时间与资源上限` 能否持久化、观测或在并发下保持不变量？ |
| 副作用 | 失败重试会不会重复执行？是否有幂等键、事务或补偿？ |
| 完成 | `销毁环境并保留审计证据` 由什么证据确认？调用方能否区分成功、部分成功与失败？ |

## 5. 对比与选型

| 决策维度 | 面试中要说清 | 生产验证 |
|---|---|---|
| **信任边界** | 用户、网页、文档、模型和工具输出默认不同信任级别 | 不可信数据不能获得指令优先级 |
| **授权** | 身份、动作、资源和字段都要校验 | 短期能力令牌替代共享长期密钥 |
| **隔离** | 高风险执行进入临时沙箱 | 文件、网络、进程、资源和产物同时受控 |
| **响应** | 检测、阻断、取证、吊销和回归是一套流程 | 红队用例进入持续安全门禁 |

真正的选型结论应带条件：**在什么规模、读写比例、故障模型、SLO 和团队维护能力下选择它**。离开约束谈“谁更快”“谁更高级”没有工程意义。

## 6. 工程实践

- 完全断网最安全但无法完成研究和依赖安装，可采用分阶段或代理白名单。
- 复用温热沙箱降低启动延迟，却增加跨任务数据残留风险。
- 录制屏幕与网络有助审计，也要控制敏感数据保留。

### 6.1 落地检查表

- 网页、邮件、附件和检索文档一律标记为不可信数据。
- 凭证短期化、按任务和资源下发，工具端独立验权。
- 代码与浏览器执行进入无长期密钥的临时沙箱。
- 审计记录谁在何时批准了什么动作，并可快速吊销与回滚。

## 7. 常见故障

1. 沙箱挂载了宿主 Docker socket，等同获得宿主控制权。
2. 浏览器沿用上个用户登录会话，造成账号串用。
3. 依赖安装脚本可任意出网并读取注入的云凭证。

### 7.1 推荐排查顺序

1. **先确认现象**：影响哪些请求、数据、租户与时间窗，是否与发布或流量变化相关。
2. **再沿关键路径定位**：从 `代码或网页任务进入隔离环境` 逐步检查到 `销毁环境并保留审计证据`，不要跳过排队、缓存、代理或外部依赖。
3. **区分原因和结果**：高 CPU、线程多、token 多、连接满可能只是症状；用日志、指标、Trace 和状态快照互相印证。
4. **最后验证修复**：用最小复现、压力或故障注入证明问题消失，同时保留一键回滚。

最常见的错误是：**沙箱挂载了宿主 Docker socket，等同获得宿主控制权。**
