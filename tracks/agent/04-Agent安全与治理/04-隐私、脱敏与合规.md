# 隐私、脱敏与合规

## 30 秒回答

Agent 会汇集对话、企业数据、工具结果和长期记忆，隐私治理应覆盖收集、传输、模型调用、存储、展示和删除全生命周期。原则是目的限定、数据最小化、租户隔离、敏感信息检测与脱敏、可配置保留期，并为模型供应商和跨境处理建立明确的数据契约。

## 核心原理

### 数据分类与最小化

识别个人信息、密钥、健康、财务和企业机密，只采集完成任务必要字段。发送模型前裁剪无关列和历史，日志默认不记录完整提示、工具参数与原文。

### 脱敏与可逆性

展示和分析使用掩码或令牌化，真正不需要时做不可逆删除。需要恢复原值的 token vault 与业务数据分离授权；脱敏规则要处理自由文本和文件，不只结构化字段。

### 生命周期与权利

记录处理目的、来源、法律依据、地域、保留期和下游处理方。支持访问、更正、导出和删除请求，并传播到向量索引、缓存、备份和记忆系统。

## 工程权衡

- 本地模型可减少第三方传输，但仍需内部访问控制和日志治理。
- 过度脱敏会破坏任务效果，可在可信执行边界内使用最小必要原文。
- 审计需要保留证据，与删除权之间要由合规策略明确平衡。

## 常见故障

1. 只删除主数据库记录，向量库和提示缓存仍保留内容。
2. 调试日志记录完整访问令牌和用户附件。
3. 模型供应商配置变化后数据被用于训练，却未重新评审。

- 数据分类与最小化在生产环境中如何验证效果？
- 脱敏与可逆性在生产环境中如何验证效果？
- 生命周期与权利在生产环境中如何验证效果？
