# Agent 可靠性与故障恢复

## 30 秒回答

Agent 可靠性依赖可分类错误、有限重试、幂等副作用、超时与取消传播、持久化检查点和明确降级，而不是提示模型永不失败。系统应区分模型、工具、编排、数据和策略故障，恢复时从最小安全步骤继续，并用故障注入验证真实行为。

## 核心原理

### 错误分类

超时、限流和瞬时网络错误可有限重试；认证失败、schema 错误和业务拒绝应修复或终止；内容安全拦截需要安全降级。统一错误码要保留原始上下文但避免泄露敏感信息。

### 幂等与不确定结果

写工具携带业务幂等键，服务端记录请求结果。若调用超时但可能已成功，先查询外部状态再重试，不能把客户端未收到响应等同于未执行。

### 降级与恢复

可切换备用模型、只读模式、确定性工作流或人工处理。取消信号向子任务和工具传播，恢复扫描处理过期租约，死信队列保留无法自动解决的任务。

## 工程权衡

- 备用模型能力不同，切换前要验证工具调用、上下文长度和安全策略兼容性。
- 重试提高成功率也会放大下游压力，应使用抖动退避和全链路重试预算。
- 降级答案必须明确能力受限，不能静默返回看似完整的错误结果。

## 常见故障

1. 模型层、SDK 和网关各自重试，形成指数级请求风暴。
2. 取消主任务后子 Agent 和浏览器仍继续运行并产生费用。
3. 工具超时后重复创建相同资源，没有幂等或对账。
