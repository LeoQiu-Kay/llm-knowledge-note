# Agent 可靠性与故障恢复 · 面试题

## Q1: 请用一分钟说明Agent 可靠性与故障恢复的核心目标与工作机制。
> 难度 ⭐⭐ ｜ 高频 🔥🔥🔥

Agent 可靠性依赖可分类错误、有限重试、幂等副作用、超时与取消传播、持久化检查点和明确降级，而不是提示模型永不失败。系统应区分模型、工具、编排、数据和策略故障，恢复时从最小安全步骤继续，并用故障注入验证真实行为。

---

## Q2: 错误分类的核心机制是什么？
> 难度 ⭐⭐ ｜ 高频 🔥🔥🔥

超时、限流和瞬时网络错误可有限重试；认证失败、schema 错误和业务拒绝应修复或终止；内容安全拦截需要安全降级。统一错误码要保留原始上下文但避免泄露敏感信息。

---

## Q3: 幂等与不确定结果为什么重要，实际如何落地？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥

写工具携带业务幂等键，服务端记录请求结果。若调用超时但可能已成功，先查询外部状态再重试，不能把客户端未收到响应等同于未执行。

---

## Q4: Agent 可靠性与故障恢复在工程落地时如何做取舍？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥🔥

备用模型能力不同，切换前要验证工具调用、上下文长度和安全策略兼容性；重试提高成功率也会放大下游压力，应使用抖动退避和全链路重试预算；降级答案必须明确能力受限，不能静默返回看似完整的错误结果。

---

## Q5: Agent 可靠性与故障恢复最常见的故障与排查重点是什么？
> 难度 ⭐⭐⭐⭐ ｜ 高频 🔥🔥

模型层、SDK 和网关各自重试，形成指数级请求风暴；取消主任务后子 Agent 和浏览器仍继续运行并产生费用；工具超时后重复创建相同资源，没有幂等或对账。排查时应关联运行状态、模型请求、工具调用、外部证据和最终结果，先判断是数据、模型、编排、权限还是依赖故障。
