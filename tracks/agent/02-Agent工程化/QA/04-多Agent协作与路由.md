# 多 Agent 协作与路由 · 面试题

## Q1: 请用一分钟说明多 Agent 协作与路由的核心目标与工作机制。
> 难度 ⭐⭐ ｜ 高频 🔥🔥🔥

多 Agent 系统通过路由器、主管或共享任务队列，把工作交给具有不同工具、权限或上下文的角色。它适合可并行、可独立验证的专业任务，不应仅为模拟团队而增加角色；生产重点是契约、上下文隔离、冲突合并、预算和端到端责任归属。

---

## Q2: 协作模式的核心机制是什么？
> 难度 ⭐⭐ ｜ 高频 🔥🔥🔥

常见模式包括主管分派、专家路由、并行扇出汇总和事件驱动接力。每个 Agent 应声明输入输出 schema、可用工具、权限和完成条件，避免靠含糊对话协作。

---

## Q3: 路由决策为什么重要，实际如何落地？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥

路由可由规则、分类模型或主模型完成。高频稳定请求优先规则，开放问题再使用模型；需要置信度阈值、默认处理器和错误路由回退。

---

## Q4: 多 Agent 协作与路由在工程落地时如何做取舍？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥🔥

增加 Agent 可能提升专业性和并行度，也会成倍增加调用成本与故障路径；角色提示应聚焦能力边界，不要依赖拟人化人格保证质量；跨 Agent 传递摘要可控成本，但重要原始证据必须可追溯。

---

## Q5: 多 Agent 协作与路由最常见的故障与排查重点是什么？
> 难度 ⭐⭐⭐⭐ ｜ 高频 🔥🔥

两个 Agent 相互转交任务形成路由循环；多个 Agent 使用不同事实版本，最终答案内部矛盾；主管只看自然语言结论，无法验证专家是否真正完成任务。排查时应关联运行状态、模型请求、工具调用、外部证据和最终结果，先判断是数据、模型、编排、权限还是依赖故障。
