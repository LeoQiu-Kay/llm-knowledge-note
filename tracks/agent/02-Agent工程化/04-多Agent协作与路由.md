# 多 Agent 协作与路由

## 30 秒回答

多 Agent 系统通过路由器、主管或共享任务队列，把工作交给具有不同工具、权限或上下文的角色。它适合可并行、可独立验证的专业任务，不应仅为模拟团队而增加角色；生产重点是契约、上下文隔离、冲突合并、预算和端到端责任归属。

## 核心原理

### 协作模式

常见模式包括主管分派、专家路由、并行扇出汇总和事件驱动接力。每个 Agent 应声明输入输出 schema、可用工具、权限和完成条件，避免靠含糊对话协作。

### 路由决策

路由可由规则、分类模型或主模型完成。高频稳定请求优先规则，开放问题再使用模型；需要置信度阈值、默认处理器和错误路由回退。

### 合并与冲突

并行结果应保留证据与置信度，由确定性聚合器或专门验证节点处理重复、矛盾和缺失。共享可变状态使用版本或事务控制，不能让多个 Agent 覆盖彼此结果。

## 工程权衡

- 增加 Agent 可能提升专业性和并行度，也会成倍增加调用成本与故障路径。
- 角色提示应聚焦能力边界，不要依赖拟人化人格保证质量。
- 跨 Agent 传递摘要可控成本，但重要原始证据必须可追溯。

## 常见故障

1. 两个 Agent 相互转交任务形成路由循环。
2. 多个 Agent 使用不同事实版本，最终答案内部矛盾。
3. 主管只看自然语言结论，无法验证专家是否真正完成任务。
