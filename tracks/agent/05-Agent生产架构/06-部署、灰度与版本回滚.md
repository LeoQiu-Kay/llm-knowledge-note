# 部署、灰度与版本回滚

## 30 秒回答

Agent 发布物不仅是代码，还包括模型、系统提示、工作流、工具 schema、检索索引和安全策略。部署必须为这些依赖建立组合版本，通过离线回归、影子流量、灰度和在线指标逐步放量；回滚要恢复兼容组合，并正确处理仍在运行的长任务。

## 核心原理

### 版本清单

每个 run 记录代码、提示、模型、路由、工具、策略、知识快照和评测版本。制品不可变，配置变更也走审查与发布流程，避免线上状态无法复现。

### 灰度验证

先离线评测和安全测试，再用影子流量比较但禁止真实副作用，随后按租户或比例灰度。守门指标包含质量、延迟、成本、拒绝率和工具错误，而非只看服务 5xx。

### 兼容与回滚

运行中任务通常固定原工作流与 schema 到结束；数据库和状态迁移采用向前/向后兼容。回滚同时处理提示、工具和索引版本，必要时暂停新任务并排空旧 worker。

## 工程权衡

- 快速模型别名升级方便，却降低可复现性，高风险功能宜固定版本。
- 影子请求可验证模型输出，但对收费和数据共享仍要受配额与合规约束。
- 全量回滚简单，局部租户回滚更灵活但版本矩阵复杂。

## 常见故障

1. 只回滚应用代码，工具 schema 和提示仍是新版本。
2. 新 worker 无法读取旧检查点，长任务全部失败。
3. 灰度指标只看基础设施健康，任务成功率已明显下降却继续放量。
