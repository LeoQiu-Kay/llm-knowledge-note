# Agent 服务架构与会话存储 · 面试题

## Q1: 请用一分钟说明Agent 服务架构与会话存储的核心目标与工作机制。
> 难度 ⭐⭐ ｜ 高频 🔥🔥🔥

生产 Agent 通常由 API/会话层、编排器、模型网关、工具网关、状态存储、队列和可观测平台组成。无状态请求服务负责接入，持久化 run 状态支持长任务恢复；会话只是一种用户视图，不能替代任务、消息、产物和权限的独立数据模型。

---

## Q2: 服务边界的核心机制是什么？
> 难度 ⭐⭐ ｜ 高频 🔥🔥🔥

接入层处理认证、限流和流式响应；编排器推进状态机；模型网关统一路由与配额；工具网关执行鉴权、schema 校验和审计。边界清晰后可分别扩容和故障隔离。

---

## Q3: 存储模型为什么重要，实际如何落地？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥

关系库保存强一致元数据和状态转移，对象存储保存附件与大产物，缓存保存短期热点，向量库保存可检索知识。消息正文、派生摘要和外部引用要有版本与血缘。

---

## Q4: Agent 服务架构与会话存储在工程落地时如何做取舍？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥🔥

单体适合早期快速迭代，模块边界仍应明确以便后续拆分；强一致适用于状态和权限，遥测与部分产物可最终一致；流式 token 改善体验，但最终消息与运行终态仍需可靠提交。

---

## Q5: Agent 服务架构与会话存储最常见的故障与排查重点是什么？
> 难度 ⭐⭐⭐⭐ ｜ 高频 🔥🔥

HTTP 连接断开就把任务标记失败，但后台实际仍在执行；会话缓存未按租户隔离，返回其他用户历史；附件已删除，向量索引和生成引用仍指向孤儿数据。排查时应关联运行状态、模型请求、工具调用、外部证据和最终结果，先判断是数据、模型、编排、权限还是依赖故障。
