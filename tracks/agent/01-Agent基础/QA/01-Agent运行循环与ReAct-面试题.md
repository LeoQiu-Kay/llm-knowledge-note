# Agent 运行循环与 ReAct · 面试题

## Q1: Agent 运行循环与普通聊天调用的本质区别是什么？
> 难度 ⭐⭐ ｜ 高频 🔥🔥🔥

普通聊天通常是一次输入到一次输出；Agent 维护显式任务状态，并在模型决策、工具执行、观察结果和下一轮决策之间循环，直到满足终止条件。它还需要处理权限、预算、持久化、重试与副作用，所以是一个受控执行系统，而不只是更长的提示词。

---

## Q2: ReAct 的核心思想是什么？
> 难度 ⭐⭐ ｜ 高频 🔥🔥

ReAct 让推理/决策与外部行动交替进行：模型基于当前观察选择动作，工具返回新证据后再修正下一步，而不是一开始生成不可变的完整答案。工程上不必暴露模型的私有推理文本，但要保存动作、工具结果和状态变化以便审计。

---

## Q3: 如何防止 Agent 陷入无限循环？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥🔥

设置步数、时间、token、费用和工具调用上限；记录近期动作与结果，检测相同调用、状态不变或目标距离没有改善；为可恢复错误设置有限重试和退避；达到阈值后输出受控失败、切换确定性流程或请求人工接管，而不是继续让模型“再试一次”。

---

## Q4: workflow 和 agentic loop 应如何选择？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥

路径稳定、合规要求高、步骤可枚举时优先确定性 workflow，便于测试和审计；环境开放、需要根据未知结果动态选择工具时再使用 agentic loop。生产系统常把两者结合：外层由工作流控制关键节点，局部节点允许 Agent 在有限工具和预算内决策。

---

## Q5: 有副作用的 Agent 任务怎样做到可恢复？
> 难度 ⭐⭐⭐⭐ ｜ 高频 🔥🔥

把每一步意图、参数、幂等键、执行状态和结果持久化为事件或检查点。恢复时先读取外部系统确认不确定步骤是否已经成功，再决定继续、补偿或人工介入。写工具必须支持幂等或提供业务唯一键，不能仅靠“异常就重跑整个任务”。
