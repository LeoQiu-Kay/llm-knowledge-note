# Agent 状态与生命周期 · 面试题

## Q1: 请用一分钟说明Agent 状态与生命周期的核心目标与工作机制。
> 难度 ⭐⭐ ｜ 高频 🔥🔥🔥

Agent 状态是一次任务从创建、运行、等待、恢复到终止的可持久化事实集合。成熟实现会把对话、计划、工具调用、审批、预算和产物分离建模，用明确状态机约束转移，并以事件和检查点支持重试、恢复、审计和并发控制。

---

## Q2: 状态模型的核心机制是什么？
> 难度 ⭐⭐ ｜ 高频 🔥🔥🔥

至少区分 run、step、message、tool call、artifact 和 approval。状态中保存事实与引用，临时提示词由事实投影生成，避免把不可查询的一长串消息当作唯一数据库。

---

## Q3: 生命周期状态机为什么重要，实际如何落地？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥

常见状态包括 queued、running、waiting_for_tool、waiting_for_human、succeeded、failed、cancelled 和 expired。每次转移校验前置状态并记录原因，终态不能被普通重试重新打开。

---

## Q4: Agent 状态与生命周期在工程落地时如何做取舍？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥🔥

完整事件溯源可解释性强，但存储、迁移和重放成本高；多数系统可采用业务表加关键事件日志；状态粒度过粗无法恢复，过细会让版本兼容和查询复杂，应围绕可重试边界划分 step；长任务需要状态过期、归档和数据保留策略，不能永久携带全部上下文。

---

## Q5: Agent 状态与生命周期最常见的故障与排查重点是什么？
> 难度 ⭐⭐⭐⭐ ｜ 高频 🔥🔥

进程重启后把 running 任务永久卡住，没有租约和恢复扫描；并发 worker 同时推进同一 run，重复调用写工具；模型消息已写入但工具结果未提交，恢复时无法判断真实进度。排查时应关联运行状态、模型请求、工具调用、外部证据和最终结果，先判断是数据、模型、编排、权限还是依赖故障。
