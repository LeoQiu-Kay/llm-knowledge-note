# 上下文工程与 Token 预算 · 面试题

## Q1: 请用一分钟说明上下文工程与 Token 预算的核心目标与工作机制。
> 难度 ⭐⭐ ｜ 高频 🔥🔥🔥

上下文工程是在有限窗口内选择、组织和标注最有用的信息，包括系统规则、任务状态、工具定义、检索证据、记忆和历史。目标不是塞满窗口，而是提高信噪比、保持指令边界，并在质量、延迟和成本之间进行可测量的预算分配。

---

## Q2: 上下文分层的核心机制是什么？
> 难度 ⭐⭐ ｜ 高频 🔥🔥🔥

稳定规则、用户目标、运行状态、外部证据和工具结果应使用清晰边界与结构化标签。低信任内容只能作为数据，不应与系统指令混合，来源和时间要随证据一起传递。

---

## Q3: 压缩与选择为什么重要，实际如何落地？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥

优先删除重复和无关内容，再做分层摘要；当前决策依赖的原始证据保留引用。可按最近性、相关性、权威性和任务阶段动态选择，而非固定截取最后 N 条消息。

---

## Q4: 上下文工程与 Token 预算在工程落地时如何做取舍？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥🔥

更长上下文不必然更好，中间信息遗失和噪声会降低决策质量；摘要模型节约主模型成本，但引入额外延迟和摘要错误；工具 schema 太多会占窗口并降低选择准确率，应按状态动态暴露。

---

## Q5: 上下文工程与 Token 预算最常见的故障与排查重点是什么？
> 难度 ⭐⭐⭐⭐ ｜ 高频 🔥🔥

截断时删除了系统约束或用户最新修改；把网页中的提示注入文本放入高优先级指令区；工具返回整份日志或数据库结果，挤掉真正的任务证据。排查时应关联运行状态、模型请求、工具调用、外部证据和最终结果，先判断是数据、模型、编排、权限还是依赖故障。
