# Data/SQL Agent · 面试题

## Q1: 请用一分钟说明Data/SQL Agent的核心目标与工作机制。
> 难度 ⭐⭐ ｜ 高频 🔥🔥🔥

Data/SQL Agent 把自然语言目标转换为数据发现、查询、分析和解释。安全实现先获取 schema 与业务口径，生成只读、受限查询，经解析器和策略校验后在隔离账户执行，再验证结果与引用；写操作、敏感字段和大规模扫描必须走更严格审批或专用工作流。

---

## Q2: 语义与 schema的核心机制是什么？
> 难度 ⭐⭐ ｜ 高频 🔥🔥🔥

向模型提供表、字段、主外键、指标定义、时间口径和样例值，而不是完整数据。语义层统一“活跃用户”等业务指标，避免每次让模型猜 join 和过滤条件。

---

## Q3: 查询护栏为什么重要，实际如何落地？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥

使用只读凭证、允许列表、AST 解析和参数化查询，限制表、列、行数、扫描量、执行时间和并发。先 EXPLAIN 评估成本，禁止多语句、DDL/DML 和不受控函数。

---

## Q4: Data/SQL Agent在工程落地时如何做取舍？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥🔥

实时 schema 提高准确性，也可能泄露敏感表名，应按用户权限裁剪；自动修复 SQL 提高成功率，但重试必须保持同一安全策略和预算；把常用问题固化为指标 API 更可靠，长尾探索再使用 Agent。

---

## Q5: Data/SQL Agent最常见的故障与排查重点是什么？
> 难度 ⭐⭐⭐⭐ ｜ 高频 🔥🔥

模型生成笛卡尔积，扫描量和费用失控；查询成功但使用错误时区或业务口径，结论错误；结果集包含个人信息并被完整写入模型日志。排查时应关联运行状态、模型请求、工具调用、外部证据和最终结果，先判断是数据、模型、编排、权限还是依赖故障。
