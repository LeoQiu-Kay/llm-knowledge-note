# Agent 产品设计与用户体验

## 30 秒回答

Agent 产品的核心体验是让用户理解系统能做什么、正在做什么、为何需要权限以及如何纠正和接管。应通过范围明确的入口、渐进授权、计划与进度、可编辑产物、证据和撤销机制建立信任；自主程度按风险分级，而不是用拟人化对话掩盖不确定性。

## 核心原理

### 能力与预期

入口展示适用任务、所需数据、预计时间和限制，复杂请求先复述目标与成功标准。系统对不确定和失败要直说，避免把建议包装成已执行结果。

### 可控执行

执行前展示高影响计划，过程中显示当前步骤、等待原因和成本，允许暂停、取消、修改与人工接管。写操作提供预览、diff、确认和可撤销窗口。

### 反馈与信任

答案展示关键证据和数据时间，产物可编辑并保留变更记录。收集“哪里错了”的结构化反馈，而非只有点赞；无障碍、移动端和国际化同样进入任务流程设计。

## 工程权衡

- 过多确认会打断体验，可按风险、用户经验和组织策略动态调整。
- 展示完整推理既不必要也可能混淆，重点展示计划、证据和动作依据。
- 拟人化可提升亲和力，但不应误导用户认为系统具有人类判断与责任。

## 常见故障

1. 进度动画持续运行但没有真实状态，用户无法判断是否卡死。
2. Agent 自动发送或发布内容，没有预览与撤销。
3. 失败只显示“出错了”，不提供已完成步骤、影响和恢复选择。

## 面试追问

- 能力与预期在生产环境中如何验证效果？
- 可控执行在生产环境中如何验证效果？
- 反馈与信任在生产环境中如何验证效果？
- 如何为Agent 产品设计与用户体验设计评测、监控与回滚方案？
