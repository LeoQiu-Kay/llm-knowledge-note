# UE UI、资源、渲染与构建排查

> **优先级**：基础 P0，底层 P2。回答要覆盖 UMG、Asset 管理、World Partition/关卡和打包诊断。

## 1. UMG 与 Slate

UMG 提供设计和蓝图层，Slate 是底层 C++ UI 框架。复杂列表要做 Entry 复用、可见性裁剪和数据驱动刷新，避免每帧重建 Widget Tree。UI 事件不要绕过权限直接改服务器状态，输入层应把点击转成命令或 RPC。

## 2. 资源与关卡

`UAsset` 通过引用关系组织材质、网格、动画、蓝图和音频；软引用适合按需加载，硬引用会把依赖带入加载链。Asset Manager、Primary Asset Label、Chunk 和异步加载共同决定补丁、首包和内存峰值。大世界要按空间和玩法拆分关卡，World Partition/Data Layer 的加载范围要和网络 relevancy、流送预算一起设计。

## 3. 渲染与性能

使用 Unreal Insights 看 CPU/线程/加载，用 RenderDoc 或平台工具看 GPU pass、带宽和 overdraw；Nanite、Lumen、Virtual Shadow Maps 等特性要按目标硬件和内容规模评估，不能把“开启功能”当成优化。材质实例、LOD、HLOD、可见性和纹理压缩常常比微调 C++ 更先见效。

## 4. 构建排查顺序

1. 记录 Engine/插件/编译器/SDK/配置和 Cook 版本。
2. 检查模块依赖、反射生成、链接错误和热重载残留。
3. 对 Cook/Package 失败定位缺失软引用、平台不支持资源、大小写路径和 Shader 编译错误。
4. 用 Shipping/Development 两种包验证符号、日志、崩溃上报、Pak/IoStore 和增量补丁。

### 高频追问

#### Q1. 硬引用和软引用的取舍？

硬引用简单、加载时可直接使用，但会扩大依赖和首屏峰值；软引用只保存路径，可异步按需加载，更适合大世界、商城和可选内容。使用软引用必须处理加载失败、版本迁移和句柄生命周期。

#### Q2. UE 构建“编辑器能跑、打包不能跑”怎么查？

先对齐目标平台配置和 Cook 日志，再查模块/插件是否打进包、反射生成代码、大小写路径、软引用是否被扫描、Shipping 下的裁剪和宏分支。最后在干净机器或 CI 复现，排除本机缓存污染。
