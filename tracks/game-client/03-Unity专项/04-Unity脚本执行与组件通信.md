# Unity 脚本执行顺序与组件通信

> **优先级**：P0。重点回答初始化依赖、Update 顺序和通信边界。

## 1. 执行阶段

把逻辑分成初始化、输入、物理、Gameplay、动画、相机和渲染阶段。不要用随机 Script Execution Order 解决所有依赖，核心服务使用显式 bootstrap，组件之间通过接口、命令或事件通信。

## 2. 通信方式

直接引用适合稳定父子关系；接口适合替换实现；事件适合一对多通知；消息队列适合跨线程/跨帧；全局单例只承载真正的进程级服务。通信契约应定义线程、顺序、异常和对象生命周期。

## 3. Update 管理

大量实体不要每个都注册 Update，可由一个系统批量 tick，并按距离、可见性和状态降频。协程和定时器归属明确，场景卸载时集中取消。

### 高频追问

#### Q1. 为什么不建议每个 MonoBehaviour 都有 Update？
每个回调都有调度、虚调用和管理开销，难以统一降频与暂停。批量系统更容易做数据布局、Job 化和性能统计。

#### Q2. 事件和消息队列怎么选？
同线程、低延迟通知可用事件；需要跨线程、顺序控制、背压或跨帧处理时用队列。两者都要有取消和生命周期托管。
