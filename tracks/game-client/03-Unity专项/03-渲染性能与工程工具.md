# Unity 渲染、性能工具与工程化

> **优先级**：渲染性能 P0/P1，编辑器工具与 DOTS P1/P2。

## 1. 从指标定位瓶颈

先用 Profiler 看 CPU Timeline、GC Alloc、Job 和渲染线程，再用 Frame Debugger 看批次与 pass，最后用 RenderDoc 或平台 GPU 工具确认 GPU 瓶颈。移动端还要记录温度、功耗、内存带宽和降频后的 1% low。

## 2. 常见渲染优化

- CPU：减少每帧 `GetComponent`、反射和重复查找；批量提交、缓存材质/网格引用。
- GPU：控制 overdraw、阴影级联、透明粒子、后处理和纹理带宽；使用 LOD、遮挡剔除和合适的压缩格式。
- 内存：按场景/功能分组资源，避免重复纹理；大图集按 UI 生命周期拆分。
- Shader：减少动态分支和关键字组合，移动端关注精度与变体数量。

## 3. 编辑器与构建

自定义 Inspector、AssetPostprocessor、菜单工具和验证器能把错误前移；CI 至少自动跑编译、资源校验、Addressables 构建、单元/冒烟测试和包体报告。构建问题要记录 Unity 版本、平台 SDK、脚本后端、裁剪和符号设置，避免“开发机能跑”成为唯一结论。

## 4. 线上诊断

线上日志要带场景、资源 key、用户/会话 ID 和构建版本，但不要泄露敏感数据。崩溃、卡顿和资源加载失败分别采集堆栈、帧时间分解和错误码；灰度发布时保留回滚包与配置快照。

### 高频追问

#### Q1. Batching、GPU Instancing 和 SRP Batcher 怎么选？

它们减少 CPU 提交或状态切换的方式不同，依赖材质、网格、平台和 Shader。不要只看 Draw Call 数，要同时看 CPU Render Thread、GPU 时间、内存和批处理是否真的生效。

#### Q2. 为什么要把 Profiler 数据放到目标机？

编辑器有额外开销，PC GPU/CPU 也与手机、主机不同。性能结论必须来自目标机或接近目标机的 Development Build，并固定场景、分辨率、温度和采样方式。
