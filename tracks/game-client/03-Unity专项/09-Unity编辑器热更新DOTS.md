# Unity 编辑器工具、热更新与 DOTS

> **优先级**：P1/P2。

## 1. 编辑器工具

自定义 Inspector、窗口、AssetPostprocessor 和验证器把错误前移；工具应可重复执行、记录版本，并避免在导入阶段做不可控网络/重 CPU 操作。

## 2. 热更新

代码、配置、资源分别版本化，catalog 与协议要兼容；更新失败可以回滚到旧版本。热更新入口要校验签名、大小、版本和磁盘空间，避免半包覆盖当前可运行版本。

## 3. DOTS/ECS

ECS 以实体、组件和系统组织同构数据，Burst/Job 提升批量计算；迁移前先找出数据布局和主线程 API 边界。内容驱动、异构对象和编辑器强依赖部分可保留 MonoBehaviour，采用混合架构。

### 高频追问

#### Q1. 热更新为什么不能只替换 DLL？
资源 catalog、序列化布局、脚本后端和平台限制可能互相依赖；需要版本化 manifest、兼容迁移、校验和回滚策略。

#### Q2. DOTS 一定比 GameObject 快吗？
不是。它在大量同构数据、批处理和并行计算中优势明显；少量异构对象或复杂编辑器逻辑迁移成本高，必须先测量热点。
