# Unity 对象模型、生命周期与运行时

> **优先级**：P0。面试官常用“为什么这一帧还没拿到引用”来考生命周期，而不是单纯问函数定义。

![Unity Script Lifecycle Flowchart](https://docs.unity3d.com/cn/2018.3/uploads/Main/monobehaviour_flowchart.svg)

*图示来源： [Unity Manual — Order of Execution for Event Functions](https://docs.unity3d.com/cn/2018.3/Manual/ExecutionOrder.html)。版本差异以项目实际 Unity 文档为准。*

## 1. GameObject、Component 与 Prefab

`GameObject` 是场景中的容器，行为与数据通常放在 `Component`；`Transform` 维护层级和局部/世界变换。Prefab 是可实例化的资源模板，实例可以有 overrides；运行时修改实例不等于修改源 Prefab。不要把所有逻辑都塞进一个 MonoBehaviour，按领域组件拆分能降低耦合。

## 2. 典型执行顺序

一般顺序是 `Awake → OnEnable → Start → FixedUpdate → Update → LateUpdate → OnDisable → OnDestroy`，但要注意：

- 同一场景中不同对象的 `Awake` 相对顺序不要依赖，跨对象初始化用显式 bootstrap 或 Script Execution Order。
- `FixedUpdate` 可能一帧执行多次或一次也不执行，物理读写放这里；渲染相机跟随通常放 `LateUpdate`。
- Instantiate/异步加载生成的对象会在生成时经历自己的初始化，不能假设它和场景对象同批完成。
- 禁用对象不会销毁；销毁通常在当前帧末生效，引用要在 `OnDestroy` 前清理。

## 3. 场景、域重载与生命周期契约

`DontDestroyOnLoad` 只应承载真正跨场景的服务，并用单例初始化保护重复实例。退出 Play Mode、脚本重编译、域重载开关都会改变静态字段和事件的存活行为。每个服务应定义：创建者、释放者、是否跨场景、是否可重入、异步任务如何取消。

## 4. 常见排查

空引用不只来自“忘记拖引用”，还可能是执行顺序、对象未激活、场景卸载后的旧引用、Addressables 异步结果晚到。排查时记录对象 instance ID、场景句柄、加载请求 ID 和 generation；回调执行前再次验证对象状态。

### 高频追问

#### Q1. `Awake`、`OnEnable`、`Start` 的区别是什么？

`Awake` 用于实例初始化，通常每个实例一次；`OnEnable` 每次启用都会调用；`Start` 在第一次启用、第一帧前调用一次。依赖其他对象的初始化不要假设 `Awake` 顺序，使用显式初始化阶段。

#### Q2. 为什么不要在 `OnDestroy` 里访问场景服务？

销毁顺序可能已经让服务失效，尤其是场景切换或应用退出时。更稳妥的方式是在所有者发起卸载时显式取消任务、解除订阅，再让组件完成轻量清理。
