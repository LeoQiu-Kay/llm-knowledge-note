# Unity 资源管线、场景与序列化

> **优先级**：P0/P1。

## 1. 资产依赖

硬引用会把依赖带入加载链，软引用支持按需异步；Addressables 的 catalog、group、label 和 profile 决定包体、缓存与更新。资源卸载必须从句柄、实例、材质、Sprite 和静态缓存逐层检查。

## 2. 序列化规则

Unity 序列化偏字段而非属性，受支持类型、`[SerializeField]`、版本迁移和引用关系影响。运行时状态、编辑器配置、玩家存档和网络协议应分离，避免把临时状态写回资产。

## 3. 场景流送

场景切换要拆分加载、激活、预热和卸载，控制每帧激活预算。大世界使用 additive/分块流送，加载失败要有降级和重试，而不是同步卡住主线程。

### 高频追问

#### Q1. 为什么卸载场景后内存还在？
可能有静态引用、Addressables 句柄、实例、事件、材质或缓存仍持有资源。用内存快照和依赖图找 owner，不能只调用一次 UnloadUnusedAssets。

#### Q2. ScriptableObject 能当存档吗？
它适合共享配置资产；玩家存档应写独立版本化数据，避免运行时修改资源、污染工程或在只读平台失败。
