# C# 运行时、GC 与语言特性

> **优先级**：Unity P0。重点不是背语法，而是回答托管对象何时分配、何时回收，以及异步代码如何回到主线程。

## 1. 值类型、引用类型与装箱

值类型通常直接存储在栈、寄存器或对象内联字段中；引用类型存储对象引用，实例位于托管堆。把值类型转成 `object` 或接口会装箱，产生对象分配；频繁枚举非泛型集合、字符串格式化和闭包捕获都可能制造隐藏分配。

`struct` 只适合小、短生命周期、语义上像值的类型；过大的 struct 会复制，包含引用的 struct 也不等于“无 GC”。

## 2. GC 与每帧分配

托管 GC 会扫描根并回收不可达对象，代际收集利用“新对象更可能短命”的假设。游戏里最怕的是在战斗帧或 UI 滚动帧大量创建临时对象，触发不可预测的停顿。做法包括缓存列表容量、使用泛型容器、复用字符串/缓冲区、避免 LINQ 和隐式装箱，并用 Profiler 的 GC Alloc 验证。

## 3. 委托、事件与异步

事件订阅是引用关系：发布者长寿、订阅者短寿时容易泄漏。对象销毁、禁用和场景切换时要解除订阅。`async/await` 不等于开新线程；默认会捕获同步上下文，Unity 代码要确认 continuation 是否回到主线程，并给网络/资源任务提供取消令牌。

协程适合把流程拆到多个帧，但不提供线程安全；Task 适合 IO 编排，Job/Burst 适合纯数据计算。三者的取消、异常和对象生命周期都要显式处理。

## 4. 语言特性答题抓手

- `readonly`、`in`、`ref` 减少复制，但不能让引用指向的对象不可变。
- 泛型比 `object` 更少装箱；接口调用、虚调用和委托调用要结合热点测量。
- `Span<T>`/`ArrayPool<T>` 适合短期缓冲，但不能跨越异步 await 保存栈引用。
- 反射和表达式树方便工具链，却可能在 AOT、裁剪和 IL2CPP 下失效，需保留元数据或改用源生成。

### 高频追问

#### Q1. Unity 中 `Update` 里最容易出现哪些 GC？

字符串拼接/插值、LINQ、foreach 枚举非泛型接口、闭包捕获、临时数组/列表、装箱和频繁创建委托。用 Profiler 逐帧看 GC Alloc，再针对热点缓存对象或改成非分配 API。

#### Q2. 协程、Task、Job 怎么选？

协程用于主线程上的时序编排，Task 用于 IO 和可组合异步，Job/Burst 用于可并行的纯数据计算。它们不能互相替代；选择时同时说明线程归属、取消方式和结果回主线程的时机。
