# C++ 核心与工程实践

> **优先级**：UE P0；即使主投 Unity，也建议掌握内存、对象模型和并发边界。

## 1. 对象模型与资源所有权

面试要能区分栈对象、堆对象、静态对象和 placement new；说明构造/析构顺序、对齐、虚表和 RTTI。资源所有权优先用 RAII 表达：独占所有权用 `unique_ptr`，共享所有权谨慎使用 `shared_ptr`，观察者用裸指针或 `weak_ptr`，但要写清谁保证生命周期。

```cpp
class TextureCache {
public:
    explicit TextureCache(RenderDevice& device) : device_(device) {}
    TextureHandle load(std::string_view path);
private:
    RenderDevice& device_; // 非拥有引用，生命周期由上层保证
};
```

拷贝构造、移动构造和 copy/move assignment 共同决定容器扩容时的成本。资源句柄应尽量可移动；禁止拷贝的对象要显式 `delete`，不要等到链接错误才发现语义不对。

## 2. 多态、模板与 ABI

基类析构函数若可能多态删除必须是 virtual。虚函数带来一次间接调用和对象布局约束，热点数据结构可以用组合、类型擦除或 CRTP 减少开销。模板在编译期展开，适合泛型算法和静态多态，但会增加编译时间与代码体积；跨 DLL/模块边界应避免暴露不稳定 STL ABI。

## 3. 并发与无锁边界

先区分数据竞争、竞态条件、可见性和原子性。`std::atomic` 不会让多个变量的业务事务自动原子；无锁队列需要明确内存序、ABA、防止对象提前回收以及容量满时的策略。游戏 Job 系统更常见的做法是把写入拆成独立块，用依赖图在阶段末合并，而不是到处加锁。

## 4. 编译、模块与调试

预编译头、Unity Build、增量链接和模块边界影响迭代速度；LTO 和符号裁剪影响发行包。排查崩溃要保留符号、崩溃地址、线程和最近资源操作；ASan/UBSan/TSan 适合开发构建，不能因为发行包关闭检查就忽略未定义行为。

### 高频追问

#### Q1. `unique_ptr` 和 `shared_ptr` 怎么选？

默认 `unique_ptr`，因为所有权唯一、开销小且生命周期清晰。只有确实存在多个独立所有者才用 `shared_ptr`，并用 `weak_ptr` 打断环；引擎对象若由 UObject/反射系统管理，不能随意套标准智能指针。

#### Q2. 为什么移动构造能改善资源容器性能？

移动只转移指针、句柄和容量，不复制资源本体。容器扩容时如果类型的移动构造是 `noexcept`，标准库更愿意移动而不是回退到拷贝；移动后对象必须保持可析构、可赋值的有效状态。
