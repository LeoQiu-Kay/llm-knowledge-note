# C++ 模板、STL 与现代特性

> **优先级**：P0/P1。结合容器迭代器、移动语义和编译期抽象回答。

## 1. 容器与迭代器

`vector` 适合连续遍历，扩容会使引用失效；`deque` 分段连续，`unordered_map` 平均 O(1) 但要关注 rehash；`map` 提供有序树结构但有节点分配和 cache 成本。回答容器时要说明失效规则、内存开销和遍历热点。

## 2. 模板与类型推导

模板支持泛型和静态多态，concepts 可以在编译期约束接口。`auto`、`decltype`、完美转发和 `std::move` 要结合值类别解释，不能把 `std::move` 当成“移动动作”；移动后对象仍需可析构。

## 3. 游戏工程取舍

热点路径优先简单、可测量的容器和数据布局；模板实例过多会增加编译与代码体积。跨模块 API 需要稳定 ABI，避免把编译器版本敏感的 STL 类型直接暴露给插件边界。

### 高频追问

#### Q1. vector 扩容为什么会影响游戏帧时间？
需要申请更大内存并搬移元素，可能触发锁、页提交和缓存失效。预留容量、分块增长或使用稳定句柄可以减少尖峰。

#### Q2. `std::move` 做了什么？
它只是把表达式转换为右值引用，真正是否移动由目标类型的移动构造/赋值决定；若类型没有移动操作，仍可能拷贝。
