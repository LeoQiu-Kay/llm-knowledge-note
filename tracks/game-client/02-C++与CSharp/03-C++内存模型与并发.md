# C++ 内存模型、并发与调试

> **优先级**：UE P0。要能解释“看起来没问题但偶发崩溃”的并发原因。

## 1. 内存模型

数据竞争是未同步的并发读写，结果是未定义行为；原子性、可见性和顺序性必须分别讨论。acquire/release 常用于发布已初始化数据，seq_cst 提供更强的全局顺序但可能增加成本。volatile 不是线程同步工具。

## 2. 并发结构

游戏更适合任务图、双缓冲、消息队列和按线程分片，而不是共享容器加大锁。锁要有明确粒度、顺序和超时策略，避免主线程等待 IO 或渲染线程等待脚本。无锁结构还要处理 ABA、内存回收和容量背压。

## 3. 工具

ASan 查越界和 use-after-free，UBSan 查未定义行为，TSan 查数据竞争；结合符号、断言、核心转储和最小复现定位。发行构建可以关闭部分检查，但要在 CI 和夜间压力测试中保留。

### 高频追问

#### Q1. `volatile` 能保证线程安全么？
不能。它只影响编译器对访问的优化，不提供原子性、锁或跨核心可见性。应使用 atomic、mutex 或消息传递。

#### Q2. 双缓冲如何避免读写冲突？
写线程只修改 back buffer，阶段结束后通过 fence 或原子交换发布，读线程一直读 front buffer；交换点必须明确，不能在交换后继续写旧 buffer。
