# 从功能到上线的综合场景题

> **优先级**：P0/P1。综合题不要求一次说出所有 API，而是看你能否把玩法、网络、资源、性能和发布闭环起来。

## 场景一：做一个可联机的技能系统

先定义权威边界：客户端只提交技能意图与目标信息，服务器校验资源、冷却、距离和命中，再产生 Attribute/Effect 结果；客户端可以预测起手动作，但伤害、掉血和掉落只能由服务器确认。同步层传状态和必要事件，VFX/SFX 通过可重建事件驱动，并为重复包设计幂等键。

## 场景二：大世界首屏加载卡顿

用时间线拆成 IO、解压、反序列化、Shader 编译、纹理上传和脚本初始化；按玩家视野和路线做分块，软引用异步加载，提前预热关键材质，后台解压并限制每帧激活预算。用目标机记录首屏时间、峰值内存、P95 帧时间和失败率，保留旧版本资源回滚。

## 场景三：战斗中偶发掉帧与状态不同步

同时采集 CPU/GPU/GC/网络快照：若主线程尖峰，检查每帧分配、UI rebuild、锁和资源回调；若 GPU 超时，检查 overdraw、阴影和后处理；若状态漂移，对比输入序号、服务器 tick、预测回滚次数和快照丢失。不要用提高发送频率掩盖服务器逻辑不一致。

## 场景四：如何设计可维护的客户端模块

按“输入—用例—领域状态—表现—基础设施”分层，Gameplay 不依赖具体 UI/网络；配置和资源通过资产 ID 注入，服务有明确启动/停止顺序。每个异步流程都支持取消、超时、重试和回滚，关键状态有埋点与可复现日志。

## 面试最后的验收表

- **正确性**：单机、联机、弱网、重连、切后台、场景切换均有行为定义。
- **性能**：目标设备有帧预算、内存上限、首屏和网络带宽指标。
- **工程**：CI 能构建、校验资源、生成符号和回滚包。
- **可观测**：线上错误带版本、场景、资源 key、请求/输入序号。
- **安全**：客户端预测不产生不可逆奖励，服务器重新验证关键参数。

### 高频追问

#### Q1. 设计技能系统时最容易遗漏什么？

除了技能释放本身，还要回答取消、打断、重复包、预测失败、死亡/换场景、晚加入、回放和配置热更。把不可逆的奖励和伤害留在权威端，把表现做成可重建事件。

#### Q2. 如何证明一次优化有效？

固定设备、版本、场景、分辨率和输入，建立优化前基线；比较帧时间分位数、峰值内存、首屏时长、带宽和错误率。上线后做灰度，并保留采样数据与回滚开关。
