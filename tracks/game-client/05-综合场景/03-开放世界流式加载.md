# 开放世界流式加载与资源预算

## 场景拆解

将世界按空间、任务和资产依赖拆块；玩家前方预取，远离区域降级或卸载。加载分为 IO、解压、反序列化、GPU 上传、激活和预热，每阶段都有线程与每帧预算。

## 资源策略

硬引用只保留核心首屏链，其他内容用软引用/catalog 异步加载；纹理、网格、动画和 Shader 按质量档位与平台打包。缓存需要上限、LRU 和版本校验，内存压力下按优先级淘汰。

## 观测指标

首屏时间、区域切换卡顿、峰值内存、IO 吞吐、资源失败率、Shader hitch 和网络下载量都要按设备与版本统计。加载失败显示降级内容，并可重试或回滚旧 catalog。

### 高频追问

#### Q1. 为什么异步加载仍会卡顿？
激活、反序列化、纹理上传和 Shader 编译可能回到主线程或 GPU 队列；要分阶段、限额和预热，不能只把 API 换成 Async。

#### Q2. 如何避免资源重复打包？
用依赖分析、分组规则和构建报告检查共享依赖，按生命周期/版本拆包，避免两个组各自包含同一大纹理或材质。
