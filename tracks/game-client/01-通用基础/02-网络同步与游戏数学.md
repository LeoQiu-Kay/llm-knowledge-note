# 网络同步、游戏数学与碰撞

> **优先级**：P0。联机岗位重点考察“谁是权威、传什么、何时修正”，数学题则要落到坐标系、误差和稳定性。

## 1. 网络同步的四个选择

### 状态同步、帧同步与客户端预测

- **状态同步**：服务器发送关键状态，客户端插值或外推。适合大世界、弱一致性的实时动作。
- **帧同步**：各端执行相同输入和确定性逻辑，只同步帧输入。带宽小，但要求确定性、断线重连和回滚。
- **客户端预测 + 服务器校正**：本地立即响应输入，服务器返回权威位置；客户端重放未确认输入，降低体感延迟。
- **插值与外推**：渲染时使用过去两个服务器快照做插值；没有新快照时才外推，并限制最大预测时间。

典型链路是：客户端发送带序号的输入 → 服务器验证并推进权威状态 → 广播快照/确认序号 → 客户端回滚到确认状态并重放未确认输入。所有消息都要考虑丢包、乱序、重复和版本兼容。

## 2. RPC 与同步数据的边界

可靠 RPC 适合低频且不能丢的事件，如购买成功；高频移动、瞄准和鼠标采样应使用不可靠消息或压缩后的输入。不要把每帧特效都做成广播：伤害、技能结果等玩法事件由权威端决定，声音、粒子和镜头震动属于可重建的表现层。

## 3. 坐标、向量与旋转

- 明确世界坐标、局部坐标、屏幕坐标和相机空间，变换链按“父到子”或“世界到视图”统一约定。
- 点、方向和法线不是同一种量；法线变换通常使用逆转置矩阵，不能直接乘模型矩阵。
- 四元数适合表示旋转和插值，避免欧拉角万向节锁；但网络传输要规范化并处理符号等价（`q` 与 `-q` 表示同一旋转）。
- 角度差要包到 `[-180°, 180°)`，速度和位置积分要乘 `deltaTime`，固定步长物理不要把渲染帧间隔混进去。

## 4. 常见碰撞题

### AABB、OBB 与球体

AABB 测试只需比较三个轴的区间是否重叠，便宜但旋转后包围盒会变松；OBB 更紧但需要坐标轴投影。球体适合粗筛，胶囊体适合角色。工程上常用 broad phase（空间网格、BVH）筛候选，再做 narrow phase（SAT、射线、几何体求交）。

### 射线与平面

射线 `p(t)=o+t·d` 与平面 `n·p + c = 0` 的交点为 `t=-(n·o+c)/(n·d)`。先判断分母接近零，再检查 `t>=0` 和命中距离。面试时要说明浮点误差、背面剔除和最大距离。

## 5. 同步系统的排查顺序

1. 记录客户端输入序号、服务器 tick、快照序号和 RTT。
2. 对比权威位置与本地预测位置，区分逻辑错误、丢包还是渲染插值问题。
3. 对瞬时事件检查幂等键和重复包；对连续状态检查压缩、发送频率和 relevancy。
4. 在高延迟、丢包、切后台、重连和版本不一致下回归。

### 高频追问

#### Q1. 为什么客户端预测后还要回滚重放？

因为客户端立即执行的是猜测，服务器才是权威。收到确认状态后，客户端回到服务器状态，再按确认序号之后的本地输入重放，既修正误差又避免玩家感觉完全“被拉回去”。

#### Q2. 帧同步为什么强调确定性？

所有客户端必须在相同输入序列上得到相同结果。浮点舍入、线程调度、随机数种子和不同物理实现都会破坏确定性，因此常用定点数、固定 tick、确定性随机和严格的执行顺序。
