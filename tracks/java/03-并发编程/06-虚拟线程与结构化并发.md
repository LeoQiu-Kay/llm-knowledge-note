# 虚拟线程与结构化并发

## 30 秒回答

虚拟线程自 JDK 21 成为正式特性，适合大量阻塞式 I/O 的 thread-per-task 模型；它提升的是并发可伸缩性而非单任务速度。结构化并发在 JDK 26 仍是预览 API，应隔离使用并评估升级成本。

## 核心原理

### 虚拟线程调度

JVM 把大量虚拟线程挂载到少量平台线程；阻塞 I/O 时通常卸载并释放载体线程。每个任务创建虚拟线程，不应再把虚拟线程本身池化。

### 资源仍然有限

数据库连接、下游 QPS、内存和文件描述符不会因线程变轻而增加，仍需要 Semaphore、连接池和限流控制并发。

### 结构化并发

StructuredTaskScope 把相关子任务作为一个工作单元管理，统一等待、失败传播、取消和可观测性；截至 JDK 26 为第六次预览，生产应封装在适配层。

## 工程权衡

- 阻塞式技术栈可较低成本采用虚拟线程，CPU 密集任务仍受核心数限制。
- ThreadLocal 数量和内容要审计，海量虚拟线程会放大每线程状态成本。
- 采用预览 API 时要锁定 JDK、启用预览参数并准备版本升级改造。

## 常见故障

1. 把虚拟线程接入无界请求入口，却没有限制数据库并发。
2. 长时间执行 native 或特定阻塞操作造成载体线程受限。
3. 用固定大小池管理虚拟线程，重新引入不必要的排队。
