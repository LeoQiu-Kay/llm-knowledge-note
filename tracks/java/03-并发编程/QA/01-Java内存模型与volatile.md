# Java 内存模型与 volatile · 面试题

## Q1: 请用一分钟说明Java 内存模型与 volatile的核心目标与工作机制。
> 难度 ⭐⭐ ｜ 高频 🔥🔥🔥

Java 内存模型定义线程之间读写共享变量的可见性和有序性。happens-before 是判断读能否看到写的核心规则；volatile 提供可见性和特定顺序约束，但复合读改写仍不具备原子性。

---

## Q2: happens-before的核心机制是什么？
> 难度 ⭐⭐ ｜ 高频 🔥🔥🔥

程序次序、监视器解锁到加锁、volatile 写到读、线程 start/join 等规则建立跨线程可见性；没有 happens-before 的数据竞争结果不可依赖。

---

## Q3: volatile 语义为什么重要，实际如何落地？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥

volatile 写具有释放语义，读具有获取语义，可用于状态发布和停止标记；它不能把 count++ 变成原子操作。

---

## Q4: Java 内存模型与 volatile在工程落地时如何做取舍？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥🔥

单写多读状态可用 volatile，涉及多个变量一致性或复合操作时使用锁或原子类；无锁并不天然更快，高竞争 CAS 自旋可能浪费 CPU；并发正确性先用状态不变量描述，再选择同步原语。

---

## Q5: Java 内存模型与 volatile最常见的故障与排查重点是什么？
> 难度 ⭐⭐⭐⭐ ｜ 高频 🔥🔥

双重检查锁定缺少 volatile，可能发布未完成对象；用 volatile 修饰集合引用，却并发修改普通集合内部状态；忙等循环没有退避或阻塞机制，CPU 被打满。排查时应先用指标和日志确认现象，再缩小到线程、资源、依赖或数据边界。
