# Java 内存模型与 volatile

## 30 秒回答

Java 内存模型定义线程之间读写共享变量的可见性和有序性。happens-before 是判断读能否看到写的核心规则；volatile 提供可见性和特定顺序约束，但复合读改写仍不具备原子性。

## 核心原理

### happens-before

程序次序、监视器解锁到加锁、volatile 写到读、线程 start/join 等规则建立跨线程可见性；没有 happens-before 的数据竞争结果不可依赖。

### volatile 语义

volatile 写具有释放语义，读具有获取语义，可用于状态发布和停止标记；它不能把 count++ 变成原子操作。

### 安全发布

对象应通过 final 字段、锁、volatile 引用、静态初始化或并发容器安全发布，避免其他线程观察到构造中的中间状态。

## 工程权衡

- 单写多读状态可用 volatile，涉及多个变量一致性或复合操作时使用锁或原子类。
- 无锁并不天然更快，高竞争 CAS 自旋可能浪费 CPU。
- 并发正确性先用状态不变量描述，再选择同步原语。

## 常见故障

1. 双重检查锁定缺少 volatile，可能发布未完成对象。
2. 用 volatile 修饰集合引用，却并发修改普通集合内部状态。
3. 忙等循环没有退避或阻塞机制，CPU 被打满。
