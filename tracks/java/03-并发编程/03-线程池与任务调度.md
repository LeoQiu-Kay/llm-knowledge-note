# 线程池与任务调度

## 30 秒回答

线程池通过复用工作线程、队列和拒绝策略控制并发资源。核心不是背参数，而是根据任务 CPU/I/O 特征、下游容量和延迟目标设置有界队列、超时、隔离和监控，防止流量高峰转化为无限积压。

## 核心原理

### 执行流程

ThreadPoolExecutor 依次考虑核心线程、工作队列、最大线程和拒绝策略。无界队列会让 maximumPoolSize 基本失效，并把过载变成长延迟和内存风险。

### 容量估算

CPU 密集型并发接近可用核心数；I/O 任务可更高，但仍受连接池、外部限流和内存约束。应以 Little 定律、压测和下游预算校准。

### 调度与生命周期

ScheduledExecutorService 适合进程内调度，但不提供分布式唯一执行和持久化。服务关闭时要停止接收、等待在途任务并处理中断。

## 工程权衡

- 按业务和依赖隔离线程池，避免一个慢下游拖死全站。
- CallerRuns 可形成背压，但若调用线程是事件循环或关键入口会放大故障。
- 线程池指标至少包含活跃数、队列长度、等待时间、拒绝量和任务耗时。

## 常见故障

1. Executors.newFixedThreadPool 默认无界队列，流量高峰 OOM。
2. 任务阻塞且无超时，工作线程永久占用。
3. 多个线程池总线程数失控，栈内存和上下文切换过高。
