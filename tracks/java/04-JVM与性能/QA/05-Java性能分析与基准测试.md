# Java 性能分析与基准测试 · 面试题

## Q1: 请用一分钟说明Java 性能分析与基准测试的核心目标与工作机制。
> 难度 ⭐⭐ ｜ 高频 🔥🔥🔥

性能优化必须以可重复测量为基础。宏观压测验证端到端容量和尾延迟，JMH 处理 JVM 微基准中的预热、死代码消除和常量折叠；profile 用采样数据寻找真正热点。

---

## Q2: 基准陷阱的核心机制是什么？
> 难度 ⭐⭐ ｜ 高频 🔥🔥🔥

JIT 会消除无副作用结果、折叠常量并根据调用形态优化。JMH 通过 fork、warmup、measurement 和 Blackhole 降低这些干扰。

---

## Q3: 延迟分布为什么重要，实际如何落地？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥

平均值会掩盖排队和暂停，需报告吞吐、并发、P50/P95/P99、错误率和资源使用，并保持测试负载模型接近生产。

---

## Q4: Java 性能分析与基准测试在工程落地时如何做取舍？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥🔥

微基准适合比较局部实现，不能替代真实网络、数据库和 GC 环境；优化目标应来自 SLO 和成本，而不是单个方法纳秒数；每次变更保留基线、环境、JDK 和参数，避免不可复现实验。

---

## Q5: Java 性能分析与基准测试最常见的故障与排查重点是什么？
> 难度 ⭐⭐⭐⭐ ｜ 高频 🔥🔥

在 Debug、低功耗或共享机器上跑基准；只测成功快路径，忽略错误和超时路径；吞吐提高但 P99 和 CPU 成本恶化。排查时应先用指标和日志确认现象，再缩小到线程、资源、依赖或数据边界。
