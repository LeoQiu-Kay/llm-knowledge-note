# Netty 与高性能网络编程

## 30 秒回答

Netty 以事件循环、Channel、Pipeline 和 ByteBuf 封装非阻塞网络编程。少量 EventLoop 处理大量连接，业务阻塞任务必须卸载；ByteBuf 引用计数、背压和连接生命周期是稳定性的关键。

## 核心原理

### EventLoop 模型

Channel 通常固定绑定一个 EventLoop，使同一连接事件串行执行并降低锁需求；在事件循环中阻塞会拖住其负责的所有连接。

### Pipeline 与编解码

入站和出站 Handler 组成处理链，帧解码先解决 TCP 粘包拆包，再进行协议对象转换和业务处理。

### ByteBuf 与背压

池化直接内存减少复制和 GC，但引用计数必须配对释放。写缓冲高低水位和 auto-read 可用于限制慢消费者带来的积压。

## 工程权衡

- CPU 轻且非阻塞逻辑留在 EventLoop，数据库和慢调用转移到受控业务池。
- 零拷贝和池化提升吞吐，也增加生命周期和排查复杂度。
- 连接、请求和下游并发需分别限流。

## 常见故障

1. Handler 中同步调用慢 RPC，事件循环延迟飙升。
2. ByteBuf 泄漏导致直接内存耗尽。
3. 协议未做长度上限，恶意帧造成内存放大。
