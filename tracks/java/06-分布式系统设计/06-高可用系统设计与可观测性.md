# 高可用系统设计与可观测性

## 30 秒回答

高可用从消除单点、限制故障域、自动恢复和可验证演练入手。可观测性用指标发现趋势、日志解释事件、Trace 还原调用链，并以 SLI/SLO 和错误预算决定发布速度与治理优先级。

## 核心原理

### 冗余与故障域

实例、机架、可用区和区域是不同故障域；冗余只有在依赖、数据和流量路径真正隔离时才有效。

### SLI 与错误预算

可用性、正确率、延迟和新鲜度等 SLI 应从用户体验定义。错误预算把可靠性目标转换为发布与治理决策。

### 三类遥测

Metrics 适合聚合和告警，Logs 适合离散上下文，Traces 适合跨服务因果链。统一 correlation ID、时间和版本信息才能关联。

## 工程权衡

- 多活提升容灾能力，也显著增加数据一致性和运维复杂度。
- 告警基于用户影响和燃烧率，减少无行动价值的噪声。
- 混沌演练从可控依赖、限流和回滚开始，逐步扩大故障范围。

## 常见故障

1. 只有实例健康监控，没有业务成功率。
2. 备用链路长期不演练，真正故障时不可用。
3. 日志、指标和 Trace 使用不同请求标识，无法关联。
