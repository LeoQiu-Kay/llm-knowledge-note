# 服务发现、配置中心与 API 网关 · 面试题

## Q1: 请用一分钟说明服务发现、配置中心与 API 网关的核心目标与工作机制。
> 难度 ⭐⭐ ｜ 高频 🔥🔥🔥

服务发现维护实例与健康状态，配置中心分发运行参数，API 网关承担统一入口的路由、认证、限流和协议转换。它们是控制面能力，故障时应尽量让数据面继续使用最近可用状态。

---

## Q2: 发现与健康检查的核心机制是什么？
> 难度 ⭐⭐ ｜ 高频 🔥🔥🔥

客户端或代理从注册中心获取实例列表并负载均衡；健康检查需区分进程存活、可接流量和关键依赖状态。

---

## Q3: 配置发布为什么重要，实际如何落地？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥

配置需要版本、校验、灰度、审计和回滚。监听更新时先构建新快照并原子替换，避免读取半更新状态。

---

## Q4: 服务发现、配置中心与 API 网关在工程落地时如何做取舍？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥🔥

控制面短暂不可用时使用本地缓存继续服务；配置动态化越多，测试状态空间越大，应限制高风险开关；网关集中治理带来统一性，也形成容量和故障关键点。

---

## Q5: 服务发现、配置中心与 API 网关最常见的故障与排查重点是什么？
> 难度 ⭐⭐⭐⭐ ｜ 高频 🔥🔥

健康检查只看端口，故障实例持续接流量；配置全量同时推送导致所有实例一起重连；网关重试写请求造成重复副作用。排查时应先用指标和日志确认现象，再缩小到线程、资源、依赖或数据边界。
