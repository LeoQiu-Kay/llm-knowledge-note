# SQL 优化与执行计划

## 30 秒回答

SQL 优化从减少扫描、回表、排序、临时结果和网络传输入手。执行计划展示访问路径和估算，实际执行统计验证估算偏差；索引设计必须结合数据分布、查询组合和写入成本。

## 核心原理

### 访问路径

关注驱动表、索引选择、连接算法、估算行数和过滤比例。使用索引不等于高效，低选择性范围和大量回表仍可能昂贵。

### 排序与聚合

ORDER BY、GROUP BY、DISTINCT 可能产生临时表和额外排序；合适联合索引、预聚合或分阶段查询可减少工作量。

### 统计信息与参数

优化器依赖统计信息估算基数，数据倾斜、相关列和参数值会让估算失真；需对比实际行数并维护统计。

## 工程权衡

- 先优化高频和高总成本 SQL，而不是只看单次最慢。
- 覆盖索引提升读性能但增加写放大和缓存占用。
- 复杂 SQL 拆分可提高可控性，也可能增加网络往返和一致性窗口。

## 常见故障

1. 隐式类型转换导致索引失效。
2. 深分页 OFFSET 扫描并丢弃大量行。
3. 测试数据分布过于均匀，线上计划完全不同。
