# SQL 优化与执行计划 · 面试题

## Q1: 请用一分钟说明SQL 优化与执行计划的核心目标与工作机制。
> 难度 ⭐⭐ ｜ 高频 🔥🔥🔥

SQL 优化从减少扫描、回表、排序、临时结果和网络传输入手。执行计划展示访问路径和估算，实际执行统计验证估算偏差；索引设计必须结合数据分布、查询组合和写入成本。

---

## Q2: 访问路径的核心机制是什么？
> 难度 ⭐⭐ ｜ 高频 🔥🔥🔥

关注驱动表、索引选择、连接算法、估算行数和过滤比例。使用索引不等于高效，低选择性范围和大量回表仍可能昂贵。

---

## Q3: 排序与聚合为什么重要，实际如何落地？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥

ORDER BY、GROUP BY、DISTINCT 可能产生临时表和额外排序；合适联合索引、预聚合或分阶段查询可减少工作量。

---

## Q4: SQL 优化与执行计划在工程落地时如何做取舍？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥🔥

先优化高频和高总成本 SQL，而不是只看单次最慢；覆盖索引提升读性能但增加写放大和缓存占用；复杂 SQL 拆分可提高可控性，也可能增加网络往返和一致性窗口。

---

## Q5: SQL 优化与执行计划最常见的故障与排查重点是什么？
> 难度 ⭐⭐⭐⭐ ｜ 高频 🔥🔥

隐式类型转换导致索引失效；深分页 OFFSET 扫描并丢弃大量行；测试数据分布过于均匀，线上计划完全不同。排查时应先用指标和日志确认现象，再缩小到线程、资源、依赖或数据边界。
