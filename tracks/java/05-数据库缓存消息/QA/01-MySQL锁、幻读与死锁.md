# MySQL 锁、幻读与死锁 · 面试题

## Q1: 请用一分钟说明MySQL 锁、幻读与死锁的核心目标与工作机制。
> 难度 ⭐⭐ ｜ 高频 🔥🔥🔥

InnoDB 通过记录锁、间隙锁和 next-key lock 协调当前读与写入；锁定范围取决于索引和查询条件。死锁是并发事务形成等待环，数据库会回滚受害者，应用仍需缩短事务、统一加锁顺序并安全重试。

---

## Q2: 锁定读与索引的核心机制是什么？
> 难度 ⭐⭐ ｜ 高频 🔥🔥🔥

UPDATE、DELETE 和 FOR UPDATE 属于当前读，会在访问的索引记录或范围上加锁；缺少合适索引可能扫描并锁住远超预期的数据。

---

## Q3: 间隙与幻读为什么重要，实际如何落地？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥

可重复读下 next-key lock 把记录和前方间隙结合，限制范围内插入；快照读主要由 MVCC 提供一致视图。

---

## Q4: MySQL 锁、幻读与死锁在工程落地时如何做取舍？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥🔥

统一业务资源排序后加锁，降低环路概率；失败重试必须有次数、退避和幂等，不能无限重放整个请求；热点行可通过分片计数、队列化或乐观并发降低竞争。

---

## Q5: MySQL 锁、幻读与死锁最常见的故障与排查重点是什么？
> 难度 ⭐⭐⭐⭐ ｜ 高频 🔥🔥

无索引更新扩大锁范围；事务内用户交互或 RPC 导致长时间持锁；捕获死锁后立即无退避重试，引发重试风暴。排查时应先用指标和日志确认现象，再缩小到线程、资源、依赖或数据边界。
