# Redis 数据结构与持久化 · 面试题

## Q1: 请用一分钟说明Redis 数据结构与持久化的核心目标与工作机制。
> 难度 ⭐⭐ ｜ 高频 🔥🔥🔥

Redis 以单线程命令执行语义和高效内存数据结构提供低延迟访问，字符串、哈希、集合、有序集合、Stream 等适合不同模型。RDB、AOF 和复制解决不同恢复目标，不能把缓存默认当作永久可靠数据库。

---

## Q2: 结构选择的核心机制是什么？
> 难度 ⭐⭐ ｜ 高频 🔥🔥🔥

Hash 适合对象字段，Set 适合去重和集合运算，Sorted Set 适合排名和时间序列索引，Stream 提供消费组和待确认消息。结构要匹配访问模式。

---

## Q3: 过期与淘汰为什么重要，实际如何落地？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥

过期由惰性删除和定期采样共同完成；达到 maxmemory 后按策略淘汰。大量同一时刻过期会造成负载尖峰。

---

## Q4: Redis 数据结构与持久化在工程落地时如何做取舍？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥🔥

缓存实例与持久状态实例最好隔离容量和淘汰策略；大 key、热 key 和高基数结构要提前分片或归档；Lua/事务适合短小原子逻辑，长脚本会阻塞其他命令。

---

## Q5: Redis 数据结构与持久化最常见的故障与排查重点是什么？
> 难度 ⭐⭐⭐⭐ ｜ 高频 🔥🔥

KEYS 或大范围 Lua 阻塞实例；超大 Hash 删除引发延迟抖动；以为写入返回成功就等同跨机房永久持久化。排查时应先用指标和日志确认现象，再缩小到线程、资源、依赖或数据边界。
