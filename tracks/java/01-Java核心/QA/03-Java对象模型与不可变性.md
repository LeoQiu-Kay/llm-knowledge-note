# Java 对象模型与不可变性 · 面试题

## Q1: 请用一分钟说明Java 对象模型与不可变性的核心目标与工作机制。
> 难度 ⭐⭐ ｜ 高频 🔥🔥🔥

Java 对象以类定义行为和状态，引用变量保存的是对象引用而非对象本身。正确设计需要区分身份与值语义，遵守 equals/hashCode 契约，并通过 final 字段、防御性拷贝和受控构造建立不可变对象；不可变性能够显著降低并发共享和缓存键设计的复杂度。

---

## Q2: 身份与值语义的核心机制是什么？
> 难度 ⭐⭐ ｜ 高频 🔥🔥🔥

默认 Object.equals 比较身份；值对象应按业务字段比较。重写 equals 时要满足自反、对称、传递、一致和非空性，并同步重写 hashCode，避免对象在 HashMap、HashSet 中出现查找和去重错误。

---

## Q3: 不可变对象为什么重要，实际如何落地？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥

不可变对象在构造完成后状态不再变化，通常使用 final 类或限制继承、private final 字段、不暴露可变内部对象，并在构造和 getter 边界做防御性拷贝。

---

## Q4: Java 对象模型与不可变性在工程落地时如何做取舍？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥🔥

值对象适合不可变设计，实体对象则通常需要稳定身份和受控状态迁移，不能把两者的 equals 语义混用；防御性拷贝提高安全性但会增加分配，应优先缩小可变状态边界，而不是到处深拷贝；record 适合数据载体，但字段引用指向的集合仍可能可变，不能把语法简洁误认为深度不可变。

---

## Q5: Java 对象模型与不可变性最常见的故障与排查重点是什么？
> 难度 ⭐⭐⭐⭐ ｜ 高频 🔥🔥

把可变字段用于 HashMap key，字段变化后再也无法按新旧值正确定位；equals 使用可变集合或关联对象，导致递归、懒加载和性能问题；getter 直接返回内部 List，调用方绕过校验修改对象状态。排查时应先用指标和日志确认现象，再缩小到线程、资源、依赖或数据边界。
