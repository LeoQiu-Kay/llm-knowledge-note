# 异常处理与资源管理 · 面试题

## Q1: 请用一分钟说明异常处理与资源管理的核心目标与工作机制。
> 难度 ⭐⭐ ｜ 高频 🔥🔥🔥

异常用于表达无法在当前层正常完成的控制流。工程上要区分可恢复业务错误、参数错误和系统故障，保持异常因果链，在正确边界转换协议错误；文件、连接和锁等资源必须用 try-with-resources 或 finally 确保释放。

---

## Q2: 受检与非受检异常的核心机制是什么？
> 难度 ⭐⭐ ｜ 高频 🔥🔥🔥

受检异常强制调用方处理，适合确实可恢复且需要显式决策的场景；非受检异常适合编程错误和无法局部恢复的失败。关键不是类别本身，而是调用方是否有合理恢复动作。

---

## Q3: 异常链与边界转换为什么重要，实际如何落地？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥

捕获异常时应保留 cause，并在领域、应用、接口边界转换为稳定错误码。日志只在能够增加上下文或最终处理的层记录，避免同一异常被重复打印。

---

## Q4: 异常处理与资源管理在工程落地时如何做取舍？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥🔥

批处理可选择逐项记录失败继续执行，交易链路则通常应快速失败并回滚；错误响应要对用户稳定、对日志可诊断，同时避免泄露堆栈和内部路径；重试只针对可判定的瞬时故障，并与超时、退避和幂等一起设计。

---

## Q5: 异常处理与资源管理最常见的故障与排查重点是什么？
> 难度 ⭐⭐⭐⭐ ｜ 高频 🔥🔥

catch Exception 后吞掉异常，调用方误以为成功；只记录 message 不保留 cause，丢失真正堆栈；手工 close 在中途异常时未执行，连接池逐渐耗尽。排查时应先用指标和日志确认现象，再缩小到线程、资源、依赖或数据边界。
