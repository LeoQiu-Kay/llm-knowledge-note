## Q1: 当代 LLM 的"默认模板"是什么？为什么大家都收敛到这个组合？
> 难度 ⭐⭐ ｜ 高频 🔥🔥🔥

**默认模板**（LLaMA 定义、几乎所有开源模型沿用）：

$$\text{Decoder-only} + \text{Pre-RMSNorm} + \text{RoPE} + \text{SwiGLU} + \text{GQA}$$

每一项的"为什么"：

| 选择 | 理由 |
|---|---|
| Decoder-only | 生成任务最直接、KV Cache 友好、Encoder-Decoder 无明显优势 |
| Pre-Norm（LN 在残差路径外） | 训练稳定性远胜 Post-Norm，深层不崩 |
| RMSNorm | 比 LayerNorm 少一个均值，计算快 ~10%，效果近似 |
| RoPE | 相对位置 + 可外推，比 ALiBi/绝对位置都强 |
| SwiGLU | 门控 + 平滑，效果优于 ReLU/GELU |
| GQA（GQA = Grouped-Query Attention，多 query 头共享 KV 头） | KV Cache 减少数倍，效果几乎无损 |

**追问：为什么不用 Encoder-Decoder（如 T5）？** 训练数据规模一上来，Decoder-only 在生成、In-context Learning、扩展性上全面超越；T5 的双向 encoder 优势主要在判别任务，在 LLM 时代不再是瓶颈。

## Q2: LLaMA-1 / 2 / 3 的关键差异是什么？LLaMA-3 为什么把词表扩到 128K？
> 难度 ⭐⭐ ｜ 高频 🔥🔥

| 维度 | LLaMA-1 | LLaMA-2 | LLaMA-3 |
|---|---|---|---|
| 数据 | 1.4T | 2T | **15T**（7.5×） |
| 序列长 | 2K | 4K | 8K（可扩 128K） |
| 词表 | 32K SP | 32K SP | **128K**（TikToken-like） |
| 注意力 | MHA | GQA（仅 70B） | **GQA 全部** |

**LLaMA-3 词表 4× 的理由**：
1. **多语种效率**：32K 词表主要是英文，中文一个字常被切成 2-3 token；128K 后中文/日文等编码效率显著提升
2. **压缩率提升**：同样文本 token 数减少 → 训练/推理省钱
3. **表达粒度**：128K 让常见短语成为单 token，模型更易学习语义边界

**代价**：embedding/lm_head 参数变大（128K × hidden ≈ 多几百 M 参数），但相对总参数可忽略。

**追问：为什么 LLaMA-3 数据上到 15T 远超 Chinchilla 最优？** Chinchilla（约 20 tokens/参数）是"训练 FLOP 受限"下的最优，而 LLaMA-3 追求**推理效率**——同样推理成本（参数固定）下，多喂数据持续涨点，是"过训练"换推理便宜。

## Q3: GQA / MQA / MHA / MLA 四种注意力的对比？为什么 GQA 成为主流？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥🔥

| 机制 | KV 头数 | KV Cache | 效果 | 代表 |
|---|---|---|---|---|
| **MHA**（Multi-Head） | = Q 头数 | 大 | 最强 | LLaMA-1、GPT-3 |
| **MQA**（Multi-Query） | 1 | 极小 | 略损 | PaLM、Falcon |
| **GQA**（Grouped-Query） | 中（如 Q 32 / KV 8） | 中 | ≈ MHA | LLaMA-2/3、Qwen-2/3、Mistral |
| **MLA**（Multi-head Latent Attention，低秩压缩 KV） | — | **最小** | 略优 MHA | DeepSeek-V2/V3 |

**为什么 GQA 主流**：
- MHA：KV Cache 太大，长序列推理瓶颈
- MQA：太极端，长上下文效果下降明显
- GQA：在 KV Cache 和效果之间取得最佳平衡，**零成本切换**（MHA 权重平均得到）
- MLA：效果更好但实现复杂，目前只 DeepSeek 在用

**追问：MLA 比 GQA 强在哪？** MLA 把 K/V 压缩到低秩 latent（典型 512 维），再投影回多头；KV Cache 只存这个 latent，比 GQA 还小一半多，且效果略好（DeepSeek-V2 论文实验）。代价是矩阵乘法多一步、需配合 decoupled RoPE。

## Q4: DeepSeek 系列的 5 个标志性贡献是什么？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥🔥

| 贡献 | 模型 | 一句话总结 |
|---|---|---|
| **MLA** | V2 | 低秩压缩 KV，比 GQA 还小 |
| **细粒度 + 共享专家 MoE** | V2/V3 | 256 路由专家 + 1 共享专家，组合更灵活 |
| **FP8 训练** | V3 | 大规模生产级 FP8（之前都 BF16） |
| **GRPO**（Group Relative Policy Optimization） | R1 | 去掉 Critic，组内相对优势，省一倍显存 |
| **R1-Zero**（纯 RL） | R1 | 不要 SFT 冷启动，纯规则奖励 RL 触发推理涌现 |

**为什么这 5 个都重要**：每个都解决了 LLM 训练/推理的实际瓶颈——MLA 解 KV Cache、MoE 解能力/成本、FP8 解训练成本、GRPO 解 RL 显存、R1-Zero 颠覆"必须 SFT"的认知。

**追问：DeepSeek-V3 总参/激活/专家配比是多少？** 671B 总参，激活 37B；256 路由专家 + 1 共享专家，每 token 激活 8 个路由 + 1 共享。激活比 ~5.5%，是当前主流 MoE 最稀疏配置之一。

## Q5: Mixtral 8×7B 的"8×7B"到底是什么意思？总参数和激活参数分别多少？
> 难度 ⭐⭐ ｜ 高频 🔥🔥

**易误解**：8×7B ≠ 56B 总参。

实际是：
- 每层有 8 个 FFN 专家
- 每个 FFN 大小 ≈ 7B 模型的 FFN（不是整个 7B 模型）
- **非 FFN 部分（Attention/Embedding）所有专家共享**
- **总参数 47B**（不是 56B），**激活参数 13B**（每 token 选 2 个专家）

**为什么不是 56B**：MoE 只把 FFN 切成专家，Attention 等部分不重复；而 FFN 约占 Transformer 参数的 2/3。

**追问：Mixtral 为什么效果远超同尺寸 LLaMA-2-13B（同等激活参数）？** 总参数 47B 提供了远超 13B 的"容量"，但每 token 只激活 13B 算力。这就是 MoE 的"免费午餐"——能力按总参，FLOP 按激活参数。

## Q6: Mistral SWA（滑动窗口注意力）的原理和有效感受野？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥

**SWA**（Sliding Window Attention，滑动窗口注意力）：每个 token 只看前 $W$ 个（Mistral 7B 中 $W = 4096$）。

**有效感受野**：单层 $W$，**$L$ 层堆叠后感受野 ≈ $L \cdot W$**。

类比 CNN：单层 3×3 卷积感受野 3，多层堆叠扩大。Mistral 7B 32 层 × 4K 窗 ≈ **理论 128K 有效感受野**（实际约 32K 内信息流通良好）。

**优势**：
- 计算从 $O(n^2)$ 降到 $O(nW)$
- KV Cache 上限固定（只需存 $W$ 个）
- 实现简单（FlashAttention 直接支持）

**劣势**：远距离信息只能通过多层"接力"传递，质量不如全 attention。

**追问：SWA 和 Longformer 的区别？** Longformer 是 SWA + 全局 token（让少数 token 看全局）；Mistral SWA 不加全局 token，纯滑窗。

## Q7: 闭源 vs 开源、Dense vs MoE 怎么选？
> 难度 ⭐⭐ ｜ 高频 🔥🔥

**闭源 vs 开源**：

| 维度 | 闭源（GPT-4 / Claude / Gemini） | 开源（LLaMA / Qwen / DeepSeek） |
|---|---|---|
| 能力 | 顶尖 | 接近（DeepSeek-V3、Qwen-2.5 已贴近 GPT-4） |
| 部署 | 只 API | 可私有部署 |
| 微调 | 受限 | 完全可控 |
| 数据合规 | 数据出域 | 可内网 |
| 成本 | 按 token 付费 | GPU 摊销 |

**Dense vs MoE**：

| 场景 | 推荐 |
|---|---|
| 边缘/小服务（显存紧） | Dense（MoE 装不下所有专家） |
| 云端大流量 | MoE（同总参算力小，吞吐高） |
| 微调 | Dense 简单；MoE 需考虑专家不均 |
| 蒸馏目标 | Dense 容易；MoE 难 |

**追问：什么时候 MoE 不如 Dense？** ① 单机显存放不下所有专家（需 offload，速度反而慢）；② batch 极小（路由开销显著）；③ 极短序列（FFN 占比小，MoE 优势不明显）。

## Q8: Gemini 1.5 的 1M 上下文怎么做到的？Claude / GPT 长上下文路线有何不同？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥

**Gemini 1.5**：
- **Ring Attention**：训练时序列分到多卡，环形传 K/V，每卡都"看过"全部
- 工程层面 TPU 巨大并行
- 1M context 实测 NIAH（Needle in a Haystack）召回率高

**Claude（200K）**：
- 闭源细节少，普遍推测 YaRN/类似 RoPE 扩展 + 长数据继续训
- 工程上 Anthropic 强调"中间也准"（lost in the middle 改善）

**GPT-4 系（128K~）**：
- OpenAI 未披露，业界推测稀疏 attention + 长数据训练

**共同点**：
1. 训练时序列加长（4K → 32K → 128K → 1M 渐进）
2. 位置编码扩展（YaRN/NTK 或自研）
3. KV Cache 优化（GQA/MLA/量化）
4. 评测都跑 NIAH + RULER + LongBench

**追问：1M context 实际有多大用？** NIAH 等"针在草堆"任务表现好，但真实长任务（长代码理解、多文档推理）效果远不如名义长度暗示——"有效长度"通常是名义长度的 1/4~1/2。

## Q9: 为什么现代 LLM 都用 RMSNorm 而不是 LayerNorm？
> 难度 ⭐⭐ ｜ 高频 🔥🔥

**LayerNorm**：

$$y = \frac{x - \mu}{\sqrt{\sigma^2 + \epsilon}} \cdot \gamma + \beta$$

**RMSNorm**：

$$y = \frac{x}{\sqrt{\text{mean}(x^2) + \epsilon}} \cdot \gamma$$

**差异**：
- RMSNorm **去掉了减均值** $\mu$ 和偏置 $\beta$
- 只做"按 RMS 缩放"
- 计算量减少 ~10-20%

**为什么效果几乎不损**：实验发现 LayerNorm 的"重新中心化"贡献远小于"重新缩放"；去掉均值不损失表达力。

**追问：Pre-Norm 和 Post-Norm 的区别？为什么现代都用 Pre-Norm？** Post-Norm 在残差之后做 LN，深层训练不稳定（梯度被 LN 切断）；Pre-Norm 在残差之前做 LN，残差路径"全程通畅"，梯度直通，深层稳定。代价是输出方差累积，最后需额外 LN。

## Q10: 国产模型现在到了什么水平？典型代表？
> 难度 ⭐⭐ ｜ 高频 🔥🔥

| 系列 | 厂商 | 特点 |
|---|---|---|
| **Qwen** | 阿里 | 中文 + 多尺寸 + 多模态最完整；3 代 0.6B-235B 全覆盖 |
| **DeepSeek** | 深度求索 | MLA + MoE + FP8；V3/R1 多项基准接近或超 GPT-4 |
| **GLM** | 智谱 | 早期 PrefixLM，GLM-4 改回 Decoder-only |
| **Baichuan** | 百川 | LLaMA-like，中等规模 |
| **Yi** | 零一万物 | 类 LLaMA-2，长上下文优秀 |
| **InternLM** | 上海 AI Lab | 长文本 + 工具调用 |
| **Kimi** | Moonshot | 200K+ 长上下文标杆 |
| **MiniMax** | MiniMax | abab 系列、多模态 |

**整体水平**：
- 中文场景：国产明显占优（Qwen/DeepSeek/GLM）
- 通用能力：DeepSeek-V3 / Qwen-2.5 已在多项基准接近或超越 GPT-4
- 推理路线：DeepSeek-R1 是 GPT-o1 之外最重要的开源推理模型

**追问：DeepSeek-R1 为什么轰动？** ① 完全开源（包括权重和论文细节）；② R1-Zero 证明**纯 RL 也能涌现推理**（不需 SFT 冷启动）；③ GRPO 比 PPO 省一半显存；④ 性能对标 o1，成本极低。
