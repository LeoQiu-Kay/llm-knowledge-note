## Q1: VLM（视觉语言模型）的基本架构是什么？三件套各负责什么？
> 难度 ⭐⭐ ｜ 高频 🔥🔥🔥

**VLM**（Vision-Language Model）三件套：

```
图像 → [视觉编码器] → 视觉特征 → [连接器] → 视觉 token
                                                ↓
                  拼接到文本 token 后 → [LLM] → 输出文本
```

| 组件 | 职责 | 典型选择 |
|---|---|---|
| **视觉编码器**（Vision Encoder） | 把图像编码为视觉特征 | CLIP-ViT、SigLIP、InternViT |
| **连接器**（Connector / Projector） | 把视觉特征映射到 LLM 输入空间（对齐维度 + 语义） | MLP、Q-Former、Linear |
| **LLM** | 处理文本 + 视觉 token，生成文本 | LLaMA、Qwen 等 |

**关键约束**：视觉 token 和文本 token 必须在**同一 embedding 空间**，LLM 才能"理解"图像。这是连接器的核心任务。

**追问：为什么不端到端从图像像素到文本训一个模型？** ① 视觉信号海量、训练昂贵；② 已有强 LLM 和强视觉编码器可复用；③ 拼接式可独立升级 LLM 和编码器。**原生多模态**（GPT-4o）才走端到端路线，但训练代价巨大。

## Q2: CLIP 是什么？为什么是 VLM 视觉编码器的默认选择？
> 难度 ⭐⭐ ｜ 高频 🔥🔥🔥

**CLIP**（Contrastive Language-Image Pre-training，OpenAI 2021）：用**图文对比学习**预训练。

**训练目标**：
- 一个 batch 内 $N$ 对 (图像, 文本)
- 视觉编码器 + 文本编码器分别编码
- 让"匹配的图文"特征相似度高，"不匹配"低
- 对比损失（InfoNCE）

**为什么对 LLM 友好**：
- 视觉特征**已对齐到文本语义空间**——同一张猫图和"a cat"的特征已在同一区域
- LLM 接 CLIP 特征几乎"开箱即用"
- 预训练数据规模大（4 亿图文对）

**主流变体**：

| 编码器 | 改进 |
|---|---|
| **CLIP-ViT** | OpenAI 原版 |
| **SigLIP**（Google） | Sigmoid 替代 Softmax，batch 小也能训好 |
| **EVA-CLIP** | CLIP 训练 + MIM 改进，效果更强 |
| **DINOv2** | 自监督（无文本对齐），细粒度强 |
| **InternViT** | 上海 AI Lab，可扩展到 6B |

**追问：DINOv2 不和文本对齐，为什么也能用？** DINOv2 视觉特征"质量高"但不在语义空间，需要 connector 做更重的语义对齐——通常配 **Q-Former** 或更深 MLP。LLaVA-Next 等会混合 CLIP + DINOv2 取长补短。

## Q3: 连接器（Connector）有哪几种？MLP 和 Q-Former 怎么选？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥🔥

| 形式 | 思路 | 代表 | 视觉 token 数 |
|---|---|---|---|
| **MLP Projector** | 2-3 层 MLP 直接映射 | LLaVA | 多（不变） |
| **Linear** | 单层线性 | Qwen-VL 早期 | 多 |
| **Q-Former** | 小 Transformer + 可学 query token，cross-attention 抽取 | BLIP-2 | 少（如 32） |
| **Resampler** | 类似 Q-Former，固定输出 token 数 | Flamingo | 少 |

**MLP vs Q-Former 核心权衡**：

| 维度 | MLP | Q-Former |
|---|---|---|
| 视觉 token 数 | 保持原数（如 576） | 压缩到少数（如 32） |
| 信息保真 | 高 | 损失 |
| 占用 LLM context | 多 | 少 |
| 训练难度 | 简单 | 难（query 难学好） |
| 当前主流 | **是**（LLaVA / Qwen） | 减少（BLIP-2 后渐少） |

**经验结论**：**MLP 简单粗暴但效果好**。LLaVA-1.5 证明 MLP > Q-Former 在大多数任务上。Q-Former 在 token 预算严格时仍有价值。

**追问：视觉 token 数为什么影响 context？** 224×224 / patch 14 → 16×16 = 256 token；336 分辨率 → 576 token；动态分辨率 + 多图可飙升到几千。这些都占用 LLM 的有限 context length，长文本+多图任务很快爆。

## Q4: 动态分辨率（AnyRes）是什么？解决什么问题？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥

**问题**：传统 CLIP 固定 224×224 输入：
- 高分辨率图片被压缩 → 细节丢失（OCR、小物体识别差）
- 不同长宽比图片被强行 resize → 形变

**AnyRes（LLaVA-Next）**：
1. 把高分辨率图像**切成多个 patch**（如 4 个 336×336）
2. 每个 patch 独立通过 CLIP 编码
3. **再加一个全局缩略图**（整体下采样）
4. 拼接所有 token 给 LLM

**优势**：
- 保留高分辨率细节
- 支持任意长宽比
- 缩略图提供全局上下文

**Qwen2-VL 的"原生动态分辨率"**：
- 不切块，直接让 ViT 处理任意尺寸（patch 数动态）
- 配合 **M-RoPE**（多维 RoPE，编码图像 2D 位置）
- 更优雅，但实现复杂

**追问：动态分辨率为什么对 OCR 重要？** OCR 需要识别小字体，224 分辨率下字符可能只有几个像素；高分辨率切块后每个字符占 10+ 像素，识别率显著提升。Qwen2.5-VL OCR 强很大程度归功于此。

## Q5: VLM 训练为什么是"三阶段"？为什么先冻结 LLM？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥🔥

**三阶段流程**：

### Stage 1：模态对齐（Pre-training）

- 数据：大量图文对（如 LAION-5B 子集）
- 训练对象：**只 connector**
- LLM 和视觉编码器：**冻结**
- 目标：让 connector 学会"翻译"视觉特征到 LLM 空间

### Stage 2：视觉-语言联合预训练

- 数据：更高质量的图文混合数据
- 训练对象：**connector + 视觉编码器后几层**（部分解冻）
- LLM：仍可冻结或部分解冻

### Stage 3：指令微调（SFT）

- 数据：多模态指令（如 LLaVA-Instruct-150K）
- 训练对象：**端到端**全可训
- 目标：学会对话、遵循指令

**为什么先冻结 LLM**：
1. **保护 LLM 的语言能力**：随机的视觉信号会破坏 LLM 已有的语言表示
2. **资源效率**：只训 connector（几百 M 参数）比训整个 LLM（几十 B）快几十倍
3. **避免灾难性遗忘**：LLM 的预训练知识不被覆盖

**追问：能不能直接 Stage 3 端到端训？** 可以但效果差——connector 还没对齐就端到端训，视觉信号会像噪声一样扰乱 LLM。**先对齐再 SFT 是工程经验最优解**。

## Q6: LLaVA 和 Qwen-VL 系列的演进和差异？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥

**LLaVA 系列**：

| 版本 | 关键变化 |
|---|---|
| LLaVA-1.0 | CLIP-ViT + 线性 projection + Vicuna；定义两阶段训练范式 |
| LLaVA-1.5 | MLP projection（替线性） + 更高分辨率 + 更多任务数据 |
| **LLaVA-Next（1.6）** | **AnyRes**（动态分辨率，切块） |
| LLaVA-OneVision | 多图、视频统一 |

**Qwen-VL 系列**：

| 版本 | 关键变化 |
|---|---|
| Qwen-VL | CLIP-ViT + 单层 cross-attention 压缩到 256 token，支持中文 |
| **Qwen2-VL** | **原生动态分辨率**（不切块）+ **M-RoPE**（2D 位置编码）+ 视频 |
| Qwen2.5-VL | 增强 OCR、文档理解、Agent（解析 UI 截图） |

**核心差异**：

| 维度 | LLaVA | Qwen-VL |
|---|---|---|
| 连接器 | MLP | 早期 cross-attn，后期升级 |
| 动态分辨率 | AnyRes（切块） | 原生（不切块） |
| 中文 | 一般 | 强 |
| 开源完整度 | 高 | 高 |
| 视频/Agent | 较弱 | 强 |

**追问：M-RoPE 是什么？** Multi-dimensional RoPE，把 RoPE 从 1D 位置扩展到处理图像的 2D（行/列）和视频的 3D（时/行/列）位置。让模型理解视觉 token 的空间结构而非"flatten 后的一维序列"。

## Q7: 原生多模态（GPT-4o / Gemini）vs 拼接式（LLaVA / Qwen-VL）的区别？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥

| 维度 | 拼接式（Stitched） | 原生多模态（Native） |
|---|---|---|
| 训练 | 训好的视觉编码器 + 训好的 LLM + projection 桥接 | 从预训练阶段就同时处理多模态 |
| 模态融合 | 浅（在 LLM 输入层） | 深（贯穿全部层） |
| 模态范围 | 主要图像（音频/视频后加） | 视觉/音频/文本统一 tokenization |
| 输入输出 | 通常输入多模态、输出文本 | 任意模态输入输出（包括音频生成） |
| 延迟 | 较高（多组件串行） | 低（端到端优化） |
| 训练数据 | 易拼凑 | 难（需多模态对齐数据） |
| 计算 | 中 | 大 |
| 代表 | LLaVA、Qwen-VL、InternVL | GPT-4o、Gemini、Chameleon、Janus |

**原生的优势**：
- **模态间深度融合**：音频和图像不只在最后一层合，全程交互
- **任意输入输出**：可直接生成图像/音频
- **延迟低**：GPT-4o 实时语音对话靠的就是这个

**为什么开源还少**：训练数据稀缺（图音文对齐数据少）、训练成本巨大、工程复杂。

**追问：Chameleon 怎么把图像变成 token？** 用 VQ-VAE（向量量化自编码器）把图像离散化为 token，和文本 token 共享词表（如文本 32K + 图像 8K），LLM 用统一的 next-token prediction 训练。生成时 LLM 直接输出图像 token，再解码回像素。

## Q8: 视频理解怎么做？长视频帧数爆炸怎么解决？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥

**朴素方法**：
- 抽关键帧 → 每帧独立编码 → 拼到 LLM
- **问题**：时序信息丢失、长视频帧数爆 context

**改进**：

| 方法 | 思路 | 代表 |
|---|---|---|
| **时序 Attention** | 在帧间加 attention | TimeSformer |
| **视频专用编码器** | ViViT、VideoMAE | InternVideo |
| **Temporal Q-Former** | Q-Former + 时序建模 | Video-LLaVA |
| **采样策略** | 均匀采样 / 自适应（关键帧检测） | 多数 VLM |
| **2D + 时序位置编码** | M-RoPE（时间维 + 空间维） | Qwen2-VL |

**长视频的 trick**：
- 每帧 token 大幅压缩（如每帧只留 64 个 token）
- 关键事件附近密集采样、其他稀疏
- 分层处理（先 coarse 后 fine）

**典型工作**：VideoLLaMA、Video-LLaVA、InternVideo、Qwen2-VL（多帧 + M-RoPE）。

**追问：1 小时视频怎么处理？** 1 小时 ≈ 90000 帧，全送进 LLM 完全不可能。实际做法：① 1 FPS 采样 → 3600 帧；② 每帧压到 16-32 token → ~10 万 token；③ 配合长上下文 LLM。或更激进：分段总结后拼总结。

## Q9: 多模态评测有哪些？分别测什么？
> 难度 ⭐⭐ ｜ 高频 🔥

| Benchmark | 类型 |
|---|---|
| **MMMU** | 大学级多模态推理（横跨数学/物理/医学等） |
| **MMBench** | 综合，分能力等级（分类、推理、OCR 等） |
| **MathVista** | 视觉数学（图表、几何） |
| **DocVQA** | 文档理解（PDF、表格） |
| **OCRBench** | OCR 能力 |
| **MME** | 14 个子任务，覆盖感知和认知 |
| **MM-Vet** | 6 个能力维度（识别、知识、空间等） |
| **Video-MME** | 视频理解 |

**评估建议**：
- 通用能力 → MMMU + MMBench
- OCR/文档 → DocVQA + OCRBench
- 推理 → MathVista
- 视频 → Video-MME

**典型陷阱**：
- **基准过拟合**：开源 VLM 在某些榜单刷分严重，实际能力差
- **答案泄漏**：合成 benchmark 可能在网络数据里出现过
- **闭源 vs 开源差距**：GPT-4o / Gemini 仍在多项榜单领先，但开源（Qwen2-VL、InternVL）已接近

**追问：MMMU 为什么是当前最受认可的多模态评测？** ① 题目来自真实大学考试，难度高且贴近实际；② 横跨多学科，单点过拟合无用；③ 推理深度足够，纯模式匹配难拿高分。

## Q10: 多模态的实际应用场景有哪些？技术难点？
> 难度 ⭐⭐ ｜ 高频 🔥

**主流应用**：

| 场景 | 用什么模型 | 难点 |
|---|---|---|
| **OCR / 文档理解** | Qwen2.5-VL、GOT-OCR | 小字、复杂版式、多语种 |
| **UI 理解（Agent）** | Qwen2.5-VL、Claude（Computer Use） | 元素定位精度、动作生成 |
| **代码生成（截图→ HTML）** | GPT-4o、Claude、Qwen-VL | 视觉细节保真 |
| **数学解题（手写公式）** | MathVista 强的模型 | 公式识别 + 推理 |
| **视频分析** | Qwen2-VL、Gemini | 长视频、时序 |
| **医疗影像** | 专用模型（如 LLaVA-Med） | 专业知识 + 高精度 |

**典型技术难点**：
1. **细粒度识别**：小物体、小字符 → 需高分辨率
2. **空间推理**：物体相对位置、几何关系 → 需 2D 位置编码
3. **多图理解**：context 爆炸
4. **幻觉**：图里没有的东西被"看到"
5. **多模态对齐数据稀缺**：高质量图文对难造

**追问：Computer Use（让 VLM 操作电脑）的核心技术挑战？** ① 屏幕截图坐标的精确定位（精度要到像素级）；② 长时序动作规划（多步交互的状态保持）；③ 错误恢复（点错了怎么办）。Anthropic Claude Computer Use 和 Qwen2.5-VL 都在解决这些问题。
