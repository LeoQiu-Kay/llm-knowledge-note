# 长上下文模型

> 128K+ 长上下文是当前热点，外推 + Ring Attention 是核心。

---

## Q1: 长上下文的核心挑战？

**答**：
**三大瓶颈**：
1. **计算**：Attention 是 $O(n^2)$，序列从 4K → 128K 时计算量增 1024×
2. **显存**：KV Cache 线性增长，128K 序列单请求几十 GB
3. **效果**：位置编码外推、注意力稀疏化导致质量下降

**衍生问题**：
- 训练成本：长序列训练 FLOPs 暴涨
- "lost in the middle"：模型对中间部分关注不足
- 数据稀缺：高质量长文档数据少

---

## Q2: 长上下文的核心技术分类？

**答**：

**1. 训练侧（让模型学会长上下文）**：
- 训练时序列加长（如 4K → 32K → 128K 渐进）
- 数据 packing（多文档拼接）
- Ring Attention / 序列并行

**2. 推理侧位置编码扩展**：
- Position Interpolation
- NTK-Aware Scaling
- YaRN
- LongRoPE

**3. 推理侧 KV Cache 优化**：
- GQA / MLA（架构层）
- 量化（INT8 / INT4）
- 淘汰（H2O / StreamingLLM）

**4. 推理侧高效 Attention**：
- FlashAttention（IO 优化）
- Sliding Window（局部注意力）
- 稀疏 Attention

---

## Q3: 稀疏注意力的方案？

**答**：

**Longformer**（2020）：
- **滑动窗口**：每个 token 只看局部 ±W
- **全局 token**：少数特殊位置（如 [CLS]）看全局
- 复杂度从 $O(n^2)$ 降到 $O(nW)$

**BigBird**（2020）：
- 滑动窗口 + 随机 attention + 全局 token
- 理论上是图灵完备
- 复杂度 $O(n)$

**Mistral 的 SWA（Sliding Window Attention）**：
- 每个 token 只看前 4K
- 多层堆叠后，有效感受野远超 4K（类似 CNN 的感受野）
- 实际能处理 32K 上下文

**问题**：
- 稀疏 attention 损失全局信息
- 不如稠密 attention + KV 压缩主流

---

## Q4: Position Interpolation（PI）？

**答**：
**问题**：训练时见过 0-4096 位置，推理需要 0-32768，外推效果暴跌。

**PI 思路**（Chen et al., Meta）：
- 把推理位置 $m'$ 映射回训练范围：$m = m' \cdot (L_{\text{train}} / L_{\text{infer}})$
- 等于"压缩"位置
- 然后用 RoPE

**好处**：
- 简单
- 短训即可适应（几千步）

**坏处**：
- 模糊了局部位置（如 1 和 2 的距离变小）
- 长距离信息丢失

---

## Q5: NTK-Aware Scaling？

**答**：
**核心**：从 NTK 理论出发，**不同频率维度应该不同程度地缩放**。

**RoPE 频率**：
$$\theta_i = b^{-2i/d}, \quad b = 10000$$

**NTK-Aware**：把 base $b$ 改成 $b' = b \cdot s^{d/(d-2)}$，其中 $s$ 是扩展比。

**效果**：
- 高频维度（短距离信息）几乎不变
- 低频维度（长距离信息）大幅缩放
- 零样本即可大幅扩展（无需训练）

**对比 PI**：PI 一刀切，NTK 差异化处理，效果好。

---

## Q6: YaRN 是什么？

**答**：
**YaRN**（Yet another RoPE extensioN）：组合多个技巧，当前主流。

**关键改进**：
1. **频率维度差异化缩放**（继承 NTK）
2. **NTK-by-parts**：把维度分成三段
   - 高频：保留（短距离精细）
   - 中频：插值
   - 低频：缩放（长距离平滑）
3. **温度修正**：缩放后注意力分布会偏，加温度修正

**效果**：
- 零样本能扩展约 4×
- 加少量短训能达到 8-16×
- 是当前 LLaMA-3、Qwen-2/3 等用的方案

---

## Q7: LongRoPE 是什么？

**答**：
**LongRoPE**（Microsoft, 2024）：每个频率维度独立搜索最优缩放。

**思路**：
- 不预设缩放规则，用进化搜索找最优 per-dim scaling
- 能扩展到 2M+ 上下文

**实践**：复杂度高，主流仍用 YaRN。

---

## Q8: Ring Attention 详解？

**答**：
**目的**：训练超长序列时跨设备并行。

**核心**：
1. 把序列分给 N 个设备，每个设备持有一段 Q/K/V
2. 每设备先用本地 K/V 算注意力
3. 环形传递 K/V 到下一设备
4. N 步后，每设备都"看过"全部 K/V，得到完整 attention

**结合 FlashAttention**：每设备内部用 FA，跨设备用 Ring 传递。

**复杂度**：
- 计算：与原 attention 一致
- 通信：环形 P2P，开销线性于序列长度
- 显存：每设备只持有 1/N 的 K/V

**应用**：
- Gemini 1.5（1M context）
- LLaMA-3 长上下文版本训练

## Q9: 长上下文的评测？

**答**：

**Needle-in-a-Haystack（NIAH）**：
- 在长文档中插入一个"针"（短句）
- 问模型那个针的内容
- 看不同位置 / 上下文长度的召回率
- 可视化为热图（颜色越绿越好）

**RULER**（NVIDIA）：
- 13 种合成任务，更复杂
- 涵盖检索、变量追踪、聚合、多跳

**LongBench**：
- 真实长文档任务（QA、摘要、代码）
- 中英文

**∞Bench**：
- 100K+ 任务
- 更接近实际应用

**典型现象**：
- 100K 模型在 NIAH 上 100%
- 但在真实任务上效果远不如短上下文模型
- 名义长度 vs 有效长度差异大

---

## Q10: "lost in the middle" 现象？

**答**：
**现象**（Liu et al., 2023）：
- 模型对**开头**和**结尾**的信息记忆好
- 对**中间**信息容易"漏掉"
- U 型曲线

**原因猜测**：
- 训练数据中信息往往集中在头尾
- attention sink 在开头
- 因果 mask 让结尾自然受最多关注
- 训练目标（CLM）也偏向结尾

**缓解**：
- 训练长上下文时增加"中间重要信息"的数据
- 改进位置编码（如某些工作设计专门强化中间）

---

## Q11: 长上下文的工程实践？

**答**：
**典型流程**：
1. **预训练**：主要用短序列（4K-8K）
2. **长上下文继续训练**：用 32K-128K 数据继续训练几千步
3. **位置编码扩展**：用 YaRN 等 + 短训适应
4. **SFT**：用长上下文指令数据
5. **评估**：NIAH + RULER + LongBench

**关键资源**：
- 长文档数据：书籍、长论文、长对话
- 合成长数据：用 LLM 生成（如 LongAlpaca）
- 算力：长训练成本高

## 🎯 高频追问

1. **128K 上下文是真的能用吗**？取决于评测：NIAH 高，真实任务往往打折。
2. **Mistral SWA 能达到多长**？滑动窗口 4K，多层堆叠后有效 ~32K。
3. **Ring Attention 与 PagedAttention 关系**？正交：Ring 是训练时跨设备并行；Paged 是推理时内存管理。
4. **YaRN 需要训练吗**？零样本可扩展几倍；进一步扩展需短训。
5. **长上下文需要多大 GPU**？128K LLaMA-3-70B 推理需要至少 2-4 张 80GB GPU（KV Cache 主导）。
