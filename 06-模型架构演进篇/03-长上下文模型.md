# 长上下文模型

> 128K+ 长上下文是当前热点。外推 + Ring Attention 是核心。

---

## 1. 三大瓶颈

**计算**：Attention 是 $O(n^2)$，序列 4K → 128K 时计算量增 1024×。
- 解：FlashAttention、稀疏 attention、SWA

**显存**：KV Cache 线性增长，128K 序列单请求几十 GB。
- 解：GQA / MLA、量化、淘汰

**效果**：位置编码外推、注意力稀疏化导致质量下降。
- 解：YaRN / NTK / LongRoPE

**衍生问题**：训练成本、"lost in the middle"、长数据稀缺。

---

## 2. 长上下文的核心技术分类

**1. 训练侧**：
- 训练时序列加长（4K → 32K → 128K 渐进）
- 数据 packing（多文档拼接）
- Ring Attention / 序列并行

**2. 推理侧位置编码扩展**：
- Position Interpolation (PI)
- NTK-Aware Scaling
- YaRN
- LongRoPE

**3. 推理侧 KV Cache 优化**：
- GQA / MLA（架构层）
- 量化（INT8/INT4）
- 淘汰（H2O / StreamingLLM）

**4. 推理侧高效 Attention**：
- FlashAttention（IO 优化）
- Sliding Window（局部）
- 稀疏 Attention

---

## 3. 稀疏注意力方案

| 方案 | 思路 |
|---|---|
| **Longformer** | 滑窗 ±W + 全局 token | $O(n W)$ |
| **BigBird** | 滑窗 + 随机 + 全局 | $O(n)$ |
| **Mistral SWA** | 每 token 看前 4K | 多层堆叠后有效感受野 ~32K |

**问题**：稀疏 attention 损失全局信息，不如稠密 + KV 压缩主流。

---

## 4. Position Interpolation (PI)

**思路**：把推理位置映射回训练范围。

$$m = m' \cdot \frac{L_{\text{train}}}{L_{\text{infer}}}$$

**符号说明**：
- $m'$：推理时的实际位置
- $m$：缩放后给 RoPE 的"等效位置"
- $L_{\text{train}}$：训练时上下文长度
- $L_{\text{infer}}$：推理时目标长度

**缺点**：模糊局部位置（1 和 2 的距离变小）。

---

## 5. NTK-Aware Scaling

**核心**：不同频率维度差异化缩放。

RoPE 的频率：

$$\theta_i = b^{-2i/d}, \quad b = 10000$$

**符号说明**：
- $\theta_i$：第 $i$ 对维度的旋转角
- $b$：base（典型 10000）
- $d$：模型维度
- 高频（小 $i$）→ 短距离精细
- 低频（大 $i$）→ 长距离平滑

**NTK-Aware**：改 base：

$$b' = b \cdot s^{d / (d - 2)}$$

**符号**：$s$ 是扩展比（如 4 倍上下文 → $s = 4$）。

**效果**：
- 高频维度几乎不变
- 低频维度大幅缩放
- **零样本**即可扩展几倍

---

## 6. YaRN（当前主流）

**YaRN**（Yet another RoPE extensioN）：组合多个技巧。

**关键改进**：
1. 频率维度差异化缩放（继承 NTK）
2. **NTK-by-parts**：分三段
   - 高频：保留（短距离精细）
   - 中频：插值
   - 低频：缩放（长距离平滑）
3. **温度修正**：缩放后注意力分布会偏，加温度修正

**效果**：
- 零样本扩展约 4×
- 加少量短训能达 8-16×
- LLaMA-3 / Qwen-2/3 用的方案

---

## 7. Ring Attention（训练用）

**目的**：训练超长序列时跨设备并行。

**核心**：
1. 把序列分给 $N$ 个设备，每设备持一段 Q/K/V
2. 每设备先用本地 K/V 算注意力
3. 环形传 K/V 到下一设备
4. $N$ 步后，每设备都"看过"全部 K/V

**与 FlashAttention 兼容**：每设备内部用 FA，跨设备用 Ring 传递。

**应用**：Gemini 1.5（1M context）、LLaMA-3 长上下文训练。

## 8. 长上下文评测

**NIAH（Needle in a Haystack）**：
- 在长文档中插一个"针"（短句）
- 问模型那个针的内容
- 看不同位置、不同上下文长度的召回率
- 可视化为热图

**RULER**（NVIDIA）：13 个合成任务，更全面。

**LongBench**：真实长任务（QA、摘要、代码）。

**∞Bench**：100K+ 任务，更接近实际。

**典型现象**：
```text
100K 模型在 NIAH 上 100%（针的位置全召回）。
但在真实任务上效果远不如短上下文模型。
名义长度 ≠ 有效长度。
```

---

## 9. "lost in the middle" 现象

**现象**（Liu et al., 2023）：
- 模型对**开头和结尾**信息记忆好
- 对**中间**信息容易"漏掉"
- U 型曲线

**原因猜测**：
- 训练数据中信息常集中在头尾
- attention sink 在开头
- 因果 mask 让结尾自然受最多关注
- CLM 目标也偏向结尾

**缓解**：
- 训练长上下文时增加"中间重要信息"的数据
- 改进位置编码

---

## 10. 工程实践

**典型流程**：
1. **预训练**：主要用短序列（4K-8K）
2. **长上下文继续训练**：用 32K-128K 数据继续训几千步
3. **位置编码扩展**：YaRN 等 + 短训适应
4. **SFT**：用长上下文指令数据
5. **评估**：NIAH + RULER + LongBench

---

## 11. 最简记忆

```text
长上下文三大瓶颈：
  计算 O(n²) → FlashAttention、稀疏 attention
  显存（KV Cache）→ GQA/MLA + 量化 + 淘汰
  位置编码外推 → YaRN/NTK/LongRoPE

外推三阶：PI < NTK < YaRN（依次更强）

训练端 Ring Attention：环形传 K/V，与 FA 兼容

评测要看真实任务：NIAH 高 ≠ LongBench 强。

"lost in the middle"：模型对中间信息记忆差。
```

## 🎯 高频追问

1. **128K 上下文真能用吗**？取决于评测：NIAH 高，真实任务往往打折。

2. **Mistral SWA 能多长**？滑窗 4K，多层堆叠后有效 ~32K。

3. **Ring Attention 与 PagedAttention 关系**？正交。Ring 是训练时跨设备；Paged 是推理时内存管理。

4. **YaRN 需要训练吗**？零样本可扩展几倍；进一步扩展需短训。

5. **128K 推理需要多大 GPU**？128K LLaMA-3-70B 至少需 2-4 张 80GB（KV Cache 主导）。
