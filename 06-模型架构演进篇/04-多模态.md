# 多模态（VLM / Vision-Language Models）

> 视觉编码器、对齐方法、原生多模态趋势。

---

## Q1: VLM 的基本架构？

**答**：
**三大组件**：
1. **视觉编码器**（Vision Encoder）：把图像编码为视觉 token
2. **连接器**（Connector）：把视觉特征映射到 LLM 输入空间
3. **LLM**：处理文本 + 视觉 token，生成文本输出

**典型流程**：
```
图像 → 视觉编码器 → 视觉特征 → 连接器 → 视觉 token
                                              ↓
                       拼接到文本 token 后 → LLM → 输出文本
```

---

## Q2: 主流视觉编码器对比？

**答**：

| 编码器 | 特点 |
|--------|------|
| **CLIP-ViT** | 图文对比学习预训练，对齐文本空间 |
| **SigLIP** | 用 Sigmoid 替代 Softmax 的 CLIP 改进版 |
| **DINOv2** | 自监督，无文本对齐 |
| **EVA-CLIP** | CLIP 改进，强大 |
| **InternViT** | 上海 AI Lab，可扩展到 6B |

**CLIP 为什么常被选**：
- 对比学习的图文对齐 → 视觉特征天然与语义相关
- 预训练数据规模大
- 表现稳定

**输入分辨率**：
- 224×224（CLIP 默认）
- 336×336（更高分辨率）
- 448×448、672×672（细粒度任务）
- 动态分辨率（处理任意尺寸，更先进）

---

## Q3: 连接器（Connector）的几种形式？

**答**：

**1. MLP Projector**（最简单）：
- 把视觉特征映射到 LLM hidden dim
- 通常 2-3 层 MLP
- LLaVA 使用

**2. Q-Former**（BLIP-2）：
- 一个小 Transformer 作为"信息瓶颈"
- 可学习的 query token 通过 cross-attention 抽取视觉信息
- 大幅压缩视觉 token 数（如 32 个查询）

**3. Resampler**（Flamingo）：
- 类似 Q-Former，固定数量输出 token

**4. Linear Projection**（极简）：
- 单层线性
- Qwen-VL 用

**视觉 token 数权衡**：
- 多 token（如 576 in LLaVA）：信息保真，但占 context
- 少 token（如 32 in BLIP-2）：节省 context，但信息损失

---

## Q4: LLaVA 系列的关键？

**答**：
**LLaVA-1.0**（2023）：
- CLIP-ViT + 线性 projection + Vicuna
- 两阶段训练：projection 对齐 + 端到端 SFT

**LLaVA-1.5**：
- MLP projection 替代线性
- 更高分辨率
- 更多任务数据

**LLaVA-Next（1.6）**：
- **AnyRes**：动态分辨率（图像分块，每块独立编码）
- 适应不同尺寸图像

**LLaVA-OneVision**：
- 多图、视频统一
- 接近 GPT-4o 能力

---

## Q5: Qwen-VL / Qwen2-VL 的特点？

**答**：
**Qwen-VL**：
- CLIP-ViT + 单层 cross-attention 压缩到 256 token
- 支持中文 + 多模态

**Qwen2-VL**：
- **动态分辨率**：原生处理任意尺寸（不是分块拼接）
- **M-RoPE**：把 RoPE 扩展到处理图像的 2D 位置
- 支持视频（多帧）

**Qwen2.5-VL**：
- 进一步增强 OCR、文档理解
- Agent 友好（可解析 UI 截图）

## Q6: InternVL 系列？

**答**：
- 上海 AI Lab 的开源 VLM
- 视觉编码器 InternViT 规模化（300M → 6B）
- 强调"视觉编码器 scaling"对效果重要
- InternVL2 / 2.5 / 3 持续迭代
- 在多个 benchmark 接近 GPT-4o

## Q7: 原生多模态 vs 拼接式多模态？

**答**：

**拼接式**（早期主流）：
- 训练好的视觉编码器 + 训练好的 LLM
- 通过 projection 桥接
- 代表：LLaVA、Qwen-VL

**原生多模态**（新趋势）：
- 从预训练阶段就同时处理多模态
- 视觉/音频/文本统一 tokenization
- 代表：GPT-4o、Gemini、Chameleon、Janus

**原生多模态的优势**：
- 模态间深度融合
- 任意模态输入输出
- 没有 alignment bottleneck

**挑战**：
- 训练数据复杂
- 不同模态信号差异大
- 计算量大

---

## Q8: 多模态训练的三阶段？

**答**：

**Stage 1：模态对齐（Pre-training）**：
- 大量图文对（如 LAION-5B）
- 只训练 projection / connector
- LLM 和视觉编码器冻结

**Stage 2：视觉-语言联合预训练**：
- 解冻部分参数（如视觉编码器后几层 + 连接器）
- 用更高质量数据

**Stage 3：指令微调（SFT）**：
- 端到端可训练
- 用多模态指令数据（如 LLaVA-Instruct-150K）

## Q9: 视频理解？

**答**：
**朴素方法**：
- 抽取关键帧
- 每帧独立编码，拼接到 LLM

**问题**：
- 时序信息丢失
- 长视频帧数爆炸

**改进**：
- **时序 attention**：跨帧 attention
- **视频专用编码器**：如 ViViT、VideoMAE
- **Temporal Q-Former**：Q-Former 加时序建模
- **采样策略**：均匀采样、自适应采样

**典型工作**：
- VideoLLaMA、Video-LLaVA、InternVideo
- Qwen2-VL（多帧 + M-RoPE）
- Gemini（原生长视频理解）

## Q11: 实际多模态应用？

**答**：
1. **OCR / 文档理解**：发票、表格、PDF
2. **UI 理解**：截图操作（Agent）

## 🎯 高频追问

1. **为什么 CLIP 视觉编码器对 LLM 友好**？因为它本就用文本对齐训练，视觉特征已在语义空间。
2. **视觉 token 数与文本 token 数的折中**？多分辨率/多图任务下视觉 token 易爆 context，需要平衡。
3. **多模态训练为什么先冻结 LLM**？避免大量随机视觉信号扰乱 LLM，先训 connector 对齐到 LLM 空间。
4. **原生多模态（GPT-4o）有什么优势**？低延迟（无串联）、模态深度融合、任意输入输出。
5. **3D / 点云 / 音频怎么接入**？类似视觉的思路：模态编码器 → projection → LLM；现有工作较多。
