# 多模态（VLM / Vision-Language Models）

> 视觉编码器 + 连接器 + LLM 三件套。

---

## 1. VLM 基本架构

**三大组件**：

```
图像 → 视觉编码器 → 视觉特征 → 连接器 → 视觉 token
                                              ↓
                       拼接到文本 token 后 → LLM → 输出文本
```

1. **视觉编码器**（Vision Encoder）：把图像编码为视觉 token
2. **连接器**（Connector）：把视觉特征映射到 LLM 输入空间
3. **LLM**：处理文本 + 视觉 token，生成文本输出

---

## 2. 主流视觉编码器

| 编码器 | 特点 |
|---|---|
| **CLIP-ViT** | 图文对比学习预训练，对齐文本空间 |
| **SigLIP** | Sigmoid 替代 Softmax 的 CLIP 改进版 |
| **DINOv2** | 自监督，无文本对齐 |
| **EVA-CLIP** | CLIP 改进，强大 |
| **InternViT** | 上海 AI Lab，可扩展到 6B |

**CLIP 为什么常被选**：
- 对比学习已让视觉特征与语义对齐
- 预训练数据规模大
- 表现稳定

**输入分辨率**：
- 224×224（CLIP 默认）
- 336×336（更高）
- 448×448、672×672（细粒度任务）
- **动态分辨率**（处理任意尺寸，更先进）

---

## 3. 连接器（Connector）

| 形式 | 思路 | 代表 |
|---|---|---|
| **MLP Projector** | 2-3 层 MLP 直接映射 | LLaVA |
| **Q-Former** | 小 Transformer + 可学 query token，cross-attention 抽取 | BLIP-2 |
| **Resampler** | 类似 Q-Former，固定输出 token 数 | Flamingo |
| **Linear** | 单层线性 | Qwen-VL |

**视觉 token 数权衡**：
- 多 token（如 LLaVA 的 576）：信息保真，占 context
- 少 token（如 BLIP-2 的 32）：节省 context，信息损失

---

## 4. LLaVA 系列

**LLaVA-1.0**（2023）：
- CLIP-ViT + 线性 projection + Vicuna
- 两阶段训练：projection 对齐 + 端到端 SFT

**LLaVA-1.5**：MLP projection 替代线性 + 更高分辨率 + 更多任务数据。

**LLaVA-Next（1.6）**：
- **AnyRes**：动态分辨率（图像分块，每块独立编码）
- 适应不同尺寸图像

**LLaVA-OneVision**：多图、视频统一。

---

## 5. Qwen-VL / Qwen2-VL

**Qwen-VL**：CLIP-ViT + 单层 cross-attention 压缩到 256 token，支持中文 + 多模态。

**Qwen2-VL**：
- **动态分辨率**：原生处理任意尺寸（不分块）
- **M-RoPE**：把 RoPE 扩展到处理图像的 2D 位置
- 支持视频（多帧）

**Qwen2.5-VL**：增强 OCR、文档理解、Agent（解析 UI 截图）。

---

## 6. 原生多模态 vs 拼接式

**拼接式**（早期主流）：
- 训练好的视觉编码器 + 训练好的 LLM
- 通过 projection 桥接
- 代表：LLaVA、Qwen-VL

**原生多模态**（新趋势）：
- 从预训练阶段就同时处理多模态
- 视觉/音频/文本统一 tokenization
- 代表：GPT-4o、Gemini、Chameleon、Janus

**原生的优势**：
- 模态间深度融合
- 任意模态输入输出
- 没有 alignment bottleneck

**挑战**：训练数据复杂、计算量大。

---

## 7. 多模态训练三阶段

### 7.1 Stage 1：模态对齐（Pre-training）

- 大量图文对（如 LAION-5B）
- **只训练 projection / connector**
- LLM 和视觉编码器**冻结**

**为什么先冻结 LLM**：避免大量随机视觉信号扰乱 LLM，先训 connector 对齐到 LLM 空间。

### 7.2 Stage 2：视觉-语言联合预训练

- 解冻部分参数（视觉编码器后几层 + 连接器）
- 用更高质量数据

### 7.3 Stage 3：指令微调（SFT）

- 端到端可训练
- 多模态指令数据（如 LLaVA-Instruct-150K）

---

## 8. 视频理解

**朴素方法**：抽关键帧 → 每帧独立编码 → 拼接到 LLM。

**问题**：时序信息丢失、长视频帧数爆炸。

**改进**：
- **时序 attention**：跨帧 attention
- **视频专用编码器**：ViViT、VideoMAE
- **Temporal Q-Former**：Q-Former 加时序建模
- **采样策略**：均匀采样、自适应采样

**典型工作**：VideoLLaMA、Video-LLaVA、InternVideo、Qwen2-VL（多帧 + M-RoPE）。

## 11. 最简记忆

```text
VLM 三件套：视觉编码器 + 连接器 + LLM

视觉编码器：CLIP / SigLIP / InternViT（CLIP 系最主流）
连接器：MLP（简单）/ Q-Former（信息瓶颈）/ Linear

训练三阶段：
  1. 冻结 LLM，只训 connector（对齐）
  2. 解冻部分参数（联合预训练）
  3. 端到端 SFT（指令微调）

原生多模态（GPT-4o, Gemini）→ 趋势
拼接式（LLaVA, Qwen-VL）→ 当前主流开源
```

## 🎯 高频追问

1. **CLIP 为什么对 LLM 友好**？本就用文本对齐训练，视觉特征已在语义空间。

2. **多模态训练为什么先冻结 LLM**？避免随机视觉信号扰乱，先让 connector 对齐到 LLM 空间。

3. **原生多模态优势**？低延迟、模态深度融合、任意输入输出。

4. **3D / 点云 / 音频怎么接入**？类似视觉：模态编码器 → projection → LLM。

5. **视觉 token 多少合适**？多分辨率 / 多图任务下视觉 token 易爆 context，需平衡。
