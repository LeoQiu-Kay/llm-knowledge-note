# 灵魂拷问 · Scaling 与认知篇

> 2 道题。Scaling laws 和"幻觉"是两个最容易考"理解深度"的话题。

---

## Q1: Chinchilla 法则的核心是什么？

### 1.0 先做背景铺垫：Scaling Laws 是什么

**Scaling Laws**：模型的 loss 随**参数量 $N$、数据量 $D$、计算量 $C$** 呈幂律下降。
最早由 OpenAI 在 2020 年提出（Kaplan et al.）。

**Kaplan 法则**（2020）：模型越大越好，数据相对次要。
**Chinchilla 法则**（DeepMind 2022）：**纠正了 Kaplan**，说数据同样重要。

### 1.1 Chinchilla 的核心结论

**给定计算预算 $C$，模型和数据应该同步增长**。

最优比例：**每参数约 20 tokens**。

举例（计算预算固定时）：
| 模型 | 数据 | 比例 |
|---|---|---|
| Chinchilla（最优） | 70B 参数 | 1.4T tokens | 1 : 20 |
| Gopher（次优） | 280B 参数 | 300B tokens | 1 : 1.07 |

→ Chinchilla 70B **小于** Gopher 280B，但因为数据多 4.7×，**效果反而更好**。

### 1.2 Kaplan vs Chinchilla 的对比

| | Kaplan 法则 | Chinchilla 法则 |
|---|---|---|
| 倾向 | 大模型 + 少数据 | 平衡 |
| 最优 token / 参数比 | 约 1.7 | **20** |
| 验证范围 | 较窄 | 更全面 |

### 1.3 为什么"训练不足"是普遍问题？

很多大模型都"训练不足"（数据相对参数太少）：
1. **大模型有面子**：业界 KPI 看"参数量"
2. **数据获取贵**：高质量数据有限
3. **训练时间长**：训 70B 模型需要几十天

### 1.4 当前现状（2024-2025）

部署导向让大家**远远超过 Chinchilla 最优**：
- LLaMA-3 8B 用 **15T tokens**（比例 1 : 1875）
- 远超 Chinchilla 推荐的 1 : 20

**为什么这样训？**
- Chinchilla 最优 = **训练 loss 最小**
- 实际部署 = **推理便宜 + 效果好**
- 训练贵但一次性，**推理几年都要付钱**

→ 小模型多训数据 = 推理时省钱 + 效果接近大模型。

## Q2: 大模型的幻觉为什么会出现？

### 2.0 先做背景铺垫

**幻觉**（Hallucination）：模型一本正经地说出**事实错误**的内容。
比如问"爱因斯坦的妻子是谁"，模型可能编造一个不存在的人名。

**关键认识**：LLM 不是数据库，不存"事实"，**它建模的是"文本分布"**。

### 2.1 5 大根本原因

#### ① 训练目标本质：CLM 不是"事实正确"

CLM（Causal LM）只预测"下一个 token 是什么"，**不验证事实**。
只要模型觉得某个 token 在统计上合理，它就会输出，哪怕事实错。

#### ② 数据噪声

训练数据本身就有错误：
- 网页内容自相矛盾
- 早期文章的错误信息没更新

#### ③ 过度自信

模型对**模糊问题**也会给出**确定回答**：
- 不会说"我不知道"
- 不会区分"高置信"和"低置信"

#### ④ 长尾知识

罕见事实在训练数据中**出现次数少**，模型记不准。

#### ⑤ 推理累积

链式推理时每一步都有误差，**累积到最后偏差极大**。
（参考 SFT 蒸馏的 compounding error 问题）

### 2.2 6 大缓解方法

| 方法 | 思路 |
|---|---|
| **RAG**（检索增强） | 提供外部 grounding，让模型基于检索结果生成 |
| **CoT**（思维链） | 让推理过程可验证 |
| **Self-Consistency** | 多次采样取一致答案 |
| **微调 + RLHF** | 训练模型"不知道就说不知道" |
| **工具调用** | 让 LLM 调用计算器、搜索引擎、代码执行 |
| **验证器** | 用另一个 LLM 或外部系统验证 |

### 2.3 根本难题

**完全消除幻觉理论上不可能**——
因为语言模型本质是分布拟合，它没有"事实数据库"作为底层支撑。

```text
现实策略：用工程方法把幻觉率从 30% 降到 3%，
而不是追求 0%。
```
