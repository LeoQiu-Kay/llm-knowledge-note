# 面试灵魂拷问（20 道高频开放题）

> 这些是最容易把人问住的开放式问题，建议形成自己的思考体系。

---

## Q1: 为什么 Transformer 比 RNN/LSTM 更适合 LLM？

**答**：
1. **长程依赖**：Attention 直接 $O(1)$ 跨距访问任意位置；RNN 信号沿时间步衰减
2. **并行训练**：Transformer 可同时算所有位置；RNN 必须串行
3. **scaling 友好**：弱归纳偏置 + 大数据，符合 scaling laws；RNN 容量随深度增加效益递减
4. **梯度路径短**：残差 + 直接 attention，避免 RNN 的梯度消失/爆炸
5. **生态成熟**：FlashAttention、KV Cache 等优化都基于 Transformer

**反例思考**：Mamba 等 SSM 试图重回线性复杂度，长上下文可能反超，但目前 LLM 主流仍是 Transformer。

---

## Q2: 为什么现在 LLM 都用 Decoder-only？

**答**：
1. **Zero-shot 能力强**：GPT-3 证明 + 后续大量验证，Decoder-only 比 Enc-Dec 更强
2. **训练目标统一**：CLM 一个目标覆盖理解 + 生成，数据利用率 100%（vs MLM 15%）
3. **架构简单**：无 Cross-Attention，部署/并行/缓存都简洁
4. **In-Context Learning 天然**：Causal mask + 任意长 prompt 完美适配
5. **Scaling 路径成熟**：从 GPT-2 到 GPT-4 一脉相承的 scaling 法则
6. **理论支持**：causal mask 提供低秩偏置，加上深度可以模拟双向

**简单回答**："训练目标更好，scaling 路径已被验证，且能做 in-context learning"。

## Q3: Attention 为什么要 scale $\sqrt{d_k}$？不 scale 会怎样？

**答**：
**动机**：保持点积输出的方差稳定。

**推导**：
- 假设 $q, k$ 各分量独立同分布，$\mathbb{E}=0, \text{Var}=1$
- $q \cdot k$ 是 $d_k$ 项独立和，$\text{Var} = d_k$
- 不 scale → softmax 输入跨度 $\sim \sqrt{d_k}$，分布尖锐 → 接近 one-hot → 梯度消失

**不 scale 的后果**：
- $d_k = 64$ 时未 scale，输入跨度约 $\pm 16$
- softmax 输出几乎是 one-hot
- 训练时梯度对 argmax 之外的项几乎为 0
- 训练困难

**为什么是 $\sqrt{d_k}$ 而不是其他**：标准差归一化的标准做法。

## Q4: RoPE 为什么是相对位置编码？它的外推能力来自哪里？

**答**：
**相对性证明**：
- 旋转矩阵 $R_m$ 应用到 Q、$R_n$ 应用到 K
- 内积 $\langle R_m q, R_n k \rangle = q^T R_m^T R_n k = q^T R_{n-m} k$
- **只依赖相对位置 $n - m$**

**外推性来源**：
1. 旋转操作连续可微，理论上可外推
2. 不需要可学习的位置 embedding（不像 Sinusoidal 的 PE 加在 input 上）
3. 每一层都注入位置信号

**但实际外推差**：
- 远距离旋转角度大，训练时未见过
- 需要 PI/NTK/YaRN 等技术修正

## Q5: MHA / MQA / GQA / MLA 如何权衡？

**答**：

| 维度 | MHA | MQA | GQA | MLA |
|------|-----|-----|-----|-----|
| KV Cache | 基线 | 1/h（极小） | g/h | 极小 |
| 效果 | 最好 | 略降 | 几乎无损 | 最好 |
| 实现 | 简单 | 简单 | 简单 | 复杂（解耦 RoPE） |
| 代表 | GPT-3 | PaLM | LLaMA-2/3 | DeepSeek-V2/V3 |

**选择**：
- 当前主流：**GQA**，效果与 MHA 持平、KV Cache 显著小
- 极致优化：**MLA**，DeepSeek 证明可行
- 历史遗留：仍有 MHA 模型存在

**何时退化为 MQA**：g=1 时 GQA 等于 MQA。
**何时退化为 MHA**：g=h 时 GQA 等于 MHA。

## Q6: FlashAttention 究竟优化了什么？为什么能加速？

**答**：
**核心**：是 **IO 优化**，不是 FLOP 优化。

**关键认识**：GPU 上 attention 是 **memory-bound**：
- HBM 带宽 ~2TB/s，算力 ~300 TFLOPs
- 标准 attention 实例化 $n \times n$ 矩阵到 HBM，IO 巨大
- 算术强度低，瓶颈是访存

**FlashAttention 做法**：
- 分块（tiling）：Q/K/V 切块，每块塞 SRAM
- Online Softmax：分块算 softmax，维护 running max/sum
- 不在 HBM 中实例化完整 attention 矩阵
- 反向时**重计算**（recomputation）代替缓存

**结果**：
- HBM IO 从 $O(n^2)$ 降到 $O(n)$
- 计算量不变（仍是 $O(n^2 d)$）
- 实际加速 2-4×

## Q7: KV Cache 占用怎么估算？如何降低？

**答**：
**公式**：
$$\text{KV Cache} = 2 \times L \times s \times h \times d_h \times \text{bytes}$$

- $L$ 层数；$s$ 序列长度；$h$ KV 头数；$d_h$ head_dim

**例**：LLaMA-3-70B，128K 序列，FP16 ≈ 42 GB（一张卡装不下！）

**降低方式**：
1. **架构层**：MQA、GQA、MLA
2. **量化**：INT8/INT4/FP8
3. **淘汰**：H2O、StreamingLLM、SnapKV
4. **复用**：Prefix Caching、PagedAttention
5. **Offload**：CPU/NVMe（性能代价大）

## Q8: PPO 和 DPO 的本质区别是什么？什么时候用哪个？

**答**：

**本质区别**：
- **PPO**：在线 RL，需要 RM 提供奖励信号，actor-critic 框架
- **DPO**：监督学习，直接用偏好对优化 policy，无需 RM

**DPO 推导**：从 RLHF 最优解的解析形式反解 reward，代入 Bradley-Terry 偏好模型 → 监督损失。

**优劣**：
| | PPO | DPO |
|---|-----|-----|
| 训练稳定性 | 难（RL） | 易（监督） |
| 显存 | 大（4 模型） | 小（2 模型） |
| 数据 | 可在线采样 | 静态偏好集 |
| 效果上限 | 高 | 略低或持平 |

**选择**：
- 学术 / 资源有限 / 快速迭代 → **DPO**
- 工业 / 持续在线数据 / 极致效果 → **PPO**

**最新趋势**：GRPO 简化 PPO（去 Critic），R1 等用得多。

## Q9: GRPO 相比 PPO 省了什么？为什么 DeepSeek 选它？

**答**：
**省了 Critic 模型**：
- PPO 需要 actor + critic + RM + reference 四个模型
- GRPO 只要 actor + RM + reference 三个

**怎么省的**：
- 不用 critic 估计 value，而是**组内归一化**
- 对同一 prompt 采样 G 个答案，用组内 mean/std 作为 baseline

**优势**：
1. 省显存（少一个大模型）
2. 数学/代码任务用规则奖励即可（无需 RM）
3. 训练更稳

**DeepSeek 选它的原因**：
- DeepSeek-R1-Zero / R1 在数学、代码上做大规模 RL
- 规则奖励（答案对错）+ GRPO 极其简洁
- 触发"推理涌现"（长 CoT、self-correction）

## Q10: LoRA 为什么有效？r 怎么选？

**答**：
**有效性原理**：
- 大模型的"任务适应"主要发生在低秩子空间（内在维度低）
- $\Delta W$ 是低秩的，可分解 $\Delta W = BA$
- 论文证明 r=1 在很多任务上够用

**初始化**：A 高斯，B 零 → 训练开始时 $\Delta W = 0$，不破坏 base 模型。

**r 的选择**：
- 简单任务（指令微调、风格）：r=4-8
- 复杂任务（领域知识、推理）：r=16-32
- 数据量大：r=64
- 经验：r=8 是甜点，往上边际递减

**α 的作用**：$\Delta W$ 实际缩放为 $(\alpha / r)$，控制 LoRA 强度，常用 $\alpha = 2r$。

## Q11: RMSNorm 相比 LayerNorm 为什么更受欢迎？

**答**：
**省了什么**：
1. 均值计算 $\mu$
2. 减均值操作（re-centering）
3. bias 参数 $\beta$（常省去）

**计算节省**：约 7-15% 归一化层时间。

**效果**：等效或略好（Zhang & Sennrich, 2019）。

**为什么有效**：LayerNorm 的两个作用 re-centering 和 re-scaling 中，re-scaling 是主要贡献，re-centering 影响小。

**现状**：LLaMA、Qwen、Mistral、DeepSeek 全用 RMSNorm，事实标准。

## Q12: SwiGLU 为什么打败了 ReLU / GELU？

**答**：
**形式**：$\text{SwiGLU}(x) = \text{Swish}(xW_1) \otimes (xW_3)$

**关键**：
1. **门控机制**：$W_3 x$ 提供门控信号，类似 LSTM 的 gate
2. **平滑可导**：Swish 比 ReLU 平滑
3. **表达力强**：3 个矩阵 vs 2 个，但参数对齐成本只多 1/3

**Shazeer 2020 实验**："GLU Variants Improve Transformer" 系统对比，SwiGLU 在多个指标上最优。

**现代地位**：LLaMA、Qwen、Mistral、DeepSeek 全用 SwiGLU。

## Q13: 为什么 MoE 模型训练这么难？

**答**：
**几个挑战**：

1. **路由不稳定**：训练初期 router 随机，专家学不到特长 → 需要 warmup 或 aux loss 引导
2. **负载不均衡**：少数专家被反复用，大多数闲置 → 加 aux loss 或 bias 调整
3. **Token Drop**：超过 capacity 的 token 被丢弃，信息损失
4. **专家坍缩**：某些专家学到完全相同，参数浪费
5. **通信开销**：EP 的 All-to-All 是分布式瓶颈
6. **数值精度**：路由分数对精度敏感（softmax 输入）

**DeepSeek 的解法**：
- Aux-loss-free 策略（动态 bias）
- 细粒度专家 + 共享专家
- 优化 All-to-All（DeepEP）

## Q14: 长上下文（128K+）训练的核心瓶颈是什么？怎么解决？

**答**：

**三大瓶颈**：

1. **计算**：$O(n^2)$，128K 比 4K 多 1024×
   - 解：FlashAttention v2/v3、稀疏 attention、SWA
2. **显存**：KV Cache + 激活值线性增长
   - 解：Ring Attention、序列并行
3. **位置编码外推**：训练 4K 用到 128K 失效
   - 解：YaRN / NTK / LongRoPE

**训练策略**：
- 先短训（4K-8K）建立基础能力
- 后长训（32K-128K）扩展
- 数据：长文档 + 合成长 QA

**评测要看真实任务**：NIAH 高不代表 LongBench 强。

## Q15: 量化为什么不能直接对所有层用 INT4？敏感层在哪里？

**答**：
**敏感层**：
1. **LayerNorm / RMSNorm 的输入**：归一化放大量化误差
2. **第一层**：直接接收 embedding，扰动放大到全网
3. **最后一层 LM Head**：决定输出分布
4. **Attention 中的 softmax 输入**：分布尖锐，量化误差被放大

**激活值的 outlier**：
- 某些 channel 数值特别大（attention sink 相关）
- 均匀量化无法兼顾所有 channel
- 需要 SmoothQuant 这类技巧转移 outlier 到权重

**实际方案**：
- 敏感层用 FP16 / FP8
- 其他用 INT4
- 混合精度量化是工业标准

## Q16: 模型出现 Loss spike 时你会怎么排查？

**答**：

**排查步骤**：
1. **看日志**：spike 前后 loss/grad_norm 走势，是否突发
2. **看数据**：当前 batch 是否异常（长度、token id、内容）
3. **看梯度**：哪一层 grad 异常大
4. **看激活**：是否有 inf/nan
5. **看精度**：FP16 下是否溢出（Loss Scaling 失效）

**处理顺序**：
1. **回滚 checkpoint** + 跳过坏 batch
2. **降低学习率** 或 增强梯度裁剪
3. **切到 BF16**（如果用 FP16）
4. **检查数据预处理**，过滤异常

**预防**：
- BF16 训练
- 充分 warmup（2-5%）
- grad_clip = 1.0
- 数据预清洗

## Q17: Chinchilla 法则的核心是什么？为什么"训练不足"是个普遍问题？

**答**：
**Chinchilla**（DeepMind 2022）核心：
- 给定计算预算，**模型和数据应该同步增长**
- 最优比例：每参数约 20 tokens

**纠正了 Kaplan**（OpenAI 2020）：
- Kaplan 认为应大模型 + 少数据
- Chinchilla 用更全实验证明应平衡

**为什么"训练不足"普遍**：
- 大模型有面子（榜单看参数量）
- 数据获取/清洗也贵
- 训练时间长，工程复杂

**实际趋势**：
- 部署友好导向：训练**远超** Chinchilla（小模型 + 大量数据）
- LLaMA-3 8B 用 15T tokens（1875:1），远超 20:1 最优
- 训练阶段贵但一次性，推理阶段省钱（关键考虑）

## Q18: 大模型的"幻觉"为什么会出现？怎么缓解？

**答**：
**原因**：
1. **训练目标**：CLM 是预测下一个 token，不是"事实正确性"
2. **数据噪声**：训练数据本身含错误信息
3. **过度自信**：模型对模糊问题也会给确定回答
4. **长尾知识**：罕见事实记忆不准
5. **推理错误**：链式推理累积偏差

**缓解方法**：
1. **RAG**：基于检索文档作答，外部 grounding
2. **CoT**：让推理过程显式化，便于验证
3. **Self-Consistency**：多次采样取一致答案
4. **微调 + RLHF**：训练模型"不知道就说不知道"
5. **工具调用**：让 LLM 调用计算器、搜索引擎等
6. **验证器**：用 LLM 或外部系统验证答案
7. **不确定度估计**：让模型输出 confidence

**根本难题**：完全消除幻觉理论上不可能（语言模型本质是分布拟合）。

## Q19: 给定 7B 模型，全参微调和 LoRA 显存各需要多少？

**答**：
**7B 模型，BF16 训练，Adam 优化器**：

**全参微调**：
- 参数（BF16）：7B × 2 bytes = 14 GB
- 梯度（BF16）：14 GB
- Adam m（FP32）：7B × 4 = 28 GB
- Adam v（FP32）：28 GB
- FP32 主权重副本：28 GB
- **模型状态小计**：~112 GB
- 激活值（4K seq, batch 4，无 GC）：~30 GB
- **总计**：~140 GB → **单卡 80GB 装不下**，需 ZeRO-3 或 TP

**LoRA（r=8）**：
- Base 模型（BF16，冻结）：14 GB
- LoRA 参数（BF16）：~50 MB（极小）
- LoRA 梯度 + Adam 状态（FP32）：~600 MB
- 激活值（开 GC）：~10 GB
- **总计**：~25 GB → **单卡 40GB 可跑**

**QLoRA（4-bit base + LoRA）**：
- Base（INT4）：~4 GB
- LoRA + 优化器：~600 MB
- 激活：~10 GB
- **总计**：~15 GB → **4090 等消费级 GPU 可跑**

## Q20: 如果让你设计下一代 LLM 架构，你会从哪里改进？

**答**：这道题没有标准答案，展示思考深度即可。

**几个可能方向**：

1. **架构**：
   - 继续优化 attention（MLA 的进一步演化）
   - 探索 SSM / Mamba 与 Transformer 的混合
   - 更细粒度 MoE + 专家共享
   - 原生多模态（不依赖 connector）

2. **训练目标**：
   - 不止 CLM，引入更多对比 / 自监督信号
   - 长 CoT 数据从预训练阶段就引入
   - 不同 token 不同 loss 权重（重要 token 更重）

3. **位置编码**：
   - 更好的外推机制
   - 适应多模态（图像 2D 位置）
   - 适应超长上下文（100M+）

4. **推理优化**：
   - 推理时 scaling（o1 路线）的进一步发展
   - 投机解码与并行推理的结合
   - 边缘端的极致小模型

5. **对齐**：
   - 更细粒度的过程奖励
   - 多目标平衡（helpful/harmless/honest）
   - 自我改进（self-improvement loop）

6. **数据**：
   - 合成数据的质量提升
   - 多模态数据规模化
   - 强化"反思 / 修正"数据

7. **效率**：
   - FP4 / FP6 训练
   - 极致 MoE 稀疏化
   - 训练时 Continuous Batching 思路

**回答原则**：选 2-3 个方向深入展开，避免泛泛而谈。

## 🎯 终极建议

**如何应对开放题**：
1. **结构化回答**：先框架，再细节，最后举例
2. **多角度**：技术 + 工程 + 业务
3. **承认局限**：诚实说"这个我不确定，但我的理解是..."
4. **互动**：可以反问面试官"你们的场景是 X 还是 Y？"
5. **更新认知**：保持跟进新论文/新模型，知识不过时

**经典回答框架**：
- **是什么**：1-2 句话定义
- **为什么**：动机 / 痛点
- **怎么做**：核心机制
- **效果**：数据 / 实际表现
- **局限 / 权衡**：什么时候不该用

把这 20 道题想清楚，LLM 面试基本无虞。
