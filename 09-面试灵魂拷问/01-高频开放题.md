# 面试灵魂拷问（20 道高频开放题）

> 这些是最容易把人问住的开放式问题，建议形成自己的思考体系。
> 每道题给出"3 分钟答题框架"，可按需展开。

---

## Q1: 为什么 Transformer 比 RNN/LSTM 更适合 LLM？

1. **长程依赖**：Attention 直接 $O(1)$ 跨距访问；RNN 信号沿时间衰减
2. **并行训练**：Transformer 同时处理所有位置；RNN 必须串行
3. **scaling 友好**：弱归纳偏置 + 大数据，符合 scaling laws
4. **梯度路径短**：残差 + 直接 attention，避免梯度消失

**反例**：Mamba 等 SSM 试图重回线性复杂度，长上下文可能反超，但目前 LLM 主流仍是 Transformer。

---

## Q2: 为什么现在 LLM 都用 Decoder-only？

1. **Zero-shot 能力强**：GPT-3 + 后续验证，Decoder-only + scaling 吊打 Enc-Dec
2. **训练目标统一**：CLM 一个目标覆盖理解 + 生成，数据利用率 100%（vs MLM 15%）
3. **架构简单**：无 Cross-Attention，部署/并行/缓存都简洁
4. **In-Context Learning 天然**：causal mask + 任意长 prompt 完美适配
5. **Scaling 路径成熟**：从 GPT-2 到 GPT-4 一脉相承

**简单答**："训练目标更好，scaling 路径已被验证，且能做 in-context learning。"

## Q3: Attention 为什么要 scale $\sqrt{d_k}$？

**动机**：保持点积输出方差稳定。

**推导**：假设 $q, k$ 各分量独立同分布、均值 0、方差 1。

$$q \cdot k = \sum_{i=1}^{d_k} q_i k_i$$

$$\text{Var}[q \cdot k] = d_k$$

不除 → 标准差 $\sqrt{d_k}$ → softmax 输入跨度大 → 接近 one-hot → 梯度对 argmax 之外几乎为 0 → 训练困难。

除 $\sqrt{d_k}$ → 方差归一到 1。

## Q4: RoPE 为什么是相对位置编码？外推性来自哪？

**相对性证明**：旋转矩阵性质 $R_m^T R_n = R_{n-m}$，所以：

$$\langle R_m q, R_n k \rangle = q^T R_{n-m} k$$

只依赖相对位置 $n - m$。

**外推性来源**：
1. 旋转操作连续可微，理论可外推
2. 不需要可学习的位置 embedding
3. 每一层都注入位置信号

**实际外推差**：远距离旋转角度大、训练时未见过。需要 YaRN/NTK/PI 修正。

## Q5: MHA / MQA / GQA / MLA 如何权衡？

| 维度 | MHA | MQA | GQA | MLA |
|---|---|---|---|---|
| KV Cache | 基线 | 1/h（最小） | g/h | 极小 |
| 效果 | 最好 | 略降 | 几乎无损 | 最好 |
| 实现 | 简单 | 简单 | 简单 | 复杂（解耦 RoPE） |
| 代表 | GPT-3 | PaLM | LLaMA-2/3 | DeepSeek-V2/V3 |

**选择**：
- 主流：**GQA**（效果 ≈ MHA、KV Cache 大幅小）
- 极致：**MLA**（DeepSeek）

**特例**：$g = 1$ → MQA；$g = h$ → MHA。

## Q6: FlashAttention 究竟优化了什么？

**核心**：**IO 优化**，不是 FLOP 优化。

**关键认识**：GPU 上 attention 是 **memory-bound**（HBM 带宽是瓶颈）。

**做法**：
- 分块（tiling）：Q/K/V 切块，每块塞 SRAM
- Online Softmax：分块算 softmax
- 不实例化完整 attention 矩阵到 HBM
- 反向时**重计算**

**结果**：HBM IO 从 $O(n^2)$ 降到 $O(n)$，计算量不变，实际加速 2-4×。

---

## Q7: KV Cache 显存怎么算？如何降低？

**公式**：

$$\text{KV Cache} = 2 \times L \times s \times h \times d_h \times \text{bytes}$$

**符号**：$L$ 层数、$s$ 序列长、$h$ KV 头数、$d_h$ 每头维度。

**例**：LLaMA-3-70B，128K 序列，FP16 ≈ 42 GB（单卡装不下）。

**降低**：
1. 架构层：**MQA / GQA / MLA**
2. **量化**：INT8 / INT4 / FP8
3. **淘汰**：H2O / StreamingLLM / SnapKV
4. **复用**：Prefix Caching、PagedAttention
5. **Offload**：CPU / NVMe

## Q8: PPO 和 DPO 的本质区别？

**本质**：
- **PPO**：在线 RL，需要 RM 提供奖励信号，actor-critic 框架
- **DPO**：监督学习，直接用偏好对优化 policy，无需 RM

**DPO 推导**：从 RLHF 最优解的解析形式反解 reward，代入 Bradley-Terry → 监督损失。

**对比**：

| | PPO | DPO |
|---|---|---|
| 训练稳定性 | 难（RL） | 易（监督） |
| 显存 | 大（4 模型） | 小（2 模型） |
| 数据 | 在线采样 | 静态偏好集 |
| 效果上限 | 高 | 略低或持平 |

**选择**：学术 / 资源有限 → DPO；工业 / 持续在线 → PPO。

## Q9: GRPO 相比 PPO 省了什么？

**省了 Critic 模型**。

**怎么省的**：
- 不用 critic 估 value
- 对同一 prompt 采样 $G$ 个答案，组内 mean/std 作为 baseline

$$A_i = \frac{r_i - \text{mean}(r_1, \dots, r_G)}{\text{std}(r_1, \dots, r_G)}$$

**优势**：
1. 省显存（少一个大模型）
2. 数学/代码任务用规则奖励即可（无需 RM）
3. 训练更稳

**DeepSeek 选它**：R1-Zero / R1 在数学、代码上大规模 RL，规则奖励 + GRPO 极简洁。

## Q10: LoRA 为什么有效？r 怎么选？

**有效性**：
- 大模型的任务适应主要发生在低秩子空间（内在维度低）
- $\Delta W$ 是低秩的，可分解为 $\Delta W = BA$
- 论文证明 $r = 1$ 在很多任务上够用

**初始化**：$A$ 高斯 + $B$ 零 → 训练开始 $\Delta W = 0$，不破坏 base。

**r 选择**：
- 简单（指令）：$r = 4 \sim 8$
- 复杂（领域）：$r = 16 \sim 32$
- 经验：$r = 8$ 是甜点

## Q11: RMSNorm 相比 LayerNorm 为什么更受欢迎？

**省了**：
1. 均值计算 $\mu$
2. 减均值操作（re-centering）
3. bias 参数 $\beta$（通常）

**计算节省**：约 7-15%。

**效果**：等效或略好（re-scaling 是主要贡献，re-centering 影响小）。

**现状**：LLaMA / Qwen / Mistral / DeepSeek 全用 RMSNorm。

---

## Q12: SwiGLU 为什么打败 ReLU / GELU？

**形式**：$\text{SwiGLU}(x) = \text{Swish}(W_1 x) \otimes (W_3 x)$

**关键**：
1. **门控机制**：$W_3 x$ 提供门控信号，类似 LSTM 的 gate
2. **平滑可导**
3. **表达力强**：3 个矩阵（vs 2 个）

**对齐参数**：FFN 中间维度 $\frac{8}{3}d$ 保持原 FFN 的 $8d^2$ 参数量。

**地位**：LLaMA / Qwen / Mistral / DeepSeek 全用。

## Q13: MoE 训练为什么难？

**挑战**：
1. **路由不稳**：训练初期 router 随机
2. **负载不均衡**：少数专家被反复用 → 加 aux loss 或 bias 调整
3. **Token Drop**：超过 capacity 的 token 被丢弃
4. **专家坍缩**：某些专家完全相同
5. **通信开销**：EP 的 All-to-All 瓶颈
6. **显存压力**：所有专家都要持有

**DeepSeek 解法**：Aux-loss-free + 细粒度专家 + 共享专家 + DeepEP 通信优化。

---

## Q14: 长上下文（128K+）的核心瓶颈？怎么解？

**三大瓶颈**：
1. **计算**：$O(n^2)$，128K 比 4K 多 1024×
   - 解：FlashAttention、稀疏 attention、SWA
2. **显存**：KV Cache + 激活值线性增长
   - 解：Ring Attention、序列并行
3. **位置编码外推**：训练 4K 用到 128K 失效
   - 解：YaRN / NTK / LongRoPE

**训练策略**：先短训（4K-8K），后长训（32K-128K）。

**评测**：看 RULER / LongBench，不要只看 NIAH。

## Q15: 量化为什么不能直接对所有层用 INT4？

**敏感层**：
1. **LayerNorm / RMSNorm 的输入**：归一化放大误差
2. **第一层**：扰动放大到全网
3. **最后一层（LM Head）**：决定输出分布
4. **Attention 中的 softmax 输入**：尖锐分布对误差敏感

**激活值的 outlier**：某些 channel 数值特别大 → 均匀量化无法兼顾 → 需要 SmoothQuant 这类技巧。

**实际**：混合精度量化（敏感层 FP16/FP8，其余 INT4）是工业标准。

## Q16: Loss spike 怎么排查？

**步骤**：
1. **看日志**：spike 前后 loss/grad_norm 走势
2. **看数据**：当前 batch 是否异常（长度、token id、内容）
3. **看梯度**：哪一层 grad 异常大
4. **看激活**：是否有 inf/nan
5. **看精度**：FP16 下是否溢出

**处理**：
1. 回滚 checkpoint + 跳过坏 batch
2. 降低 LR / 加强梯度裁剪
3. 切到 BF16
4. 检查数据预处理

**预防**：BF16 + 充分 warmup + grad_clip=1.0 + 数据预清洗。

## Q17: Chinchilla 法则的核心是什么？

**Chinchilla**（DeepMind 2022）：给定计算预算，**模型和数据应该同步增长**。最优比例：每参数约 **20 tokens**。

**纠正 Kaplan**：Kaplan 认为大模型 + 少数据，Chinchilla 用更全实验证明应平衡。

**为什么"训练不足"普遍**：
- 大模型有面子（看参数量）
- 数据获取贵
- 训练时间长

**当前现状**：
- 部署友好导向：**远超** Chinchilla（小模型 + 大量数据）
- LLaMA-3 8B 用 15T tokens（1875:1 比例）
- Chinchilla 最优是 loss 最小，**不是部署最优**

## Q18: 大模型的幻觉为什么会出现？

**原因**：
1. **训练目标**：CLM 是预测下一个 token，不是"事实正确"
2. **数据噪声**：训练数据本身含错误
3. **过度自信**：模糊问题也给确定回答
4. **长尾知识**：罕见事实记忆不准
5. **推理累积**：链式推理累积偏差

**缓解**：
1. **RAG**：外部 grounding
2. **CoT**：让推理过程可验证
3. **Self-Consistency**：多次采样取一致
4. **微调 + RLHF**：训练"不知道就说不知道"
5. **工具调用**：让 LLM 调计算器、搜索引擎
6. **验证器**：用 LLM 或外部系统验证

**根本难题**：完全消除幻觉理论上不可能（语言模型本质是分布拟合）。

## Q19: 7B 模型全参微调 vs LoRA 显存？

**7B 模型，BF16 训练，Adam**：

**全参微调**：
- 参数（BF16）：14 GB
- 梯度（BF16）：14 GB
- Adam m（FP32）：28 GB
- Adam v（FP32）：28 GB
- FP32 主权重：28 GB
- **模型状态合计**：**~112 GB**
- 激活（4K seq, batch 4，无 GC）：~30 GB
- **总：~140 GB** → 单卡 80GB 装不下，需 ZeRO 或 TP/PP

**LoRA（r=8）**：
- Base（BF16，冻结）：14 GB
- LoRA + 优化器：~600 MB
- 激活（开 GC）：~10 GB
- **总：~25 GB** → 单卡 40GB 可跑

**QLoRA（4-bit base）**：
- Base（INT4）：~4 GB
- LoRA + 优化器：~600 MB
- 激活：~10 GB
- **总：~15 GB** → 4090 等消费级 GPU 可跑

## Q20: 如果让你设计下一代 LLM 架构，会改进什么？

**没有标准答案**，展示思考深度即可。可能方向：

1. **架构**：MLA 演化、SSM/Mamba 混合、细粒度 MoE、原生多模态
2. **训练目标**：不止 CLM，引入对比学习；不同 token 不同 loss 权重
3. **位置编码**：更好的外推、适应多模态、超长上下文
4. **推理**：推理时 scaling 进一步发展、投机解码与并行结合
5. **对齐**：细粒度过程奖励、多目标平衡、self-improvement
6. **数据**：合成数据质量、多模态规模化、反思/修正数据
7. **效率**：FP4/FP6 训练、极致 MoE 稀疏化

**回答原则**：选 2-3 个方向深入展开，避免泛泛而谈。

## 🎯 终极建议：怎么应对开放题

1. **结构化回答**：先框架，再细节，最后举例
2. **多角度**：技术 + 工程 + 业务
3. **承认局限**：诚实说"这个我不确定，但我的理解是..."
4. **互动**：可以反问面试官"你们的场景是 X 还是 Y？"
5. **更新认知**：保持跟进新论文 / 新模型

**经典回答框架**：
- **是什么**：1-2 句话定义
- **为什么**：动机 / 痛点
- **怎么做**：核心机制
- **效果**：数据 / 实际表现
- **局限**：什么时候不该用

把这 20 道题想清楚，LLM 面试基本无虞。
