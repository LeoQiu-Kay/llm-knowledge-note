> 2 道题。MoE 和长上下文是 2024-2025 LLM 演进的两大主线。

## Q1: MoE 训练为什么难？

### 1.0 先做背景铺垫

**MoE**（Mixture of Experts，混合专家）：
- 把 FFN 层换成"**多个并行的小 FFN（专家）+ 一个路由器**"
- 每个 token 只激活其中 **K 个专家**（典型 K=2 或 8）
- 总参数极大（如 DeepSeek-V3 671B），**激活参数远小**（37B）

**核心优势**：参数量爆炸但计算量受控。
**核心难度**：训练极难稳定。

### 1.1 6 大挑战

| 挑战 | 含义 |
|---|---|
| **路由不稳** | 训练初期 router 随机，专家分配混乱 |
| **负载不均衡** | 少数"明星专家"被反复用，其他专家被冷落 |
| **Token Drop** | 单个专家容量满了，超额 token 被丢弃 |
| **专家坍缩** | 专家学到完全相同的表示，失去多样性 |
| **通信开销** | EP 的 All-to-All 是分布式瓶颈 |
| **显存压力** | 所有专家都要持有，显存压力巨大 |

### 1.2 经典解法

#### Aux Loss（辅助损失）

强制平衡负载——惩罚"分配过度集中"的情况：

$$\mathcal{L}_{\text{aux}} = N \sum_i f_i \cdot p_i$$

- $f_i$：分配到第 $i$ 个专家的 token 比例
- $p_i$：路由器给第 $i$ 个专家的平均概率
- 让 $f$ 和 $p$ 都接近 $1/N$（均匀）

#### Capacity Limit（容量上限）

每个专家最多处理 $\text{capacity\_factor} \times \text{batch\_size} / N$ 个 token。
超额的 token 被 drop 掉（直接走残差）。

### 1.3 DeepSeek 的最新解法

1. **Aux-loss-free 策略**：用 bias 调整替代 aux loss，避免 loss 干扰
2. **细粒度专家**：把每个专家进一步切小，提高组合多样性（256 个专家 vs 8 个）
3. **共享专家**：1-2 个"始终激活"的专家学通用知识
4. **DeepEP 通信优化**：自研 All-to-All kernel，通信和计算重叠

```text
MoE 现状：能用、好用、但门槛高。
开源 MoE：Mixtral、Qwen-MoE、DeepSeek-V3、Kimi K2
```

## Q2: 长上下文（128K+）的核心瓶颈？怎么解？

### 2.0 先做背景铺垫

**长上下文** = 让模型一次能处理 100K-1M+ token 的输入。
**典型场景**：长文档分析、代码仓库理解、超长对话历史。

**核心矛盾**：模型架构和数据规模都没完全适配长上下文。

### 2.1 三大瓶颈

#### ① 计算瓶颈（attention 是 $O(n^2)$）

- 4K → 128K，attention 计算量增加 **1024 倍**
- 训练成本爆炸

**解法**：
- **FlashAttention**：IO 优化（不是减少计算，是减少 HBM 读写）
- **稀疏 attention**：Longformer / BigBird 之类
- **SWA（Sliding Window Attention）**：只看近 N 个 token

#### ② 显存瓶颈（KV Cache + 激活值线性增长）

- 128K 序列的 KV Cache 单用户就 ~42 GB（70B 模型）
- 训练时激活值也线性增长

**解法**：
- **Ring Attention**：把 KV 分布到多卡，环形传递
- **序列并行**（SP / Megatron-SP）
- **Gradient Checkpointing**

#### ③ 位置编码外推问题

- RoPE 训练 4K，直接推 128K → 远距离旋转角度落在训练分布之外，attention 失常

**解法**：
- **YaRN**：调整 RoPE 频率分布
- **NTK 插值**：高频和低频差异化处理
- **PI（Position Interpolation）**：直接缩放位置索引
- **LongRoPE**：搜索式找最优插值

### 2.2 训练策略

```text
1. 短上下文预训练（4K-8K）→ 学会语言基础
2. 长上下文继续训练（32K-128K）→ 适应长依赖
3. 评测看 RULER / LongBench → 不要只看 NIAH（针在草垛中）
```

### 2.3 评测的注意点

**NIAH（Needle in a Haystack）"刷分"陷阱**：
NIAH 只考察"能不能在长文中找到一个特定片段"，但不能反映模型对**长程理解、多跳推理**的能力。

→ **要看 RULER / LongBench 等多任务评测**，才能反映真实长上下文能力。
