## Q1: FlashAttention 究竟优化了什么？

### 1.0 先做背景铺垫

**朴素 attention 的实现**：
```
1. 算 S = Q K^T          # n × n 大矩阵
2. P = softmax(S)
3. O = P V
```

把整个 **$n \times n$ 注意力矩阵**写到 HBM（GPU 全局显存），再读回来算 softmax 和 V 乘——**反复读写显存**。

**HBM** = High Bandwidth Memory，GPU 的"主显存"，容量大但带宽相对慢。
**SRAM** = on-chip 的小快内存，比 HBM 快 ~10 倍但只有几 MB。

### 1.1 核心：是 IO 优化，不是 FLOP 优化

**关键认识**：GPU 上 attention 是 **memory-bound**（HBM 带宽是瓶颈，不是算力不够）。

朴素实现的痛点：
- 显存占用 $O(n^2)$（要存完整 attention 矩阵）
- HBM 读写次数 $O(n^2)$（每次访问都过显存）

### 1.2 FlashAttention 三大技巧

1. **分块（Tiling）**：把 Q/K/V 切成小块塞进 SRAM
2. **Online Softmax**：分块算 softmax，维护 running max 和 running sum
3. **反向时重计算**：不存中间结果，反向需要时重新算

→ **HBM IO 从 $O(n^2)$ 降到 $O(n)$，计算量不变**。

### 1.3 实际效果

| 版本 | 加速比 |
|---|---|
| FlashAttention v1（2022） | 2-3× |
| FlashAttention v2（2023） | 再快 1.5× |
| FlashAttention v3（H100 优化） | 再快 1.5× |

**实际加速**：相对朴素 attention 约 2-4×，序列越长加速越显著。

## Q2: KV Cache 显存怎么算？如何降低？

### 2.0 先做背景铺垫

**为什么需要 KV Cache**：
LLM 自回归生成时，每生成一个新 token 都要算 attention。
但**历史 token 的 K 和 V 不会变**——所以缓存起来下次复用，每次只算新 token 的 K/V。

→ 把 attention 复杂度从"每步 $O(t^2)$"降到"每步 $O(t)$"。

### 2.1 显存公式（必背）

$$\text{KV Cache} = 2 \times L \times s \times h \times d_h \times \text{bytes}$$

**符号说明**：
- $2$：K 和 V 两份
- $L$：层数
- $s$：序列长度
- $h$：KV 头数（MHA 中 = 头数；GQA 中 = 组数）
- $d_h$：每头维度
- $\text{bytes}$：精度（BF16/FP16 = 2，INT8 = 1，INT4 = 0.5）

### 2.2 一个具体例子

**LLaMA-3-70B，128K 序列，FP16**：
- $L = 80, s = 131072, h = 8, d_h = 128$，FP16 = 2 bytes
- KV Cache = $2 \times 80 \times 131072 \times 8 \times 128 \times 2 / 10^9$
- ≈ **42 GB / 用户**

→ 单卡 80GB 装不下！这就是为什么长上下文部署这么困难。

### 2.3 5 大降低手段

1. **架构层**：MQA / GQA / **MLA**（DeepSeek MLA 缩 30+×）
2. **量化**：INT8 / INT4 / FP8 KV Cache
3. **淘汰**：H2O / StreamingLLM / SnapKV，丢弃低注意力 token
4. **复用**：Prefix Caching、PagedAttention（vLLM）
5. **Offload**：把不常用的 KV 卸到 CPU 内存或 NVMe

```text
真实部署常用组合：
  GQA + Paged + Prefix Caching + INT8 KV Cache
```

## Q3: 量化为什么不能直接对所有层用 INT4？

### 3.0 先做背景铺垫

**量化** = 把 FP16/BF16 权重压到 INT8 / INT4 / FP8。
**好处**：显存减半甚至减 1/4、推理快 1.5-3×。
**代价**：精度损失。

**问题**：能不能把整个模型一刀切都量化到 INT4？**不行**——某些层敏感。

### 3.1 4 类敏感层

1. **LayerNorm / RMSNorm 的输入**：归一化会**放大**量化误差
2. **第一层**：直接接收 embedding，扰动会被放大到全网
3. **最后一层（LM Head）**：决定输出 logits 分布，量化误差直接影响生成
4. **Attention 中的 softmax 输入**：尖锐分布对误差敏感（一个 token 概率从 0.99 变 0.50 就可能改变输出）

### 3.2 激活值的 outlier 问题

某些 channel 的激活数值**特别大**（outlier），均匀量化无法兼顾：
- 量化范围按 outlier 设 → 普通值损失精度
- 量化范围按普通值设 → outlier 截断

**解法**：**SmoothQuant** 等技巧——把激活的 outlier "搬到" 权重上：

$$Y = X W = (X / s) (s W)$$

让 $X / s$ 平滑、$s W$ 仍易量化。

### 3.3 工业实践：混合精度量化

```text
敏感层 → FP16 / FP8
其余层 → INT4 / INT8
```

→ **性能 + 显存 + 精度**三方平衡。
