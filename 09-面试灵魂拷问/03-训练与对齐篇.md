## Q1: PPO 和 DPO 的本质区别？

### 1.0 先做背景铺垫

**PPO**（Proximal Policy Optimization）：经典强化学习算法，OpenAI 用它做 InstructGPT/ChatGPT 的 RLHF。

**DPO**（Direct Preference Optimization, NeurIPS 2023）：用偏好数据**直接做监督学习**，绕过 RM 和 RL。

### 1.1 本质区别

| | PPO | DPO |
|---|---|---|
| 范式 | 在线 RL（actor-critic） | 监督学习（pairwise 偏好损失） |
| 是否需要 RM | **是**（先训 RM，再 RL） | **否**（直接用偏好对训 policy） |
| 模型数量 | 4（actor + critic + RM + ref） | 2（policy + ref） |
| 训练稳定性 | 难（RL 调参敏感） | 易（监督学习） |
| 显存 | 大 | 小 |
| 数据 | 在线采样（rollout） | 静态偏好集 |
| 效果上限 | 高 | 略低或持平 |

### 1.2 DPO 推导核心

DPO 的精妙之处：**从 RLHF 最优解的解析形式反解 reward**，代入 Bradley-Terry 偏好模型 → 得到一个纯监督形式的损失：

$$\mathcal{L}_{\text{DPO}} = -\mathbb{E}\left[\log \sigma\left(\beta \log \frac{\pi_\theta(y_w|x)}{\pi_{\text{ref}}(y_w|x)} - \beta \log \frac{\pi_\theta(y_l|x)}{\pi_{\text{ref}}(y_l|x)}\right)\right]$$

→ 把 RL 问题变成"对比学习"，**没有 reward model 也没有采样过程**。

### 1.3 怎么选

| 场景 | 选 |
|---|---|
| 学术 / 资源有限 | **DPO**（实现简单、稳定） |
| 工业 / 持续在线数据 / 极致效果 | **PPO**（探索能力强） |

## Q2: PPO 损失函数完整构成 + 大模型场景下 advantage / returns 怎么算？

> 这是 RLHF 面试**最深的题**。要能把每一项的来源、含义、在大模型里的具体计算讲清楚。

### 2.0 先做背景铺垫：4 个核心概念

| 概念 | 含义 | 在 LLM 里的对应 |
|---|---|---|
| **state** $s_t$ | 当前状态 | 已生成的 prompt + 历史 token |
| **action** $a_t$ | 动作 | 选择下一个 token |
| **reward** $r_t$ | 奖励 | RM 分数 + KL 惩罚 |
| **advantage** $A_t$ | 优势 = "比平均好多少" | 用 GAE 算（见 Q5） |
| **returns** $R_t$ | 回报 = "未来累积奖励" | $A_t + V(s_t)$ |

### 2.1 PPO 完整目标函数

**3 项组合**：

$$\mathcal{L}_{\text{PPO}}(\theta) = \mathbb{E}_t \left[ \mathcal{L}_t^{\text{CLIP}}(\theta) - c_1 \, \mathcal{L}_t^{\text{VF}}(\phi) + c_2 \, S[\pi_\theta](s_t) \right]$$

**符号说明**：
- $\theta$：actor（policy）参数
- $\phi$：critic（value head）参数
- $c_1, c_2$：损失加权系数（典型 $c_1=0.5, c_2=0.01$）

### 2.2 三项分别拆解

**① 策略损失（CLIP）—— 核心**：

$$\mathcal{L}_t^{\text{CLIP}}(\theta) = \min\left( \rho_t(\theta) \, A_t, \; \text{clip}(\rho_t(\theta), 1-\epsilon, 1+\epsilon) \, A_t \right)$$

- $\rho_t(\theta) = \dfrac{\pi_\theta(a_t \mid s_t)}{\pi_{\theta_{\text{old}}}(a_t \mid s_t)}$：**重要性采样比**（ratio）
- $A_t$：**优势**
- $\epsilon$：clip 阈值（典型 0.2）
- 作用：**单步策略更新被限制在 $\pm \epsilon$ 内**，防止 RL 不稳

**② Value 损失（MSE）**：

$$\mathcal{L}_t^{\text{VF}}(\phi) = \big( V_\phi(s_t) - R_t \big)^2$$

- 让 critic 学会准确估计每个状态的"未来总收益"

**③ 熵奖励**：

$$S[\pi_\theta](s_t) = -\sum_a \pi_\theta(a \mid s_t) \log \pi_\theta(a \mid s_t)$$

- 鼓励 policy 不要过早收敛到尖锐分布
- 在 LLM RLHF 中通常很小（KL 已经在控制）

### 2.3 ratio 的直觉

$$\rho_t = \frac{\pi_\theta(a_t \mid s_t)}{\pi_{\theta_{\text{old}}}(a_t \mid s_t)}$$

- $\rho_t > 1$：新策略对该动作概率**比旧策略高** → 倾向"鼓励"
- $\rho_t < 1$：新策略**降低**了该动作概率
- $\rho_t = 1$：策略未变

**为什么需要它**：PPO 是 **off-policy**——用旧策略采的样本训新策略，需要重要性采样校正。
**clip 的作用**：偏离 1 太多就**截断梯度**，防止策略跳得太远。

### 2.4 advantage 的直觉

$$A_t \approx Q(s_t, a_t) - V(s_t)$$

- $A_t > 0$：动作 $a_t$ 比"当前状态平均水平"好 → 推高它的概率
- $A_t < 0$：比平均差 → 降低概率

**为什么不直接用 $r_t$**？方差极大。减掉 baseline $V(s_t)$ → 方差骤减、训练稳定。

### 2.5 大模型 RLHF 中 advantage 怎么算？

**关键认识**：把"生成一个回答"看作一个 episode，**每个 token 是一步 action**。

**Step 1：reward 设计**

$$r_t = \begin{cases}
- \beta \log \dfrac{\pi_\theta(a_t \mid s_t)}{\pi_{\text{ref}}(a_t \mid s_t)}, & t < T \\[6pt]
r_{\text{RM}}(x, y) - \beta \log \dfrac{\pi_\theta(a_t \mid s_t)}{\pi_{\text{ref}}(a_t \mid s_t)}, & t = T
\end{cases}$$

- 中间 token 只有 KL 惩罚（per-token）
- 最后一个 token 加上 RM 给的总分（end-of-sequence reward）
- $\beta$：KL 系数（典型 0.01-0.1）

**Step 2：critic 估每个状态的 value**

通常在 actor 模型上加一个标量输出 head 作为 critic（共享前向）：

$$V_\phi(s_t) = \text{value\_head}(\text{hidden}_t)$$

**Step 3：用 GAE 算 advantage**（详见 Q5）

$$\delta_t = r_t + \gamma V(s_{t+1}) - V(s_t)$$

$$A_t^{\text{GAE}} = \sum_{l=0}^{T-t} (\gamma \lambda)^l \, \delta_{t+l}$$

### 2.6 大模型 PPO 中 returns 具体怎么求解？

**returns** = "状态 $s_t$ 之后的累积奖励"。

**方法 A：returns = advantage + value**（推荐，与 GAE 配合）

$$R_t = A_t^{\text{GAE}} + V_\phi(s_t)$$

直觉：$A_t = R_t - V_t$，所以 $R_t = A_t + V_t$。

**方法 B：直接折扣累积**

$$R_t = r_t + \gamma r_{t+1} + \gamma^2 r_{t+2} + \dots$$

从尾部往前递推。

```text
RLHF 实践通常是：
  returns = GAE_advantage + value
  critic loss = MSE(V_φ(s_t), returns)
```

### 2.7 完整训练循环（伪代码）

```python
for ppo_step in range(num_ppo_epochs):
    # 1. Rollout：用 policy 采样
    responses = policy.generate(prompts)
    log_probs_old = policy.log_prob(responses)        # 旧策略 log π_old

    # 2. 算 reward（RM 评分 + KL 惩罚）
    rm_scores = rm(prompts, responses)
    kl = log_probs_old - ref.log_prob(responses)
    rewards = build_rewards(rm_scores, kl)            # per-token reward

    # 3. 算 value、advantage、returns（GAE）
    values = critic(responses)
    advantages, returns = compute_gae(rewards, values)
    advantages = (advantages - mean) / std            # 归一化

    # 4. PPO 多轮更新（off-policy 优势）
    for _ in range(num_inner_epochs):
        log_probs_new = policy.log_prob(responses)
        ratio = exp(log_probs_new - log_probs_old)

        L_clip = min(ratio * advantages, clip(ratio, 1-ε, 1+ε) * advantages)
        L_vf   = (critic(responses) - returns) ** 2

        loss = -L_clip + c1 * L_vf - c2 * entropy
        loss.backward()
        optimizer.step()
```

## Q3: GRPO 相比 PPO 省了什么？

### 3.0 先做背景铺垫

**GRPO**（Group Relative Policy Optimization）：DeepSeek 在 DeepSeek-Math 论文提出，DeepSeek-R1 大规模验证。

### 3.1 省了 Critic 模型

PPO 需要 4 个模型：actor + critic + RM + ref。
GRPO **去掉 critic**：3 个模型即可。

### 3.2 怎么省的？

不再用 critic 估 value、不再用 GAE 算 advantage。
**对同一 prompt 采样 $G$ 个答案，组内 mean/std 作为 baseline**：

$$A_i = \frac{r_i - \text{mean}(r_1, \dots, r_G)}{\text{std}(r_1, \dots, r_G)}$$

- $G$：组大小（典型 4-16）
- $r_i$：第 $i$ 个答案的奖励（规则给出或 RM 给出）

### 3.3 优势

1. **省显存**（少一个大模型）
2. **数学/代码任务用规则奖励即可**（无需 RM）
3. **训练更稳**（组内归一化天然降方差）

### 3.4 DeepSeek 选它的原因

R1-Zero / R1 在数学、代码上做大规模 RL：**规则奖励 + GRPO 极简洁** → 触发"推理涌现"（长 CoT、self-correction）。

## Q4: LoRA 为什么有效？r 怎么选？

### 4.0 先做背景铺垫

**LoRA**（Low-Rank Adaptation, Microsoft 2021）：
冻结原模型 $W$，只训练一个**低秩增量** $\Delta W = BA$：

$$y = W x + B A x$$

**符号**：$A \in \mathbb{R}^{r \times d}$，$B \in \mathbb{R}^{d \times r}$，$r \ll d$（典型 8-32）。

### 4.1 为什么有效？

1. **大模型的任务适应主要发生在低秩子空间**（"内在维度"低）
2. $\Delta W$ 是低秩的，可分解为 $\Delta W = B A$
3. 论文证明 **$r = 1$ 在很多任务上都够用**

### 4.2 初始化技巧

- $A$ 用高斯随机初始化
- $B$ 用零初始化
- 训练开始时 $\Delta W = 0$ → **不破坏原模型**，逐步学习增量

### 4.3 r 怎么选？

| 任务复杂度 | $r$ |
|---|---|
| 简单（指令格式）| 4-8 |
| 中等（领域适应） | 16-32 |
| 复杂（新能力） | 32-64 或全参微调 |

**经验**：$r = 8$ 是甜点。

### 4.4 缩放系数 $\alpha$

实际公式：

$$y = W x + \frac{\alpha}{r} B A x$$

- $\alpha$ 控制 LoRA 的"强度"
- 典型 $\alpha = r$ 或 $\alpha = 2r$
- 调 $\alpha$ 等价于调 LoRA 的学习率

## Q5: MSE 损失 + GAE 在大模型 RL 训练中的作用

### 5.0 先做背景铺垫：critic 是什么

PPO 框架里的 critic = 一个**输出标量的小网络**，用来估每个状态 $s_t$ 的"未来总收益期望" $V(s_t)$。

LLM RLHF 中通常**和 actor 共享 backbone**，只换一个 value head（一个标量输出 head）→ 共享前向，省一半显存。

### 5.1 MSE 损失：critic 怎么学

$$\mathcal{L}_{\text{MSE}} = \frac{1}{N} \sum_t \big( V_\phi(s_t) - R_t \big)^2$$

**符号**：
- $V_\phi(s_t)$：critic 在状态 $s_t$ 估的 value
- $R_t$：真实 returns（GAE 算出来的目标值）
- $N$：样本数

**作用**：
1. **训练 critic**：让 $V_\phi$ 学会准确估计每个状态的"未来总收益"
2. **为 advantage 提供基准**：$A_t = R_t - V_\phi(s_t)$，需要 critic 准才能减小方差

**为什么用 MSE**：value 是连续标量 → 回归问题 → MSE 自然，梯度均匀。

### 5.2 GAE：advantage 怎么算（必背）

**先看朴素做法的问题**：

| 方法 | 形式 | 偏差 / 方差 |
|---|---|---|
| 真实 returns 减 value | $R_t - V(s_t)$ | 无偏，**方差极大** |
| 1-step TD | $r_t + \gamma V(s_{t+1}) - V(s_t)$ | **偏差大**（$V$ 估不准时） |

→ 都不好。

**GAE 思想**：**多步 TD 的指数加权平均**，平衡偏差和方差。

$$\boxed{ A_t^{\text{GAE}} = \sum_{l=0}^{T-t} (\gamma \lambda)^l \, \delta_{t+l} }$$

**符号**：
- $\delta_t = r_t + \gamma V(s_{t+1}) - V(s_t)$：1-step TD 误差
- $\gamma$：折扣因子（典型 0.99，RLHF 常用 1.0）
- $\lambda$：GAE 平滑因子（典型 0.95）
  - $\lambda = 0$：退化为 1-step TD（低方差、高偏差）
  - $\lambda = 1$：退化为 Monte Carlo returns（高方差、无偏）
  - $\lambda = 0.95$：经验最优折中

### 5.3 GAE 反向递推实现

正向算太麻烦，**反向递推**最简洁：

$$A_t = \delta_t + \gamma \lambda \cdot A_{t+1}$$

```python
def compute_gae(rewards, values, gamma=1.0, lam=0.95):
    """
    rewards: [T] per-token reward
    values:  [T+1] value estimates
    """
    T = len(rewards)
    advantages = [0] * T
    last_gae = 0
    for t in reversed(range(T)):
        delta = rewards[t] + gamma * values[t+1] - values[t]
        last_gae = delta + gamma * lam * last_gae
        advantages[t] = last_gae
    returns = [adv + v for adv, v in zip(advantages, values[:-1])]
    return advantages, returns
```

### 5.4 角色总结表

| 概念 | 算什么 | 谁用 | 怎么算 |
|---|---|---|---|
| **MSE** | critic 损失 | PPO（不是 GRPO） | $(V_\phi - R_t)^2$ |
| **GAE** | per-token advantage | PPO | $\sum (\gamma\lambda)^l \delta_{t+l}$ |
| **returns $R_t$** | value 学习目标 | PPO 的 critic | $A_t + V_t$ |
| **advantage $A_t$** | policy 梯度权重 | PPO / GRPO | GAE 或组内归一化 |

```text
PPO：每 token advantage（GAE）+ critic（MSE）
GRPO：每 episode advantage（组内归一化）+ 无 critic
```

## Q6: 7B 模型全参微调 vs LoRA 显存？

### 6.0 先做背景铺垫：训练时显存大头

每个参数训练时要存：

| 项 | 大小（每参数） |
|---|---|
| 参数（BF16） | 2 字节 |
| 梯度（BF16） | 2 字节 |
| Adam $m$（FP32） | 4 字节 |
| Adam $v$（FP32） | 4 字节 |
| FP32 主权重副本 | 4 字节 |
| **合计** | **16 字节 / 参数** |

→ 7B 模型模型状态约 **112 GB**（远超单卡 80GB）。

### 6.1 全参微调

- **模型状态**：~112 GB
- **激活值**（4K seq, batch 4，无 GC）：~30 GB
- **总：~140 GB** → 单卡 80GB 装不下，需要 ZeRO 或 TP/PP

### 6.2 LoRA（r=8）

LoRA 只训练 $A, B$ 两个小矩阵（参数量 ~0.5%）：

- **Base**（BF16，**冻结**）：14 GB
- **LoRA + 优化器**：~600 MB
- **激活**（开 Gradient Checkpointing）：~10 GB
- **总：~25 GB** → 单卡 40GB 可跑

### 6.3 QLoRA（4-bit base）

进一步把 base 量化到 4-bit：

- **Base（INT4）**：~4 GB
- **LoRA + 优化器**：~600 MB
- **激活**：~10 GB
- **总：~15 GB** → **4090 等消费级 GPU 可跑**

### 6.4 一张总结表

| 方案 | 显存需求 | 可跑硬件 |
|---|---|---|
| 全参微调 | ~140 GB | 多卡 A100/H100 + ZeRO |
| LoRA | ~25 GB | 单 A6000 / A40 |
| QLoRA | ~15 GB | RTX 4090 |
