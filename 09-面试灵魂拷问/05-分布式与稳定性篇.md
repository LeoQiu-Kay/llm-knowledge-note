# 灵魂拷问 · 分布式与稳定性篇

> 1 道题。**Loss spike 排查**——大模型训练工程师的"日常题"。

---

## Q1: Loss spike 怎么排查？

### 1.0 先做背景铺垫

**Loss spike**（loss 毛刺）：训练过程中 loss 突然飙升（如从 2.5 跳到 8.0）。

**3 种典型形态**：
- **可恢复**：spike 后自动回落 → 不影响最终训练
- **发散**：loss 完全停不下来 → 必须回滚
- **NaN**：直接出现 nan/inf → 立刻挂掉

→ 大模型训练动辄几十天 + 几千卡，**spike 一旦失控就等于浪费几十万美元算力**。

### 1.1 排查 5 步法（按顺序）

#### Step 1：看日志

- 检查 spike 前后的 **loss 走势**和 **grad_norm**
- spike 是突然发生还是渐进？grad_norm 是先涨还是同步涨？
- 这能初步判断是"梯度爆炸"还是"数据问题"

#### Step 2：看数据

当前 batch 是否异常？
- **token 长度异常**（比如某个 sample 是 100K token）
- **token id 异常**（tokenizer bug 产生 OOV）
- **内容异常**（重复的 spam 数据）

→ 单独跑这个 batch，能不能复现？

#### Step 3：看梯度

哪一层 grad 异常大？
- 通常是**第一层**或**最后一层**先出问题
- 看是否跨层"传染"
- 看激活值是否有 **inf / nan**

#### Step 4：看精度

FP16 下：
- 是否溢出？loss scaling 是否过大？
- 切到 BF16 试试

#### Step 5：看优化器状态

- Adam 的 $v$ 是否突然很小？分母趋零会让步长爆炸
- 检查是否需要重置优化器状态

---

### 1.2 处理方案

| 问题 | 处理 |
|---|---|
| 数据异常 | 回滚 checkpoint + 跳过坏 batch |
| 梯度过大 | 降低 LR / 加严梯度裁剪（grad_clip 1.0 → 0.5） |
| FP16 溢出 | 切到 BF16 |
| 优化器异常 | 检查 warmup、$\beta_2$ 调到 0.95 |
| 数据流污染 | 检查数据 pipeline，加上长度过滤 |

---

### 1.3 预防三件套（必做）

```text
✓ BF16 替代 FP16（不需要 loss scaling）
✓ 充分 warmup（前 1000-2000 步线性升 LR）
✓ grad_clip = 1.0
+ 数据预清洗（过滤超长 / 异常 / 重复样本）
```

---

### 1.4 几个真实案例

| 模型 | spike 原因 | 处理 |
|---|---|---|
| OPT 175B | FP16 数值不稳 | 多次回滚 + 调 LR |
| GLM-130B | 数据混合比例突变 | 调整数据 pipeline |
| BLOOM | 梯度尖峰 | 加严 grad_clip |

```text
大模型训练日志 ≈ 调试史。Spike 一定会出现，关键是有没有充分的
监控 + 回滚机制。
```
