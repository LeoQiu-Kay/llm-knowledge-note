# 量化（Quantization）

> 让大模型跑在小硬件上的关键技术，GPTQ/AWQ 必知。

---

## Q1: 为什么需要量化？

**答**：
**问题**：
- LLaMA-2-70B 用 FP16 需要 140GB 显存，单 A100/H100 80GB 装不下
- 推理是 memory-bound，更小数据类型 = 更快加载 = 更快推理
- 边缘设备（手机、笔记本）只有 8-32GB 内存

**量化的好处**：
- **显存节省**：INT4 是 FP16 的 1/4
- **带宽节省**：HBM 读速度等比提升
- **推理加速**：通常 1.5-3×
- **代价**：精度损失（要尽量小）

---

## Q2: PTQ vs QAT？

**答**：

| 维度 | PTQ（训练后量化） | QAT（量化感知训练） |
|------|------------------|-------------------|
| 时机 | 训练完后量化 | 训练过程中模拟量化 |
| 数据需求 | 少量校准集（几百样本） | 完整训练集 |
| 训练成本 | 低（几小时） | 高（重新训练） |
| 精度 | 中等 | 高 |
| LLM 主流 | **是**（GPTQ、AWQ） | 少（成本高） |

**为什么 LLM 多用 PTQ**：
- 重训成本高（动辄数百万美元）
- PTQ 用聪明的算法（GPTQ、AWQ）已能保持效果

## Q3: 对称量化 vs 非对称量化？

**答**：
**对称量化**：
$$x_{quant} = \text{round}(x / s)$$
$$x_{dequant} = x_{quant} \cdot s$$
- 0 映射到 0
- 简单，硬件友好

**非对称量化**：
$$x_{quant} = \text{round}(x / s) + z$$
$$x_{dequant} = (x_{quant} - z) \cdot s$$
- 引入 zero-point $z$
- 更精确（特别是分布偏移的情况）

**LLM 中**：权重多对称（接近正态分布），激活/KV Cache 多非对称（有偏移）。

## Q4: GPTQ 的原理？

**答**：
**核心思想**：基于二阶信息（Hessian）的逐层量化。

**算法**（OBQ 优化版）：
1. 逐层量化（按重要性排序）
2. 对每个权重列：
   - 量化当前列
   - 用剩余未量化列**补偿**量化误差
3. 利用 Hessian 矩阵的逆来计算最优补偿

**关键公式**：
$$\Delta W_{\text{rest}} = -\frac{w_q - \hat w_q}{[H^{-1}]_{qq}} \cdot [H^{-1}]_{q, \text{rest}}$$

**优势**：
- 效果好（INT4 几乎无损）
- 速度快（4-bit 70B 模型几小时完成）
- 开源实现成熟（AutoGPTQ）

---

## Q5: AWQ 的原理？

**答**：
**AWQ**（Activation-aware Weight Quantization）核心：**激活值大的 weight channel 更重要**，保护它们。

**关键观察**：
- 直接量化所有 weight 一视同仁，效果差
- 实际只有 1% 的 weight 是"显著"的（对应 outlier 激活）
- 保留这 1% 用 FP16，其余 INT4，效果就显著提升

**算法**：
1. 用少量校准数据统计激活幅度
2. 对 weight 做 per-channel scaling，把"重要" channel 缩放到能更精确量化
3. 量化后乘回缩放

**伪代码**：
```python
s = activation_scale  # 重要 channel scale 大
W' = W * s            # 缩放
W_q = quantize(W')    # 量化
# 推理: y = (W_q @ x) / s
```

**优势**：
- 比 GPTQ 略好或持平
- 不需要 backward
- 硬件友好

## Q6: SmoothQuant 的原理？

**答**：
**目的**：让 W8A8（权重和激活都 INT8）成为可能。

**问题**：激活值有 outlier，直接 INT8 量化失真严重。

**SmoothQuant 解法**：把 outlier 从激活"转移"到权重。

**关键公式**：
$$Y = (X \text{diag}(s)^{-1}) \cdot (\text{diag}(s) W)$$

- $X' = X / s$：激活变平滑
- $W' = s \cdot W$：权重承担难度
- 数学上等价，但 X' 更易量化

**$s$ 的选择**：让 X' 和 W' 都易量化的平衡点（如 $s = \max(|X|)^\alpha / \max(|W|)^{1-\alpha}$，$\alpha=0.5$）。

**适用**：需要 INT8 激活的场景（如 INT8 推理）。

## Q7: NF4 数据类型？

**答**：
**NF4**（Normal Float 4）：QLoRA 提出，专为正态分布权重设计的 4-bit 类型。

**原理**：
- 量化值不均匀分布，而是按标准正态分布的分位数选取
- 让正态分布权重的量化误差最小化

**对比**：
- INT4：均匀分布 16 个量化点
- FP4：浮点 4-bit，1 符号 + 2 指数 + 1 尾数
- NF4：16 个非均匀点（中间密、两端疏）

**效果**：在正态分布权重上误差比 INT4 / FP4 都小。

## Q8: W4A16 / W8A8 / W4A8 是什么意思？

**答**：
**符号约定**：W = Weight 精度，A = Activation 精度。

| 类型 | 含义 | 节省 | 适用 |
|------|------|------|------|
| W16A16 | FP16 权重 + FP16 激活 | 基线 | 标准 |
| W8A8 | INT8 权重 + INT8 激活 | 2× 显存 + 算力 | TRT-LLM |
| W4A16 | INT4 权重 + FP16 激活 | 主要省显存 | GPTQ/AWQ 主流 |
| W4A8 | INT4 权重 + INT8 激活 | 更激进 | 高性能场景 |
| FP8 | 8-bit 浮点 | 介于 INT8 和 BF16 | H100 友好 |

**最常用**：**W4A16**（GPTQ/AWQ），平衡精度与速度。

---

## Q9: 量化敏感层有哪些？

**答**：
**经验**：以下层对量化更敏感，应保留更高精度：
1. **LayerNorm / RMSNorm 的输入**：normalization 之后会放大量化误差
2. **第一层**：直接接收 embedding，敏感
3. **最后一层（LM Head）**：决定输出分布
4. **Attention 中的 softmax 输入**：尖锐分布对量化误差敏感

**应对**：
- 这些层用 FP16 / FP8
- 其他层用 INT4
- 称为**混合精度量化**

## Q10: KV Cache 量化 vs Weight 量化？

**答**：

| 维度 | Weight 量化 | KV Cache 量化 |
|------|------------|-------------|
| 节省什么 | 权重显存 | 长上下文显存 |
| 时机 | 一次性（PTQ） | 流式（每个 token 量化） |
| 敏感度 | 较低 | K 高、V 低 |
| 主流方案 | GPTQ、AWQ、INT4 | INT8、FP8 per-token |

**可组合**：权重 W4 + KV Cache INT8，节省叠加。

---

## Q11: 量化对效果的影响？

**答**：
**经验数据**（典型 LLM）：

| 精度 | MMLU 损失 | 显存节省 |
|------|-----------|---------|
| FP16 | 0%（基线） | 1× |
| INT8 (W8A8) | < 0.5% | 2× |
| INT4 (W4A16, GPTQ/AWQ) | 1-2% | 4× |
| INT3 | 3-5% | 5.3× |
| INT2 | > 10% | 8× |

**结论**：
- **INT4 是甜点**：效果损失可接受，节省显著
- INT3 / INT2 损失大，仅在极端场景用

## Q12: 量化的硬件支持？

**答**：

| 硬件 | INT8 | INT4 | FP8 | FP4 |
|------|------|------|-----|-----|
| V100 | ✓ | × | × | × |
| A100 | ✓ | ✓（emulated） | × | × |
| H100 | ✓ | ✓ | ✓（E4M3/E5M2） | × |
| B200 | ✓ | ✓ | ✓ | ✓ |

**FP8 在 H100 / Blackwell**：原生支持，速度比 BF16 翻倍。
**INT4**：需要打包到 INT8/INT32 中存储，反量化为 FP16 计算。

## 🎯 高频追问

1. **GPTQ 和 AWQ 哪个更好**？效果接近，AWQ 略简单（无需 backward），GPTQ 历史悠久。实践上 AWQ 略主流。
2. **为什么不用 INT2**？精度损失大，硬件支持差，目前不实用。
3. **量化要重新校准吗**？PTQ 需要校准数据（几百个样本），通常用 WikiText 等通用数据。
4. **量化模型还能微调吗**？是 QLoRA 的核心：base 量化 + LoRA 微调。
5. **FP8 与 INT8 哪个好**？FP8 有指数位，动态范围大，对 outlier 友好；INT8 精度均匀。H100 上 FP8 通常更好。
6. **量化对长上下文影响大吗**？是的，长上下文 KV Cache 量化误差累积明显，需要精细方案。
