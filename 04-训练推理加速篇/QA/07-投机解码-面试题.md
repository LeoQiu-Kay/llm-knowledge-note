## Q1: 投机解码的核心思想是什么？为什么能加速？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥🔥

**核心三步**：
1. **快草稿模型** $M_q$ **顺序**生成 $k$ 个 token
2. **慢目标模型** $M_p$ **并行**（一次 forward）验证这 $k$ 个 token
3. 接受正确的、从错误位置重新开始

**为什么有效**：
- Decode 是 memory-bound，单 token forward 算力闲置
- 大模型一次 forward $k$ 个 token 比 $k$ 次 forward 1 个 token 快**得多**（接近 prefill，矩阵乘吃满算力）
- 草稿模型成本远低于目标模型

**加速来源**：把"$k$ 次串行 decode"变成"1 次并行验证 + 草稿成本"。

**符号说明**：$M_p$ target model（目标，慢但准），$M_q$ draft model（草稿，快但不准），$k$ 草稿长度。

## Q2: 投机解码的拒绝采样算法（白板题）
> 难度 ⭐⭐⭐⭐ ｜ 高频 🔥🔥🔥

```text
Repeat:
    1. 草稿: 从 M_q 顺序采样 x_1, ..., x_k，记录每个 q(x_i)
    2. 验证: 用 M_p 一次 forward 这 k 个 token，得每个位置的 p(x_i)
    3. 对每个 i = 1..k 顺序检查:
       u ~ Uniform(0, 1)
       if u < min(1, p(x_i) / q(x_i)):
           接受 x_i
       else:
           拒绝 x_i
           从分布 max(0, p - q)（归一化后）采一个 token x'
           跳出，从下一轮重新开始
    4. 若全部接受: 从 M_p 的第 k+1 位置采一个 bonus token
```

**关键性质**：**输出分布与直接用 $M_p$ 采样完全一致**——拒绝采样的标准结果。

**追问：bonus token 是怎么"白送"的？** $M_p$ 验证 $k$ 个 token 时，第 $k+1$ 位置的 logits 顺带算出来了，全部接受时直接采样即可。

## Q3: 为什么投机解码不改变输出分布？
> 难度 ⭐⭐⭐⭐ ｜ 高频 🔥🔥

**直觉**：
- 接受概率 $\min(1, p/q)$ 把草稿分布 $q$ "校正"成 $p$（高估的 token 被以 $p/q$ 概率保留）
- 被拒时从 $\max(0, p - q)$ 重采样，恰好补上分布差（草稿欠的部分）
- 这是经典拒绝采样的标准技巧

**严格证明**：对任意 token $x$，最终被采纳的概率 = $q(x) \cdot \min(1, p/q) + \text{(被拒后重采到 } x\text{)} = p(x)$。

**意义**：可以放心用，不会损失质量。

## Q4: 加速比公式是什么？哪些因素决定加速效果？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥

$$\text{Speedup} = \frac{1 - \alpha^{k+1}}{(1 - \alpha)(1 + c k)}$$

**符号说明**：
- $\alpha$：单 token 接受率（典型 0.5-0.8）
- $k$：草稿长度（典型 4-8）
- $c$：草稿/目标的成本比（越小越好）

**核心驱动**：
- $\alpha$ 高（草稿和目标接近） → 加速明显
- $c$ 小（草稿便宜） → 加速明显
- $k$ 太小：加速有限；太大：草稿成本暴涨

**典型加速**：
- 普通投机解码：1.5-2.5×
- + EAGLE：3-4×

**何时收益小**：高 batch（大模型已 GPU 满载）；接受率低（领域不匹配）。

## Q5: 草稿模型怎么选？
> 难度 ⭐⭐ ｜ 高频 🔥🔥

**硬性要求**：
1. **同 tokenizer**（词表必须一致，否则 $p, q$ 比不了）
2. **同分布**（草稿和目标预测相似）→ 高接受率
3. **足够小**（成本远低于目标）
4. **覆盖目标领域**

**常见选择**：
- Llama-3-8B 作为 Llama-3-70B 的草稿（同系列）
- TinyLlama 或自训小模型
- **量化版本**：INT4 大模型作为草稿，FP16 大模型作为目标
- **N-gram 模型**：极轻量，适合特定模式
- **检索式草稿**：从历史 / 文档检索短语

## Q6: Medusa 是怎么改造投机解码的？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥

**核心改动**：**不用独立小模型**，在**目标模型本身**上加多个 head，并行预测多个未来 token。

**结构**：
```text
基础 Transformer 主干
  ↓ 最后一层 hidden state
LM Head                  → 预测 token[t+1]（原 head）
Medusa Head 1           → 预测 token[t+2]
Medusa Head 2           → 预测 token[t+3]
...
```

**推理流程**：
1. 一次 forward 得到 token[t+1] + token[t+2..] 候选
2. 构造**候选树**（每个位置取 top-k，组合成树）
3. 大模型再 forward 验证整棵树（**树 attention**）

**优点**：硬件友好，不需独立小模型
**缺点**：需要训练 Medusa head；多 head 预测越远准确率越降

**典型加速**：1.5-2.5×。

---

## Q7: EAGLE 为什么比 Medusa 好？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥🔥

**核心创新**：用一个小 Transformer 解码器作草稿，输入是目标模型的**隐藏状态**（而非 token）。

**结构**：
```text
Target model: [base layers] → hidden state h_t → token x_t
                                    ↓
EAGLE Draft: [small decoder using h_t] → x_{t+1}, x_{t+2}, ...
```

**为什么更好**：
- 隐藏状态比 token 信息更丰富（包含上下文、不确定性）
- 草稿模型基于 hidden state 比基于 token 更准确
- 接受率比 Medusa 高 → 加速更大

**EAGLE-2/3 改进**：动态调整草稿长度、优化候选树选择，加速进一步提升。

**典型加速**：3-4×（当前 SOTA）。

## Q8: Lookahead Decoding 有什么特别？
> 难度 ⭐⭐ ｜ 高频 🔥

**特点**：**无需训练**，纯算法层面。

**原理**：
- 维护 n-gram 候选池
- 每步同时验证旧候选 + 生成新候选
- 类似 Jacobi 迭代的并行计算

**优势**：即插即用，无需训练
**劣势**：加速比有限（1.5-2×）；实现较复杂

**适用场景**：无法训练草稿模型的部署环境（如直接拿现成模型）。

## Q9: 投机解码和 Continuous Batching 是什么关系？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥

**单请求场景**：投机解码加速明显。

**多请求 / 高 batch 场景**：
- Continuous Batching 已让大模型保持高利用率（多请求摊薄权重读取）
- 投机解码的**相对**收益降低（因为 decode 不再 memory-bound 主导）
- 但在**长 CoT** 等场景仍能受益

**实践规律**：
- 高 QPS / 短回复 → 主要靠 batching
- 低 QPS / 长 CoT → **投机解码 + EAGLE** 显著加速

## Q10: 为什么推理模型（o1/R1）特别受益于投机解码？
> 难度 ⭐⭐⭐ ｜ 高频 🔥🔥

**两个核心原因**：

1. **CoT 中有大量"思考连接词"和推理模板**——草稿模型容易猜对（"Let me think", "Therefore", "Wait"），接受率超 70%
2. **生成超长（数千 token）**——加速的绝对收益巨大

**实测**：EAGLE + 投机解码可让 R1-style 推理加速 3-4×，是目前生产部署推理模型的关键技术。

**追问：普通 Chat 模型为什么收益小？** 输出短（几百 token）；token 分布更随机（多样化措辞），接受率较低。

---

## Q11: 投机解码有质量风险吗？多级（hierarchical）能行吗？
> 难度 ⭐⭐⭐ ｜ 高频 🔥

**质量风险**：理论上**无**（数学等价于直接从 $M_p$ 采样），但实现 bug 可能引入差异（如 numerical issue）。

**多级投机**：可以——比如 INT4 → INT8 → FP16，每级都是上一级的草稿。
- 优势：每级加速叠加
- 劣势：复杂度高，每级都要校准接受率

实践中两级（草稿 + 目标）已够，三级以上工程收益边际递减。
