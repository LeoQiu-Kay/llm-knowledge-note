# 投机解码（Speculative Decoding）

> 推理加速关键技术。Medusa / EAGLE 是 SOTA。

---

## 1. 核心思想

**问题**：自回归解码是**串行**的，单步只生成 1 个 token，GPU 利用率低（decode 是 memory-bound，但算力闲置）。

**思路**：
1. 让一个**快的草稿模型** $M_q$ 一次生成多个 token
2. 让**慢的目标模型** $M_p$ **并行**验证这些 token
3. 接受正确的、从错误位置重新开始

**为什么有效**：
- 大模型一次 forward 处理 $k$ 个 token 比 $k$ 次 forward 处理 1 个 token 快得多（GPU 喜欢大矩阵乘）
- 草稿模型快但不准；大模型慢但准
- 总体 tokens/sec 大幅提升

---

## 2. 算法详解

**符号说明**：
- $M_p$：target model（目标模型，慢但准）
- $M_q$：draft model（草稿模型，快但不准）
- $p(x)$：目标模型给 $x$ 的概率
- $q(x)$：草稿模型给 $x$ 的概率
- $k$：草稿长度（典型 4-8）

**算法**：
```
Repeat:
    1. 草稿: x_1, ..., x_k ~ M_q（顺序采样 k 个 token）
       记录每个 token 的概率 q(x_i)
    
    2. 验证: 用 M_p 一次 forward 这 k 个 token
       得到 M_p 给每个位置的概率 p(x_i)
    
    3. 对每个位置 i = 1..k 顺序检查:
       u ~ Uniform(0, 1)
       if u < min(1, p(x_i) / q(x_i)):
           接受 x_i
       else:
           拒绝 x_i
           从分布 max(0, p - q) 重采一个 token x'
           跳出循环，从下一步重新开始
    
    4. 若全部接受: 从 M_p 的 k+1 位置采一个 bonus token
```

**关键保证**：**输出分布与直接用 $M_p$ 采样完全一致**（数学证明）。

---

## 3. 为什么不改变输出分布？

**关键性质**：拒绝采样后的分布等价于直接从 $M_p$ 采样。

**直觉**：
- 接受概率 $\min(1, p/q)$ 调整 $q$ 让其匹配 $p$
- 被拒时从 $\max(0, p - q)$ 采样恰好补足分布差
- 经典拒绝采样的标准结果

```text
可以放心使用，不损失质量。
```

---

## 4. 加速比公式

$$\text{Speedup} = \frac{1 - \alpha^{k+1}}{(1 - \alpha)(1 + c k)}$$

**符号说明**：
- $\alpha$：单 token 接受率（典型 0.5-0.8）
- $k$：草稿长度
- $c$：草稿模型 / 目标模型成本比（越小越好）

**实际加速**：
- 普通投机解码：1.5-2.5×
- + EAGLE：3-4×

**何时收益小**：
- 高 batch（大模型已 GPU 满载）
- 接受率低（领域不匹配）

---

## 5. 草稿模型怎么选？

**要求**：
1. **同 tokenizer**：词表必须一致
2. **同分布**：草稿和目标预测相似（接受率高）
3. **足够小**：成本远低于目标模型
4. **覆盖目标领域**

**常见选择**：
- Llama-3-8B 作为 Llama-3-70B 的草稿
- TinyLlama / 自训小模型
- 同系列小模型（如 Qwen 系列）
- **量化版本**（如 INT4 大模型作为草稿，FP16 大模型作为目标）

**特殊形式**：
- **N-gram 模型**：极轻量草稿（适合特定模式）
- **检索式草稿**：从历史检索短语作为草稿

## 6. Medusa：在目标模型上加多 head

**思路**：不用独立小模型，在目标模型上加多个 head，并行预测多个未来 token。

**结构**：
```
基础 Transformer 主干
  ↓
LM Head (预测下一个 token)
+
Medusa Head 1 (预测下下个 token)
+
Medusa Head 2 (预测下下下个 token)
+ ...
```

**推理流程**：
1. 一次 forward 得到下一个 token + 多个未来 token 候选
2. 构造**候选树**（每个位置取 top-k，组合成树）
3. 大模型再 forward 验证整棵树（树注意力）

**优点**：
- 不需要独立小模型，硬件友好
- 实现简单

**缺点**：
- 需要训练 Medusa head
- 多 head 准确度递减

**典型加速**：1.5-2.5×

---

## 7. EAGLE：当前 SOTA

**EAGLE**（Extrapolation Algorithm for Greater Language-model Efficiency）：

**核心创新**：用一个**小 Transformer 解码器**作为草稿，输入是目标模型的**隐藏状态**（而非 token）。

**为什么更好**：
- 隐藏状态比 token 信息更丰富（包含上下文）
- 草稿模型从隐藏状态更准确预测下一个 token
- 接受率比 Medusa 高

**结构**：
```
Target model: [base layers] → hidden state h_t → token x_t
                                ↓
EAGLE Draft: [small decoder] → x_{t+1}, x_{t+2}, ...
```

**EAGLE-2 / EAGLE-3**：进一步优化候选选择、动态调整草稿长度，加速 3-4×。

---

## 8. Lookahead Decoding

**特点**：不需要训练，纯算法层面。

**原理**：
- 维护 n-gram 候选池
- 每步同时验证旧候选 + 生成新候选
- 类似 Jacobi 迭代的并行计算

**优势**：即插即用，无需训练。
**劣势**：加速比有限（1.5-2×）；实现复杂。

---

## 9. 投机解码 + Continuous Batching

**单请求场景**：投机解码加速明显。

**多请求场景**：
- Continuous Batching 已让大模型保持高利用率
- 投机解码相对收益降低
- 但仍能在**长 CoT 等场景**受益

**实践**：
- 高 QPS / 短回复场景：主要靠 batching
- 低 QPS / 长 CoT 场景：投机解码 + EAGLE 显著加速

## 🎯 高频追问

1. **草稿长度 $k$ 怎么选**？典型 4-8。太大草稿成本高，太小加速有限。

2. **草稿完全错怎么办**？拒绝后从大模型采样，最多退化为标准自回归（不会更慢）。

3. **可以多级投机吗**？可以（hierarchical），如 INT4 → INT8 → FP16，但复杂度高。

4. **投机解码会有质量风险吗**？理论上无（数学等价分布），实现 bug 可能引入微小差异。

5. **GPU 利用率为什么提高**？大模型一次 forward $k$ 个 token 接近 prefill，矩阵乘比单 token decode 快得多。
