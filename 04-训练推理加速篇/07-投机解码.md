# 投机解码（Speculative Decoding）

> 推理加速的关键技术，Medusa / EAGLE 是当前 SOTA。

---

## Q1: 投机解码的核心思想？

**答**：
**问题**：自回归解码是串行的，单次只生成 1 个 token，GPU 利用率低。

**思路**：
1. 让一个**快的草稿模型**（小模型）一次生成多个 token
2. 让**慢的目标模型**（大模型）**并行**验证这些 token
3. 接受正确的，从错误位置重新开始

**为什么有效**：
- 大模型一次 forward 处理 k 个 token 比 k 次 forward 处理 1 个 token 快得多（GPU 喜欢大矩阵乘）
- 草稿模型快但不准；大模型慢但准
- 总体 token/s 大幅提升

---

## Q2: 投机解码的算法详解？

**答**：
**符号**：
- $M_p$：目标模型（target），生成最终 token
- $M_q$：草稿模型（draft），生成候选 token

**算法**：
```
Repeat:
    1. 草稿: x_1, ..., x_k ~ M_q (k 个 token)
       记录每个 token 的概率 q(x_i)
    
    2. 验证: 用 M_p 一次 forward 这 k 个 token
       得到 M_p(x_i | history) = p(x_i)
    
    3. 对每个位置 i = 1..k:
       u ~ Uniform(0, 1)
       if u < min(1, p(x_i) / q(x_i)):
           接受 x_i
       else:
           拒绝 x_i
           从分布 max(0, p - q) 重采一个 token x'
           跳出，从下一步重新开始
    
    4. 若全部接受: 从 M_p 的 k+1 位置采一个 bonus token
```

**关键保证**（论文证明）：**最终输出分布与直接用 $M_p$ 采样完全一致**。

---

## Q3: 投机解码为什么不改变输出分布？

**答**：
**关键性质**：拒绝采样后的分布等价于直接从 $M_p$ 采样。

**直觉**：
- 接受概率 $\min(1, p/q)$ 调整了 $q$ 让其匹配 $p$
- 被拒时从 $\max(0, p-q)$ 采样恰好补足分布差
- 这是经典拒绝采样的标准结果

**意味着**：可以放心使用，不损失质量。

---

## Q4: 投机解码的加速比？

**答**：
**理论加速**：
$$\text{Speedup} = \frac{1 - \alpha^{k+1}}{(1-\alpha)(1 + ck)}$$

- $\alpha$：单 token 接受率（典型 0.5-0.8）
- $k$：草稿长度
- $c$：草稿模型 / 目标模型成本比（越小越好）

**实际**：
- 普通投机解码：1.5-2.5× 加速
- 投机解码 + EAGLE：3-4× 加速
- 推理任务（长 CoT，可预测）加速更明显

**何时收益小**：
- 高 batch（大模型本身 GPU 已满载）
- 接受率低（领域不匹配）

## Q5: 草稿模型怎么选？

**答**：
**要求**：
1. **同 tokenizer**：词表必须一致
2. **同分布**：草稿和目标模型预测应该相似（接受率高）
3. **足够小**：成本远低于目标模型
4. **覆盖目标领域**：草稿对应任务表现要 OK

**常见选择**：
- Llama-3-8B 作为 Llama-3-70B 的草稿
- TinyLlama / 自训小模型
- 同系列小模型（如 Qwen 系列）
- 量化版本（如 INT4 大模型作为草稿，FP16 大模型作为目标）

**特殊形式**：
- **N-gram 模型**：极轻量草稿（适合特定模式）
- **检索式草稿**：从历史检索短语作为草稿

## Q6: Medusa 是什么？

**答**：
**思路**：不用独立小模型，在目标模型上加多个 head 并行预测多个未来 token。

**结构**：
```
基础 Transformer 主干
  ↓
LM Head (预测下一个 token)
+
Medusa Head 1 (预测下下个 token)
+
Medusa Head 2 (预测下下下个 token)
+ ...
```

**推理流程**：
1. 一次 forward 得到下一个 token + 多个未来 token 候选
2. 构造**候选树**（每个位置取 top-k，组合成树）
3. 大模型再 forward 验证整棵树（树注意力）

**优点**：
- 不需要独立小模型，硬件友好
- 上手简单
- ~2× 加速

**缺点**：
- 需要训练（Medusa head）
- 多 head 准确度递减

## Q7: EAGLE 是什么？

**答**：
**EAGLE**（Extrapolation Algorithm for Greater Language-model Efficiency）：

**核心创新**：用一个**小 Transformer 解码器**作为草稿，但输入是目标模型的**隐藏状态**而非 token。

**为什么用隐藏状态**：
- 隐藏状态比 token 信息更丰富（包含上下文）
- 草稿模型可以从隐藏状态更准确预测下一个 token
- 接受率比 Medusa 高

**结构**：
```
Target model: [base layers] → hidden state h_t → token x_t
                                ↓
EAGLE Draft: [small decoder] → x_{t+1}, x_{t+2}, ...
```

**EAGLE-2 / EAGLE-3**：进一步优化候选选择、动态调整草稿长度，目前是 SOTA，加速 3-4×。

## Q8: Lookahead Decoding？

**答**：
**特点**：不需要训练，纯算法层面。

**原理**：
- 维护 n-gram 候选池
- 每步同时验证旧候选 + 生成新候选
- 类似 Jacobi 迭代的并行计算

**优势**：
- 即插即用，无需训练
- 适合特定可预测模式

**劣势**：
- 加速比有限（1.5-2×）
- 复杂场景效果弱

---

## Q9: 投机解码 vs 减少 token 数量？

**答**：
**两类加速思路**：

1. **保持质量，提高每步效率**：
   - 投机解码、Medusa、EAGLE
   - 输出与原模型一致

2. **减少需要生成的 token**：
   - 减少 CoT 长度
   - 跳过冗余表达
   - 改变输出分布

**实际**：两者可组合，投机解码先用，再考虑能否减少冗余 token。

---

## Q10: 投机解码与 Continuous Batching 的关系？

**答**：
**单请求场景**：投机解码加速明显。

**多请求场景**：
- Continuous Batching 已让大模型保持高利用率
- 投机解码的相对收益降低
- 但仍能在长 CoT 等场景受益

**实践**：
- 高 QPS / 短回复场景：主要靠 batching
- 低 QPS / 长 CoT 场景：投机解码 + EAGLE 显著加速

## Q12: 推理模型（o1/R1）如何受益于投机解码？

**答**：
**特别适合**：
- CoT 中有大量"思考连接词"、推理模板，草稿模型容易预测
- 接受率往往超过 70%
- 投机解码 + EAGLE 可让 R1 推理加速 3-4×

**实际**：R1 类长 CoT 模型是投机解码最佳受益场景。

## 🎯 高频追问

1. **投机解码的 k 怎么选**？典型 4-8。太大草稿成本高，太小加速有限。
2. **如果草稿模型完全错怎么办**？拒绝后从大模型采样，最多退化为标准自回归（不会更慢）。
3. **可以多级投机吗**？可以（hierarchical speculative），如 INT4 → INT8 → FP16，但复杂度高。
4. **投机解码会有质量风险吗**？理论上无（数学证明等价分布）；实现 bug 可能引入差异。
5. **GPU 利用率为什么会提高**？大模型一次 forward k 个 token 接近 prefill，矩阵乘比单 token decode 快得多。
