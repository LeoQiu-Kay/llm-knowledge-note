# 高效注意力（FlashAttention / PagedAttention）

> 现代 LLM 推理引擎的两大基石。

---

## 1. FlashAttention 解决了什么？

**问题**：标准 Attention 需要在 HBM 中读写完整 $n \times n$ 注意力矩阵 $S = QK^T$。

- 显存：$O(n^2)$（attention 矩阵本身）
- HBM 读写量：极大

**关键认识**：GPU 上 attention 是 **memory-bound**，不是 compute-bound！

```text
A100：算力 ~300 TFLOPs，HBM 带宽 ~2 TB/s。
attention 的算术强度太低，瓶颈是访存。
```

**FlashAttention 核心**：**IO-aware** 算法。
- 重新组织计算，**永远不在 HBM 中实例化完整 $S$ 和 $P = \text{softmax}(S)$**
- 用**分块**（tiling）+ **online softmax** + **重计算**（recomputation）
- 减少 HBM 读写，把数据保持在 SRAM 中复用

**结果**：HBM IO 从 $O(n^2)$ 降到 $O(n)$，计算量不变。

---

## 2. 分块策略（Tiling）

**分块思想**：把 $Q, K, V$ 都按行分块，每块塞进 SRAM 计算。

**伪代码**：
```
for j in range(N / B):              # K, V 块循环（外层）
    load K_j, V_j into SRAM
    for i in range(N / B):          # Q 块循环（内层）
        load Q_i into SRAM
        S_ij = Q_i @ K_j.T          # 块矩阵乘
        在 SRAM 中做 online softmax
        累积更新 O_i
    write O_i back to HBM
```

**符号说明**：
- $N$：序列长度
- $B$：块大小（block size）
- $Q_i, K_j, V_j$：分块后的 Q、K、V
- $S_{ij}$：块对应的局部 attention scores
- $O_i$：第 $i$ 个 Q 块对应的输出

---

## 3. Online Softmax：关键技巧

**问题**：softmax 需要全局 max 和 sum，分块时不知道全局值。

**算法**：维护 running max $m$ 和 running sum $\ell$：

```python
m = -inf, l = 0, O = 0
for block in blocks:
    m_new = max(m, max(block))
    # 缩放旧的累积值
    O = O * exp(m - m_new)
    l = l * exp(m - m_new)
    # 加入新块的贡献
    l += sum(exp(block - m_new))
    O += exp(block - m_new) @ V_block
    m = m_new
O = O / l
```

**符号说明**：
- $m$：running max（保证数值稳定）
- $\ell$：running sum（softmax 分母）
- $O$：累积的输出
- $m_{\text{new}}$：当前块的新最大值

**保证**：与一次性算的 softmax 数值等价。

## 4. FlashAttention v1 / v2 / v3

| 版本 | 关键创新 | 效果 |
|---|---|---|
| **v1**（Tri Dao 2022） | tiling + online softmax | 2-4× 加速 |
| **v2**（2023） | 优化 work partitioning（Q 外层）、减少非矩阵乘 | 再加速 2× |
| **v3**（2024） | 针对 Hopper（H100）优化、TMA 异步加载、FP8 | 接近峰值算力（~75%） |

**典型加速**（H100 上 v3 vs PyTorch SDPA）：约 2-3×。

## 5. 反向传播：重计算（Recomputation）

**问题**：反向需要 $S, P$ 矩阵，但前向没保存。

**解法**：只保存 $O$ 和 softmax 归一化常数（$m, \ell$），反向时**重新算** $S = QK^T$ 和 $P$。

```text
代价：~30% 额外算力
收益：显存从 O(n²) 降到 O(n)
```

## 6. PagedAttention（vLLM）

### 6.1 解决什么？

**朴素 KV Cache 问题**：
- 每个请求一次性分配 max_seq_len 大小的连续内存
- 大部分时间未填满 → **内存碎片化**
- 实际利用率往往只有 20-40%

### 6.2 借鉴操作系统分页

**核心做法**：
1. KV Cache 切成固定大小的 **block**（如 16 个 token 一块）
2. 每个请求维护一个 **block table**（类似页表）
3. 物理上 block 分散在内存中，逻辑上通过 block table 连接
4. 按需分配，用完即释放

```
请求 1 [token_1, ..., token_35]
逻辑视图: [block 0][block 1][block 2]
block table: [phys 7][phys 3][phys 11]
物理内存: 离散分散
```

**效果**：
- 内存利用率 > 90%
- 支持更高并发
- 自然支持 **block 级共享**（多个请求共享 prefix block）

### 6.3 Block Sharing

多个请求共享相同前缀时：
- 检测前缀 block hash 相同
- 多个请求的 block table 指向**同一物理 block**
- 引用计数管理生命周期
- **Copy-on-Write**：如果某请求要修改共享 block，先拷贝再改

## 7. RadixAttention（SGLang）

**核心**：基于 **Radix Tree**（基数树）的 KV Cache 前缀复用。

**与 vLLM Prefix Caching 区别**：
- vLLM：基于 block 的哈希匹配（粒度较粗）
- SGLang：基于字符级 Radix Tree，**更精细**

**优势**：
- 多分支共享更好（如同 prompt 不同 few-shot 例子）
- LRU 自动淘汰
- 长上下文 / 多分支推理（Tree-of-Thoughts）场景明显加速

---

## 8. Ring Attention（训练用）

**目标**：训练超长上下文（百万 token+）。

**核心**：在多设备间**环形传递** K/V 块。

**算法**：
1. 把序列按设备数 $N$ 切分，每设备持有一段 Q/K/V
2. 每个设备先用本地 K/V 算注意力
3. 在环形拓扑中传递 K/V 到下一设备
4. 累积所有设备的贡献，得到全局 attention 输出

**优势**：
- 支持任意长度（与设备数线性扩展）
- 与 FlashAttention 兼容

**应用**：Gemini 1.5（1M context）、LLaMA-3 长上下文训练。

## 10. 最简记忆

```text
FlashAttention（kernel 层）：
  分块 + online softmax + 重计算
  不实例化 n×n 矩阵 → HBM IO 从 O(n²) 降到 O(n)
  v1/v2/v3 迭代优化

PagedAttention（内存层 - vLLM）：
  把 KV Cache 切 block，类似 OS 页表
  消除碎片 → 利用率 > 90%
  block 共享支持 Prefix Caching

RadixAttention（SGLang）：
  Radix Tree 管理前缀，更细粒度复用
  适合多分支、Tree-of-Thoughts

Ring Attention（训练）：
  环形传 K/V，支持任意长序列
```

## 🎯 高频追问

1. **FlashAttention 加速的本质**？减少 HBM IO，数据保持在 SRAM 中复用。

2. **PagedAttention 的 block size 怎么选**？典型 16（vLLM 默认）。太小调度开销大；太大碎片回来。

3. **FlashAttention 必须用 GPU 吗**？是。专为 GPU 内存层级（HBM/SRAM）设计。

4. **训练和推理都能用 FlashAttention 吗**？都能。训练用 forward + backward；推理只用 forward。

5. **PagedAttention 比 FlashAttention 更上层吗**？是。FA 是 kernel 优化，PA 是内存管理；通常一起用。
